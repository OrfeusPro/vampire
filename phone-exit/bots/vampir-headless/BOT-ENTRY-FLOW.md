# Вход бота и проверки аккаунта

Это требования к общему контроллеру будущего бота. Отдельного переключателя в
попапе аккаунта нет. Сейчас реализованы очередь верификации панели и её CLI;
встраивание проверок в обычный игровой вход и восстановление после отключения
ещё не подключены. Отдельная успешная верификация их не подтверждает.

## Последовательность

1. Один владелец аккаунта закрепляет допущенный пакет точного SHA клиента,
   назначенный шаблон и маршрут. Ключи и общее имя устройства берутся из
   хранилища, а не генерируются при каждом входе.
2. Свежий NID / SDK ответ определяет необходимые проверки. Известные состояния
   `device-registration` и `workplace` обрабатываются существующим адаптером:
   регистрация устройства перед снятием защиты. Незнакомое состояние останавливает
   автомат с причиной и возможностью ручного продолжения.
3. Официальные формы открываются из того же контекста авторизации. Имя для
   регистрации берётся из шаблона. Вторую авторизацию параллельно текущему этапу
   не создавать; весь `verify-account.py` из уже авторизованного входа не вызывать.
4. Свежий код `@vampir.top` получать существующим IMAP-адаптером отдельно для
   аккаунта и этапа. Для Google пользователь проходит вход и вводит код Gmail.
   При невозможности автоматического ввода открывать нужную официальную форму
   с причиной ожидания ручного ввода. CAPTCHA остаётся ручной. Срок кода — десять
   минут; истёкший код или неизвестный результат не отправлять повторно вслепую.
5. Продолжение требует положительного ответа и callback формы. Результат
   сохраняется с fingerprint устройства, этапом и временем. Закрытие окна само
   по себе не означает успех. Stop отменяет ожидания и дальнейшие действия.
6. Отдельная задача «Верифицировать» закрывает свои соединения. Обычный вход
   бота после проверок продолжает сервер / персонажа и мир только по действующему
   игровому admission. Проверка почты не предоставляет отсутствующий допуск.

## Отключение и требование перезапуска

Различать потерю транспорта, явное требование повторного входа, регистрацию
устройства, защиту аккаунта и Stop. Сохранять причину и последний подтверждённый
этап. Незнакомому ответу не приписывать смысл «нужен перезапуск»: сначала
подтвердить его контракт на текущем SHA.

По подтверждённому требованию сервера завершать только старый транспорт аккаунта
и выполнять один последовательный повторный вход с тем же устройством и свежими
временными credentials. Затем проходить реально запрошенные проверки. Повтор
того же требования, известный отказ / ограничение и неизвестный результат
останавливают автомат до ручного продолжения. Бесконечного цикла входов нет.
После Stop автомат не запускается самостоятельно.

Одно событие не создаёт второй worker или несколько запросов письма. Пользователь
видит причину отключения, этап и ожидание ручного ввода. В журнал не попадают
пароли, коды, токены и URL с ними.

## Подключение к существующим частям и обновлению

Готовые части: `verify-account.py` (`verify`, `web_url`, `browser`),
`run-nid-sdk-sign-in.py` (свежий контекст), `nid-mail-code.py` (новое письмо),
`account-worker.py` и очередь в `account-manager.py`. При интеграции выделить
продолжение официальных форм из `verify` в общий адаптер и передавать уже
полученные SDK данные и подготовленный контекст. [Текущий контракт](ENTRY-DIAGNOSTICS.md).

Критерии реализации: только одна / обе / ни одной известной проверки, IMAP и
ручной код, отказ и истечение срока, подтверждённый повторный вход, дубликат
события, Stop и незнакомый ответ. Серверное требование перезапуска ещё нуждается
в доказательстве; его wire code не придумывать. Fixtures отдельно от онлайн.

База — существующие `verification-web-current.json`,
`google-verification-web-current.json`, source check SDK Launcher и группа
`account-verification`. Новый общий helper и потребителей сразу зарегистрировать
в зависимостях `research-checks.json` / `tooling-groups-v1.json`. Новый серверный
контракт оформлять через `prepare → collect → finish`, adapter и `on_update`
с кэшем. Готовые неизменные доказательства вручную не повторять.
[Критерий готовности](../AGENTS.md#новая-возможность-vampir-и-автообновление).
