# Runtime: запрос списка и выбор персонажа

20 октября 2026. В общем переносимом коде добавлен владелец состояния
`CharacterSelectionFlow`: он связывает уже проверенные codecs с очередью
отправки одного соединения. В модуле нет сокетов, Unreal, эмулятора или
инструментов исследования. Это часть будущего сетевого клиента, а не готовый
runner реального входа.

## Поведение

Владелец сетевой сессии создаёт одну очередь `OutboundFrames` и один flow
для каждого соединения. Он отвечает за авторизацию, подтверждение устройства,
транспорт, разделение входящих кадров и вызов `close()` при разрыве.

```text
waiting_entry
  → enter_list() → ID101 → list_pending
  → ID102, code 0 → list_available
  → select(index) → ID109 → select_pending
  → ID110, code 0 → select_response
```

`enter_list()` — явное разрешение от внешнего жизненного цикла. Flow сам
не вызывает его после LoginResult: одного результата входа недостаточно
для подтверждения policy и перехода в выбор персонажа. Проверенные native
пути запроса списка описаны в источниках ниже; их автоматическое подключение
к реальному соединению остаётся отдельной задачей.

ID102 декодируется целиком с лимитами байт, персонажей и вложенных записей.
Предпочтительный индекс доступен для UI, но выбор требует явного `select()`.
Пустой список не превращается в выбор индекса 0. ID109 использует ключ текущей
записи, raw32 = 0 и текущий rawF0, первоначально полученный из `tail[3]` ID102.
`update_raw_f0()` позволяет владельцу применить подтверждённое изменение
контекста до выбора, сохраняя установленное поведение native setter.

ID110 также разбирается полностью с общим лимитом вложенных записей.
`select_response` означает получение успешного тела ответа. Оно не означает
готовый игровой мир, известную позицию, завершённую загрузку или возможность
отправки ID205. Не добавлены автоматические запросы ID201–205.

## Ошибки и границы соединения

- Допустим один ожидаемый запрос. Повторное действие и ответ вне ожидаемого
  состояния отклоняются без новой отправки; другие ID возвращают false для
  обработки остальным клиентом.
- При отказе очереди состояние запроса и sequence не меняются. После
  освобождения очереди допустим явный повтор действия до создания запроса.
- Таймаут отсчитывается с постановки в очередь, по монотонным часам владельца.
  Ответ в момент deadline уже считается поздним. Автоматических повторов нет.
- Повреждённое тело, превышение лимита, таймаут или неподдержанный result code
  переводят flow в `failed`, удаляют данные персонажей и закрывают очередь,
  включая неотправленный остаток частичного кадра. Владелец должен закрыть
  соответствующий сокет; flow сам сетевых операций не выполняет.
- Локальная политика допускает только code 0. Особая native-ветвь `0x1197`
  зависит от дополнительного состояния, которого здесь нет; она требует
  внимания владельца, а не считается универсальной ошибкой игры.
- `close()` очищает данные и всю очередь соединения, включая ping и
  подтверждения смены ключа. После разрыва создавать новые queue / flow;
  старые ответы нельзя передавать новому экземпляру. Автовосстановление
  авторизации и повторного входа пока не реализовано.

Фреймы используют общие sequence и ключ соединения. Подтверждение смены ключа
сохраняет прежний порядок: ack под старым ключом, последующая отправка под новым.
В repr не выводятся поля персонажей и содержимое ответа; ошибки декодирования
не содержат входные байты.

`character-select-result-replay.json`. Это синтетические профили исполнения
настоящего кода, а не сетевые записи аккаунта. SHA исходных отчётов записаны
в fixture. Эти тесты запускаются без Ghidra, EXE, Capstone и Unicorn.

```powershell
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_selection_flow.py
python -X utf8 -m unittest discover -s phone-exit/bots -p 'test_vampir_headless_send*.py'
```

Пройдены 12 новых и 15 прежних тестов: полная локальная цепочка, 19 native
кадров, ключ и sequence, частичная отправка, отказ очереди, некорректный индекс,
дубликаты, чужие ID, ошибочные тела / лимиты / коды, таймаут и разрыв.
Реальная сессия и движение персонажа этими тестами не проверяются.

входа, затем продолжение после ID110 и источник мировой позиции.
