# Настоящий игровой Version через HK

20 октября 2026. Проверка выполнена без запуска игры. Использованы код и
данные установленного клиента, а не исходный C++ проект.

## Результат

Свежий SDK SignIn → LobbyVersionResult 0 → LobbyLoginResult 0 → ID 104 с
кодом 0. Список полностью разобран: 55 групп, 98 серверных записей, тело
11 338 байт; обмен с лобби — 545 байт отправлено, 11 466 получено.

Затем открыто отдельное соединение с игровым endpoint из этого списка.
Получен **игровой VersionResult, ID 2, код 0**: отправлено 199 байт,
получено 25, уведомлений смены ключа не было. Выбран server ID 101,
group ID 1. Сокет закрыт; временный HK-клиент остановлен с exit 0.
Игровой Login, список персонажей, выбор и позиция ещё не получены.

Выбор `lowest-valid-id` — явная локальная диагностическая политика:
наименьший ID, для которого запись уникальна и endpoint проходит проверки.
Она не доказывает доступность сервера, регион или наличие персонажа.
Порядок массива не влияет на выбор. Можно вместо неё задать `--server-id`.
Отказ выбранного сервера не запускает перебор других адресов.

До успешной проверки одна попытка завершилась общим RuntimeError без
сохранённого этапа. Её причину установить по этому результату нельзя.
После добавления отметок этапов и повторной проверки HK новая ограниченная
попытка прошла цепочку до игрового VersionResult. Автоматических повторов нет.

## Источники и воспроизведение

EXE SHA256:
`c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`.
Профиль `recovered-base`, AppVersion `1.12.14`; его loader проверяет SHA
кода и данных клиента. Поля Version собираются существующим
[builder](probe-game-version.py) из наблюдённых CPU, Windows, NMDeviceKey
и локального IPv4 текущего соединения.

Свежие публичные снимки получены через SOCKS на 127.0.0.1:17948:

- CDN: `F:/PhoneExit Resources/Vampir/public-cdn-snapshots/e96053f62ad71ee54486b14cf9c24f30ca0f9ebb8b0d8185f970c6d142034ba4/manifest.json`;
  HTTP 200, 6000 байт.
- GMC2: `F:/PhoneExit Resources/Vampir/public-gmc2-snapshots/8d0bdf6c921f960c7b7b6109a74aa69060143b51b8013dce1104feaf2835beda/manifest.json`;
  HTTP 200, 13 777 байт.

Имена каталогов — SHA256 manifest. Источник полей endpoint и ограничения
selector описаны в [связи записи лобби с игровым адресом](../resource-tools/vampir/knowledge/evidence/network/HEADLESS-LOBBY-RECORD-ENDPOINT.md).
Схема Version и обработка ключа — в [предыдущем исследовании](VERSION-PROBE.md).
В этой проверке использован игровой адрес из ID 104, поэтому старый timeout
игрового Version на адресе CDN-лобби к этому результату не относится.

Запуск из корня проекта; пароль передаётся только через stdin:

```powershell
python -X utf8 phone-exit/bots/vampir-headless/probe-selected-game-version.py `
  --email bot-hk-test@vampir.top --profile recovered-base `
  --manifest 'F:/PhoneExit Resources/Vampir/public-cdn-snapshots/e96053f62ad71ee54486b14cf9c24f30ca0f9ebb8b0d8185f970c6d142034ba4/manifest.json' `
  --socks-port 17948 --server-policy-byte 0 --selection lowest-valid-id --password-stdin
```

Перед повторной внешней проверкой нужны действующий выбранный HK-транспорт
и свежие CDN / GMC2 snapshots. Маршруты Windows этот инструмент не меняет.
Таймауты: окно NID — 180 секунд, лобби — 15, игровой обмен — 10.
Диагностика печатает фиксированные названия этапов, коды, счётчики и ID;
пароли, ключи устройства, токены и сырые ответы не сохраняются.

## Локальные проверки и следующий шаг

Прошли 20 проверок: четыре selected-game-version, пять Version probe,
шесть SDK runner и пять lobby login probe. Проверены выбор независимо от
порядка, неоднозначные ID, неподдерживаемая ветвь, отказ до сети, сохранение
этапа ошибки без её содержимого и закрытие игрового сокета при ошибке decoder.

Следующий шаг — завершить источники оставшихся полей игрового Login и
связать его с принятым Version на том же соединении. Нельзя использовать
этот закрывающий сокет Version probe как готовую игровую сессию.
