# NID → SDK: первая попытка входа без игры

Windows osVersion теперь заполняется наблюдением GetVersionExW собственного
процесса бота. Отказ API сохраняет пустое поле. Повторный SDK SignIn через HK
с заполненным значением успешен. [Источник и границы](../resource-tools/vampir/HEADLESS-VERSION-WINDOWS-CONTEXT.md).

Актуальный результат 20 октября: отдельный аккаунт зарегистрирован через HK;
его SDK SignUp и SignIn приняты, получены player ID и SDK token.
Игрового входа пока нет. [Сценарий и источники](NID-REGISTRATION.md).
Следующие абзацы описывают предшествовавшие отказы UA-аккаунта.

Добавлен явный `--socks-port` для общего маршрута WebView2 и SDK. Публичный
GMC2 перед ним нужно заново получить через тот же порт. Реальные попытки HK
не устранили 1602; установлено различие NID joinedCountryCode UA и SDK country HK.
[Установка, проверки и текущий результат](SOCKS-ROUTE.md).

Текущее уточнение: сообщение SignIn 1203 — `not exist player channel`.
Найден и добавлен отдельный SDK SignUp. Явный `--create-sdk-player` выбирает
создание вместо входа; без автоматического fallback или последующего SignIn.
Две попытки получили HTTP 400 / 1602, `not allowed country for game`.
Создание SDK-игрока и игровая сессия не подтверждены.
[Источники, countryCode и проверки](../resource-tools/vampir/HEADLESS-SDK-SIGN-UP.md).

20 октября 2026. Добавлен `run-nid-sdk-sign-in.py`: проверка источников и
локального устройства → окно NID → один SDK sign-in с результатом окна.
Игровая сессия, список и выбор персонажа этим запуском ещё не подтверждены.

Обновление: обе реальные попытки со штатной формой во встроенном окне дали
принятый NID callback и дошли до SDK POST. Сервер вернул HTTP 400; после
добавления диагностики во второй попытке установлен errorCode 1203.
Смысл кода пока неизвестен. Нельзя объявлять его ошибкой пароля, региона
или подтверждения устройства без дополнительного источника.

## Запуск

```powershell
python -X utf8 phone-exit/bots/vampir-headless/run-nid-sdk-sign-in.py --email bot-test@vampir.top --timeout 300
```

Для однократного автоматического заполнения добавить `--password-stdin`
и передать пароль через stdin вызывающего процесса. В аргументы, файлы,
команды из документации или журналы настоящий пароль не включать.
Без этого флага окно допускает ручной вход. Автоматическая регистрация
и обработка CAPTCHA этим флагом не добавляются.

Нужны зависимости [окна NID](NID-BROWSER.md), наблюдённые ключи в локальном
реестре бота и проверенные файлы исследования вне Git. Перед открытием окна
runner сверяет SHA установленного EXE и профиля, повторно читает три ключа
Windows и проверяет их совпадение с локальной записью. Состояние подтверждения
`required` останавливает запуск; `unknown` не означает подтверждённое устройство.

После callback используются разные ключи: NID DeviceKey для страницы,
SDK DeviceKey для SDK-запроса. Страна берётся из результата NID. Provider token
передаётся как credential с channelCode 33, а не как готовый SDK accessToken.
Полученный SDK response возвращается вызывающему коду в памяти. CLI печатает
только признаки результата и завершает работу, не сохраняя токен для следующего
запуска. Пароли, callback и токены в журнал не выводятся.

## HTTP и проверки

Общий `vampir_core/sdk_sign_in_http.py` выполняет один HTTPS POST без повторов,
redirect и системного proxy. Проверяются endpoint, лимиты тела и заголовков,
статус, Content-Encoding, Content-Length, размер и время чтения ответа.
Существующий parser проверяет структуру SDK response. Неизвестная ошибка
не переименовывается в «нужно подтвердить устройство» без доказательств.

Прошли пять HTTP-тестов, три теста runner и три теста адаптера окна.
Тесты проверяют разделение ключей, единственный POST после callback,
остановку до POST при ошибке окна или required, границы ответа и отсутствие
повтора при redirect. Три проверки Ghidra и smoke WebView2 также прошли.
Позднее выполнены два настоящих SDK POST после NID callback; оба отклонены.
Ограниченный HTTP error reader принимает только числовой errorCode в диапазоне
signed int32. Дубликаты ключей, некорректный JSON и превышение бюджета не дают
диагностического кода. Серверные сообщения и исходное тело не сохраняются.
Теперь проходят 14 целевых тестов: шесть HTTP, четыре adapter, три runner
и один тест DOM fixture, плюс отдельный smoke WebView2.

## Реальная попытка и регистрация

Окно NID запущено, наличие окна подтверждено по процессу; его содержимое
автоматизацией не проверено. Пользователь уточнил, что тестовая почта ещё
не зарегистрирована в Netmarble, и поручил создать аккаунт и получить письмо.
Защищённый IMAP с проверкой сертификата успешно принял предоставленные данные;
INBOX открыт только для чтения. Пароль в файлы проекта не записан.

Первоначально Browser use был отключён в Work; после изменения настройки
доступ появился. Регистрация продолжена через официальный сайт в Chrome,
а не через управление встроенным WebView2. Пользователь отдельно подтвердил
принятие обязательных условий. Terms of Service и Privacy Policy отмечены,
Marketing Consent оставлен выключенным. Запрошенное письмо пришло от
`noreply@netmarble.net`; код принят сайтом, открыт шаг Set Password.
Во время продолжения управление исходной вкладкой потеряно; позднее вкладка
отсутствовала в списке. Отдельная попытка входа не установила состояние аккаунта:
сайт сообщил об ошибке соединения с сервисом reCAPTCHA. После одной перезагрузки
регистрация продолжена, получено новое письмо и подтверждён новый код.

По прямому запросу пользователя заполнены пароль и его подтверждение.
После Next сайт показал `Account Registration Complete`; Confirm перевёл
на `/me/home`, где видны тестовая почта и `Services In Use 0`. Аккаунт
Netmarble создан, вход в личный кабинет подтверждён. Видимой CAPTCHA
в успешной цепочке не было. Пароль и коды в документы не сохранены.
Снимки результата находятся в игнорируемой `.local/previews/`.

Автоматический сценарий регистрации в runtime не реализован. Вход на сайт
не заменяет NID callback с контекстом бота и SDK response. Остаются реальные
Version / Login, список, выбор и позиция персонажа. Отображаемое имя NID
из личного кабинета не подставляется в протокол вместо проверенного поля
Netmarble ID из callback.
