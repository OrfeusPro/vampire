# Аккаунты ботов на Windows

Панель запускается отдельно от игры и инструментов исследования:

```powershell
python -X utf8 phone-exit/bots/vampir-headless/account-manager.py
```

Открыть `http://127.0.0.1:17949/`. Сервер принимает соединения только через
loopback. Остановка процесса панели закрывает принадлежащие ему рабочие процессы.
Кнопка «Остановить» закрывает процесс только выбранного аккаунта.

## Настройки и регистрация

1. Добавить почту Netmarble и игровой пароль. Для автоматического получения кода
   регистрации отдельно указать пароль этого почтового ящика. Пустое поле при
   следующем сохранении оставляет прежний пароль; браузер его не получает.
2. Сохранить настройки. Для регистрации сервер и персонаж пока не обязательны.
3. Для одной явной регистрации отметить принятие обязательных условий Netmarble
   и нажать «Зарегистрировать аккаунт». Необязательная рекламная подписка выключена.
4. Откроется официальная форма в отдельном WebView. Код читается только из новых
   писем выбранного ящика через IMAP `mail.vampir.top:143` с проверенным STARTTLS
   до передачи пароля.
   Поддержаны только ящики `@vampir.top`. Создание самого почтового ящика выполняется
   отдельно. Капча и изменившаяся форма требуют вмешательства пользователя.
5. Завершение регистрации подтверждается экраном завершения и проверенным NID
   callback. Только после обоих сигналов панель сохраняет статус «подтверждена».
   Неизвестный результат не считается успехом и не повторяется автоматически.

Если Netmarble отвечает «This email is already in use», регистрация останавливается
со статусом «Почта уже используется». Это не подтверждение входа или владения
аккаунтом; отправка повторной регистрации блокируется. Такой ответ получен для
новой EU-почты 22 октября и подтверждён скриншотом пользователя.

После этого отдельный обычный вход новой EU-почты подтвердил NID callback,
но launcher SignIn игрового SDK вернул HTTP 400 / код 1203. Панель сохраняет
«Вход Netmarble подтверждён» отдельно от результата SDK. Это ещё не подтверждение
доступа к лобби, списка персонажей или игровой сессии.

Для этого случая добавлена отдельная кнопка «Создать игровой профиль SDK».
Она доступна только после подтверждённого NID и последнего ответа SDK 1203
в текущем запуске панели. Используется явный SDK SignUp; автоматического перехода
с SignIn нет. Успешный ответ должен содержать player ID и сохраняет состояние
«Игровой профиль SDK создан», без запуска лобби или создания персонажа.
После перезапуска панели требуется новое наблюдение ответа SDK.
Историческое сообщение `not exist player channel` при коде 1203 относится
к прежнему endpoint и аккаунту; оно не доказывает универсальный смысл кода.
[Исторический разбор SignUp](../resource-tools/vampir/knowledge/evidence/auth/HEADLESS-SDK-SIGN-UP.md).
Последняя повторная загрузка серверов остановилась на таймауте NID, до SDK;
живая проверка новой кнопки пока не выполнена.

При недоступном IMAP перед регистрацией можно выбрать «Ввести код из письма
вручную». После отправки письма появляется отдельное поле кода. Панель передаёт
ровно один пятизначный код только ожидающему процессу выбранного аккаунта через
stdin; код не сохраняется в базе, API-снимке или логах. После остановки либо
перехода на другой этап отправка отклоняется. Переключение режима явное;
ошибка TLS не отключает проверку сертификата и не запускает регистрацию повторно.

22 октября порт 993 не прошёл проверку цепочки сертификата. Порт 143 с STARTTLS
прошёл проверку TLS, реальную авторизацию выбранного ящика и read-only открытие
INBOX. Исправлено сохранённое значение почтового пароля новой EU-почты;
игровой пароль не менялся. Предыдущая регистрация дошла до письма и передачи
кода, но подтверждённого завершения не получила. Позднейшее сообщение Netmarble
«почта уже используется» хранится отдельно от подтверждённой регистрации / входа.

Пароли хранятся раздельно в `.local/console.sqlite3`, зашифрованы Windows DPAPI
для текущего пользователя ОС. База и каталоги WebView исключены из Git.
Пароли и коды не передаются аргументами процессов и не выводятся в состояние API.
Флаг принятия условий не сохраняется для будущих регистраций.

Регистрация Netmarble отличается от создания SDK-игрока и создания персонажа.
Эти действия не выполняются скрытно при ошибке обычного входа.

## Серверы, персонажи и параллельный запуск

«Загрузить серверы» получает свежий каталог через SDK и лобби выбранного региона.
Названия берутся из ответа: подпись группы и числовой суффикс записи сервера.
Например, EU возвращает группу `Prelude` и запись `프렐류드2`; панель показывает
`Prelude 2`, сохраняя исходную подпись. Если суффикс неизвестен, остаётся исходное
название без придуманного номера. Адреса соединений в каталог панели не включаются.
Каталог региона общий для аккаунтов и сохраняется после перезапуска панели;
после обновления меняются и выпадающий список, и подписи карточек.
Отказ лобби, неоднозначные ID или пустой регион не заменяют прежний каталог.
После выбора сервера сохранить настройки и нажать «Прочитать персонажей».
Назначение персонажа сохраняет его ключ как десятичную строку: после изменения
порядка списка выбирается прежний ключ. Отсутствующий или неоднозначный ключ
останавливает выбор. Смена региона или сервера очищает выбор в форме.
Подтверждённые списки хранятся отдельно по аккаунту, региону и server ID,
с временем получения. Они остаются после перезапуска панели и неудачной
авторизации. Только принятые Login 0 и CharacterList 0 обновляют список;
успешный пустой список заменяет прежние записи. Это сохранённое наблюдение,
а не обещание текущего состояния сервера: перед выбором ключ сверяется заново.

«Запустить два аккаунта» запускает первые два включённых аккаунта отдельными
процессами. Одновременно допускаются не более двух операций; повторный запуск
одного аккаунта отклоняется. Отключённые аккаунты сохраняются, но не запускаются.
Настройки работающего бота нельзя редактировать.

На первом этапе доступен общий профиль «Текущий ПК». Он использует наблюдённые
данные устройства и сохраняет существующие привязки. Cookies WebView изолированы
по аккаунтам. Произвольные идентификаторы и другие профили устройств пока не
подключены. Все операции используют прямой маршрут без изменения VPN и маршрутов ОС.

Статус «В мире» возникает после получения серверной позиции. Без назначенного
персонажа запуск читает список; пустой список показывается отдельно от отказа
Login. Ник для создания сохраняется, но сетевое создание персонажа ещё не подключено.

В настройках добавлен явный выбор класса. По указанию пользователя начальное
значение — Carnage (`Gunner`); случайного класса нет. Пять подписей взяты из
Class / ClassName-en извлечённого каталога, entries 36 / 401, строки CSV 2–6.
Каталог `maps/catalog-classes.json` имеет SHA256
`5af03a839e38ada2e1e247da6b5b22c6bb116496bc816be572c7f19c188b768e`,
его исходный EXE — `c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`.
Это смысловой выбор пользователя, не подтверждённый wire ID класса текущей
сборки. Числовая передача класса серверу остаётся открытой.

«Случайный ник, если персонажей нет» включён по умолчанию. Кнопка «Другой
случайный ник» подставляет вариант в форму; запись происходит только при
сохранении. При принятом пустом списке worker готовит отсутствующий ник и
сохраняет его. Предложение состоит из десяти латинских букв; это локальная
политика генерации, допустимость и свободность проверяет сервер при создании.
В новой EU-записи сохранены Carnage и подготовленный ник; после перезагрузки
страницы значения сохранились. Основной аккаунт и назначение XI не изменялись.

Локальный план изолирован по аккаунту, региону и серверу. Он отклоняет
отсутствующий / непустой подтверждённый список и уже назначенного персонажа.
Даже при неназначенном слоте существующий персонаж запрещает подготовку нового.
После подтверждённого `name_taken` меняется только ник; история исключает
повтор вариантов и ограничивает план пятью кандидатами. Таймаут / неизвестный
результат и ответ о другом нике ничего не меняют. При ручном нике автоматическая
замена выключена. Реальная привязка `name_taken` к декодированному серверному
результату ещё не выполнена: wire-код не угадан, сетевых повторов пока нет.
Случайная внешность пока не подключена.

Сессия ограничена 300 секундами наблюдения после входа в мир; автоматических
повторов, квестовых действий и reconnect здесь пока нет.

## Проверки и границы

Локальные тесты проверяют DPAPI, отсутствие паролей в API, сохранение настроек,
отдельный почтовый пароль, обязательное подтверждение регистрации, прямой маршрут
и освобождение IMAP, две отдельные тестовые службы и независимая остановка,
запрет третьего процесса, проверка HTTP Host / Origin / token, выбор по свежему
ключу персонажа, формы регистрации, получение кода и существующий вход.
Дополнительно проверены названия и фильтрация региона, неизвестные подписи,
дубли ID и сохранение прежнего каталога при отклонённом обновлении.
Списки персонажей проверены на изоляцию аккаунтов / серверов, перезапуск,
отклонение повреждённых записей и обновление только после успешного ответа.
Эти тесты используют fixtures и не выполняют реальную регистрацию или игровой вход.
Для текущего изменения прошли 16 тестов панели, включая запрет SDK SignUp без
подтверждённого NID / ответа 1203, отдельный запрос создания и сохранение прежнего
состояния при ошибке. В расширенном запуске прошли 49 из 50 тестов; исторический
native replay SignUp отклонил изменившийся SHA установленного EXE. Его материалы
не перенесены на новую сборку, и полная native-проверка актуального SignUp остаётся
открытой. Затем исторический replay получил явный SHA-снимок: все пять тестов
SignUp прошли, включая четыре native сценария старой сборки и отказ повреждённого
снимка. Текущие две функции SignUp разобраны отдельно статически;
это ещё не native-проверка новой сборки.
[Текущий разбор и оставшиеся проверки](../resource-tools/vampir/knowledge/evidence/auth/HEADLESS-RELEASE-SDK-SIGN-UP.md).
Семь текущих initializers ключей прошли 28 native случаев: имена полей SignUp
и ключи errorCode / resultData подтверждены для нового SHA. Полный caller и
constructor ключей player callback этой проверкой не покрываются.
[Ключи, fixtures и границы](../resource-tools/vampir/knowledge/evidence/auth/HEADLESS-RELEASE-SIGN-UP-KEYS.md).
Проверка синтаксиса JavaScript прошла.
После добавления параметров создания прошли 53 теста выбранного набора,
включая 18 тестов панели: сохранение ника после перезапуска, неизменность класса
при коллизии, лимит вариантов, изоляция аккаунта / сервера, запрет неизвестных
повторов и запрет подготовки при существующем персонаже.
Панель открыта и проверена в браузере с двумя локальными аккаунтами.
22 октября через панель выполнена живая загрузка EU-каталога без VPN:
12 серверов Aria / Prelude / Opus / Canon / Requiem / Waltz, по два в группе.
У обоих аккаунтов в интерфейсе подтверждено имя Prelude 2 для server ID 384.
Проверка закончилась в лобби, без игрового соединения и создания персонажа.
Следующая живая проверка основного EU-аккаунта дошла до Game Login 0 и списка
с одним персонажем. Его ключ назначен в настройках. Отдельная попытка входа
в мир завершилась на NID-авторизации до игрового соединения. После следующего
успешного чтения списка запуск того же персонажа получил серверную позицию;
статус «В мире» подтверждён в панели. Это проверка одного аккаунта, без квестовых
действий и автоматического создания.
[Наблюдения EU-сессии](../resource-tools/vampir/knowledge/evidence/network/HEADLESS-EU-ACCOUNT-CONSOLE.md).
Живая регистрация через новую панель и одновременный вход двух аккаунтов в мир
ещё не подтверждены. Хранилище DPAPI и WebView относятся к Windows;
перенос в лёгкий Android runtime не выполнен.
