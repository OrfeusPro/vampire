# Аккаунты ботов на Windows

Для `bot-tw-test@vampir.top` подтверждены регистрация Netmarble и повторный
SDK-вход со страной JP; статус — `sdk_created`. Раздельные пароли сохранены
локально под DPAPI. Повторная регистрация не нужна. JP-маршрут проверялся
отдельным CLI SOCKS; jobs панели пока используют прямой маршрут. Сервер и
персонаж не назначены: игровой source profile ещё не прошёл проверку.
[Условия, результат и следующий этап](../resource-tools/vampir/knowledge/evidence/auth/HEADLESS-JP-SDK-RETRY-20261024.md).

Панель запускается отдельно от игры и инструментов исследования:

```powershell
python -X utf8 phone-exit/bots/vampir-headless/account-manager.py
```

Открыть `http://127.0.0.1:17949/`. Сервер принимает соединения только через
loopback. Остановка процесса панели закрывает принадлежащие ему рабочие процессы.
Кнопка «Остановить» закрывает процесс только выбранного аккаунта.

## Таблица аккаунтов и подготовка группы

Для отдельного создания доступна кнопка «Создать Carnage, если персонажей нет».
Она использует сохранённый сервер, класс Carnage и ник из настроек; случайный
ник подготавливается при принятом пустом списке. Существующие персонажи исключают
создание. Результат сохраняется в постоянном журнале до назначения слота.
После успеха или неподтверждённой попытки отдельно прочитайте персонажей.
Подтверждённый server key назначается только по уникальному совпадению в свежем списке.
Другие классы пока не поддержаны сетевым factory. Живая отправка ещё не проверена.
[Журнал, сценарии и ограничения](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-CREATE-WORKER-JOURNAL.md).
Живой контроль нового аккаунта остановился на SDK HTTP 400 / 1203 до игры;
Create ещё не отправлялся. Исправлена передача callback через вложенный wrapper,
но успешный ответ создания на настоящем сервере ещё не получен.
[Текущий результат проверки](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-CREATE-LIVE-PREFLIGHT.md).

Таблица содержит почту, раздельные пароли почты / Netmarble, подтверждённый ник,
класс создания, назначенный сервер и состояние. Ник берётся из принятого списка
персонажей; предлагаемое имя не выдаётся за созданного персонажа. Класс пока
показывает план создания, а не декодированный класс существующего персонажа.
Пароли остаются в Windows DPAPI. По явному нажатию «глазика» POST `/api/reveal`
возвращает только выбранный пароль с проверкой loopback Host / Origin и токена
панели, Cache-Control no-store. Общий `/api/state` паролей не содержит.
Открытое значение скрывается при уходе из окна или повторном нажатии.

```powershell
python -X utf8 phone-exit/bots/vampir-headless/prepare-account-batch.py --batch eu-20261023-24
```

Команда атомарно готовит минимум 24 локальные записи с разными паролями,
по две на каждый доступный сервер сохранённого каталога EU. Если серверов больше
12, записей будет больше 24. Повтор того же имени группы не создаёт дубликаты;
изменение параметров существующей группы отклоняется. Имена — осмысленные
игровые псевдонимы NightRaven, AshHunter и другие; почта — псевдоним в нижнем
регистре @vampir.top. Почтовый пароль содержит спецсимвол по требованию DirectAdmin.
До реального создания ящики имеют `mail_status=planned`, Netmarble — unknown,
запуск отключён. Команда не создаёт ящик, регистрацию или персонажа.
Переименование разрешено только для ещё не созданных и не зарегистрированных
заготовок; пароли, ID записей и назначения серверов сохраняются.

квота каждого 100 МБ. Все 24 проверены входом через mail.vampir.top:143 с
проверенным STARTTLS, read-only INBOX; в базе mail_status=verified.
Единственный созданный ранее случайный адрес удалён по отдельному подтверждению
пользователя; существующие ящики не изменялись. Пароли и приватная база в Git

игровых персонажей: создание персонажей остаётся отдельным этапом.

Первый NightRaven прошёл почтовый код и отправку пароля. SDK-вариант формы может
сразу возвращать проверенный NID callback вместо отдельного экрана завершения:

каждого обязательного шага. Остальные регистрации выполняются последовательно,

## Настройки и регистрация

Актуальный результат 23 октября: XI и Prox одновременно вошли в мир ботами
через прямой launcher flow на EU / Prelude 2. Семь снимков API за 30,068 секунды
подтвердили running / active обоих; затем оба worker штатно остановлены.
Позиция каждого получена через world callback. Длительная устойчивость,
reconnect, движение и квесты этим не проверены.
Сводка:
`F:/PhoneExit Resources/Vampir/live-account-console/dual-world/c90650813190393ba9d1d8d915f1b13dc04677fff1325447a5cd7d9bf1051e15/manifest.json`.
SHA256 совпадает с именем каталога; credentials, ключей персонажей и координат нет.

Предыдущие шаги: после создания персонажа пользователем
новый EU-аккаунт прошёл автоматический вход через launcher, Game Login 0
и свежий список с одним Prox на Prelude 2. Он назначен по серверному ключу.
Отдельная следующая попытка войти в мир остановилась на NID HTTP 400,
`read_failed`, до SDK. На том этапе позиция Prox ещё не была получена. Прежний SDK 1203
в успешной попытке не повторился; создание персонажа и пауза между попытками
не изолированы как причины изменения. SignUp и создание персонажа ботом
не выполнялись. Сводка без токенов, ключей персонажа и адресов:
`F:/PhoneExit Resources/Vampir/live-account-console/post-character/00677f94d75c8c49e44fceeb5257a701d182fb6767eb3d8eb077bb00405b28c6/manifest.json`.
SHA256 совпадает с именем каталога. Ниже сохранены условия предыдущих попыток.

1. Добавить почту Netmarble и игровой пароль. Для автоматического получения кода
   регистрации отдельно указать пароль этого почтового ящика. Пустое поле при
   следующем сохранении оставляет прежний пароль; в общий снимок он не попадает.
2. Сохранить настройки. Для регистрации сервер и персонаж пока не обязательны.
3. Для одной явной регистрации отметить принятие обязательных условий Netmarble
   и нажать «Зарегистрировать аккаунт». Необязательная рекламная подписка выключена.
4. Откроется официальная форма в отдельном WebView. Код читается только из новых
   писем выбранного ящика через IMAP `mail.vampir.top:143` с проверенным STARTTLS
   до передачи пароля.
   Поддержаны только ящики `@vampir.top`. Создание самого почтового ящика выполняется
   отдельно. Капча и изменившаяся форма требуют вмешательства пользователя.
5. Завершение регистрации требует проверенного NID callback и экрана завершения
   либо всех четырёх наблюдённых шагов регистрации, описанных выше.
   Неизвестный результат не считается успехом и не повторяется автоматически.

Если Netmarble отвечает «This email is already in use», регистрация останавливается
со статусом «Почта уже используется». Это не подтверждение входа или владения
аккаунтом; отправка повторной регистрации блокируется. Такой ответ получен для
новой EU-почты 22 октября и подтверждён скриншотом пользователя.

После этого отдельный обычный вход новой EU-почты подтвердил NID callback,
но launcher SignIn игрового SDK вернул HTTP 400 / код 1203. Панель сохраняет
«Вход Netmarble подтверждён» отдельно от результата SDK. Это ещё не подтверждение
доступа к лобби, списка персонажей или игровой сессии.

23 октября пользователь подтвердил, что игровой аккаунт уже зарегистрирован и
вручную входит в лаунчер. Предположение о необходимости создавать SDK-профиль
по коду 1203 было ошибочным. Кнопка и операция SDK SignUp удалены из панели;
обычный вход не создаёт аккаунт и не вызывает SignUp. Прежние попытки этой
операции остановились на повторной авторизации NID до запроса создания.
Исторический разбор SignUp сохраняется как исследование протокола,
а не инструкция регистрации существующего EU-аккаунта.
[Исторические границы](../resource-tools/vampir/knowledge/evidence/auth/HEADLESS-SDK-SIGN-UP.md).

У основного и нового EU-аккаунтов локально сверены игровой пароль, регион,
сервер и три наблюдённых ключа устройства: совпадают. NID parameters из
текущего source profile также совпадают; WebView-каталоги раздельны по почте.
Fixtures подтверждают одинаковый browser request для launcher SignIn и
прежней явной ветви SignUp: различие начинается после NID callback.
Реальный контекст официального лаунчера этим не сопоставлен.

В настройках доступен явный способ авторизации: «Через лаунчер» использует
launcher/token → launcher/sign-in, «Прямой SDK SignIn» — v1/sign-in. Перед обоими
путями используется одна форма Netmarble; выбор относится к следующему SDK-запросу. Это только
вход в существующий аккаунт; автоматического переключения или регистрации
при ошибке нет. Прежние записи сохраняют launcher по умолчанию.

При сравнении настроек 23 октября у bot-test выбран launcher, у bot-eu-test —
nid после диагностического переключения. Последние результаты поэтому относятся
к разным SDK-путям: основной аккаунт получил список с XI через launcher, новый
после ручного NID получил 1203 на v1/sign-in. Ранее новый аккаунт получал 1203
также на launcher SignIn. Это не устанавливает причину различия аккаунтов.
В доступном основном журнале официального лаунчера `main.log` не обнаружены
маркеры launcher/token, launcher/sign-in, v1/sign-in или 1203; сравнить реальные
SDK-запросы по этому журналу не удалось. Сырые строки журнала не сохранялись.

По следующей просьбе пользователя новый EU-аккаунт переключён обратно на
launcher и проверен в автоматическом режиме с сохранённым паролем. Ручное
ожидание перед этим остановлено. Попытка получила Login Failed / HTTP 400
на NID, после отправки формы; до launcher/token, SDK и персонажей не дошла.
Прежний `read_failed` не позволял различить ошибку получения response из WebView,
чтения потока и декодирования. Диагностика теперь разделяет эти случаи:
`response_observation_failed`, `content_unavailable`, `read_failed`, `invalid_utf8`.
Это фиксированные локальные статусы, не коды причины отказа Netmarble.
Тексты ответов и исключений не выводятся; лимит чтения остаётся 16 385 байт
для обнаружения превышения допустимых 16 384. Изменение проверено на fixtures,
включая некорректный UTF-8 и закрытый поток, без новой авторизации.
Причина последнего реального `read_failed` ретроспективно не установлена.

Ошибка чтения затем воспроизведена без аккаунта на синтетическом HTTP 400
в настоящем WebView2. В закреплённом `Microsoft.Web.WebView2.Core.dll`
1.0.3856.49 (`8219a3135436c147f8eb02fb831e99596103eebc18b6d7b794ca93f4c67018a2`)
`COMStreamWrapper.Read` отвергает ненулевой buffer offset с
NotImplementedException. Прежний цикл после первого непустого чтения передавал
накопленное смещение, поэтому даже корректный ответ терял числовой код.
Теперь поток читается с offset 0 в отдельный буфер, данные копируются в прежний
ограниченный результат; оба буфера очищаются. Блокирующие COM-чтения выполняются
в Task.Run вне UI-потока. Лимиты и отсутствие записи тел / сообщений сохранены.

`nid-browser.py --smoke` теперь перехватывает все WebView-запросы локально,
создаёт синтетический ответ 400 / code 321 и проверяет чтение кода вместе
с callback и блокировкой внешних URI / попапов. С реальным Netmarble smoke
не связывается. До исправления воспроизводился `read_failed`, после —
`numeric_code`. Fixtures дополнительно проверяют поток с разрешённым только
нулевым offset и короткими чтениями; выбранные 30 тестов прошли.
Исправление диагностики не доказывает устранение причины настоящего HTTP 400.

### Прямой захват после создания персонажа

23 октября пользователь сообщил, что создал персонажа и вошёл в мир через
официальный клиент без Phone Exit. Ожидаемый контекст — новый EU-аккаунт и
Prelude 2; сообщение подтверждает создание и вход, но имя / класс и аккаунт
в пакетах ещё не проверены. Параллельный вход бота не запускался.

PktMon через штатный UAC записал сетевые интерфейсы за 180 секунд, лимит
ETL 32 МиБ, без изменения имеющихся фильтров. Перед запуском подтверждены
остановленный PktMon и пустые фильтры. Запись автоматически остановлена;
исходники и результат приватные, вне Git:
`C:/Users/Валентин/.phone-exit/diagnostics/direct-151bbbcbeded44059ddd2fbd415cc427/`.
PCAPNG: 10 778 084 байта, 22 489 пакетов, SHA256
`7e634ac59077026bd999ac96f56d343c602f2ca93e7f604fdfe8f7efc60d5599`.
PktMon сообщил No events lost; это не доказательство непрерывного TCP.
Снимок активных соединений процесса игры содержит один TCP endpoint на 12000
и четыре на 443; адреса сохранены только в приватном каталоге.

[Импортёр](../resource-tools/vampir/import-pcapng-tcp.py) проверяет SHA и границы
PCAPNG, собирает Ethernet / IPv4 TCP только явно заданного порта, удаляет
совпадающие повторы и отвергает конфликтующие перекрытия, пропуски и повторное
использование TCP tuple с другим SYN. Выход — приватный JSONL для существующих
декодеров; файл создаётся только после проверки всех потоков, без перезаписи.
Отсутствие SYN явно помечает недоказанный префикс. IPv6, TCP-фрагменты,
выбранные offload-пакеты с нулевой длиной IP и другие link types не поддержаны;
IP / TCP checksums не проверяются. End означает завершение импорта, не сессии.

В этой записи найдены три TCP-потока на 12000. Третий имеет пропуски в обоих
направлениях; первый наблюдённый c2s payload начинается на 230 байт позже
ожидаемого начала после SYN. Полный импорт отклонён, `game-tcp.jsonl` не создан.
Причина пропусков не установлена; целые Login / Create из записи не доказаны.
Следующая проверка должна изменить точку захвата или инструмент и подтвердить
непрерывность TCP перед декодированием. Созданного персонажа повторно создавать
не нужно; следующий вход проверяет список и выбор существующего.

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/import-pcapng-tcp.py <traffic.pcapng> --sha256 <SHA256> --port 12000 --output <новый-game-tcp.jsonl>
```

Для одной следующей операции можно отметить «Ввести логин и пароль в окне
Netmarble вручную». Флаг передаётся только выбранному worker через
`--manual-sign-in`: пароль для WebView становится пустым, автозаполнение
и отправка формы отключены. После ручного входа выполняется выбранная цепочка
servers / characters / start; режим сам не добавляет вход в мир или создание.
Для register этот флаг отклоняется до запуска процесса. В настройках аккаунта
он не сохраняется и после запуска / выбора другой карточки сбрасывается.
«Запустить два аккаунта» использует обычный режим; ручная проверка запускается
отдельной кнопкой нужного аккаунта.

23 октября пользователь выполнил ручной NID-вход нового EU-аккаунта в нашем
WebView. Операция characters с auth_flow=nid перешла к SDK SignIn и получила

## Диагностика отказа NID

23 октября добавлено наблюдение страницы после единственной отправки формы.
Видимая отдельная строка `Login Failed` на официальной странице `/auth` или
её дочерней странице вне signup завершает ожидание отдельным отказом. Пароль повторно
не отправляется, SDK / лобби / игра не запускаются. Другой текст не выдаётся
за известную ошибку; капча и подтверждение устройства не обходятся.

WebView наблюдает ответы POST только от точного HTTPS-домена
`members.netmarble.com` на стандартном порту. Полные URL, запросы, заголовки,
пароли, callback и ответы не выводятся в диагностическое состояние.
Сохраняется HTTP-статус; из JSON извлекается только int32 `errorCode`, `code`,
`resultCode` либо `error.code`. Десятичная строка кода преобразуется в int32;
другие строки и тексты сообщений отбрасываются. Чтение возможно лишь при
Content-Type application/json и ограничено 16 384 байтами. Отсутствующий
Content-Length разрешён: читается максимум 16 385 байт, лишний байт означает
превышение лимита. При известной длине она также сверяется; неверный UTF-8,
слишком большой ответ или отсутствие числового поля не дают код ошибки.
Фиксированное состояние разбора объясняет, почему код недоступен. Эти необязательные
числа не определяют успешность входа и не разрешают повтор или регистрацию.

При отказе / таймауте панель показывает безопасную стадию формы и доступные
HTTP / NID-код. Отсутствие числового кода не доказывает отсутствие серверного
отказа: другие домены и неподдержанные схемы JSON не разбираются.
После Login Failed закрытие ждёт уже начатую диагностику максимум 1,5 секунды,
чтобы не прервать чтение ответа сразу после его заголовков.

## Серверы, персонажи и параллельный запуск

«Загрузить серверы» получает свежий каталог через SDK и лобби выбранного региона.
Названия берутся из ответа: подпись группы и числовой суффикс записи сервера.
Например, EU возвращает группу `Prelude` и запись `프렐류드2`; панель показывает
`Prelude 2`, сохраняя исходную подпись. Если суффикс неизвестен, остаётся исходное
название без придуманного номера. Адреса соединений в каталог панели не включаются.
Каталог региона общий для аккаунтов и сохраняется после перезапуска панели;
после обновления меняются и выпадающий список, и подписи карточек.
Отказ лобби, неоднозначные ID или пустой регион не заменяют прежний каталог.
После выбора сервера сохранить настройки и нажать «Войти и прочитать персонажей».
Эта операция делает один свежий вход NID / SDK, получает каталог серверов,
сохраняет его и в той же цепочке продолжает выбранное лобби → Game Login →
CharacterList. Отдельная предварительная загрузка серверов для уже выбранного
сервера не требуется. Она нужна, когда ещё предстоит выбрать сервер из каталога.
Ранее операция персонажей уже имела цельную сетевую цепочку, но не сохраняла
полученный каталог; теперь общий каталог обновляется и здесь. Отказ каталога
не заменяет прежние данные. Чтение списка не выбирает персонажа и не входит в мир.

Назначение персонажа сохраняет его ключ как десятичную строку: после изменения

Случайная внешность пока не подключена.

подготовку до запуска worker. Успех сохраняет sdk_created; обычный вход и создание
персонажа остаются отдельными действиями. Новая кнопка ещё не проверена живым входом.
[Контракт панели и проверки](../resource-tools/vampir/knowledge/evidence/auth/HEADLESS-CONSOLE-FIRST-SDK-LOGIN.md).

При завершении подключения подготовки SDK к панели установленный EXE изменился:
SHA256 `d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.
Проверки этого этапа относятся к прежнему SHA `98802d550890…`; совместимость
новой сборки ещё не подтверждена. Перед следующим живым входом сверить обновление.
