# Изолированные живые сессии

[Наблюдаемый NPC subset](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-OBSERVED-ENVIRONMENT-11316.md):
ID 324 добавляет / обновляет NPC, ID 302 убирает actor keys. `coverage.entities=partial`
не означает полный список рядом; начальный SightEnter и players ещё не подключены.
HP и XYZ — при появлении, с явными `stats_current=false` / `position_current=false`.
Максимум 512 NPC на сессию; world / close и decoder errors очищают subset.
HTTP `/bots/<bot>/state?entity_page=0|1` отдаёт по 256 NPC, без параметра —
первую страницу. `environment` содержит `known_count`, `entity_page`,
`page_size`, `shown_count`; страницы отражают изменяемое состояние, а не архив.
Состояние нескольких аккаунтов не разделяется. Это проверено на fixtures,
игровая live проверка этого слоя ещё не выполнена.

[Онлайн-журнал и изменяемый локальный обработчик](LIVE-DIAGNOSTICS.md):
API / браузер проверены на fixture и реальном персонаже через OPPO / HK;
смена локальной обработки и SyntaxError не разорвали игровую сессию.

Запускатель `run-live-sessions.py` держит отдельный socket owner каждого бота
и общий HTTP API на `127.0.0.1:17947`. Пароли вводятся через скрытый stdin,
не входят в JSON, ответы API или журнал. Список аккаунтов хранить вне Git.
Один аккаунт запускается один раз; повторные email и `bot_id` отклоняются.

Пример файла с вымышленными аккаунтами:

```json
[
  {"bot_id":"bot-01","email":"one@example.com","socks_port":17948,"region":"JP","server_id":256,"character_index":0},
  {"bot_id":"bot-02","email":"two@example.com","socks_port":17949,"region":"JP","server_id":256,"character_index":0}
]
```

```powershell
python -X utf8 phone-exit/bots/vampir-headless/run-live-sessions.py --accounts '<приватный JSON>' --manifest '<актуальный public CDN manifest>' --client-version <текущая patch revision>
```

Телефонные транспорты должны уже работать на указанных SOCKS-портах.
Запускатель ими не владеет и не запускает их. Совпадающий SOCKS-порт допускается;
это общий выход, а не объединение игровых сессий. Используется проверенный
`candidate-11316`; проверки SHA и capabilities остаются действующими.
Существующий персонаж выбирается по явно указанному индексу принятого списка.

Одновременно выполняются два SDK-входа по умолчанию (`--sign-in-parallelism`
от 1 до 8). После закрытия браузера авторизации слот освобождается, а вошедший
игровой owner продолжает работать: ограничение входов не ограничивает число
активных игровых сессий. Stop отменяет ещё ожидающие входа workers. Список сессий
читает только краткий статус и не копирует все stats каждого бота.
50 одновременных fixture owners проверены с разными HP и одним character key;
пиковое число fake SDK-входов — 2. Это не проверка 50 реальных аккаунтов.

После world finish сессия работает до Stop, разрыва или ошибки heartbeat.
Лимиты чтения: 4 MiB и 4096 неизвестных пакетов за окно 60 секунд;
максимум 128 различных неизвестных ID за сессию; существующие ограничения
очередей и receive stream сохраняются.
После Stop повторного подключения нет. Ctrl+C запрашивает Stop у всех владельцев
и ждёт завершения потоков. Stop во время SDK-авторизации вступает в силу при
передаче управления игровому owner; текущие сетевые операции имеют свои таймауты.
После завершения всех потоков общий API закрывается.

## Состояние и остановка

- `GET /sessions`: ID бота, ID сессии и состояние каждого владельца.
- `GET /bots/<bot_id>/state`: schema 2, отдельный snapshot.
- `GET /bots/<bot_id>/control`: ID и временный токен для Stop и диагностики.
- `POST /bots/<bot_id>/stop`: заголовок `X-Session-Token`, тело JSON с точными
  `bot_id` и `session_id`. Чужой токен и устаревший ID отклоняются.

Разрешён Origin локального UI `http://127.0.0.1:17946` либо запрос без Origin;
Host обязан указывать реальный loopback-порт. Токены не сохраняются.
`GET /state` работает только при одном боте; schema 2 не совместима с прежним
atlas schema 1 автоматически. Текущая проекция карты после смены PAK не доказана;
`position` карты остаётся `null`. Исходная серверная цель находится в
`character.position` с явной семантикой, это не гарантированная позиция actor.

Передаются подтверждённые ключ / имя выбранного персонажа, world ID, серверная
цель и счётчики heartbeat. Для текущего source SHA HP, MaxHP, MP, MaxMP и уровень поступают из принятого
начального списка stats и ID 321 / 322 своего персонажа. Отсутствующие /
небезопасные для JS значения остаются `null`; `entities=[]` вместе с `coverage.entities=not_verified`
не означает отсутствие монстров или игроков. Неизвестные пакеты только считаются;
их тела по умолчанию в API и на диск не попадают. Явно включённые ограниченные
samples доступны по отдельной lease через диагностический API. После отключения
персонаж / объекты и samples очищаются.

## Подключение компонентов UI

`VampirLiveState.create({botId, sessionId, onChange})` создаётся один раз на окно;
`onChange` передаёт snapshot в `playerStatus.updateLive(snapshot)` или
`titleBar.updateLive(snapshot)`. Один адаптер обновляет всех потребителей окна;
компоненты сами не создают таймеров. При закрытии вызвать `dispose()`.
При скрытии страницы опрос приостанавливается, запрос отменяется и live-значения
очищаются. Чужие bot/session IDs отклоняются. Неизвестные значения показываются «—»;
нулевой подтверждённый HP сохраняется как 0. Адаптер не пишет демомодель и storage.
Основной прототип принимает тот же адаптер в режиме
`index.html?mode=live&bot=<bot_id>&session=<session_id>`. Запускатель печатает этот
адрес: один снимок обновляет HP/MP, параметры, меню, карту и онлайн-журнал.
Демопрофиль в таком окне не активируется. Точная сессия обязательна;
неподтверждённые карта / квесты остаются неизвестными.
[Подключение и границы UI](../vampir/UI-PROTOTYPE-LIVE.md).
Также доступен отдельный диагностический просмотр
на тех же общих компонентах: `http://127.0.0.1:17946/maps/ui-prototype/live.html?bot=<bot_id>`.
Он один раз выбирает session ID; при наличии `&session=<session_id>` требует
точное совпадение. Новая сессия не подхватывается в фоне. В этом просмотре нет
демомодели / storage: HP/MP, уровень, мир, heartbeat и таблица stats приходят из API.
Stop требует отдельного клика; закрытие страницы не останавливает бота.
Запускатель печатает готовые `ui_urls`, статический UI-сервер запускается отдельно.
Портрет пока статический, остальные игровые окна не подключены этим просмотром.

Локально проверены две параллельные сессии с fixtures, изоляция маршрутов / паролей,
HTTP Stop, завершение socket owner, скрытие / закрытие адаптера и отсутствие
демочисел в live. Допустимый лимит конфигурации 50 не доказывает нагрузочную
проверку 50 реальных аккаунтов.

Первая проверка 25 октября постоянного режима через HK остановилась на Game Login:
Version 0, Login 58 `BlockedIp`, initial Ping / ответ получены, список не запрошен.
До мира режим не дошёл. Для прежнего выхода повторять тот же отказ без изменений не нужно. Предыдущие 120 секунд успешной bounded-сессии не подтверждают
этот постоянный режим. Тестовый транспорт остановлен.

После замены телефона на Redmi / HK тот же персонаж прошёл 315 секунд в мире:
Login / Select / world — 0, 63 periodic Ping / 64 ответа. Stop API вернул 202,
owner завершился как `session_stopped`; API и тестовый транспорт закрыты.
[Полный результат и границы](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-PERSISTENT-SESSION-11316.md).

Текущий stats-контракт: до 1024 типов, значения `character.stats[].value` —
десятичные signed64 строки без потери точности, `name` — исходное EStat имя.
Это wire values; в частности, type 134 в engine масштабируется отдельно.
Flat HP/MP/level — неотрицательные безопасные целые; при ошибке notify они
сбрасываются в неизвестные. Начальные значения не затирают более поздние события,
повторные types дают последнее значение. Сортировка / сборка stats происходит
по изменению данных, а не на каждом pump. Источник жёстко привязан к текущему SHA.
