# Runtime: поток приёма и два уровня кадров

20 октября 2026. `vampir_core.receive_stream.ReceiveStream` соединяет
существующие транспортный parser, декомпрессор и receive-B parser. Это
переносимый код без Ghidra, Capstone, Unicorn или зависимости от EXE.
Сокетом и авторизацией продолжает управлять внешний владелец соединения.

## Порядок приёма

1. `feed(bytes)` добавляет очередную порцию TCP-данных в ограниченный буфер.
2. `next_packet(key_bits=..., max_transport_frames=...)` читает транспортный
   size23 / compressed flag, ждёт полный кадр и при необходимости распаковывает
   его существующим `decode_transport_block`. Для receive-B внешний заголовок
   из трёх байт удаляется: это проверенная ветвь skip = 3.
3. Полученные байты добавляются во второй буфер. В нём могут находиться
   неполный внутренний кадр, один кадр или несколько кадров.
4. Полный внутренний кадр проходит существующий `take_receive_b_frame`.
   Результат — `IncomingPacket(packet_id, body)`; ID расположен после трёх
   байт внутренней длины, тело — после ID. Исходящие CRC / sequence сюда
   не добавляются: у исследованного входящего пути другой layout.

Каждый вызов возвращает не более одного пакета. Ключ передаётся заново для
каждого пакета, поэтому владелец может обработать KeyChangeNotify и изменить
ключ до разбора следующего кадра из того же TCP-чтения или сжатого блока.
Stream сам не изменяет ключ, не подтверждает его и не вызывает handlers.
Предположение о целостности всего протокола из отсутствия CRC здесь не делается.

Владелец передаёт ID102 / ID110 и полное тело в
[CharacterSelectionFlow](SELECTION-FLOW.md). Другие ID обрабатываются
соответствующими подсистемами. Факт получения пакета не подтверждает вход
или готовность мира.

## Ограничения и завершение

`ReceiveLimits` требует явных лимитов транспортного кадра, выхода одного
блока, внутреннего кадра и двух буферов. Это бюджеты бота, а не найденные
максимумы сервера. Распаковка ограничена максимумом 1 MiB на блок.

`input_capacity` ограничивает размер следующего чтения сокета. Превышение
сырого буфера даёт `BufferError`, не потребляя переданные байты: сначала
нужно разобрать накопленные данные. Владелец ограничивает число возвращённых
пакетов за итерацию; `max_transport_frames` отдельно ограничивает количество
распакованных блоков в одном вызове, включая пустые несжатые блоки.
Если этот бюджет исчерпан, `next_packet()` может вернуть None при наличии
полных транспортных кадров. Продолжить разбор в следующей итерации, не ожидая
обязательно нового события чтения сокета.

Некорректная длина, повреждённое сжатие, превышение выхода блока или общего
буфера декодированных данных закрывает stream и очищает оба буфера.
Автоматического поиска следующего похожего заголовка нет. Владелец должен
закрыть сокет и flow этого соединения; метод stream сам сокет не закрывает.

При EOF вызвать `end_input()`, затем дочитать полные накопленные пакеты.
`finished` означает EOF без остатка и без ошибки. Неполный транспортный
или внутренний хвост при дальнейшем разборе вызывает `truncated_input`.
Для явной остановки вызвать `close()`. Старый stream после reconnect
не используется. Содержимое тела не выводится в repr и ошибках stream.

локальная политика. Обработка очереди запросов списка / выбора остаётся
в `CharacterSelectionFlow`, а не выводится из native bookkeeping.

```powershell
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_receive_stream.py
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_selection_flow.py
python -X utf8 -m unittest discover -s phone-exit/bots -p 'test_vampir_headless_receive*.py'
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_headless_block_decode.py
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_headless_transport_stage.py
```

11 новых тестов проверяют все разрезы сжатого / несжатого кадра, внутренний
кадр из нескольких блоков, несколько пакетов и смену ключа, бюджеты работы
и памяти, повреждённые данные, EOF и очистку. Локальный socketpair-тест
проводит ID101 → сжатый ID102 → ID109 → ID110 через настоящий сокет,
принимая по семь байт за чтение. Сверяются исходящие поля и итоговое состояние.
Это синтетический локальный сервер, не сервер игры и не проверка авторизации.
21 прежний тест приёма / распаковки / транспортного этапа также прошёл.
