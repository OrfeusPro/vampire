# Регистрация тестового аккаунта через HK

20 октября 2026. По поручению пользователя создан отдельный ящик
`bot-hk-test@vampir.top` с квотой 100 МБ. Штатная регистрация Netmarble
пройдена во встроенном WebView2 через личный HK-выход Phone Exit.
Письмо получено по защищённому IMAP, пятизначный код принят формой,
заданный пользователем пароль установлен. NID callback разобран существующим
parser и вернул `joinedCountryCode=HK`.

Затем отдельно выполнены SDK SignUp и SignIn через тот же выход.
Оба ответа приняты: SignUp вернул player ID, SignIn — player ID и SDK token.
Игра не запускалась. Игровой сокет, Version / Login, список персонажей,
выбор и позиция ещё не проверены на сервере.

## Запуск и границы

`register-nid-account.py` требует явные `--email`, `--socks-port`,
`--accept-required-terms` и `--passwords-stdin`. Последний режим читает две
строки из pipe: пароль Netmarble, затем пароль почты. В аргументы, файлы,
SQLite и журналы пароли, код и токены не записываются. Существующие ключи
Windows-устройства наблюдаются заново и фиксируются для отдельного профиля
с происхождением. Уже записанные ключи не заменяются; подтверждение устройства
автоматически не выставляется.

Перед запуском нужен подключённый SOCKS Phone Exit и свежий GMC2 через тот же
порт, как описано в [общем маршруте](SOCKS-ROUTE.md).

```powershell
python -X utf8 phone-exit/bots/vampir-headless/register-nid-account.py --email bot-hk-test@vampir.top --socks-port 17948 --timeout 300 --accept-required-terms --passwords-stdin
```

Секреты подаются из доверенного родительского процесса. Завершённую регистрацию
повторно не запускать. Для существующего аккаунта использовать [обычный вход](NID-SDK-RUNNER.md).
Регистрация NID сама не вызывает SDK SignUp. Создание SDK-игрока остаётся
отдельным явным действием `run-nid-sdk-sign-in.py --create-sdk-player`.

## Штатные формы и почта

`windows/nid-register.js` действует только на точном HTTPS origin
members.netmarble.com. Последовательность наблюдена в настоящем окне:

- `/auth/signin` → Sign in with email → Create an Account.
- `/auth/signup/terms`: отдельные обязательные Terms of Service и Privacy Policy;
  Marketing Consent отключён, общее согласие на все пункты не выбирается.
- `/auth/signup/email/input`: Enter email → Send verification email, один раз.
- `/auth/signup/email/verify`: Enter only numbers. → Confirm Verification Code.
- `/auth/signup/password/input`: два password-поля → Next, один раз.
- Callback удерживается внутри host и проходит общий NID parser.

Значения проверяются после React input events перед отправкой. Неоднозначные
контролы не выбираются. Изменение заполненного значения останавливает сценарий.
Ограничение частоты отправки завершает попытку без автоматического повтора.
CAPTCHA не решается и не обходится; при появлении пользователь проходит её
в штатном окне.

`nid-mail-code.py` подключается только к указанному пользователем
mail.vampir.top:993 с проверкой TLS. INBOX открыт readonly; UIDNEXT фиксируется
до отправки формы, старые письма исключены. Чтение BODY.PEEK ограничено 128 КиБ,
поиск — 100 сообщениями и 120 секундами. Проверяются получатель, наблюдённый
sender `noreply@netmarble.net` и subject регистрации; принимается единственный
пятизначный код. Фильтр заголовков не является проверкой подписи отправителя.
Письма и их флаги не изменяются.

Первый запрос helper передаётся строкой JSON через stdin; во время ожидания
почты родитель передаёт только код отдельной строкой. UI не блокируется чтением
pipe. Watchdog ограничивает время host и завершает только его дерево процессов.
Обычный вход и synthetic smoke сохраняют прежний API.

## Источники и реальная проверка

Происхождение NID URL, ключей устройства и SDK endpoint сохранено
в [описании окна](NID-BROWSER.md), [Windows identity](WINDOWS-IDENTITY.md)
и [SDK SignUp](../resource-tools/vampir/HEADLESS-SDK-SIGN-UP.md).
Новые привязки контролов проверены на актуальных штатных страницах,
показанных собственным WebView2 через HK.

Cloudflare trace подтвердил HK; GMC2 через тот же SOCKS вернул HTTP 200,
13 777 байт и geoIp.isoCountry HK. Неизменяемый manifest:
`F:/PhoneExit Resources/Vampir/public-gmc2-snapshots/e06b06d3f44ddd7bf8ef952c489256c94845c2c87d91af0dd6afe1faa637e62a/manifest.json`.
SHA256 manifest совпадает с именем каталога. Секреты SDK не включены в документ.

Во время разработки остановлены неполные попытки после уточнения форм.
Повторная отправка письма встретила ограничение сервера; после паузы пройден
полный сценарий с новым письмом. Успешный callback вернулся после отправки
пароля, до отдельного наблюдения страницы Account Registration Complete.
Серверное принятие подтверждено последующими SDK SignUp и SignIn.
Прежний UA-аккаунт через HK получал 1602; единственная причина серверной
проверки из этого сравнения не устанавливается.

Проверки охватывают формы регистрации и входа, почтовый parser / UID baseline,
адаптер и SDK runner: однократные отправки, отсутствие маркетинга, origin / port,
ограничение частоты, неоднозначный код и исключение старой почты.
Настоящий synthetic WebView2 smoke также прошёл.

Всего прошли 17 целевых тестов. Временный клиент Phone Exit остановлен штатно
после SDK-проверок, exit 0; системные маршруты не менялись.
