# Runtime: владелец подключённого сокета

20 октября 2026. `vampir_core.game_connection.GameConnection` объединяет
[приём потока](RECEIVE-STREAM.md), очередь отправки и
[список / выбор персонажа](SELECTION-FLOW.md). Он получает уже подключённый
сокет, переводит его в неблокирующий режим и владеет им до закрытия.
Подключение к серверу, SDK / device context и подтверждение устройства ещё
не реализованы этим классом. Version / Login из явных payload подключены
следующим изменением: [LOGIN-FLOW.md](LOGIN-FLOW.md).

## Контракт владельца

Конструктору передаются явные ключ и sequence, лимиты приёма, списка / выбора
и очереди отправки, а также синхронный `on_packet(packet)` для остальных ID.
Handler должен быстро возвращаться и не накапливать тела без ограничения.
После `start_login()` ID2 / ID4 направляются в LoginFlow, а не в этот callback.
Вызов `pump(now=..., budget=PumpBudget(...))` выполняет ограниченный объём
работы. Часы монотонные; повторный вход в pump запрещён.

За проход выполняются:

1. Проверка таймаута ожидаемого ответа списка / выбора.
2. Разбор накопленного пакета либо ограниченное чтение сокета.
3. Обработка ID11: точное тело u64 → ack ID12 под старым ключом → новый
   ключ для последующих отправок и приёма. Следующий пакет, даже из того же
   сжатого блока, разбирается только после обработки смены ключа.
4. Передача ID102 / ID110 в `CharacterSelectionFlow`; остальные ID
   поступают в `on_packet`. Полный игровой dispatcher пока не реализован.
5. Ограниченная отправка очереди с сохранением частично отправленного хвоста.

`PumpBudget` ограничивает число пакетов, транспортных блоков на попытку
извлечения пакета, чтений, размер чтения и число отправок. Накопленные данные
могут оставаться после прохода: вызывать pump регулярно, даже без нового
события чтения. Максимальное число попыток извлечения ограничено числом
пакетов плюс числом чтений и одной финальной проверкой. Внутренние бюджеты
не являются установленными лимитами сервера.

`enter_character_list()` остаётся явным разрешением внешнего lifecycle.
`select_character(index)` использует текущий список. Свойство `selection`
предоставляет состояние, ответы, предпочтительный индекс и обновление rawF0.
Успешное тело ID110 не означает готовность мира или известную позицию.
`queue_ping(payload)` ставит явно заданный Ping; периодичность и смысл его
двух raw-полей здесь не угадываются. Автоматического heartbeat пока нет.

## Ошибки и остановка

Таймаут, неподдержанный результат выбора, повреждённый кадр / тело,
невозможность поставить ack, ошибка сокета или исключение callback закрывают
соединение и удаляют очередь / данные персонажей / буферы приёма. Внешнее
закрытие selection flow также приводит к закрытию сокета при следующем pump.
`error` содержит короткую локальную причину; исключение обработки выдаётся
без содержимого пакетов и деталей callback. Значение ключа в repr скрыто.

При EOF сначала обрабатываются полные накопленные пакеты. Неполный хвост
считается ошибкой. Чистый EOF закрывает соединение без ошибки. `close()`
можно вызывать повторно. Переподключение требует нового сокета и экземпляра;
автоматической повторной отправки старых кадров нет.

Состояние соединения означает только владение транспортом, а не успешную
авторизацию. Устройство и почта не используются в этих локальных проверках.

## Источники и проверка

Порядок смены ключа подтверждён кодом клиента:
[HEADLESS-KEY-CHANGE.md](../resource-tools/vampir/HEADLESS-KEY-CHANGE.md).
Общий source SHA256:
`c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`.
Native игнорирует результат отправки ack; локальная очередь при отказе
закрывает соединение и не продолжает обмен. Это явная политика бота.
Источники framing и полей перечислены в RECEIVE-STREAM.md / SELECTION-FLOW.md.
Полный native lifecycle этот владелец не воспроизводит.

```powershell
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_game_connection.py
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_receive_stream.py
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_selection_flow.py
```

Все 32 теста прошли: девять новых тестов владельца и 23 теста потока / выбора.
Новые socketpair-проверки покрывают полную цепочку списка / выбора, EOF,
смену ключа между объединёнными пакетами и ack под старым ключом, лимит
пакетов, таймаут до отправки, ошибку результата, повреждённый key notify,
отказ очереди ack, неполный EOF, исключение callback и явный Ping.
Локальные ответы синтетические; совместимость с сервером игры не проверена.

Далее — реальные поля Version / Login и остальные обязательные обработчики,
подтверждённое событие запроса списка, SDK / device context для реального
входа и восстановление после разрыва. Игру для этих проверок не запускали.
