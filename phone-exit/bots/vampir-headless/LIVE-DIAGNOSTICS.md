# Журнал и обработка во время работы

25 октября добавлены журнал каждого bot/session и отдельный
локальный обработчик, который можно менять без перезапуска владельца игрового
соединения. Проверены локальный API / браузер на fixture и смена обработчика
на настоящем персонаже через OPPO / HK, включая SyntaxError и восстановление.
[Живой результат и границы](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-LIVE-JOURNAL-11316.md).

`live.html?bot=<bot>&session=<session>` показывает журнал, фильтр по ID пакета,
паузу отображения и отдельные результаты обработчика. Используется тот же опрос
состояния раз в секунду, отдельный таймер журнала не создаётся. Пауза отображения
не останавливает сессию. История относится к зафиксированному session ID.

Пример подключения к уже работающему владельцу:

```powershell
python -X utf8 phone-exit/bots/vampir-headless/watch-live-session.py --bot hk-test --session <точный ID из /sessions> --handler <свой локальный Python файл>
```

Для начала скопировать [пример](observe-stats-example.py) в личный рабочий файл.
Функция `analyze(batch)` получает `state`, новые `events`, `samples`, `previous`
и возвращает словарь. Основной файл читается и компилируется заново на каждой
итерации; каждый вызов работает в новом процессе с таймаутом 2 секунды.
Вспомогательные модули также импортируются без прежнего bytecode-кэша; папка
`vampir-shared` доступна для подключения декодеров. `revision` — SHA основного файла,
не полный перечень SHA его зависимостей.
Синтаксическая ошибка, исключение и зависание не блокируют socket pump.
Результат до 16 KiB записывается в отдельное поле `analysis` и истекает через
6 секунд без обновления. Проверенные HP/MP и другие поля персонажа он не меняет.
Процесс не является песочницей безопасности: запускать только свой доверенный код.

Ctrl+C закрывает наблюдатель, а не игровую сессию. Изменение сетевого владельца,
его транспорта и исходящих игровых команд этим механизмом не выполняется.
Для обработки нового wire-формата можно подключить новые декодеры в наблюдателе;
внедрение их результатов в подтверждённую модель требует отдельной проверки.

По умолчанию журнал содержит только время, ID / размер пакета, изменения
HP/MP/уровня и служебные события. Тела пакетов и credentials на диск не пишутся.
Журнал ограничен 256 событиями, snapshot содержит последние 32; cursor API
возвращает до 128 и сообщает о пропусках.

Для временного чтения содержимого явно добавить `--trace-packet 322` (флаг
повторяемый). Разрешены только world IDs 301, 302, 307, 321, 322, 324, 325.
SDK, auth, lobby, login, selection и world-entry тела не допускаются.
Захват — в памяти: до 128 пакетов / 256 KiB, одно тело до 64 KiB, срок 60 секунд.
Наблюдатель продлевает свою lease каждые 20 секунд, чужая lease отклоняется.
Остановка владельца очищает samples. Это ограниченная диагностика, не полный
lossless capture; пропуски нужно учитывать при разборе.

API на том же loopback-порту и с прежними Host / Origin проверками:

- `GET /bots/<bot>/events?session=<ID>&after=<cursor>` — журнал.
- `POST /bots/<bot>/trace` — точные bot/session, `lease`, `packet_ids`.
- `GET /bots/<bot>/samples?session=<ID>&lease=<lease>&after=<cursor>` — samples.
- `POST /bots/<bot>/analysis` — точные bot/session, `revision` SHA256,
  `values` словарь, `error` код либо null.

Изменения и чтение samples требуют токен `X-Session-Token` из `/control`.
API не принимает путь к Python файлу и не запускает переданный код.

Локальные проверки диагностики, session API, probe и JS adapter пройдены.
Интеграционный fixture API подтвердил смену ревизии с `eb086981…` на `0ffef661…`
при том же session ID: heartbeat продолжился с 55 до 108. Получен один sample
ID 322 в очередном batch. Fixture остановлен через API, HTTP 202.
Приватный результат без credentials:
`F:/PhoneExit Resources/Vampir/live-checks/hk-20261025/journal-hot-reload-result.json`.
Это синтетический владелец, не доказательство hot reload в реальной игре.

После перезапуска Codex проверен браузер: явная маркировка тестовых данных,
обновление журнала, фильтр ID 322, пауза текста при росте heartbeat с 30 до 53,
новая ревизия обработчика `0ffef661…` и результат `updated_while_running`.
Snapshot UI `4d81998f2951895eca78367d7f655b4cd337c9139a7f16dfde14a576009b6ab6`.
Автопрокрутка следует за последними событиями, пока пользователь не прокрутил
историю вверх. Горизонтального переполнения страницы на проверенном viewport нет.
Screenshot: `F:/PhoneExit Resources/Vampir/live-checks/hk-20261025/live-journal-fixture.jpg`.
После Ctrl+C наблюдателя захват выключился, результат обработчика очистился,
а fixture heartbeat продолжился до 226. Затем fixture остановлен кнопкой UI.
Итоговый набор: 69 Python-тестов, JS adapter / syntax и byte/provenance verifier
сборки прошли. Это разные проверки: native stats scenarios предыдущего этапа
не выдаются за проверку нового браузерного журнала.

Отдельная живая проверка OPPO / HK подтвердила смену обработчика и восстановление
после SyntaxError при неизменном session ID и продолжающемся heartbeat.
Hot reload самого socket owner, wire-протокола и применение команд персонажа
этим механизмом не выполняются.
