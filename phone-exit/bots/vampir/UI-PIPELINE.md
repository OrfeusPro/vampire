# Единый конвейер интерфейса

Сборка развивается по готовности подтверждённых правил. Общий аудит
[характеристик](UI-PROPERTY-TASKS.md) продолжается; приближения по скриншотам
этим решением не разрешены. Задачи — UI-27.09 в [плане](UI-TASKS.md).

## Запуск

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-ui-pipeline.py --audit-only --snapshot 'F:/PhoneExit Resources/Vampir/maps/ui-prototype/snapshots/4ceec6f214cbe9d28e35d1a05d5a3c4731d45296e15336575075202793d0cde9'
python -X utf8 phone-exit/bots/resource-tools/vampir/build-ui-pipeline.py --build-ready --snapshot 'F:/PhoneExit Resources/Vampir/maps/ui-prototype/snapshots/4ceec6f214cbe9d28e35d1a05d5a3c4731d45296e15336575075202793d0cde9'
```

Поддерживаются `--root` и `--output`; результаты находятся вне Git,
по умолчанию в `ui-property-scans/pipeline` ресурсного каталога.
Стадии: полный source audit → исходные Outer-ветви → индекс общих компонентов
→ отчёт допуска; build-ready дополнительно вызывает builder и verifier.
Неучтённый slot candidate сохраняется как unknown; source error останавливает сборку.

## Кеш и допуск

Ключ стадии содержит полные SHA входов, инструментов и зависимостей.
Перед reuse проверяются все выходные файлы. Повреждённый или незаконченный
кеш вызывает ошибку и сохраняется для диагностики; успешный receipt не создаётся
при исключении. При изменении исходников полный source audit выполняется заново;
пока это кеш стадий, а не отдельных exports. Проверка и хеширование имеют стоимость
и при cache hit. Время находится в отдельных run-отчётах и не меняет идентичность данных.

[Реестр правил](UI-RULES.json) содержит ID, версию, provider, свойства,
зависимости и обязательные проверки. Отчёт readiness привязывает правила
к полным SHA provider / реестра, исходным наборам и результатам проверок.
Builder повторно воспроизводит проверку исходных ветвей и индекса потребителей.

Первые правила подтверждают анализ Outer ownership и static consumers.
Они имеют renderer_allowed=false: новые свойства оформления и геометрии
ещё не разрешены. build-ready сохраняет существующий демослой с его прежними
ограничениями; applied_renderer_rules остаётся пустым и фиксируется в manifest.
Нельзя выдать эту пересборку за исправление неизвестных Brush / DPI / событий.

Отчёт включает четыре приоритетных общих компонента со всеми найденными
подключениями, ограничения и timings стадий. Тесты, проверка данных и визуальная
сверка имеют разный охват. Критерии UI-W автоматически этим отчётом не закрываются.
Сканирование выполняется при подготовке общего набора, а не в 50 окнах ботов.

## Следующий проход

Подтвердить renderer правила приоритетных компонентов и их зависимости,
добавить применение и проверку всех подключений; связать изменения правил
с очередью UI-W. После визуальных проверок записать скорость прохождения
полного конвейера. Срок всего восстановления определяется по этому результату,
а не по скорости одного source audit.

## Проверенный проход

### Очередь изменений по baseline

К audit-only или build-ready можно добавить `--baseline-readiness <index.json>`
и `--baseline-sha256 <полный SHA>`. Baseline проверяется до сканирования:
SHA readiness, component index и composition graph. Старые readiness без SHA
графа сохраняются, но для сравнения требуется новый baseline через audit-only.

`ui_rule_impact.py` переиспользует compare / affected существующего графа.
Изменение версии, определения, результата проверки или provider SHA правила
распространяется на зависимые правила и обратных потребителей по прежнему
и новому графам. `widget_types` задаёт область, `criteria` — критерии UI-W
.01–.06. Два нынешних правила анализа имеют общую область и критерий .01.
Неизвестная область расширяет очередь консервативно и записывается отдельно.

Добавление / изменение / удаление источника создаёт проверки всех шести
критериев для затронутых ресурсов. Архивные варианты, циклы, исчезнувшие
компоненты и прежние потребители сохраняются; активный вариант не выбирается.
Один ресурс получает один UI-W пункт со списком вариантов, причин и критериев.
Основные статусы UI-WINDOW-TASKS не перезаписываются.

Выход `impact/<SHA>/index.json` и `TASKS.md` воспроизводим; run-отчёт содержит
ссылку и размеры очереди. Нулевая очередь означает отсутствие новых изменений,
а не готовность интерфейса или закрытие прежних неизвестных.

Readiness содержит автоматический `priority_coverage`: собственные варианты
приоритетных классов и прямые / косвенные ресурсы-потребители. Сейчас Badge
охватывает 367 ресурсов, ItemIconT 287, ShortcutkeyHudT 237, PopupBgTitle 234.
Это статические кандидаты, а не подтверждённые runtime bindings.

Проверки расширения: 35 тестов вместе с builder / кешем, включая смену provider
SHA, зависимости правил, удаление компонента, циклы / архивные варианты,
неизвестную область, некорректные критерии и подмену baseline / графа / индекса.
Первый полный baseline проход 92,315 с; повтор со сравнением 14,417 с, все стадии
анализа reused=true, новых ресурсов в очереди нет. Отчёты в каталоге pipeline:
`run-1792941730487141000.json` и `run-1792941775191257800.json`.
Повтор после подключения автоматического priority_coverage прошёл за 90,337 с:
`run-1792941988933988600.json`, исходные стадии пересчитаны после изменения инструмента.

Пример проверенного baseline: `readiness/990acc72467e7c7a25ac830140a010c33ec73a53427db637a75393dd35e6bd70/index.json`
в каталоге pipeline, SHA256 `990acc72467e7c7a25ac830140a010c33ec73a53427db637a75393dd35e6bd70`.

### Первая сборка с поэтапным допуском

25 октября 2026 года полный build-ready прошёл для 1970 ресурсов / 2376 вариантов;
verifier проверил snapshot с 1502 текстурами. Первый проход занял 159,165 с,
следующие — 78,846 с и 64,740 с. Два последних запуска при одинаковых входах
дали один snapshot `8e29050c84c16209e40dff8cd791e7987e9b76715feb564a9170f64958707cab`.
Во всех трёх стадиях анализа повторного запуска reused=true; чтение SHA входов,
независимый replay допуска и verifier сборки продолжают выполняться.
Это замеры конвейера данных, не оценка времени восстановления неизвестных свойств.

Отчёты в `F:/PhoneExit Resources/Vampir/ui-property-scans/pipeline`:
`run-1792940901903960100.json`, `run-1792941154228323600.json`,
`run-1792941236690603500.json`. Каждый содержит SHA входов через receipts стадий,
ссылку на immutable readiness и результаты verifier.
Первый диагностический запуск во время изменения builder остановился на SHA mismatch;
несовместимые инструменты не были приняты как проверенные.

Прошли 27 локальных тестов: reuse / смена зависимости / повреждение и удаление
выходного файла / незавершённая стадия / запрет неподтверждённых renderer rules,
а также прежние проверки builder. JavaScript прошёл node --check.
В браузере проверены русские ограничения каталога, закрытие Escape и возврат
фокуса к открывшей кнопке. Снимок `catalog-check.png` находится рядом с отчётами.
Проверка трёх разрешений, полное визуальное соответствие и 50 окон этим проходом
не подтверждены; UI-27.09.02–.04 остаются открытыми.
