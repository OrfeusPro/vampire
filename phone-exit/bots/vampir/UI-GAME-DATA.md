# Игровые данные в графе автосборщика

Квесты, NPC / монстры, боевые параметры и пространственные данные входят
в [этап сканирования](UI-PROPERTY-SCANNER.md). Затем проверяются характеристики
и связи, после этого они используются для генерации. Данные общие и неизменяемые;
состояния 50 ботов должны оставаться отдельными. Сканирование не запускается
заново в каждом окне и не отправляет команды игры.

## Что собрано

`scan-game-ui-data.py` читает существующие quest-graph, monster-manifest,
подробные записи NPC и схемы 1565 извлечённых CSV таблиц. Узлы имеют пространства
имён Quest, QuestTask, QuestTaskAction, WorldSpot, Tutorial, TutorialStep,
TutorialUI, Npc и Battle. Одинаковое число в разных таблицах не создаёт связь.
Сохранены исходные поля, точные CSV записи, SHA, прямые и обратные индексы.

В графе 1353 квеста, 5944 этапа, 3892 записи действий, все 588
WorldSpot, 26 обучений, 139 шагов, 94 TutorialUI, 5285 NPC и 5163 записи
боевых параметров. Пространственная ветвь добавляет 254 World, 154 Map,
501 Area, 1460 AreaBox, 69 Waypoint, 61307 NpcSpawn, 1685 GadgetSpawn,
744 Gadget, 51 MapIcon и 30 MapIconLayer. Всего 152634 связи.
Не все NPC являются монстрами. Проверка сверила 88739 записей с исходными
CSV строками, включая совпадение WorldSpot между квестами и атласом.

Навыки, эффекты, награды, добыча и размещение дополнительно сохранены ссылками
на исходные подробные записи NPC. Остальные таблицы пока представлены схемами
колонок. PreQuestId сохранён как исходное поле и ссылки на токены: AND / OR,
ветвления, доступность следующего задания и цели-монстры ещё требуют разбора.
Связи TutorialUI из прежнего каталога не являются подтверждёнными кликами.

## Карта, полигоны и лифты

В `map_evidence_refs` сканер учитывает существующие atlas/index, projection,
lift-preview, navigation-overlay-manifest и geometry-readiness. Для проекции,
лифта и overlay проверяет SHA явных зависимостей; сохраняет ссылки на полные
исходные отчёты, не сворачивая их геометрию в плоский список точек.
Вложенные источники этих отчётов требуют отдельного аудита происхождения.

`spatial_inventory.objects` содержит 18559 адресуемых записей: 18430 NavTile,
62 SpecialLink, 63 Lift и 4 NavigationFilter. Каждая запись указывает на
исходный JSON pointer; полный SHA файла входит в inputs набора. Векторы,
диапазоны высот и индексы поверхностей проверены на допустимую форму / границы.
Это структурная проверка overlay, не геометрический разбор всего native mesh.
Grid, coordinate proof и семь явно связанных navigation evidence проверены
по SHA. Старые адреса из evidence не применялись к текущему EXE.

Обнаружено 292 пространственные характеристики, у каждой постоянный ID
и [собственный чекбокс](UI-SPATIAL-PROPERTY-TASKS.md). Сканер различает поля CSV
и поля производного отчёта; поля placement / initial_fields, missing,
runtime_verified, условия и допущения не объединяются в готовое состояние.
Наблюдения вложенных массивов учитываются по полю с `[]`; векторы и массивы
индексов сохраняются целиком в исходном отчёте, не разворачиваются в свойства
по отдельной координате. Число наблюдений не является числом проверенных объектов.

Начат разбор World.MapId, WorldSpot.PosZ, Waypoint.TeleportSpot,
NavTile.polygons и Lift.placement.RelativeRotation:

- World 11, 12, 13, 14, 15 и 101 ссылаются на отсутствующий Map 3.
  Все шесть ссылок сохранены как unresolved, замена ближайшей картой запрещена.
- Waypoint.TeleportSpot связывается с WorldSpot.Id по существующему правилу
  атласа. Наличие записи не подтверждает активацию, оплату или успешный переход.
- WorldSpot.PosZ сохранён в исходном виде. Overlay хранит XY и общий диапазон
  высот; он не сохраняет Z каждой вершины и не подтверждает конкретный этаж.
- NavTile.polygons индексирует vertices текущего overlay. После исключения
  special polygons номер поверхности не равен исходному native polygon index;
  сопоставление и соседство требуют отдельного источника.
- У шести лифтов отсутствует RelativeRotation; не подставляется ноль.
  Даже у остальных 57 рассчитанные точки остаются условными до проверки
  мирового transform, направления, активации и игрового состояния.

Найденный overlay содержит 18430 ячеек / 101090 поверхностных полигонов,
62 специальных полигона исключены. Предварительный слой лифтов содержит
63 размещения; рассчитанные связи условные. Эти числа относятся к прежним
отчётам; совместимость с установленным клиентом и проходимость не подтверждены.
`navigation_ready=false` сохраняется. Исследования и ограничения:
[атлас карты](../resource-tools/vampir/knowledge/evidence/maps/MAP-ATLAS.md).

## Повтор сканирования

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/scan-game-ui-data.py --verify
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_ui_property_coverage.py -v
```

Наборы хранятся вне Git в `F:/PhoneExit Resources/Vampir/ui-game-data-scans/<SHA>/`.
SHA набора учитывает входные файлы и сканер. verification.json подтверждает
перенос статических записей и хеши входов; полнота смысловых связей и текущая
совместимость этим не подтверждаются. Новый клиент требует нового аудита.

Для нового чеклиста можно указать `--spatial-tasks <новый-файл.md>`.
Существующий файл не перезаписывается; проверенные отметки сохраняются при
ручном объединении новых ID. На runtime окна передаются только необходимые
проверенные проекции: полный аналитический JSON (около 114 МБ) туда не загружать.
Разделение на runtime chunks и измерение 50 окон ещё не реализованы этим сканером.

Предыдущий проверенный набор 25 октября 2026:
`6747dd3a2987f8dd0308767ea7b8f893a59369a8c430d46dd84b4e6e06a6e9c3`;
6867 входных файлов. Проверены исходные строки и SHA пространственных входов.
Локальные проверки: 7 новых Python fixtures, 22 проверки прототипа и 60 Node
тестов прошли. В том числе проверены подмена пространственного источника,
выход пути за корень, несовпадающие родительские ID и варианты боевых записей.

Текущий расширенный набор:
`b34542d3ff0dd9ddbaac7bbced237a9c70d46f2c08cc81545acfdb03030212b6`;
6877 входных файлов, 88739 записей проверены. Девять Python fixtures прошли,
включая конфликт WorldSpot, отсутствующий Map, отрицательные / логические
индексы полигонов и стабильность ID характеристик при добавлении записей.
