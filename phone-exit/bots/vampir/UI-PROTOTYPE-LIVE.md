# Живой режим основного прототипа

Основной адрес: `/maps/ui-prototype/index.html?mode=live&bot=<bot_id>&session=<session_id>`.
Сборка остаётся результатом общего `build-ui-prototype.py --preview-during-audit`;
новой отдельной сборки или обхода UI gate нет. Без live-параметров остаётся демо.

«Окружение» показывает NPC и других игроков через тот же адаптер: тип / ключ,
имя игрока / код NPC, уровень, HP/MP и начальную XYZ. Неизвестные поля — «—».
Проверка браузера выполнена на явно помеченном fixture; при разрыве строки очищаются.
[Источник полей и ограничения](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-INITIAL-ENVIRONMENT-11316.md).

Проекция Map10/11 перепроверена для 1.13.16. Первая подтверждённая позиция
центрирует и приближает карту после загрузки атласа; polls / выбор объекта
не меняют ручной вид. Постоянное слежение — отдельная выключенная по умолчанию
настройка окна. [Источник и проверки](../resource-tools/vampir/knowledge/evidence/maps/HEADLESS-MAP-POSITION-11316.md).

## Данные и действия

ID 1854 теперь передаёт последнее полученное сообщение через quests /
quest_snapshot. Правая панель принимает его при совпадении персонажа / мира,
показывает записи и raw progress; названия и активный шаг ещё не установлены.
Следование отключено. Проверены 50 synthetic owners и браузер через API;
настоящий новый список ещё не проверен.
[Контракт и ограничения](../resource-tools/vampir/knowledge/evidence/scenarios/HEADLESS-LIVE-QUEST-MODEL-11316.md).

`prototype-live.js` создаёт один `VampirLiveState` с точными bot/session IDs.
Чистая проекция `prototype-live-model.js` передаёт значения общим HP/MP,
основному меню, параметрам, заданиям, журналу и карте. Виджеты не опрашивают
сеть и не управляют socket owner. Live-ветка не вызывает загрузку / сохранение
демопрофиля, не приобретает его writer lease и не принимает демособытия карты.
Скрытие / закрытие освобождает опрос; возвращение из BFCache восстанавливает
адаптер с прежней идентичностью. Закрытие UI не отключает персонажа.

Параметры: HP/MaxHP, MP/MaxMP, уровень, мир, серверная XYZ-цель;
stat 1 отображается исходной строкой, stat 134 — целая часть native деления
на 100. Все исходные stats доступны через существующую кнопку «Боевая статистика».
Источник семантики — [проверка stats](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-STAT-NOTIFY-11316.md).
Неизвестные значения / валюты показываются «—», signed64 строки сохраняют точность.

«Персонаж» и «Боевая статистика» доступны при полученных данных. «Задания»
доступны при `coverage.quests=received` либо проверенном last_received_message
контексте выше; отсутствие данных не считается пустым списком. Контракт карточки:
`quests[].id` и `title`; у raw ID 1854 title пока неизвестен. Выбор полученной карточки
локальный, «Следовать по заданию» отключено до проверки команды и адаптера действий.
«Настройки» / «Назначение клавиш» относятся к просмотру этого окна;
остальные исходные пункты видны и отключены с пояснением. Портрет пока статический.

Журнал получает `snapshot.journal` / `analysis` / `tutorial` от того же адаптера,
хранит до 256 событий в памяти окна; разрыв последовательности обозначается.
Пауза и фильтр меняют отображение, обработка сессии продолжается.
Подробный диагностический просмотр / Stop доступны по ссылке «Диагностика».
Игровые команды из нового контроллера не отправляются.

Последнее сообщение ID 9905 выводится отдельным диагностическим блоком:
до 64 записей raw08 / raw0c / raw10 / state, с явным отличием от активного
локального шага. Оно не включает меню заданий. Проверены границы, очистка,
копирование и реальные 16 записей без перезапуска game owner.
[Доказательства и временное размещение](../resource-tools/vampir/knowledge/evidence/scenarios/HEADLESS-LIVE-TUTORIAL-JOURNAL-11316.md).

## Карта и границы позиции

Большая карта использует существующий iframe атласа. Отдельного API-опроса
в iframe нет; parent передаёт состояние через same-origin postMessage с точными
bot/session IDs. Режим читается из исходного `iframe.src`, поскольку сам атлас
переписывает query при загрузке. Демо / live сообщения разделены.

Маркер разрешён только для `snapshot.position`, принятой backend-проекцией:
совпадение world ID, известная карта 10 / 11, конечные XYZ / pixel XY и явная
семантика серверной цели. `character.position` само по себе не создаёт маркер.
Это серверная цель до engine correction, не доказанная актуальная позиция actor.
При неизвестных данных / отключении маркер очищается; центрирование недоступно.
Автоцентрирование можно выключить в локальных настройках.

Текущий owner 1.13.16 публикует raw XYZ, но `position=null`: новая привязка
Map / World и native projection ещё не проверена. Старый SHA guard сохранён.
Поэтому настоящий маркер этого персонажа пока не заявлен как работающий.
Слои статических NPC, объектов, порталов и квестов скрыты; остаются справочные
области исторического атласа. Они не означают живые объекты рядом.
При `coverage.entities=partial` показан только полученный NPC subset и его размер
с пометкой неполноты. Кнопка «Окружение» открывает ключи, raw код, HP / MaxHP и
XYZ при появлении; текущие изменения stats / движения ещё не подключены.
При отсутствии данных или ошибке карточка очищается. [Контракт и проверки](../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-OBSERVED-ENVIRONMENT-11316.md).

## Паспорт представления

Повторно используются [общий статус / портрет](UI-PLAYER-STATUS.md) и
[исходное меню](UI-MENU.md), их ресурсные пути, SHA, схема и ограничения.
Контролы меню сохраняют исходные IDs и иконки; добавленная доступность — правило
просмотра по данным адаптера, не восстановленные игровые callbacks.

Размещение live HUD, справочных полей, карточки задания и окна журнала временное,
явно отмечено `temporary-live-shell`. Оно задано отдельно в `prototype-live.css`;
это не восстановленная геометрия игровых окон персонажа / квестов / настроек.
Общая шкала компонента использует reference 2400 × 1350 с нижним пределом 0,55;
активные DPI / UI Scale игры неизвестны. Окна ограничены viewport, содержимое
прокручивается. Будущий native layout должен заменить эти допущения через общий
сборщик. Это подключение данных не закрывает геометрию / оформление / callbacks.
