# Vampir — первый ограниченный запуск

Обновлено 16 октября 2026. Версия кандидата: 1.0.8, движок 3.
Главный указатель: [README.md](README.md); состояние задач: [TASKS.md](TASKS.md).

## Что собираем

Имеющийся бот: запуск Android-пакета `com.netmarble.thered`, включение игрового
автоквеста на распознанном HUD, 18 проверенных учебных действий, известные
диалоги/пропуск сцен, Guide-награды и обработчик покупки Guide901030.
Это ограниченный кандидат для испытания, не полная автономная прокачка.

Профиль [first-run.settings.json](first-run.settings.json) включает квестовый режим,
автозапуск пакета и пропуск подтверждённых сцен. Фарм, восстановление и разбор
выключены. Файл — образец полного профиля для отправки через существующий Bot API
или настройки ПК; установка ZIP сама его не применяет. defaults.json сохраняет
quest_enabled=false: назначение/установка не запускают бота автоматически.

## Порядок проверки

1. Локально выполнить `python -X utf8 -m unittest discover -s phone-exit/bots -p 'test_vampir*.py'`
   из корня проекта; затем `python -X utf8 phone-exit/bots/resource-tools/vampir/replay-shop.py`.
2. Собрать подписанный пакет:
   `powershell -NoProfile -File phone-exit/pc/build-bot-package.ps1 -Bot vampir`.
   Выход: `phone-exit/.tools/bot-release/vampir-1.0.8.zip` и `.zip.json`.
3. Отдельный следующий этап — публикация/установка на Pixel 5 · JP и отправка
   настроек с подтверждением применённой редакции. До этого на телефоне остаётся 1.0.7.
4. Первый прогон начать с персонажем в мире. Проход титульного экрана/выбора
   персонажа пока не включён (`launch_buttons=[]`). Запуск пакета не равен
   входу до персонажа. Последнее сообщение отключения сессии пользователь
   проверяет самостоятельно; бот его не обходит и не переподключает сессию.
5. Наблюдать 10–15 минут: распознавание → игровое авто-задание → известное
   обучение/диалог → награда → следующее подтверждённое действие. Записывать
   фактически достигнутый участок; если ранее пройденное обучение не появилось,
   это не считается его повторной проверкой. Бой/перемещение выполняет игровой автоквест.
6. При остановке сохранить исходный кадр, модель/разрешение, версии игры/бота,
   статус step/reason/error, последнее действие и наблюдаемый tutorial/task.
   Последнее наблюдение не выдавать за текущий серверный этап.
7. Искать препятствие по существующим таблицам и UI-индексу, затем при необходимости
   продолжать разбор кода/данных клиента. Добавить ограниченный обработчик,
   проверку результата и кадры для повторного прогона, собрать следующую версию.

## Ограничения и завершение первого этапа

Неизвестные окна — пауза, без кликов по предположительным координатам. Неизвестный
результат покупки блокирует повторное списание и после перезапуска; успешного
кадра результата ещё нет. Журнал purchases не очищать для обхода этой проверки.
Подтверждённые задержки и ограниченные повторы сохраняются. OCR не используется.

Первый этап завершён, когда на Android записан непрерывный участок квестовой
работы с хотя бы одним подтверждённым переходом после действия/награды и
понятной диагностикой остановки. Один запуск процесса или зелёный статус
не подтверждает этот критерий. Длительный автономный тест, полный вход,
магазин и поздние задания имеют отдельные критерии V07/V09/V17.

Локальные проверки не подключаются к телефону. Живые проверки были отложены
пользователем; сборка не меняет установленный пакет, профиль и состояние телефона.
