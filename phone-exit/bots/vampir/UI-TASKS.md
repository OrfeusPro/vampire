# Интерфейс Vampir: задачи

## Правила отметок

- `- [ ]` — не начато.
- `- [ ] ~` — в процессе, включая проверку.
- `- [x]` — выполнено и проверено.
- `- [ ] Заблокировано: …` — причина и ID зависимости.
- `- [ ] Отменено: …` — причина; не мешает закрытию родителя.

ID постоянны: новые пункты добавляются без перенумерации. Новые подзадачи добавлять
сразу при обнаружении. Родитель получает тильду при начале работы и закрывается
после проверки всех обязательных подзадач. Недоделка открывает задачу и родителя
заново; расширение получает новый ID. Для существенных пунктов указывать критерий
готовности, для закрытых — результат проверки. Демо и реальный бот проверяются отдельно.

При обновлении клиента создавать отдельный чеклист с версией и полным SHA256.
Прежние результаты относятся к прежним источникам; реализация окна не открывается
заново без обнаруженного дефекта. Совместимость новой версии требует новой проверки.

## Принятые решения

Отдельная локальная страница рядом с атласом, HTML/CSS/JavaScript. Визуально близко
к 11 изображениям; отдельные интерактивные контролы и извлечённые ресурсы. В игре
2D-карта заменяет мир, HUD и окна находятся поверх. Персонажи представлены в 2D;
ползунки сохраняют параметры, полноценное изменение 3D не имитируется.
Весь каталог учтён; неизвестные связи видны в каталоге проверки. Демонстрационное
состояние изолировано от реальных профилей, сетевые игровые команды не отправляются.
Критерий готовности прототипа: проход UI-04 → UI-10, согласованные локальные действия,
проверенные окна и попапы, визуальная сверка и разрешения из UI-15.

## Этапы

ресурсов и кэш; изолированное состояние каждого окна. UI-18 проверяется отдельно
от реальных 50 сетевых сессий. Массовое открытие окон при проверке не выполнять
без явного запроса; сначала измерять ограниченный набор и модель 50 состояний.
