# Распознавание состояния без root и OCR

<a id="что-реализовано-в1014"></a>

## Что реализовано в 1.0.14

recognition.py задаёт общий порядок поиска. После подтверждённой подсказки
сначала проверяется ожидаемый шаг из quest-runtime.json. Неинтерактивные шаги
4(пауза) и 18(подготовка цели) пропускаются только для приоритета поиска,
а не для ввода. Затем проверяется прежняя подсказка и её учебная цепочка.
Если они не совпали, остаётся весь список других подсказок. Предсказание не
разрешает tap. Тип tutorial/inventory/item_info/enhancement определяется из
источника реально найденной подсказки; это владелец контрола, не полное дерево
видимых окон. Классификатор всех неизвестных окон пока не реализован.

bot.py кеширует match только до следующего capture. Старые координаты/совпадения
не используются для следующего кадра. Проверка HUD перенесена после обучения,
чтобы не искать его кнопки, когда уже опознана учебная цель. Общие сообщения,
отключение и вход обрабатываются до квестов. Поиск безопасности не пропускается.
Неизвестный экран остаётся в прежнем ограниченном ожидании/паузе.

Полного отказа от шаблонов нет: данные клиента задают смысл и ожидаемую цепь,
а реальные пиксели подтверждают состояние и кнопку. Root, OCR, чтение памяти и
внутренних файлов игры не используются. Неизвестный текст не запускает действие.

## Проверка и измерение

benchmark-recognition.py использует настоящий bot.py на сохранённых кадрах,
сравнивая игнорируемую копию предыдущего состояния .tools/vampir-recognition-before.
Результат в библиотеке phone-tests/tutorial4007-2026-10-16/recognition-benchmark.json.
Повторные наблюдения: 40–52 match и 1678–2109 ms до; 21–22 match и 504–539 ms после.
Первое распознавание: почти тот же объём, 39–51 match; оно не ускорено существенно.
Это единичный DesktopOpenCV замер, не Android и не гарантия частоты кадров.
Во время settle бот не ищет квестовые кнопки, но проверяет общие сообщения.

## Tutorial4007

Связи 4007004→Hud_Inventory, 4007007→Inventory_EnchantItem,
4007009→ItemInfoPopup_Enchant, 4007011→ItemEnchant_MaterialSlot,
4007012→ItemEnchant_Enchant. 23 подтверждённые визуальные привязки генерирует
build-tutorial-bindings.py. Кадры/crop/SHA/повторяемый инструмент:
enhancement-reference.json,enhancement-observations.json,
resource-tools/vampir/build-enhancement-observations.py. Для сумки переиспользован
hud_inventory, для выделенного предмета/свитка — рамка, без изображения предмета.
Улучшение требует точную финальную подсказку, кнопку со стоимостью 2500,
безопасный диапазон и выделенный+1. Только одна попытка в текущем состоянии,
ошибка результата не разрешает авто-перезапуск. Другие улучшения не включены.
Источники UI: InventoryUI.TileViewList, ItemInfoPopup. ButtonEnchant,
ItemEnchantMultiUI.ButtonMaterialSlot/ButtonEnchantMulti; полная динамическая
геометрия не доказана, поэтому координаты сверяются с кадром/рамкой.

Живые ручные диагностические переходы: выбор выделенной брони→описание→Enhance→
свиток→финальная подсказка. Золото/свиток ещё не тратились в этой проверке.
Бот 1.0.13 подтвердил только открытие сумки; настоящий автоматический прогон
новых четырёх действий и скорость 1.0.14 проверяются отдельно.

## Android-проверка

1.0.14 подписана/опубликована/установлена после 208 тестов. На Pixel 5 бот сам
нажал финальную учебную Enhance: 31470→28970Gold, броня+1, обучение завершено.
Открытое окно Enhance пока не распознано как общий выход; tick 5915 и 9495 ms.
Это полный неизвестный поиск, не быстрый повторный путь. Бот поставлен на паузу.
Следующий приоритет: общий распознаватель/выход этого окна, затем измерение
скорости по нескольким Android-кадрам. Состояние известных учебных кадров не
означает реализованный универсальный классификатор всех экранов.
