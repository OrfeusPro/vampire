# Сканер характеристик и связей интерфейса

Это первая стадия общего автосборщика, а не отдельный продукт.
Порядок: сканирование → многомерный каталог → проверка каждой характеристики
→ правила применения → генерация внешнего вида. До аудита генерация остановлена
через [UI-GENERATION-GATE.json](UI-GENERATION-GATE.json); прежний snapshot сохранён.

Сканер читает все варианты имеющегося извлечённого ui-catalog. Недекодированные
UProperties, стили, dynamic bindings, callbacks и активные настройки остаются
пробелами. Наличие поля не доказывает его runtime применение. Метаданные
экспорта offset / size нельзя принимать за положение или размеры на экране.

## Формат данных

Вложенная структура хранится как набор JSON с индексами, чтобы не загружать
весь массив для одного вопроса:

```text
index.json
  datasets[SHA].resources[полный путь].variants[файл] → variants/файл.json
  datasets[SHA].variants[файл].source → полные SHA каталога / uasset / uexp
  properties[постоянный ID] → определение поля / типы / число наблюдений
  widget_types[тип] → все экземпляры
  required_characteristics → обязательные свойства, включая ненайденные
variants/файл.json
  widgets[export] → все исходные поля и свойства виджета
  slots[slot export] → исходная геометрия и provenance
  excluded_slots → недекодированные ветви
properties/ID.json → все места, где найдено поле
relations.json → parent / content / slot, порядок контейнера, nested class candidates
reverse-components.json → обратные потребители компонента
```

Это вложенные словари с прямыми ссылками и обратными индексами. Номер позиции
массива не используется как идентификатор виджета, свойства или порядка детей.
Все исходные значения сохраняются; совпадения имён относятся к кандидатам.
Вариант клиента / видимый root / native handler автоматически не выбираются.

## Запуск

Из корня репозитория:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/scan-ui-properties.py --requirements phone-exit/bots/vampir/ui-property-requirements.json
```

Вывод — `F:/PhoneExit Resources/Vampir/ui-property-scans/<SHA>/index.json` и
связанные файлы. SHA набора зависит от всех каталогов, сканера и требований.
Наборы сохраняются раздельно; при обновлении прежние результаты не объявляются
проверкой новой версии. Данные анализа не включаются в runtime 50 окон.

Для первого перечня задач можно явно передать `--tasks <новый файл.md>`.
Существующий файл с результатами сканер не перезаписывает. ID найденных полей
вычисляется из namespace / типа владельца / пути свойства, а не его значения;
у обязательных характеристик ID закреплён в ui-property-requirements.json.

## Первый набор

[Чекбоксы характеристик и полей](UI-PROPERTY-TASKS.md).
Набор `ae23e2f540c216777073fb621b03e668312022f9441a913bc3cb458890a24e60`
хранится в ui-property-scans вне Git: 2376 вариантов, 117916 виджетов,
72153 слота и 2783 исключённых слота. Найдено 8915 полей:
8815 catalog_control (метаданные), 19 explicit_properties,
10 inherited_properties, 67 slot и 4 container_relation.
83 обязательные характеристики учитываются отдельно; кандидат по имени не
закрывает их проверку. Поля Brush / Font / события не объявляются отсутствующими
в игре только потому, что прежний декодер не выдал их в этом каталоге.
Проверено 1586351 наблюдение: матрица полностью совпала с декодированными
источниками, все указатели полей, типы значений и связи прошли verifier.
Результат сохранён рядом с набором как `<SHA>-verification.json`.

Проверка матрицы и каждого обратного указателя:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/verify-ui-property-scan.py 'F:/PhoneExit Resources/Vampir/ui-property-scans/ae23e2f540c216777073fb621b03e668312022f9441a913bc3cb458890a24e60'
```

Verifier сравнивает все widgets / slots / excluded_slots с каталогами по полным
SHA, затем проверяет каждое наблюдение, тип значения, связи и обратные индексы.
Это доказательство полноты переноса декодированного каталога, а не полноты
исследования нативных свойств. Исходный пробный набор и чеклист сохранены
отдельно; фиктивное пустое поле, выявленное проверкой, в текущий список не входит.

## Как проходить каждую характеристику

У каждого пункта отдельно подтвердить:

1. Где свойство объявлено: тип, ресурс, вариант, export / offset, полный SHA.
2. Как читается: схема / тип / единицы, serialized field, inherited default,
   dynamic binding и условия смены значения.
3. К чему относится: владелец / родитель / ребёнок, прямые и обратные связи;
   что нужно применить раньше, где возможны override и двойное применение.
4. Как применяется: вычисление, оформление, состояние или событие; отличие
   native контракта от явной адаптации демо.
5. Как проверено: источники, fixtures и runtime / визуальная сверка в нужном
   объёме, оставшиеся неизвестные и зависимости.

Только после этой цепочки закрывается чекбокс характеристики. Генерация DOM,
наличие PNG или успешное сканирование не закрывают такой пункт.
