# Сканер характеристик и связей интерфейса

Это первая стадия общего автосборщика, а не отдельный продукт.
Порядок: сканирование → многомерный каталог → проверка каждой характеристики
→ правила применения → генерация внешнего вида. До аудита генерация остановлена
через [UI-GENERATION-GATE.json](UI-GENERATION-GATE.json); прежний snapshot сохранён.

Сканер читает все варианты имеющегося извлечённого ui-catalog. Недекодированные
UProperties, стили, dynamic bindings, callbacks и активные настройки остаются
пробелами. Наличие поля не доказывает его runtime применение. Метаданные
экспорта offset / size нельзя принимать за положение или размеры на экране.

## Формат данных

Вложенная структура хранится как набор JSON с индексами, чтобы не загружать
весь массив для одного вопроса:

```text
index.json
  datasets[SHA].resources[полный путь].variants[файл] → variants/файл.json
  datasets[SHA].variants[файл].source → полные SHA каталога / uasset / uexp
  properties[постоянный ID] → определение поля / типы / число наблюдений
  widget_types[тип] → все экземпляры
  required_characteristics → обязательные свойства, включая ненайденные
variants/файл.json
  widgets[export] → все исходные поля и свойства виджета
  slots[slot export] → исходная геометрия и provenance
  excluded_slots → недекодированные ветви
properties/ID.json → все места, где найдено поле
relations.json → parent / content / slot, порядок контейнера, nested class candidates
reverse-components.json → обратные потребители компонента
```

Это вложенные словари с прямыми ссылками и обратными индексами. Номер позиции
массива не используется как идентификатор виджета, свойства или порядка детей.
Все исходные значения сохраняются; совпадения имён относятся к кандидатам.
Вариант клиента / видимый root / native handler автоматически не выбираются.

## Запуск

Из корня репозитория:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/scan-ui-properties.py --requirements phone-exit/bots/vampir/ui-property-requirements.json
```

Вывод — `F:/PhoneExit Resources/Vampir/ui-property-scans/<SHA>/index.json` и
связанные файлы. SHA набора зависит от всех каталогов, сканера и требований.
Наборы сохраняются раздельно; при обновлении прежние результаты не объявляются
проверкой новой версии. Данные анализа не включаются в runtime 50 окон.

Для первого перечня задач можно явно передать `--tasks <новый файл.md>`.
Существующий файл с результатами сканер не перезаписывает. ID найденных полей
вычисляется из namespace / типа владельца / пути свойства, а не его значения;
у обязательных характеристик ID закреплён в ui-property-requirements.json.

Набор `ae23e2f540c216777073fb621b03e668312022f9441a913bc3cb458890a24e60`

Проверено 1586351 наблюдение: матрица полностью совпала с декодированными
источниками, все указатели полей, типы значений и связи прошли verifier.
Результат сохранён рядом с набором как `<SHA>-verification.json`.

Проверка матрицы и каждого обратного указателя:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/verify-ui-property-scan.py 'F:/PhoneExit Resources/Vampir/ui-property-scans/ae23e2f540c216777073fb621b03e668312022f9441a913bc3cb458890a24e60'
```

Verifier сравнивает все widgets / slots / excluded_slots с каталогами по полным
SHA, затем проверяет каждое наблюдение, тип значения, связи и обратные индексы.
Это доказательство полноты переноса декодированного каталога, а не полноты
исследования нативных свойств. Исходный пробный набор и чеклист сохранены
отдельно; фиктивное пустое поле, выявленное проверкой, в текущий список не входит.

## Как проходить каждую характеристику

Дополнительные ветви общего анализа: [объявления нативных свойств и пробелы
декодеров](UI-PROPERTY-COVERAGE.md), [квесты, NPC / монстры, полигоны, лифты
и другие объекты карты](UI-GAME-DATA.md). Они входят в тот же конвейер;
успешный перенос статических данных не открывает фазу генерации.
У пространственной ветви есть [292 отдельных пункта проверки](UI-SPATIAL-PROPERTY-TASKS.md):
поля исходных CSV отделены от полей предварительной геометрии / лифтов.

У каждого пункта отдельно подтвердить:

1. Где свойство объявлено: тип, ресурс, вариант, export / offset, полный SHA.
2. Как читается: схема / тип / единицы, serialized field, inherited default,
   dynamic binding и условия смены значения.
3. К чему относится: владелец / родитель / ребёнок, прямые и обратные связи;
   что нужно применить раньше, где возможны override и двойное применение.
4. Как применяется: вычисление, оформление, состояние или событие; отличие
   native контракта от явной адаптации демо.
5. Как проверено: источники, fixtures и runtime / визуальная сверка в нужном
   объёме, оставшиеся неизвестные и зависимости.

Только после этой цепочки закрывается чекбокс характеристики. Генерация DOM,
наличие PNG или успешное сканирование не закрывают такой пункт.


Дополнительная [проверка полноты исходных Slot exports](UI-MENU.md#проверка-полноты-слотов-перед-восстановлением-сетки)
выявила классы, не попавшие ни в decoded, ни в excluded каталогов. Команда
audit-ui-slot-coverage.py сверяет исходные uasset / uexp и сохраняет отдельный
отчёт; наличие 72153 decoded слотов не доказывает полный охват. Прежние
результаты сканирования остаются результатами прежних входных каталогов.

## Дополнительный слой кандидатных свойств

`scan-ui-candidate-layer.py` связывает базовую матрицу с проверенными отчётами
разбора слотов. Базовый набор и его UI-23 ID остаются прежними. Новый слой
хранится отдельно, имеет собственный SHA ID и не подключается к renderer.
Перед переносом скрипт проверяет всю базовую матрицу, повторяет reconciliation,
сверяет raw package / export SHA и принадлежность каждого ресурса варианту.

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/scan-ui-candidate-layer.py build --base 'F:/PhoneExit Resources/Vampir/ui-property-scans/ae23e2f540c216777073fb621b03e668312022f9441a913bc3cb458890a24e60' --reconciliation 'F:/PhoneExit Resources/Vampir/ui-property-scans/ui-slot-evidence-reconciliation-all-01.json' --reconciliation-sha256 eb338aed22670d216863db30bf668f053c435fc6642ae3fc27a7486552f8f6bd
python -X utf8 phone-exit/bots/resource-tools/vampir/scan-ui-candidate-layer.py verify 'F:/PhoneExit Resources/Vampir/ui-property-scans/candidate-layers/8ded226119edbc34a5d3bbf45c64e5eb994b5b7405a57584fa6d1f9eaa38c614'
```

Первоначально подтверждён перенос слоя `a7e46459e1e2f484adb6e0268447368af368f56640e1990587957fd148d62f98`:
440 узлов (429 кандидатных разборов, 11 классификаций контейнера), 25 свойств,
2077 наблюдений значений, 1529 отметок пропуска и 869 отношений. Проверка повторно
строит весь слой из источников и сравнивает все файлы, включая каждый указатель
наблюдения / пропуска и прямой / обратной связи. Результат проверки:
`ui-property-scans/candidate-layer-verification-01.json` вне Git.
SHA256 результата: `180f14aa27a1b988562e3edffedad5c1471ad5c195aa473436238948518a9685`;
SHA256 index слоя: `6adb334a7db724a4b9d318427857792824881c29cb0bbf7b85a9b6da31387a33`.
Повторный build вернул `reused=true` после сравнения всего набора.

Формат слоя:

```text
index.json → source/base/reconciliation SHA, native_source, версии схем, статистика
  nodes[UI-CN-ID] → variants/<catalog file>.json, export
  properties[UI-27.CP-ID] → типы, число наблюдений и пропусков
  resources[полный путь или unresolved] → ID кандидатных узлов
variants/<catalog file>.json → узлы, исходные значения, omissions, unknowns, SHA
properties/<ID>.json → указатели наблюдений node / field
properties/<ID>-omissions.json → указатели пропусков node / field
relations.json[UI-CR-ID] → candidate parent / content / outer, target export / SHA
reverse-relations.json[variant#export] → постоянные ID отношений
```

Составные значения хранятся атомарно: вложенные числа legacy-кандидата не
становятся независимо подтверждёнными native полями. Непрочитанный NamedSlot
payload сохраняется без перечня придуманных свойств. Поля без наблюдаемых значений
также остаются в индексе: например GridSlot.Layer имеет 300 пропусков, а не ноль.
Все `geometry_verified` / `implementation_verified` остаются false.

[25 отдельных чекбоксов](UI-CANDIDATE-PROPERTY-TASKS.md) имеют собственные стабильные
ID. Для нового списка можно передать `--tasks <новый файл.md>`; существующие
отметки не перезаписываются. При совпадении входов build проверяет и переиспользует
готовый слой, изменённые файлы отвергает. Неизвестные версии схем не читаются
по старым правилам. Сборка выполняется при подготовке общего набора, а не в каждом
из 50 окон. Полный runtime UI, совместимость клиента и свойства по-прежнему требуют
своих проверок; перенос данных не открывает фазу генерации.

## Исходное владение и разделение корней

Дополнительный [слой Outer scopes](UI-OUTER-SCOPES.md) связывает каждый экспорт
с его исходным Blueprint-корнем. Он разделяет многокорневые пакеты, сохраняет
foreign / unowned / unresolved данные и строит source-scoped схемы. Outer /
Parent-Content / runtime visibility остаются разными отношениями. Scope слой
не изменяет старую матрицу и не запускается отдельно в каждом окне бота.
