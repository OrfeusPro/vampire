# Общий механизм автоматизации квестов

16 октября 2026. Точка входа: README.md. Реализация общего исполнителя:
quest_executor.py; подключение 24 учебных правил и получения Guide-награды:
quests.py. Описания действий и условий: vision.json. Это общий исполнитель
известных действий, а не распознавание любого неизвестного квеста.

## Порядок работы

1. Один свежий кадр. bot.py кеширует результаты match только внутри этого кадра.
2. recognition.py выбирает приоритет по ожидаемому шагу из цепочки клиента,
   затем проверяет остальные известные действия. Предсказание не разрешает клик.
3. Правило требует подтверждённый prompt/якоря, условия и найденный контрол.
   source_observation сверяет tutorial_id → step_id → ui_key с quest-runtime.json.
4. Общий исполнитель проверяет область и точку в пределах текущего разрешения.
   Небольшое смещение разрешается только внутри найденного контрола.
5. До передачи нажатия телефону записывается попытка и неизвестный результат.
   Потерянный ответ Android запрещает повтор и ставит сценарий на паузу.
6. Подтверждение Android означает принятие ввода, не завершение квеста.
   Следующий свежий экран сверяется с текущим и ожидаемым шагом. Источники задают
   минимальные паузы; повтор ограничен правилом, только при повторно видимом условии.
7. Исчезновение prompt сбрасывает счётчик его видимости, но само по себе не
   объявляет квест завершённым. Награды требуют положительных признаков результата.

Записи quest.executions содержат id правила, число попыток, время, область,
точку, исходный и ожидаемый шаг, исход ввода. Они живут между кадрами процесса.
Устойчивость после убийства процесса для обычных действий не обещается.
Покупки не проходят через этот исполнитель: shop.py использует отдельный
устойчивый журнал reserved/completed и проверяет предмет, валюту и количество.

Для каждого действия source_tutorial содержит запись CSV, WBP, виджет, контрол
и связь следующего шага. Подробные размеры/проверки перечислены в README по

и build-runtime-chain.py. Новый исполнитель не меняет извлечённую семантику
действий, не угадывает числовые типы и не выполняет все найденные в таблицах шаги.

## Расширение без нового сценария Python для каждого персонажа

Новые правила добавляются через известное семейство: учебная рамка, диалог,
карточка задания, награда, карта, магазин. Сначала связываются таблица и контрол,
потом описываются якоря, доступная область и положительный результат.
Имя персонажа, номер уровня и таймер не заменяют подтверждение экрана.
Граф заданий даёт ожидаемую последовательность; серверный прогресс устанавливается
по наблюдаемому интерфейсу, а не по факту отправки tap. OCR/root не требуются.

Следующий этап: общий журнал наблюдений с компонентами интерфейса и планировщик
по условиям задачи/награды; затем перенос дополнительных семейств контролов.
Неизвестный текст или непроверенная связь остаются неизвестными. Без OCR/доступа
к внутреннему состоянию игры невозможно гарантировать смысл произвольного окна.
