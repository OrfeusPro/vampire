# Сообщения и ручное / автоматическое управление прототипом

Пользовательский сценарий: показывать полученные сообщения, давать выбор реплики
и «Пропустить». Пропуск диалогов включён по умолчанию. При включённом
автовыполнении клик по квесту запрашивает его запуск. Требование подойти к NPC
показывается явно и приостанавливает запуск квестового действия до нового
подтверждённого состояния. Экипировка и выбор обязательного ответа не превращаются
в автоматический пропуск по одному тексту сообщения.

## Происхождение и паспорт панели

Это новая временная панель live-прототипа, не восстановленная геометрия WBP игры.
Source EXE: `d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.
Из прежних связей обучения найдены SkipButtonMove / SkipButtonHide и
Hud_Inventory → ItemInfoPopup_Equip. Они служат навигацией, не доказывают
current native обработчик пропуска или диалога.
[Прежний сценарий и границы](../resource-tools/vampir/knowledge/evidence/scenarios/QUEST-DEPENDENCIES.md).

Потребители: `ui-prototype/prototype-live.js`, компонент данных / поведения
`live-interaction.js`, транспортный адаптер `live-state.js`. Размещение внутри
существующего aside `live-quests`, два label/input и отдельная область сообщений;
общие кнопки / dialog используются через прежние helpers. Layout — временный CSS
`prototype-live.css`, физические единицы браузера в прежней live shell. Правый
контейнер ограничен высотой и прокручивается; карта и ручное смещение не меняются.
У панели, сообщений, кнопок ответов и пропуска не установлены original WBP /
slot chain / DPI / brushes / native callbacks. Новый код не закрывает эти пункты
аудита; сборка только через явный requested preview.

## Контракт адаптера

Опциональный snapshot.interaction имеет semantics=observed_prompts, полный
source_sha256, character_key / world_id, revision SHA и actions_ready.
Scope должен совпадать с подключёнными bot / session / character / world.
Лимиты: 16 сообщений, 4096 символов текста, 128 символов speaker, 12 ответов,
48 описателей действий. Тексты выводятся textContent, не HTML.
Действие содержит id / kind / context SHA / ограниченные decimal uint64 arguments
и явное enabled. Неизвестный контракт / другой source не делает кнопку активной.
Это прикладная схема будущего decoder/owner adapter, не доказанный wire-формат игры.

Сообщение содержит kind, active, text, speaker, choices с action_id и необязательный
skip_action_id. Автопропуск требует active, kind dialogue/cutscene, auto_skip=true
и доступный dialogue_skip. Подсказка обучения / notice / выбор ответа автоматически
не нажимаются. История сообщений сама по себе не разрешает старое действие.
Связь quest_actions указывает только доступное действие конкретного quest_id.
automation.state=waiting_npc показывает npc_label и блокирует новый запуск квеста.
Клиент не угадывает расстояние до NPC и не объявляет подход выполненным по таймеру.

Флажки хранятся отдельно для каждого bot в новом ключе localStorage.
Default skip_dialogues=true, auto_quests=false; прежний явный выбор сохраняется.
При mount / чтении storage не записывается. Два окна одного bot читают последние
настройки, разные bot их не смешивают. Блокировка storage не ломает окно.
Автовыполнение не запускается от одного флажка или открытия панели: нужен клик
по заданию. Policy передаётся с действием; изменение доступной policy передаётся
отдельно, с ожиданием подтверждения. При недоступном backend сохраняется только
локальное предпочтение и показывается отсутствие управления.

Будущие endpoints /actions и /policy используют тот же session control token.
Adapter повторно проверяет scope / context после получения token и подтверждение
bot / session / request ID в ответе. API сейчас ещё не реализует эти endpoints.
Возвращённое queued/sent означает ожидание, не выполнение игры. Request ID
детерминирован по bot / session / action / context: два окна не создают разные
намерения для одного пропуска. Backend должен сохранять идемпотентность этого ID.
После неизвестного результата автопропуск останавливается; повтор не отправляется.
Polling / visibility / dispose используют прежний один адаптер, новых таймеров нет.
Фоновое исполнение после закрытия UI должно принадлежать owner, а не браузеру.

## Проверки и текущая граница

`live-interaction.test.cjs`: default skip, настройки / 50 scopes, ручной ответ,
клик по квестовому действию с auto policy, ожидание NPC, отсутствие auto-equip,
дедупликация между окнами, unknown, потеря связи, раннее серверное подтверждение,
scope / source / bounds и HTTP headers / action / policy identity.
Прежние live-state / projection Node проверки также выполняются.
Ни один тест не отправляет игровые команды и не сохраняет реальные настройки.

В текущем онлайн-owner Infinix поле interaction отсутствует. Поэтому реальная
панель показывает, что текстовые сообщения ещё не получены, и не отправляет
действия. Квест «Зов крови» и HP/MP остаются настоящими, флажки доступны как
предпочтения. Включение флажка не выдаётся за запуск персонажа.
Для настоящих реплик / пропуска / квестового действия нужны decoder и owner-side
handlers / API; текущий owner сохраняется без перезапуска. Проверка этой панели
на synthetic сообщениях не доказывает реальные ответы / пропуск / движение.
