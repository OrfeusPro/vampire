# Локальный прототип интерфейса Vampir

Это интерактивная демонстрация перед подключением бота. Реальные учётные данные
не требуются, игровые команды не отправляются. Состояния разных окон разделены
по параметру `bot`. Текущие задачи — в [UI-TASKS](../UI-TASKS.md), отдельные окна
и компоненты — в [реестре задач](../UI-WINDOW-TASKS.md).

## Сборка и запуск

Из корня репозитория:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-ui-prototype.py
python -X utf8 phone-exit/bots/resource-tools/vampir/serve-ui-prototype.py
```

По умолчанию используются уже извлечённые данные из
`F:/PhoneExit Resources/Vampir`. Builder поддерживает `--root` и переменную
`PHONEEXIT_VAMPIR_RESOURCES`; серверу альтернативный корень передавать через `--root`.
Сервер слушает только `127.0.0.1:17946`; остановка — Ctrl+C в его терминале.
Если порт занят сервером атласа, второй сервер на нём не запускать.

[Открыть прототип](http://127.0.0.1:17946/maps/ui-prototype/index.html?bot=demo-01).
Для других ботов использовать `?bot=demo-02` … `?bot=demo-50` в отдельных окнах.
Автоматический запуск 50 окон и 50 реальных сессий пока не реализован и не проверен.

Вход: любое вымышленное имя и тестовый пароль. Имя `error` показывает отказ.
Недоступный Franz 3 показывает ошибку; Franz 2 и Kurzel 1 открывают демо.
Пароль очищается после отправки локальной формы и не сохраняется.

В игре: `I` — сумка, `M` — управление картой, Enter — чат,
`1`–`5` — быстрые слоты, `F1`–`F5` — демонстрация способностей.
Escape закрывает верхнее модальное окно. Для расходников и способностей
используются локальные правила; они не подтверждают игровую механику.

## Текущее покрытие и ограничения

- Реализован проход авторизация → сервер → стартовый экран → персонажи →
  выбор класса / создание → карта с HUD.
- В локальной модели работают покупка, количество, проверка баланса, сумка,
  экипировка, расчёт характеристик, расходники, быстрые слоты, шаги и награда
  задания, подарок почты и простая коллекция. Цены, названия демопредметов,
  бонусы и персонажи вымышлены. Изображения взяты из извлечённой игры;
  их привязка к демопредмету не является доказанным runtime brush binding.
- У каждого персонажа свой банк предметов, экипировки, валют, прогресса,
  HP/MP, быстрых слотов, коллекции, подарка и позиции. Переключение / удаление
  не меняет банки остальных персонажей. Настройки интерфейса общие для окна.
  Это правила демомодели; распределение данных между персонажем и аккаунтом
  реальной игры здесь не устанавливается. Разделение списков по серверам ещё открыто.
- Ввод имени открывается отдельным окном после кнопки создания, а не полем
  в нижней панели кастомизации. Отмена сохраняет имя и внешность; ошибки остаются
  в форме. Используется кандидат `WBP_NameInputPopup` (640 × 480, центральный
  PanelPopup); прямой native callback из кастомизации в него не подтверждён.
- Каталог учитывает 1764 известных ресурсных пути и ещё 206 root-классов без
  установленного пути: всего 1970 записей и 2376 архивных вариантов.
  Каждая структура загружается отдельно. Просмотр структуры не означает,
  что все эти окна уже визуально восстановлены или их сценарии реализованы.
- Для сумки, магазина, покупки и карточки предмета введены отдельные профили
  размещения с происхождением WBP / slots / size constraints и кадрами пользователя.
  Пропорции из кадров — временная адаптация; точный runtime DPI / desired size
  не восстановлен. Постоянное правило расчёта — в
  [AGENTS](../../AGENTS.md#геометрия-интерфейса-как-в-игре).
- Для кнопок покупки, закрытия карточки, старта и удаления персонажа builder
  сохраняет отдельные цепочки контрол → слот → родитель в `button-evidence.json`.
  Canvas-позиции вычисляются из anchors / offsets / alignment, а не из общей
  CSS-колонки. При изменении размера контейнера выполняется один отложенный
  пересчёт через ResizeObserver; постоянного покадрового обхода нет.
  Кнопка покупки расположена снизу по центру (исходный размер 400 × 80,
  отступ 20 логических единиц). У старта / удаления пока явно обозначено
  допущение заполнения рамки HorizontalBox / WidgetSwitcher.
- `geometry.js` разделяет физические, CSS- и логические единицы; для расчёта
  реального DPI требует явные входы, не подставляя активный масштаб игры.
  Сейчас экран персонажей использует демонстрационную ширину 2400 логических
  единиц, а внешние окна — временные профили по кадрам. Поэтому вычисленные
  внутренние слоты ещё не доказывают полное совпадение со Slate runtime.
  AutoSize без desired size и неподдержанный контейнер возвращают unknown.
- 2D-изображения классов имеют ограниченное разрешение. Параметры внешности
  сохраняются; изменение 3D-модели и звуковой preview не реализованы.
- Неизученные действия, например особый призыв и массовый разбор, показывают
  объяснение и не меняют предметы. Они остаются открытыми задачами.

Экономичный режим включён по умолчанию: карта выгружается при потере активности
окна и загружается при возврате. `?bot=demo-01&economy=off` оставляет карту
загруженной в видимом окне. Скрипты не опрашивают состояние реального бота.
Отдельная модель 50 профилей проверена тестами; память и CPU 50 окон не измерены.

## Источники и обновления

Builder проверяет SHA256 используемых изображений и фиксирует SHA каталогов,
таблицы предметов, индекса карты, файлов WBP и установленного EXE. Версия клиента
автоматически не определена; совместимость исторических извлечений с ним не
подтверждается автоматически. Размер экспорта не используется как размер окна.

Сборки находятся вне Git в `maps/ui-prototype/snapshots/<SHA256>/`.
Предыдущие наборы сохраняются. Для статических ресурсов этих наборов сервер
отдаёт `Cache-Control: public, max-age=31536000, immutable`.
Карта и справочники используют существующий общий атлас: их собственные файлы
пока не заморожены целиком внутри снимка UI. Это ограничение UI-14.06.

После обновления клиента сначала выполнить существующий workflow
`knowledge-index.py update` с явным baseline согласно
[RESEARCH-WORKFLOW](../../resource-tools/vampir/knowledge/RESEARCH-WORKFLOW.md).
Затем собрать UI с явным прежним manifest:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-ui-prototype.py --baseline 'F:/PhoneExit Resources/Vampir/maps/ui-prototype/snapshots/<PREVIOUS_SHA256>/manifest.json'
python -X utf8 phone-exit/bots/resource-tools/vampir/sync-ui-window-tasks.py
```

Builder формирует JSON сравнения и `UPDATE-<SHA256>.md` с чекбоксами.
Сравниваются ресурсы, изображения, входные таблицы / индексы, реализация и клиент.
Это сравнение файлов, не доказательство сохранения семантики каждой строки.
Sync добавляет новые задачи, сохраняя ID, выполненные и текущие отметки.

Демосохранение использует отдельный ключ каждого бота и идентификатор данных.
Текущая схема состояния — 2. Сохраняются нормализованные банки персонажей;
активная проекция HUD не дублируется в записи. Пространство ключей `ui-demo.v1`
сохранено намеренно, чтобы старую схему 1 обнаруживать и показывать запрос
явного сброса, а не скрывать её сменой ключа. Исходная запись до сброса сохраняется.
Изменение только кода интерфейса не делает данные несовместимыми. При смене
данных или повреждении записи автоматическая перезапись блокируется; доступен
явный сброс через «Каталог → Версии и обновления». Реальные профили не затрагиваются.

## Проверки

```powershell
node --test phone-exit/bots/vampir/ui-prototype/model.test.cjs
node --test phone-exit/bots/vampir/ui-prototype/geometry.test.cjs
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_ui_prototype.py -v
python -X utf8 phone-exit/bots/resource-tools/vampir/verify-ui-prototype.py 'F:/PhoneExit Resources/Vampir/maps/ui-prototype/snapshots/<SHA256>'
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py check
```

24 октября 2026: 11 проверок модели и 4 проверки сборки / учёта ресурсов прошли.
Модель 50 ботов / 1000 действий в последнем отдельном прогоне схемы 2: около 49 мс;
это не измерение браузерных окон или реальных сессий.

Через браузер проверены вход до игры, создание персонажа, отказ недоступного
сервера, экипировка с атакой 120 → 162, покупка с обновлением валюты и сумки,
награда задания, вложенная карточка, Escape и восстановление фокуса, выбор точки
карты и демонстрационное прибытие. Магазин и попапы просмотрены при 1280 × 720;
игровой экран и персонажи — при 1920 × 1080. Это не полная сверка всех окон и DPI.
Снимки находятся в `F:/PhoneExit Resources/Vampir/ui-prototype-checks/`.
Проверены также ошибка авторизации и повтор, отдельное окно имени, отмена
с сохранением ввода, неверное имя, история пресета и параметра роста, reset,
изолированная покупка второго персонажа (2250 алмазов при 2400 у первого),
восстановление обоих после загрузки, отмена удаления и пустой список.
Снимок окна имени: `character-name-popup.png`.

Дополнительно прошли 6 тестов геометрии: нижняя рамка покупки, различие
растянутых margins и фиксированных размеров, AutoSize, явные неизвестные,
преобразования при DPI 100 / 125 / 150 / 200% и запрет некорректных размеров.
Это математические fixtures, не проверка игры при этих DPI. В браузере
проверены перенос кнопки покупки вниз, её работа при 1280 × 720 / 1920 × 1080,
кнопка закрытия карточки и пересчёт после смены viewport. Сохранены
`purchase-button-1280.png`, `purchase-button-1920.png`, `item-button-1920.png`.

Общее назначение Canvas-слотов сверялось с
[API SConstraintCanvas](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Slate/SConstraintCanvas).
Конкретные значения и цепочки взяты из локального каталога WBP; общая
документация Unreal не подтверждает поведение установленного клиента Vampir.
