# Локальный прототип интерфейса Vampir

Основной прототип поддерживает живой режим через общий адаптер:
`http://127.0.0.1:17946/maps/ui-prototype/index.html?mode=live&bot=<bot_id>&session=<session_id>`.
Запускатель печатает этот адрес с точной сессией. В режиме live существующие
HP/MP и меню получают данные из одного адаптера; добавлены уровень, опыт,
боевая мощь, исходные stats, большая карта, задания и кнопка журнала.
Неизвестные значения — «—», неподключённые разделы меню отключены.
Карта принимает только подтверждённую проекцию; для текущего клиента она ещё
не подключена. Квесты / окружение и игровые действия также остаются открытыми.
[Контракт, паспорт временного размещения и проверка](../UI-PROTOTYPE-LIVE.md).

Подробная диагностика общего HP/MP-компонента остаётся в отдельном просмотре:
`http://127.0.0.1:17946/maps/ui-prototype/live.html?bot=<bot_id>`.
Backend `run-live-sessions.py` печатает адрес с точным session ID каждого бота.
Страница показывает HP/MP, уровень, мир, heartbeat и stats из API; демомодель,
localStorage и отправка игровых команд не используются. Закрытие окна не
останавливает соединение; Stop — отдельной кнопкой. Портрет пока статический.
Через Xiaomi / HK проверены 207 реальных stats, HP 2700/2700, MP 2000/2000,
уровень 1 и очистка после Stop. [Результат и границы](../../resource-tools/vampir/knowledge/evidence/characters/HEADLESS-LIVE-STATS-CHECK-11316.md).

Общие HP/MP-компоненты поддерживают `updateLive(snapshot)` через отдельный
`live-state.js`: точные bot/session IDs, неизвестные значения «—», отмена опроса
при скрытии / закрытии. Без `mode=live` или `session` основной прототип остаётся
демонстрационным; живой режим не активирует демопрофиль и не пишет его storage.
[Контракт адаптера и общего запуска нескольких сессий](../../vampir-headless/LIVE-SESSIONS.md).

Текущая фаза общего сборщика — [сканирование характеристик и связей](../UI-PROPERTY-SCANNER.md)
и поэлементный аудит. По прямому запросу пользователя допускается пересборка
текущего демоварианта с `--preview-during-audit`; manifest записывает
`generation_policy.mode=requested_preview` и исходную закрытую фазу.
Это не закрывает UI-23 и не подтверждает неизвестные свойства или совместимость.
Дополнительно разрешён [единый конвейер](../UI-PIPELINE.md) `--build-ready`:
он проверяет исходники и допуск правил, затем собирает демонстрацию и запускает
verifier. Сейчас подтверждены правила анализа; новые renderer rules ещё не допущены.
Обычный build без этого флага сохраняет запрет через UI-GENERATION-GATE.json.

Это интерактивная демонстрация перед подключением бота. Реальные учётные данные
не требуются, игровые команды не отправляются. Состояния разных окон разделены
по параметру `bot`. Текущие задачи — в [UI-TASKS](../UI-TASKS.md), отдельные окна
и компоненты — в [реестре задач](../UI-WINDOW-TASKS.md).
Повторная проверка размещения всех экранов: [UI-GEOMETRY-TASKS](../UI-GEOMETRY-TASKS.md).

## Сборка и запуск

Из корня репозитория:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-ui-prototype.py --preview-during-audit
python -X utf8 phone-exit/bots/resource-tools/vampir/serve-ui-prototype.py
```

По умолчанию используются уже извлечённые данные из
`F:/PhoneExit Resources/Vampir`. Builder поддерживает `--root` и переменную
`PHONEEXIT_VAMPIR_RESOURCES`; серверу альтернативный корень передавать через `--root`.
Сервер слушает только `127.0.0.1:17946`; остановка — Ctrl+C в его терминале.
Если порт занят сервером атласа, второй сервер на нём не запускать.

[Открыть прототип](http://127.0.0.1:17946/maps/ui-prototype/index.html?bot=demo-01).
Для других ботов использовать `?bot=demo-02` … `?bot=demo-50` в отдельных окнах.
Автоматический запуск 50 окон и 50 реальных сессий пока не реализован и не проверен.

Вход: любое вымышленное имя и тестовый пароль. Имя `error` показывает отказ.
Недоступный Franz 3 показывает ошибку; Franz 2 и Kurzel 1 открывают демо.
Пароль очищается после отправки локальной формы и не сохраняется.

В игре: `I` — сумка, `M` — управление картой, Enter — чат,
`1`–`5` — быстрые слоты, `F1`–`F5` — демонстрация способностей.
Escape закрывает верхнее модальное окно. Для расходников и способностей
используются локальные правила; они не подтверждают игровую механику.

## Текущее покрытие и ограничения

- Реализован проход авторизация → сервер → стартовый экран → персонажи →
  выбор класса / создание → карта с HUD.
- В локальной модели работают покупка, количество, проверка баланса, сумка,
  экипировка, расчёт характеристик, расходники, быстрые слоты, шаги и награда
  задания, подарок почты и простая коллекция. Цены, названия демопредметов,
  бонусы и персонажи вымышлены. Изображения взяты из извлечённой игры;
  их привязка к демопредмету не является доказанным runtime brush binding.
- У каждого персонажа свой банк предметов, экипировки, валют, прогресса,
  HP/MP, быстрых слотов, коллекции, подарка и позиции. Переключение / удаление
  не меняет банки остальных персонажей. Настройки интерфейса общие для окна.
  Это правила демомодели; распределение данных между персонажем и аккаунтом
  реальной игры здесь не устанавливается. Списки персонажей, выбранный / основной персонаж и их банки разделены по серверам. Franz 2 начинается с Nocturne, Kurzel 1 — с пустым списком. Имена и ID могут совпадать на разных серверах. Настройки интерфейса общие для окна.
- Ввод имени открывается отдельным окном после кнопки создания, а не полем
  в нижней панели кастомизации. Отмена сохраняет имя и внешность; ошибки остаются
  в форме. Используется кандидат `WBP_NameInputPopup` (640 × 480, центральный
  PanelPopup); прямой native callback из кастомизации в него не подтверждён.
- Каталог учитывает 1764 известных ресурсных пути и ещё 206 root-классов без
  установленного пути: всего 1970 записей и 2376 архивных вариантов.
  Каждая структура загружается отдельно. Просмотр структуры не означает,
  что все эти окна уже визуально восстановлены или их сценарии реализованы.
- Для сумки, магазина, покупки и карточки предмета введены отдельные профили
  размещения с происхождением WBP / slots / size constraints и кадрами пользователя.
  Пропорции из кадров — временная адаптация; точный runtime DPI / desired size
  не восстановлен. Постоянное правило расчёта — в
  [AGENTS](../../AGENTS.md#геометрия-интерфейса-как-в-игре).
- Для кнопок покупки, закрытия карточки, старта и удаления персонажа builder
  сохраняет отдельные цепочки контрол → слот → родитель в `button-evidence.json`.
  Canvas-позиции вычисляются из anchors / offsets / alignment, а не из общей
  CSS-колонки. При изменении размера контейнера выполняется один отложенный
  пересчёт через ResizeObserver; постоянного покадрового обхода нет.
  Кнопка покупки расположена снизу по центру (исходный размер 400 × 80,
  отступ 20 логических единиц). У старта / удаления пока явно обозначено
  допущение заполнения рамки HorizontalBox / WidgetSwitcher.
- `geometry.js` разделяет физические, CSS- и логические единицы; для расчёта
  реального DPI требует явные входы, не подставляя активный масштаб игры.
  Сейчас экран персонажей использует демонстрационную ширину 2400 логических
  единиц, а внешние окна — временные профили по кадрам. Поэтому вычисленные
  внутренние слоты ещё не доказывают полное совпадение со Slate runtime.
  AutoSize без desired size и неподдержанный контейнер возвращают unknown.
- 2D-изображения классов имеют ограниченное разрешение. Параметры внешности
  сохраняются; изменение 3D-модели и звуковой preview не реализованы.
- Неизученные действия, например особый призыв и массовый разбор, показывают
  объяснение и не меняют предметы. Они остаются открытыми задачами.

Экономичный режим включён по умолчанию: карта выгружается при потере активности
окна и загружается при возврате. `?bot=demo-01&economy=off` оставляет карту
загруженной в видимом окне. Скрипты не опрашивают состояние реального бота.
Отдельная модель 50 профилей проверена тестами; память и CPU 50 окон не измерены.

## Источники и обновления

Builder проверяет SHA256 используемых изображений и фиксирует SHA каталогов,
таблицы предметов, индекса карты, файлов WBP и установленного EXE. Версия клиента
автоматически не определена; совместимость исторических извлечений с ним не
подтверждается автоматически. Размер экспорта не используется как размер окна.

Сборки находятся вне Git в `maps/ui-prototype/snapshots/<SHA256>/`.
Предыдущие наборы сохраняются. Для статических ресурсов этих наборов сервер
отдаёт `Cache-Control: public, max-age=31536000, immutable`.
Карта и справочники используют существующий общий атлас: их собственные файлы
пока не заморожены целиком внутри снимка UI. Это ограничение UI-14.06.

После обновления клиента сначала выполнить существующий workflow
`knowledge-index.py update` с явным baseline согласно
[RESEARCH-WORKFLOW](../../resource-tools/vampir/knowledge/RESEARCH-WORKFLOW.md).
Затем собрать UI с явным прежним manifest:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-ui-prototype.py --baseline 'F:/PhoneExit Resources/Vampir/maps/ui-prototype/snapshots/<PREVIOUS_SHA256>/manifest.json'
python -X utf8 phone-exit/bots/resource-tools/vampir/sync-ui-window-tasks.py
```

Builder формирует JSON сравнения и `UPDATE-<SHA256>.md` с чекбоксами.
Сравниваются ресурсы, изображения, входные таблицы / индексы, реализация и клиент.
Это сравнение файлов, не доказательство сохранения семантики каждой строки.
Sync добавляет новые задачи, сохраняя ID, выполненные и текущие отметки.

Демосохранение использует отдельный ключ каждого бота и идентификатор данных.
Текущая схема состояния — 2. Сохраняются нормализованные банки персонажей;
активная проекция HUD не дублируется в записи. Пространство ключей `ui-demo.v1`
сохранено намеренно, чтобы старую схему 1 обнаруживать и показывать запрос
явного сброса, а не скрывать её сменой ключа. Исходная запись до сброса сохраняется.
Изменение только кода интерфейса не делает данные несовместимыми. При смене
данных или повреждении записи автоматическая перезапись блокируется; доступен
явный сброс через «Каталог → Версии и обновления». Реальные профили не затрагиваются.

## Общие элементы и оригиналы

В каталоге проверки доступен раздел «Общие элементы»: валюты, кнопки, иконки
и оформление с поиском и кнопкой происхождения. `shared-elements.json`
генерируется из уже извлечённых источников; загружается только при открытии.
PNG используются без перерисовки и проверяются полным SHA256.

78 строк определения валют из `table-study/ProjectRED-Windows-6076.csv`
соединяются по числовому ID с историческим `EAsset`, затем по символу с
английской таблицей `ProjectRED-Windows-6096.csv`. Порядок строк не используется
для соединения. 12 значений enum без определения сохранены отдельно.
Золото, обычные / платные / бесплатные / событийные / клановые алмазы и прочие
типы не объединяются по совпадению картинки. OwnerType остаётся исходным числом;
его смысл и текущая совместимость не доказаны. Русские подписи демо — перевод
прототипа. Полный SHA архива таблиц неизвестен; sample SHA не выдан за полный.

Реестр текстур хранит полный asset path, SHA PNG, архив, entry и offset.
Короткий alias допускается только для уникального имени. Семейства кнопок
сопоставляют `_Press` как кандидат нажатого состояния; `_On` не считается hover.
Отключённость пока изображается CSS opacity, это не оригинальная текстура.
Красные и обычные прямоугольные кнопки используют original PNG normal / pressed;
назначение конкретному WBP требует дальнейшей проверки. Рамки / вкладки /
слоты остаются отдельной незакрытой задачей UI-20.04.

## Разделение демо по серверам

Схема сохранения 3 содержит `serverStates` с отдельными списками персонажей,
выбором и банками прогресса. Отображение получает только активную проекцию;
сохранение не дублирует её. Действия покупки, экипировки, заданий, карты,
создания и удаления ограничены текущим сервером. Смена сервера сохраняет его
предыдущий банк; повторный выбор того же сервера не сбрасывает данные.
Это локальная модель: общие валюты аккаунта реального клиента здесь не выводятся.

Схемы 1 / 2 и несовместимый dataset сохраняются без перезаписи: для нового демо
нужен явный сброс через служебное окно. Реальные профили не затрагиваются.
Автотесты проверяют одинаковые имена / ID на разных серверах, покупки, удаление,
возврат, сохранение, повреждение неактивного банка и отказ недоступного сервера.

Браузерная проверка схемы 3: Kurzel 1 показал пустой список, создание KurzelOnly
и покупка меча уменьшили только его баланс 2400 → 2250. Возврат на Franz 2
показал Nocturne и 2400. После перезагрузки и повторного входа KurzelOnly
восстановился с 2250. Снимок во внешней библиотеке:
`ui-prototype-checks/server-bank-kurzel-restored.png`. Проверены 13 тестов модели,
6 тестов геометрии и 7 тестов сборки / каталогов. Это не проверка реальных сессий.

## Настройка навыков и панель способностей

Схема 4 добавляет отдельные уровни, пять слотов, настройки автоприменения и
сроки перезарядки в банк персонажа. Прежние схемы 1–3 сохраняются без перезаписи
до явного сброса. Курированный набор: по три навыка для каждого из пяти классов,
всего 15. Два доступны в начальном демо, третий изучается за 500 золота.
Уровни ограничены 3; повышение стоит 100 / 200 золота. MP 40 / 80 / 120 и
перезарядка 3 / 6 / 9 секунд — явные локальные правила `skills.js`, не расчёт
игровой механики. Автоприменение пока сохраняет настройку, автоматический бой
не запускается. Недостаток MP, повторное изучение, чужой класс, неверный слот
и применение на перезарядке отклоняются без списания ресурсов.

Окно «Навыки» содержит поиск, фильтры, список, сведения, обучение, улучшение,

## Одно окно на ID бота

Перед чтением демосохранения страница получает эксклюзивный Web Lock по ключу
профиля. В версии с этой защитой повторное открытие того же `?bot=` показывает
«ID бота уже открыт». Модель, игровые кнопки, карта и сброс демо в дубликате
не запускаются. Запись и адаптер действий дополнительно проверяют владение.
Разные ID независимы; скрытие и потеря фокуса не освобождают профиль.

В разделе «Версии и обновления» есть «Освободить ID бота». Освобождение закрывает
диалоги, выгружает карту и останавливает таймеры. Другое окно получает ID только
по нажатию «Получить управление» и заново читает сохранение. Очереди автоматического
перехвата, heartbeat и опроса нет. Запоздалые переходы авторизации / загрузки
персонажей не продолжают старый экран после освобождения.

`pagehide` освобождает владение, `pageshow` после восстановления страницы пытается
получить его заново с чтением актуального состояния. Если API отсутствует или
отклоняет запрос, запуск демо блокируется с объяснением. Механизм основан на
[Web Locks request](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request),
режим exclusive / ifAvailable; события жизненного цикла описаны в
[pagehide](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagehide_event).

Область защиты — один origin и раздел хранилища браузера. Ключ владения общий
для разных snapshots этого прототипа, а не привязан к хешу сборки. Старые страницы
до внедрения Web Locks этому правилу не следуют: при обновлении их закрывать;
их совместная работа остаётся UI-18.10. Отдельные браузерные профили имеют
собственные localStorage / locks. Это не владение реальной сетевой сессией бота.

Проверка 24 октября 2026 в двух вкладках IAB: первый владелец купил меч,
2400 → 2250 алмазов; второй сначала был заблокирован. После явной передачи
он вошёл с 2250, первый не смог получить занятый ID. После закрытия второго
первый снова получил управление; reload также прошёл. Другой ID открылся
параллельно. Снимок: `ui-prototype-checks/duplicate-profile-blocked.png` во
внешней библиотеке. Четыре теста lease проверяют конкуренцию, освобождение,
50 независимых ключей, отсутствие API / отказ, отмену запоздалого callback.
50 настоящих окон, сон ОС, BFCache и аварийное завершение пока не проверены.

## Общие роли оформления и проверка пакетов

`skin-roles.json` связывает 10 повторно используемых ролей с полными путями
оригинальных текстур и семью историческими WBP. В прототипе подключены
`Slot_ItemSlot`, `BTN_Close`, `PopUp_DefaultBG_texture_01`, `HUDShortcutkey_Frame`
и нормальное оформление вкладки; обычные / основные кнопки продолжают использовать
оригинальные normal / pressed PNG. Декор `PopUp_Default_Title_texture` сохранён
в каталоге, пока не размещён в заголовках: для него требуется отдельная геометрия.
Оригинал PNG не перерисовывается и не изменяется; размер в CSS пока адаптирован.

Builder читает исходные UAsset / UExp, проверяет полные SHA256 против каталога,
повторно применяет существующий `inspect-ui.py exports`, сравнивает всю таблицу
имён и SHA экспортов контролов. В каждой роли сохранены индекс имени (с нуля),
архив / entry, SHA каталога, JSON пакета, UAsset, UExp, PNG и декодера. Декодер
остаётся инструментом сборки; его код не загружается в браузер. Его SHA учитывается
в manifest.tools и сравнении обновлений. Изменение сырых источников, неоднозначный
полный путь, несовпадающий ресурс, таблица имён или контрол прерывают сборку.

Эта проверка доказывает наличие ссылки на текстуру в пакете и происхождение
экспорта. Назначение конкретному полю brush, порядок состояний, tint и margins /
nine-slice не декодированы. Совместимость исторического UI и выбранного варианта
текстуры с текущим клиентом не подтверждена. Поэтому `runtime_brush_binding_verified`
остаётся false, UI-20.04 / UI-20.13 открыты. Прямые / нажатые состояния вкладок
не выдумываются: пока используется normal и отмеченное CSS-выделение прототипа.

Небольшой `skin-tokens.json` загружается при старте. Полный `skin-evidence.json`
загружается при открытии «Общие элементы → Привязки оформления». Общая библиотека
теперь содержит 659 оригинальных текстур. URL неизменяемых PNG общие для ролей и
50 окон; нет новых покадровых расчётов или опроса. Verifier связывает роли с
manifest.resources / inputs / tools и проверяет соответствие токенов текстурам.

Браузером проверены сумка и категории, покупка, вложенная карточка, оригинальный
крестик, Escape и возврат фокуса. Сумка осмотрена при 1280 × 720 и 1920 × 1080;
вкладки больше не разрывают названия по буквам. Снимки во внешней библиотеке:
`ui-prototype-checks/original-skin-bag-1280.png` и `original-skin-bag-1920.png`.
Два теста источников дополнительно проверяют отказ при повреждённом UExp,
изменении таблицы имён и неоднозначной текстуре. Результат не означает полной
визуальной идентичности игровому runtime.

## Вход на сервер: загрузка, отказ, повтор и отмена

Стартовый экран использует отдельный локальный `entry-flow.js`: три этапа,
успех, тестовый отказ или таймаут. Контекст попытки фиксирует ID окна, сервер
и регион; только актуальное успешное завершение на стартовом экране открывает
список персонажей. Контроллер не меняет демобанк, не хранит credentials и не
содержит транспорта. Контроллер входа не определяет схему сохранения; текущая общая схема — 5.

Во время загрузки доступны «Отмена входа», крестик и Escape. Закрытие немедленно
отменяет попытку. Новый переход, смена сервера, освобождение владения ID и
pagehide отменяют загрузку; токен поколения игнорирует старый callback.
После отказа / таймаута доступны ручной повтор, выбор другого сервера и закрытие.
Автоматических повторов нет. Фокус возвращается на кнопку входа.

Для проверки открыть «Каталог проверки → Версии и обновления» и выбрать
«Сценарий следующего демовхода». Отказ / таймаут применяется один раз, повтор
по умолчанию успешен. Поле и счётчик попыток — служебные, не сохраняются в профиле.
Коды `DEMO_REJECTED` / `DEMO_TIMEOUT` не являются кодами сервера Vampir.

У каждой попытки максимум один таймер; после результата и отмены он отсутствует.
Во время этапов обновляются только текст и progress, кнопка отмены не создаётся
заново. В скрытом окне эти обновления и CSS-анимация приостановлены; конечный
результат контроллера сохраняется. Уменьшение движения учитывается через
prefers-reduced-motion. Постоянного опроса, сетевых retry и изменения реальных
профилей нет.

Ресурсные кандидаты: `WBP_LoadingPageUI` с TextMessage / TextTipMessage /
ImageLoading и `WBP_MessageBoxPopup` с ButtonOk / ButtonCancel / TextMessage.
Их SHA и исходные slots находятся в placement-evidence. Прямые native callbacks,
тексты отказов и внешний вид ещё не подтверждены. Прогресс, отмена, CSS-индикатор
и третья кнопка выбора сервера — явная адаптация демо; native animation / brush
не выдаются за восстановленные. UI-06.01 / UI-06.04 и соответствующие UI-W задачи
остаются открытыми.

Браузером проверены успех, отмена кнопкой / крестиком / Escape, отказ → повтор,
таймаут → Kurzel 1, пустой список и отсутствие переноса Nocturne с Franz 2.
Окно отказа осмотрено при 1280 × 720, загрузка — при 1920 × 1080. Снимки во
внешней библиотеке: `ui-prototype-checks/entry-rejected.png`,
`entry-rejected-1280.png`, `entry-loading-1920.png`. Шесть тестов контроллера
проверяют этапы, оба отказа и повтор, отмену, поздний callback, отмену внутри
подписчика, неверный контекст и 50 независимых попыток. Это не 50 игровых сессий.

ручной повтор; постоянного опроса нет. Это оценка размеров файлов, не измерение
потребления памяти 50 браузеров.

справа и явно обозначена как демо. Регистрация исходных требований, частичное

Ручные rect в window-layouts остаются резервами с открытыми unknowns;
нативная цепочка при наличии native_frame применяется поверх этого резерва.

Коллекции перестроены в строки с предметами справа и отдельной колонкой

ширина 655 и bottom 122. Свидетельства и SHA — в button-evidence.json.
Эти значения вычисляют рамки, а не заменяются процентами изображения.
CanvasPanel_41 получает viewport демо; SafeZone и активные DPI / ApplicationScale /
UI Scale игры пока не установлены. Reference width 2400 — система координат
демо. Внутренние строки, шрифты, tint и brush bindings остаются частично временными.
Извлечённые звезда, замок / открытый замок и галочка используются как оригинальные
изображения; полная привязка каждого состояния к brush ещё не подтверждена.

Предоставленный кадр коллекций сохранён во внешней библиотеке по SHA256
`1177cd4fa4059932c3c09e7f34046487e09fc59318dffd1f6df501c75f06b95f`.
Он включён в inputs манифеста как ui-references/collection-<SHA>.png;

исторических Krvna / Poenari / Kicel / Bezdan. Эти названия сохранены из таблиц,
соответствие не угадывается; пятый исходный раздел доступен в фильтрах.

Повторный проход других окон уже начат: name-window-frame использует
PanelPopup / slot 14 WBP_NameInputPopup (640 × 480, центр), skills-window-frame —
PanelPopup / slot 37 WBP_SkillSettingPopup (ширина 1810, привязка вправо).
Для их внешних Canvas тоже явно выделена рамка viewport. Внутренние controls,
DPI и внешняя иерархия остаются открытыми: UI-G-09 / UI-G-15 не закрыты.

Схема демосостояния — 5. Коллекции хранятся разреженно в банке персонажа:
метаданные посещённых действием коллекций, зарегистрированные требования,
избранное, блокировка и предметы по ключу ID@усиление. Только отображение
каталога ничего не сохраняет. Исходные предметы видны в той же сумке, отдельная
категория позволяет их отфильтровать. Они не объединяются с условными demo blade /
book по похожей картинке. Экипировка / продажа исходных предметов ещё не восстановлены.

«Выдать недостающие предметы · демо» явно подтверждается, выдаёт один тестовый
набор на коллекцию и не тратит валюты. Регистрация отдельного требования
подтверждается, проверяет точное совпадение усиления, количество, блокировку,
повтор, персонажа / сервер и SHA набора. Отмена ничего не списывает.
Старое подтверждение не применяется к другому персонажу. Смешивание источников
или изменение уже сохранённого определения отклоняется. Полное заполнение
включает бонусы в правую колонку и характеристики: суммы Min / Max по исходному
типу и IsPercentage. Это локальная демонстрационная формула; Basic DMG не
добавляется произвольно к общей атаке. Процент прогресса — доля завершённых
коллекций всего каталога, также правило демо. Область действия серверных
коллекций / бонусов не подтверждена и в прототипе ограничена персонажем.

Проверено: 4 079 исходных определений проходят нормализацию; шесть тестов модели

## Иконки, свойства оформления и цепочки событий

Повторный проход иконок / оформления / событий каждого уже реализованного окна —
[UI-APPEARANCE-TASKS](../UI-APPEARANCE-TASKS.md), отдельно от геометрии и функциональных
галочек. Паспорт включает связь Image / Brush / Style, все состояния, цвет и
оттенок, tint, LinearColor / sRGB, ColorAndOpacity, RenderOpacity и наследование,
nine-slice, шрифты, тени, эффекты, анимации и динамические свойства. Неизвестные
параметры не заменяются утверждением о точном совпадении. Для события проверяется
контрол → binding → handler → callees → состояние / запрос → подтверждение;
имя / ID, аргументы, условия и export / адрес привязаны к полному SHA клиента.
Демо-функция не считается native callback или подтверждённой командой бота.
Прямые имена OnPressed / OnReleased / OnClicked в проверенных таблицах имён
WBP_CommonFavoriteT и WBP_ItemCollectionUI не найдены; native / inherited bindings
не исследованы, отсутствие событий этим не доказано.

У поиска, фильтра и сброса коллекций применены оригинальные IMG_Flat_Search,
IMG_Flat_Filter и IMG_Flat_Refresh. Все три проверены по полным путям / PNG SHA
и ссылкам в исходном пакете WBP_ItemCollectionUI, записи добавлены в skin-roles.
Это проверка членства ресурса в пакете, не декодирование Brush. У ImageFilterOff /
ImageFilterOn есть собственный WidgetSwitcher; его переходы, material
MI_Flat_AuctionFilter_On, реальный tint / opacity и связи с обработчиками пока
не подтверждены. Кнопка фильтра в демо открывает локальную форму; сброс очищает
запрос, исходный раздел, редкость и избранное. Подписи сохранены в aria-label /
title, на лице кнопок отображаются иконки.

Рамки фильтра и сброса рассчитаны по source ButtonFilter / slots 103 → 77 и
ButtonRefresh / 102 → 77, оба 80 × 80. Рамка поиска — Overlay / 101 → 77,
растянута с резервом 180 справа. Корень CanvasPanel_41 выделен по viewport демо.
Рамка, активное оформление и focus outline пока CSS; normal / hover / pressed /
released / selected / disabled, Brush / Style и native delegates требуют
отдельного прохода. Демонстрационный aria-pressed означает выбранные фильтры,
а не физическое удержание кнопки.

## Desired size покупки и широкий viewport

Geometry.desiredTree рассчитывает Overlay / HorizontalBox / VerticalBox из
явных размеров и padding; неизвестный тип или padding останавливает расчёт.
Сборщик извлекает дерево из исходных controls / slots, сохраняет export SHA и
проверяемый список исключений. SizeBox требует обеих explicitly_enabled
WidthOverride / HeightOverride. У обычной демопокупки SizeBox_1 задаёт 1236 × 816,
Overlay padding сверху равен 107, поэтому ограниченный desired size — 1236 × 923.
Слоты 59 / 127 центрируют Overlay_1 со сдвигом +4 / −55. StepUp, декоративная
CanvasPanel_10, крестик и фоновый WBP исключены только из измерения демо с явными
причинами. Их native visibility / intrinsic size и inherited min/max не доказаны.
Вариант StepUp остаётся открытой задачей; эта ветка не подтверждает все товары.
Verifier повторно собирает desired tree из опубликованных controls / slots и
сверяет с binding; изменённая схема / отсутствующее исключение отклоняются.
У магазина CanvasPanel_4 / slot 28 растянут на выделенный CanvasPanel_21.

Для привязок сцены reference frame демо теперь явно 2400 × 1350: scale берётся
по меньшему отношению ширины и высоты и умножается на UI Scale один раз.
Широкий viewport расширяет растянутые контейнеры; постоянные размеры не растут
по одной только ширине. Это демонстрационный fit, не восстановленная DPI curve
игры. Рамки локальных кнопок сохраняют собственные reference width родителя.
Новая схема сохранения не вводится, игровые данные не меняются.

Аудит сумки: CPanelRoot имеет исходную ширину 626 и центральную привязку к
CanvasPanel_1. Это не доказывает положение внешнего правого host-контейнера;
переносить центр сразу в экранные координаты нельзя. У карточки предмета
PanelPopup / slot 70 использует AutoSize; ширина 590 CanvasPanel_85 относится
к внутренней ветке. Полный desired size зависит от составных блоков / текста
и остаётся неизвестным. UI-G-11 / UI-G-14 не закрыты ручными размерами.


Результаты предыдущего прохода: 62 автоматических теста (50 Node, 12 Python)
прошли. В браузере проверены три оригинальные иконки без текстовых заглушек,
поиск, применение фильтра (22 записи), сброс (4 079 записей), Enter / Escape
и возврат фокуса. Размеры проверены при 1280 × 720, 1920 × 1080 и 3440 × 1440.
Кадры — ui-prototype-checks/collection-original-filter-icons-1280.png и
collection-original-filter-icons-1920.png. На широком viewport кнопки имеют
размер около 85,27 CSS px по выделенному корню; блок покупки — примерно
1318,40 × 984,53 без переполнения по ширине. Кадр — purchase-source-desired-wide.png.
При 1280 × 720 покупка имеет рамку около 659,20 × 492,26; нажатие покупки меча
списало 150 демоалмазов (2400 → 2250) и обновило сумку. Это проверки прототипа,
не native DPI / видимости ветвей / выполнения команд на сервере.

## Общие компоненты и автоматический сборщик

Общая задача — [автоматический сборщик интерфейса](../UI-BUILDER.md), а прототип
служит его стендом. Начальный `composition-graph.json` строится из всех записей
при сборке, не загружается фоново каждым ботом. Учтены 2376 вариантов, 8572
вложенных контрола; у 1370 класс не найден, у 4367 несколько кандидатов.
Варианты сохраняются по пути / catalog file / SHA; граф не выбирает активную
сборку и не доказывает Brush / handlers. Verifier повторно строит его из
опубликованных окон. `--baseline <manifest.json>` создаёт отдельный отчёт
`*-to-*-composition.json` с транзитивными потребителями старого и нового графа.

`components.json` и `component-evidence.json` фиксируют реальные nested widget
classes и полные источники. Коллекции и магазин содержат WBP_TitleBarUI,
который содержит WBP_PCStatusProgressBarT. Общие JS-компоненты в components.js
получают состояние и callbacks без собственных подписок, таймеров и транспорта.
Портрет / HP / MP подключены в HUD и оба заголовка; валюты берутся из общей
модели. Меню и выход используют оригинальные IMG_Flat_Menu / IMG_Flat_Exit,
полное оформление и внешняя геометрия заголовка остаются адаптацией демо.

Рамки HP / MP рассчитаны по исходным CanvasPanelHP / CanvasPanelMP в выделенном
локальном frame 390 × 100. Значения и заполнение полос используют одни лимиты
модели (HP 12440, MP 4085); это демонстрационные значения, не данные живой сессии.
Цвета, шрифты, Brush и внешние SafeZone / DPI не восстановлены полностью.
WBP_PCStatusUI содержит TileViewOperationPanelList и дочерний статус персонажа;
активные эффекты, их данные, сведения и handlers пока не подключены. Наличие
предмета в сумке не трактуется как активный баф.

Проход общих компонентов: 67 автоматических тестов (52 Node, 15 Python), проверка snapshot
и структурная проверка знаний прошли. В браузере проверены HUD → коллекции →
меню → магазин → меню → сумка → зелье: HP 10576 → 11776 и ширина 94,6624%
согласованы во всех трёх статусных компонентах, MP 2453 / 4085 не изменилось.
После закрытия вложенных окон фокус вернулся на меню коллекций.
Кадр shared-status-1270x1246.png хранится в ui-prototype-checks; это проверка
текущего viewport, не новый проход трёх стандартных разрешений.
Повторное открытие меню сейчас оставляет несколько экземпляров в стеке;
политика вложенности и полное исходное меню / footer остаются UI-21.09–10.

## Компиляция локальной схемы размещения

Сборщик создаёт 2376 отдельных layout-схем и небольшой component-layouts.json.
Первый потребитель — общий портрет / HP / MP: components.js теперь вычисляет
рамки через layout-schema.js из текущих parent / content slots, без ручных
цепочек button-evidence. Последние сохранены как прежнее независимое evidence.
Полный каталог схем не загружается в каждое окно; запрашивается только схема
общего статуса. Blueprint root и видимый root не отождествляются.

Canvas-интерпретатор требует явного root и frame, отклоняет циклы, несколько
родителей, неверную принадлежность слота и отсутствующий desired size. Другие
контейнеры пока не рассчитываются через этот путь. Пропущенный AutoSize в
статусе принимается false только по явной политике демо; семь таких допущений
видны в data-layout-assumptions. Это не доказанный inherited default игры.

Проверка прохода локальных схем: 73 теста (56 Node, 17 Python), полная пересборка схем
verifier и проверки знаний. В браузере HUD, коллекции и магазин используют
data-layout-engine=local-widget-schema; сохранённое HP 11776 / 12440 и MP
2453 / 4085 восстановились без сброса. Ширина обеих полос одинакова у всех
трёх потребителей: около 155,20 CSS px на 1280 × 720 и 232,79 на 1920 × 1080;
на 3440 × 1440 — 310,40. Это проверка демо fit, не native DPI curve.
Кадры: schema-status-1280.png, schema-status-shop-1920.png,
schema-status-wide.png в ui-prototype-checks. Временный viewport сброшен.

До перехода к аудиту добавлен widget-renderer.js: он строит выбранные 14 узлов
статуса (включая настоящие ProgressBar / NkTextBlock / NkButton из схемы).
В b3ae35f8ee28… проверены три потребителя, HP 11776 → 12440, текст и 100% заполнение,
портретное демодействие, возврат и масштабы 1280 × 720 / 1920 × 1080 / 3440 × 1440.
Заливки, шрифт и demo_layer остаются адаптацией; callbacks освобождаются при
замене HUD / закрытии заголовка. Полный native порядок / стили ещё неизвестны.
Кадры widget-tree-collections-1280.png и widget-tree-shop-1920.png — в ui-prototype-checks.
Временный viewport сброшен. Текущие автоматические проверки кода: 82 теста
(60 Node, 22 Python), включая сканер / импорт настроек / закрытую фазу генерации.

Общее меню HUD / магазина / коллекций использует подключаемый main_menu в

## Отбор окон с UI в имени

В каталоге проверки добавлена область «Заглавные UI в имени» и быстрый переход
«Пройти имена с UI». Этот режим проверяет точный uppercase фрагмент в имени
ресурса / класса; обычный поиск по имени и пути сохранён отдельно. Фильтры
попапов и текстовый запрос применяются дополнительно; unresolved имена входят.
Ни suffix UI, ни совпадение по имени не доказывают runtime роль окна.

[Очередь повторного прохода](../UI-NAMED-WINDOW-TASKS.md) содержит 551 исходную
запись / 635 вариантов со ссылками на единые чекбоксы источников, геометрии, оформления,
событий, интерактивности и проверки. Большой чеклист не загружается окнами ботов.
