# Боты Phone Exit

ПК хранит профили телефонов и управляет установкой. Python 3.11 выполняет
`bot.py:tick(host, settings, state, directory)` на Android в процессе `:bot`.
`state` существует только в памяти текущего запуска. После перезапуска сценарий
заново распознаёт экран. Изображения остаются на телефоне. OCR и ML Kit отсутствуют.

Каталог модуля содержит `manifest.json`, `bot.py`, описание настроек и ресурсы.
Manifest задаёт `id`, `version`, `engineVersion`, `settingsVersion`, `entrypoint`,
список разрешённых пакетов Android и функции. HTTP API и настройки — версия 1.
Движок 2 (APK 0.8.3) поддерживает модули движка 1 и 2. Модуль Lord Nine 1.0.3
требует движок 2: фильтр золотого окружения маркера появился в этой версии.
Старый APK отклонит такой пакет до установки. Подготовленные масштабированные
шаблоны и маски ограниченно кэшируются на телефоне, алгоритм и пороги сохраняются.
Изменение Python или OpenCV требует нового APK; совместимые сценарии — пакета.
Движок 3 (APK 0.8.4) также поддерживает предыдущие модули; добавлены исходные
HSV-контуры кнопок подтверждения, признаки областей и маска/цвет значка миникарты.
Модуль Lord Nine 1.1.8 требует движок 3. Нативные проверки этих функций пройдены
на vivo по сохранённым кадрам realme SG; APK 0.8.5 и модуль 1.1.8 установлены на SG.
APK 0.8.5 сохраняет движок 3; кэш результата между кадрами применяется только
при совпадении SHA256 всех пикселей области и полного описания шаблона.
Результатов максимум 1024; подготовленный шаблон не зависит от зоны поиска.
На vivo восемь повторных сравнений неизменившегося кадра занимают 5–8 мс,
исходные confidence сохранены, изменение внутри зоны отменяет кэш.
На SG 0.8.5 загружена; подтверждение установки и живое измерение ещё нужны.

## HTTP Bot API 1

Адрес: `http://127.0.0.1:17842/bot/v1/`. Авторизация совпадает с защищённым
локальным API Phone Exit. Ключ хранится через Windows DPAPI, не в репозитории.

| Метод и путь | Назначение |
| --- | --- |
| GET `catalog` | Локальные manifests модулей |
| GET `phones` | Телефоны, состояние бота, сохранённый профиль |
| GET `devices/{id}/profile` | Настройки и номер редакции |
| POST `devices/{id}/settings` | `{settings: {...}}`, сохранить полную редакцию |
| POST `devices/{id}/copy` | `{targets: [id, ...]}`, независимые копии профиля |
| POST `devices/{id}/action` | `{op, botId?, version?}`, асинхронная операция |
| GET `jobs/{id}` | `running`, `done` с result либо `failed` с error |
| GET `assets/{module}/index.json` | Каталог карт |
| GET `assets/{module}/{name}.png` | Карта для редактора |

Операции: `assign`, `install`, `rollback`, `status`, `start`, `pause`, `resume`,
`stop`, `editor`. Редактор принимает `{op:"editor",kind:"point"|"capture",mapId}`;
результат задания — `{point:[x,y],mapId}` либо `{ready:true,mapId}`. Требуется
актуальная версия модуля. Редактор приостанавливает сценарий, временно передаёт
одноразовый запрос распознавания, затем восстанавливает обычные настройки.
Бот остаётся на паузе; автоматически не возобновляется. Неизвестная локация для
определения точки отклоняется. Захват обучающего образца требует открытой карты,
выбор соответствия Current Location выбранной локации делает пользователь.
Отмена передаётся существующей командой `bot/pause`, без повторения вводов.
Назначение не запускает бот. Перед запуском ПК передаёт ожидающие
настройки. В один момент разрешена одна операция на телефон. Команды действий
автоматически не повторяются при неизвестном результате; нужно запросить статус.
VMOS API сохраняется.

## Канал ПК → Android

Существующая защищённая команда `bot` переносит JSON с `op` и аргументами.
Настройки: `settingsBegin(revision,size,sha256)` → последовательные
`settingsChunk(revision,offset,data)` → `settingsCommit(revision)`.
`data` — Base64, до 4096 байт после декодирования; полный документ — до 1 МиБ.
Неполная передача не заменяет применённые настройки. Commit проверяет SHA256
и атомарно заменяет файл. Движок читает редакцию перед следующим завершённым
действием. Состояния: ожидает отправки на ПК, `receiving`, `received`, `applied`.
Полученная и применённая редакции показываются отдельно.

Статус содержит `botId`, `version`, `desired`, `status`, `step`, `activePoint`,
`reason`, `error`, `receivedRevision`, `appliedRevision`, `settingsStatus`,
`updatedAt`, `tickMs`. `updatedAt` — время последнего отчёта исполнения,
`lastSeenAt` — время запроса статуса, не доказательство прогресса сценария.

## Пакеты

Сборка: `pc/build-bot-package.ps1`. RSA-ключ издателя хранится через DPAPI отдельно
от аккаунта; APK содержит только открытый ключ. Подпись SHA256withRSA покрывает
точные UTF-8 байты `payload` с id, версиями, размером и SHA256 архива.
Телефон получает manifest и ZIP через авторизованный HTTPS из закрытого каталога
продукта. Публичный доступ к каталогу должен давать HTTP 403.
Проверяются подпись, размер, хеш, совместимость, manifest и пути внутри ZIP.
Установка выполняется в staging, затем переключается текущая версия;
предыдущая сохраняется для отката. Опубликованная версия неизменна.

# Модуль 1.1.13 и сведения о телефонах

Дополнительный автобой перед картой ограничен одноразовым флагом распознанного
входа в игру. Этот флаг не создаётся обычным запуском бота на готовом персонаже,
сменой настроек или повторным маршрутом. При входе в городе проверка погашается.
Неподтверждённая миникарта теперь повторно проверяется на свежих кадрах в пределах
исходного числа попыток; без подтверждения кнопки нажатий нет.

`POST /bot/v1/devices/{id}/identity` принимает `characterName` (до 80 символов,
без управляющих символов) и `provider` (`VMOS`, `UgPhone`, `Другое`, пустая строка).
Эти данные хранятся на ПК в профиле, не входят в настройки игрового сценария и
не отправляются на телефон. Копирование настроек сохраняет identity получателя.
Windows показывает имя, поставщика и состояние бота; при устаревшей связи отмечает
последнее известное состояние. На главном экране — исходная эмблема LN из MultiBot и состояние, без названия игры.

Проверены 53 Python replay-теста и 7 Bot API-тестов, Windows редактор и smoke/layout.

Kirtosav: running / farm_travel_confirm, без farm_minimap_not_confirmed. Исходный

# Временный журнал ошибок: APK 0.8.6

Телефон хранит `files/bot-errors/<время>-<случайный id>/report.json` и `screen.jpg`.
Сохраняется последний кадр распознавания текущего запуска, а не новый снимок после
остановки. Если кадра нет или он превышает 1 МиБ, отчёт содержит причину отсутствия.
Архив ограничен 100 записями / 64 МиБ; срок хранения 12 часов, период очистки 3 часа.
Очистка также выполняется при добавлении записи и обращении к архиву. После выключения
службы очистка возобновляется при её следующем запуске. Настройки, ключи и Python
стек не сохраняются. Ошибка записи не мешает поставить сценарий на паузу.

Защищённые команды `bot diagnosticsList` и `bot diagnosticsGet {id}` доступны
при capability `botDiagnostics: 1`. ПК копирует новые записи в `bot-errors`
каталога профиля пользователя и применяет те же ограничения. Чтение идёт по
существующему зашифрованному каналу, без отправки кадров распознавания во время фарма.
Панель открывает папку кнопкой «Папка ошибок и скриншотов…»;
`GET /bot/v1/errors` возвращает путь, политику хранения и список отчётов.

Для APK 0.8.5 ПК может сохранить лишь снимок после остановки — в JSON это отмечено
`source: snapshot_after_pause`. Текущие ошибки Kirtosav и Orfeus сохранены именно так.
В текущем профиле путь: `C:/Users/Валентин/.phone-exit/bot-errors`.
