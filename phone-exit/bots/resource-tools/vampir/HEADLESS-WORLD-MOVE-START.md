  `0x14991a080`. Этот конструктор исполняется перед каждым чтением.
- Таблица `+0x20` указывает на reader `0x145845140`; `+0x28` — на getter

  ссылается на ASCII `PktWorldMoveStartResult` по адресу `0x14990eca8`.

  её слот `+0x10` содержит `0x1467a61a0`.

## Полное тело: 30 байт

| Wire-смещение | Формат | Поле native-объекта | Нормализация |
| --- | --- | --- | --- |
| 0 | u32 | `+0x10`, код результата | Без изменения |
| 4 | u32 | `+0x14`, новый ID мира | Без изменения |
| 8 | 3 × float32 | `+0x18`, три double | Расширение float32 → double |
| 20 | u8 | `+0x30`, enum | `min(value, 22)` |
| 21 | u8 | `+0x31`, bool | Любой ненулевой байт → true |
| 22 | u64 | `+0x38` | Без изменения; семантика не установлена |

Все целые little-endian. Вектор читает уже проверенный
`CharacterSelect_ReadVector`; последнее поле — `Archive_ReadScalar20`.
Поля `+0x30` и `+0x38` не названы направлением / временем без доказательства.

Исполнены 24 полных тела: три кода результата, четыре значения enum,
два значения bool. Проверены отрицательная координата и signed zero.
Все 30 коротких префиксов отклонены без выхода за доступные данные.
В отдельном сценарии native-reader потребляет 30 байт из 31 и оставляет хвост.
Общий декодер требует ровно 30 байт и отклоняет хвост на границе тела пакета.

## Общий API

`vampir_core.world_move_start_result.decode_world_move_start_result(body, *, max_payload_size)`
принимает immutable `bytes` и явный лимит от 30 до `0xffffff`.
Превышение лимита — `BufferError`, неподдержанный тип / длина — `ValueError`.
Возвращается неизменяемый `WorldMoveStartResultBody(result_code, data)`.
Данные скрыты из repr; поля `data.at(offset)` используют смещения native-объекта.
Вектор `data.at(0x18)` хранит исходные float32 bits через общий `WireVector3`.
Декодер не применяет политику принятия ответа и не объявляет сессию готовой.

## Продолжение протокола: статические связи

Соседние пакеты по их таблицам / именам / ID getters:

| Пакет | ID | Таблица |
| --- | --- | --- |
| `PktWorldMoveReserve` | 201 | `0x149919f60` |
| `PktWorldMoveReserveResult` | 202 | `0x149919fb8` |
| `PktWorldMoveStart` | 203 | `0x14991a030` |
| `PktWorldMoveStartResult` | 204 | `0x14991a080` |

Принятый ответ резервирования вызывает `0x145dbf640`. Этот метод переносит
поля ответа в сервис и вызывает его слот `+0x68`. В таблице `0x1499f11f0`
слот `+0x60` равен `0x145dc29c0`, `+0x68` — `0x145dc2e60`, `+0x70` —
ранее проверенный запрос ID205 `0x145dc2930`.

Метод `0x145dc2e60` вызывает конструктор `PktWorldMoveStart` и отправку.
У него есть разные ветви транспорта по аргументу enum; полный encoder ID203
и этот метод целиком в новом replay не исполняются.

Обработчик ID204 после принятия фильтром передаёт пакет в `0x145dbf720`.
Инструкции хвоста обработчика подтверждают переход на этот адрес; первоначально
Ghidra включала тело сервиса в псевдокод обработчика. После отдельного экспорта
граница функций видна явно.

Сервис переносит прежний ID из `+0x40` в `+0xf4`, новый из пакета `+0x14`
в `service+0x44`, вектор в `service+0x60`, enum в `+0x59`. Далее выбираются
переход через `SelectionService_SetState` либо путь сервисного слота `+0x70`.
Эти условные ветви прочитаны статически и ещё не проверены исполнением.

## Открытая работа

Проверить ID204 reader → handler → сервис в одном сценарии, включая ошибки
и условия выбора загрузки / ID205. Затем найти инициатор резервирования после
ID110 и проверить ID201–203 до отправки. Уровень, `DefaultGameMode` и реальный
порядок серверных пакетов остаются открытыми. Вектор ответа не объявляется
подтверждённой мировой позицией без проверки его потребителя.
