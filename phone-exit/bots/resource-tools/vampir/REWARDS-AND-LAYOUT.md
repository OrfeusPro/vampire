## Квесты и награды

`build-reward-links.py` соединяет CSV pakchunk1-Windows:
Quest 1448 → RewardGroupId1..5 → Reward 1475 по GroupId;
QuestTask 1454 → Quest по QuestInfoId.

Результат `quest-graph/rewards.json`: 1353 квеста, 1348 групп, 5759 записей наград.
Отсутствующих групп наград 0, отсутствующих RequireCompleteQuestInfoId 0.
Сохранены PreQuestId, RequireCharacterLv, RequireCompleteQuestInfoId,
ContentsLockInfoId, Retryable, ServerServiceGroupId и исходные условия задач.
Поля Reward: Type, Param, MinCount/MaxCount, Rate, BonusReward, RewardGroup,
FixedTermId, OpenBoxImmediately и прочие флаги сохранены без пересчёта вероятностей.
ContentsLockInfoId соединён с 269 блокировками и 330 условиями; подробности
и ограничения: [CONTENTS-LOCKS.md](CONTENTS-LOCKS.md). Нативная семантика
числовых типов и комбинаций условий пока не восстановлена.

Пример подтверждённой связи: Quest 110540 Meeting the Bookseller требует
завершения 901030, а не только предыдущего 110530. Награда 901010 — группа
23000010; в её строках есть Type=2 Count=100, Type=0 Param=Gold Count=1000,
предмет 80000000 Count=10 и предмет 100000001 Count=3. Это соответствует числам
на сохранённом окне награды. Теперь Type=2 независимо подтверждён как
 ERewardType::Exp массивом дескрипторов EXE; 0=Asset, 1=Item.
См. [NATIVE-SEMANTICS.md](NATIVE-SEMANTICS.md): источник, значения и проверки.

Для каждого квеста и каждой строки награды записаны entry и логический csv_record.
Полные SHA256/смещения CSV — в разделе sources отчёта.
Данные награды не доказывают её фактическое получение персонажем.
Обработчик 1.0.7 пока использует текст Claim Quest Rewards + отметку завершения
и затем окно Quest Complete; полного сравнения инвентаря с Reward ещё нет.

## CanvasPanelSlot

`decode-canvas-slots.py` читает сериализованные экспорты из ui-layout-study.
Результат `ui-geometry/canvas-slots.json`: 2013 разобранных слотов, 2 исключения
с полным источником и причиной. Все байты каждого принятого слота учтены,
Parent и Content указывают на существующие экспорты, родитель имеет тип CanvasPanel.

Восстановленная схема: unversioned header с skip/value fragments и zero mask;
CanvasPanelSlot LayoutData/AutoSize/ZOrder/Parent/Content; внутри LayoutData —
Offsets (FMargin), Anchors Min/Max, Alignment. Геометрия в логических единицах,
не в пикселях скриншота. Отсутствующие поля заполнены предполагаемыми нулевыми
значениями структуры; переопределения архетипа пока не разрешены.

Для каждого слота сохранены: исходный JSON пакета, номер экспорта, смещение,
SHA256 сериализованных данных, исходный PAK, родитель и контрол.
Схема **выведена из cooked-данных и проверок ссылок**, а не из доступного C++
исходника движка. `absolute_screen_geometry_verified=false`.

Пример: pakchunk500-Windows-9236, ButtonEquip, CanvasPanel_61:
Offsets right=360, bottom=80, Anchors Min=Max=(0.5,1), Alignment=(0.5,1).
Это условие размера и привязки, а не готовая абсолютная координата клика.
Размеры самого SizeBox, масштаб, safe area, видимость, анимация и родительские
переопределения ещё требуют разбора. Поэтому извлечённая геометрия пока не
заменяет визуальное подтверждение цели и не используется для слепого ввода.

## Панели и порядок детей

`decode-panel-slots.py` разобрал ещё 2050 слотов: HorizontalBox 549,
VerticalBox 437, Overlay 721, WidgetSwitcher 117, SizeBox 149, Border 37,
ScaleBox 5, SafeZone 35. Учтены поля размера дочернего элемента (Automatic/Fill),
padding, выравнивания и ссылки Parent/Content там, где они сериализованы.
Числовые выравнивания отдельно подтверждены native-массивами HAlign/VAlign.
Схема сериализации пока выведена из cooked-данных, а не из C++ деклараций.

286 исключений сохраняются с причиной: 283 родителя пользовательских типов
NkButton/NkTabBar/NkVerticalTabBar и 3 SafeZone с неразобранными явными полями.
Нельзя считать их доказанными стандартными классами только по похожему имени.
Два Canvas-исключения JoinedCountryVisibilityCanvasPanel также сохранены.

`build-ui-topology.py` читает исходные байты родителей, проверяет SHA256 тела
пакета и экспорта, ищет единственный массив count + ссылки на известные слоты.
Результат `ui-geometry/topology.json`: 1945 родителей, 4063 дочерние связи,
неоднозначных/отсутствующих массивов среди обработанных родителей 0.
Порядок берётся из массива, а не из номера экспорта: встречается [38,36, 37].
Эти числа относятся только к уже разобранным слотам, не ко всему интерфейсу игры.

Не разрешены desired size, архетипы, runtime DPI, активная страница Switcher,
видимость и анимации. Slot SizeBox — это расположение ребёнка внутри SizeBox,
а не доказанные WidthOverride/HeightOverride самого контейнера.
Данные не передаются напрямую в бот как координаты ввода.
