Продолжение [текущего mapper](HEADLESS-RELEASE-LOBBY-ERRORS.md).

## Проверка

Два последовательных read-only контроля через `probe-selected-game-login.py`:
основной `bot-test@vampir.top` на Aria 1 / ID 381, затем тот же аккаунт на его
прежнем Prelude 2 / ID 384. Свежие public CDN и GMC2, current source profile,
прямой выход, launcher flow, явный EU, partial metadata, language code 1,
актуальная patch revision из установленного manifest. Перед началом не было
игры или другого account worker. Пароль прочитан через DPAPI из приватной
SQLite в read-only соединении и не выводился. Токены / тела ответов не сохранялись.

Параметры контроля совпадают с worker входом, кроме явно выбранного сервера
и запрета создания / выбора персонажа. Использован обычный probe, без monkeypatch
сетевых функций. Никаких исправлений байтов запросов под результат не делалось.

| Аккаунт / цель | NID / launcher SDK | Выбранное лобби | Game Login / список |
| --- | --- | --- | --- |
| Основной, Aria 1 / 381 | Приняты | 10036 | Не отправлялись |
| Основной, Prelude 2 / 384 | Приняты | 10036 | Не отправлялись |

Обе операции завершились `selected_lobby_context_not_received`,
stage `selected_lobby_login`, без SDK или browser error. Отдельно после каждой
операции проверено равенство исходного assignment в базе: true.
Новый список не сохранён, ник / класс / персонаж / сервер аккаунта не изменены.
Creation factory, character index и world start отсутствовали.

До этого новый `nightraven` после первого SDK SignUp и отдельного ручного NID
входа получил тот же результат на Aria 1:
[живые результаты](../auth/HEADLESS-FIRST-SDK-LIVE-AND-NID-HINTS.md),
[последующий ручной контроль](../../../../../vampir-headless/ACCOUNT-CONSOLE.md).
Последняя ссылка ведёт к текущим итогам панели; подробный native mapper хранится
отдельно. Все эти результаты относятся к текущему SDK/лобби, не к старому HK.

## Вывод и пределы

Отказ воспроизводится на основном аккаунте с уже существующим персонажем,
а также на его прежнем сервере. Отсутствие нового персонажа / нового SDK-профиля
не объясняет это сравнение. NID/SDK приняты, поэтому последний этап 10036
отделён от ранее встречавшихся NID HTTP 400 / признака капчи.

Текущий mapper исполнялся native и возвращает IsInspect. Это согласуется
с клиентским описанием техработ. Но два запроса через один runtime не изолируют
серверные техработы от общего несовпадения параметров нашего клиента.
Работу всех EU-серверов или успешность официального клиента в этот момент
эта проверка не доказывает. Причина, длительность и масштаб остаются неизвестны.

Новых повторов создания или смены назначения для обхода отказа нет.
SDK-профиль nightraven подтверждён; SignUp повторять не нужно.

## Дальше

При наличии нового наблюдения сравнить штатный клиент на Prelude 2 с текущим
ответом бота: если штатный вход проходит, исследовать актуальные lobby context /
поля Login; если он также сообщает техработы, дождаться изменения состояния.
До этого продолжать независимую работу над подключением первого SDK-входа к
панели и состояниями аккаунтов. Для создания персонажа по-прежнему требуется
успешный игровой Login и принятый пустой список на назначенном сервере.
