# Проверка канала через Google Pixel 5

22 октября 2026. Пользователь добавил телефон у другого поставщика услуг
для проверки доступа к Vampir. Проверялся Google Pixel 5 с объявленным выходом JP.
Изменений runtime игры в этой проверке не было.

## Привязка и доступность

Первый обычный запрос каталога показал свежий Redmi M2101K6G / JP.
Подключение к нему не достигло готовности; дальнейшие объявления стали старыми,
локальный API также показал offline. Владелец этой попытки явно остановлен.

При проверке расшифрованных объявлений каталога обнаружен свежий Pixel 5 / JP,
чей идентификатор присутствовал в списке ранее заблокированных привязок.
Обычный Directory скрывал его по этому условию. Запросы каталога возвращали
HTTP 200; расхождение часов с сервером составляло около секунды.

Пользователь явно разрешил восстановить именно Pixel 5 и проверить его.
До изменения сохранена зашифрованная DPAPI-копия `account.bin` в каталоге
`backups` пользовательского профиля Phone Exit. Удалена ровно одна блокировка,
новых блокировок нет. Сравнение остальных полей до / после подтвердило полное
совпадение; ключи и capability аккаунта сохранены. Профиль не заменялся другим.
После этого Pixel появился в свежем обычном каталоге как свободный JP.

## Результат транспорта

Первая попытка через Pixel завершилась с code 1 до готовности SOCKS;
вспомогательный скрипт не показывал причину из stderr. Затем выполнен один
диагностический повтор с выводом только разрешённых названий стадий и ошибок,
без pairing code, токенов и сетевых адресов.

Полученная последовательность:

```text
pairing_requested
WebRTC: connecting
WebRTC: failed
direct_connection_failed
stopped: code 1
```

Сигнализация и запрос сопряжения прошли; прямой канал не установился.
SOCKS не достиг готовности. Авторизация Vampir, Game Login и подтверждение
обучения не запускались. Из этой проверки нельзя заключить, что новый выход
заблокирован игровым сервером: ответа игры не было.

Причина отказа прямого канала пока не выделена. Возможны особенности NAT,
фильтрация UDP или поведение приложения / сети телефона; эти варианты не
проверены отдельно. Сторонний relay и изменение защиты ОС не применялись.
После завершения владельцев слушателей на портах маршрута 17948 и feed 17947 нет.
Восстановленная пользователем привязка Pixel сохраняется.

Публичная сводка вне Git:
`F:/PhoneExit Resources/Vampir/live-login-observations/22fa1baad034472124d70b40dc4cf9e4476583640d64b4261e02137c63db69e3/manifest.json`.
SHA256 файла совпадает с именем каталога. В ней только стадии, результат
сверки профиля и SHA вспомогательного скрипта; credentials и captures отсутствуют.

Следующая проверка — прямой канал с Pixel при изменённой сети либо с другого
доступного JP. После готовности транспорта можно выполнить одну подготовленную
проверку [подтверждения обучения](../scenarios/HEADLESS-LIVE-INITIAL-TUTORIAL-ACK.md).
