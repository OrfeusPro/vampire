23 октября 2026. Реализация и проверки относятся к EXE SHA256:
`98802d550890354da73cfef101bc49c1691f104beccb8b6d878594ba8952807e`.
Использован готовый экспорт `144506cf0`, без нового запуска Ghidra.
Источник и проверенная цепочка:
[первый SDK-вход](HEADLESS-RELEASE-FIRST-SDK-LOGIN.md),
[живой результат отдельного runner](HEADLESS-FIRST-SDK-LIVE-AND-NID-HINTS.md).

## Поведение

В панели есть отдельная операция `prepare-sdk`: «Подготовить профиль SDK».
Пользователь явно задаёт country, locale и вариант BasicTerms. Пустые или
некорректные параметры отклоняются до запуска worker. Значения не выводятся
из региона сервера и не подменяют сохранённый способ обычного входа.

Worker использует текущий `run-nid-sdk-sign-in.py` с `first_sdk_login=True`,
`auth_flow=nid`, `selected_profile=recovered-release`. Свежий Fetch и строгая
проверка условий остаются в существующем flow: успех Fetch ведёт к SignIn;
только HTTP 400 / code 1203 и два ответа NO DATA допускают один SDK SignUp,
затем SignIn с проверкой совпадения player ID. Доступные условия останавливают
операцию с фиксированным сообщением о необходимости просмотра и принятия.

Операция не регистрирует почту / NID, не загружает игровые серверы, не подключает
игровое лобби и не создаёт персонажа. После подтверждённого SignIn сохраняется
`sdk_created`, токен и player ID не попадают в stdout или таблицу аккаунтов.
Для дальнейшего списка персонажей нужен отдельный обычный вход.

Подтверждённый `sdk_created` или назначенный персонаж запрещают подготовку на
стороне панели и worker. Ограничение двух процессов, изоляция аккаунтов,
остановка и ручной ввод Netmarble используют прежний manager. При неизвестном
результате нет автоматического повторения; новое явное действие снова начинает
со свежего Fetch. Обычные операции не переключаются на подготовку после ошибки.

## Проверки и границы

- Четыре offline теста проверили обязательность параметров, запрет подтверждённого
  профиля / назначенного персонажа, передачу параметров без credentials в argv,
  запрет параллельного запуска одного аккаунта и результат worker.
- В worker fixtures проверены успешный ответ, ручной пароль, доступные условия
  и неизвестный ответ. Только валидный SignIn сохраняет `sdk_created`; игровые
  и CDN modules не загружаются, каталог и персонажи не сохраняются.
- Прошли также 20 тестов панели, 9 runner и 12 первого SDK-входа. Fixtures
  не выполняют авторизацию, SDK SignUp или игровые действия.
- `node --check` проверил синтаксис JavaScript. Визуальная проверка новой формы
  не выполнена: Browser use отключён в настройках Work.
- После перезапуска локальной панели HTTP GET вернул новую форму. Контрольный
  POST подготовки уже подтверждённого профиля получил HTTP 400; снимок jobs
  не изменился, активных процессов ботов нет. Настройки аккаунта не менялись.

Живой вход через новую кнопку ещё не проверен. Прежний отдельный runner
подтвердил nightraven; повторять его SDK SignUp для проверки интерфейса нельзя.
Показ / принятие доступных условий и автоматическая обработка остальных новых
аккаунтов остаются открытыми. Отказ EU-лобби `10036` этим изменением не устраняется.

## Следующая проверка

Проверить новую форму без отправки, затем выполнить одну явно выбранную подготовку
аккаунта без подтверждённого SDK-профиля. После успеха отдельно получить принятый
список на назначенном сервере; создавать персонажа только при свежем пустом списке.

## Изменение установленного клиента

Во время завершения этапа полный SHA установленного EXE изменился на
`d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.
`finish` задания installed остановился на проверке версии. Результат панели
фиксируется только для прежнего явного SHA / сохранённого снимка; совместимость
новой сборки не заявляется. Guards runtime не отключались. Перед новым живым
входом требуется проверка обновления и перенос затронутого auth-контракта.
