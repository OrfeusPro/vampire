# JP: регистрация Netmarble 24 октября 2026

Для этой проверки пользователь разрешил только `bot-tw-test@vampir.top`.
Имя ящика сохраняется, регион регистрации после уточнения — JP. Другие почты
предназначены для Global EU без VPN; повторную регистрацию для них не запускать.
Почтовый ящик уже существовал, создавался аккаунт Netmarble.

## Маршрут и регистрация

Отдельный CLI Phone Exit выбрал свободный realme RMX3511 / JP. Нативный WebRTC
открыл SOCKS на `127.0.0.1:1080`; HTTPS Cloudflare trace подтвердил `loc=JP`.
Это отдельный маршрут формы и SDK, не включение системного Windows VPN.
Существующие подключения и аккаунты не переключались.

Node первоначально не доверял TLS-цепочке каталога. `--use-system-ca` и
`NODE_USE_SYSTEM_CA=1` позволили использовать системное хранилище доверия.
Проверка сертификатов не отключалась. IMAP `mail.vampir.top:143` с STARTTLS
и проверкой сертификата прошёл; почтовый пароль оказался правильным.
Ранние отказы IMAP возникли при неполной передаче специальных символов через
управляемый TTY. Последующая передача точного значения восстановила вход.

Использована официальная форма SDK / NID, как при прежнем входе лаунчера:
условия → email → проверка кода → пароль. Отдельный EXE лаунчера / игры не запускался.
Первая отправка письма показала `Unexpected error … (unknown)`; отметка helper
`email_sent` означала нажатие кнопки и сама по себе не доказывала доставку.
Пользователь закрыл сообщение и повторил отправку в том же окне.

После этого форма перешла в `/auth/signup/email/verify`. Из выбранного ящика
прочитано одно подходящее письмо, код принят формой. Затем пройдена установка
пароля и получен проверенный NID callback с `joined_country=JP`.
Все четыре шага регистрации наблюдались. Аккаунт Netmarble зарегистрирован.
Код, пароли, callback и токены в отчёты не записывались.

## Где остановился игровой вход

Отдельный обычный вход этого аккаунта через тот же JP SOCKS подтвердил NID.
Launcher token получен; launcher sign-in SDK вернул **HTTP 400 / код 1203**.
Это отказ SDK до запроса серверного каталога. Причина 1203 не установлена;
он не отменяет подтверждённую регистрацию Netmarble и не доказывает блок IP.

Отдельная проверка SDK Fetch остановлена локальным guard до отправки: текущий
source profile разрешает launcher sign-in, но ещё не прямые SDK операции.
Проверка `game-source-profile.py --profile recovered-release --check` также
вернула `source_profile_not_verified`. Для установленного EXE 1.13.16 / SHA
`d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`
полный игровой профиль остаётся неперенесённым. Guards не обходились.

Каталог JP, список персонажей, вступительное видео и игровая сессия этой
проверкой не получены. Create не отправлялся. Без выбора подтверждённого сервера
создание не запускать: SDK вход → каталог JP → выбор сервера → принятый список
персонажей → создание только при пустом списке.

Запись добавлена в локальную панель: регион JP, launcher flow, класс Carnage,
без назначения сервера / персонажа, registration status `registered`.
Пароли сохранены под DPAPI. Панель по-прежнему запускает обычные jobs напрямую;
данная JP-проверка выполнялась отдельным CLI с явным SOCKS, не кнопкой панели.
Нельзя выдавать сохранённый регион за настроенный маршрут панели.

После проверки собственный CLI получил Stop, дочерний транспорт завершился
с кодом 0. Автоматического reconnect / смены телефона не запускалось.
Приватная сводка без credentials находится вне Git:
`F:/PhoneExit Resources/Vampir/live-registration/jp-20261024/3e8d32e81837fed5f4f712798a62a6b3da3a6dde4076c3673e2d0b0175a5e5ff/manifest.json`.
SHA256 совпадает с именем каталога.

Следующий этап — выяснить отказ первого игрового SDK-входа и перенести нужные
проверки на текущую сборку. Netmarble повторно не регистрировать и SDK SignUp
по коду 1203 автоматически не вызывать. Исторические исследования первого
SDK-входа не являются подтверждением его совместимости с 1.13.16.
