# Регистрация устройства и защита аккаунта Vampir 1.13.22

Область проверена для EXE SHA256 `03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
Вход выполняется существующим SDK Launcher профилем. Открываемые формы определяет
`playerStatus` в свежем ответе SDK. Для `deviceSecure=["device-registration"]`
используется регистрация устройства, для `restriction=["workplace"]` — снятие
защиты. Если сервер прислал оба состояния, первой открывается регистрация устройства.
Незнакомые значения, отсутствующий статус и незавершённые этапы останавливают очередь.

| Форма | Ключ GMC2 | Адрес | Корень в EXE |
| --- | --- | --- | --- |
| Регистрация устройства | `deviceWebViewUrl` | `/secure/device` | `0x1444e0a00` |
| Защита аккаунта `workplace` | `unrestrictionWebViewUrl` | `/restriction` | `0x1444e1720` |

Обе формы находятся на `https://profile-auth-view.netmarble.com`. При проверке
публичных маршрутов 5 ноября 2026 обе страницы вернули HTTP 200 и одинаковый HTML
SHA256 `360beb3c626bf43a4cb2b2af868c41b05ce93a52410d6f9307d23b7b4a10506e`.
JavaScript SHA256 `42d2c37313e69f7fd68e9b1c4507cf3196de1ec3e6b02d5df19df90152742cde`
прочитан из `verification-web-snapshots/<SHA>/main.js` в библиотеке ресурсов.
Оба builder подтверждены экспортом `run-82316fcdff9b/details.json` SHA256
`76c59a37473c37edfe654635efbf2de555b2f1626b8425b7c690a4c94c4dadb7`.

Нативные builders формируют `playerId`, `accessToken`, `countryCode`,
`joinedCountryCode`, `language`, `gameCode`, `buildCode`, `osType`, `nmDeviceKey`,
`deviceIp`, `deviceName`. Регистрация устройства дополнительно передаёт SDK
`deviceKey`. Нативный клиент при наличии настройки `redirectCookieUrl` проводит
формы через `oven` с дополнительными метаданными. Адаптер открывает официальный
адрес напрямую и передаёт `webViewType=sdk`. Публичный JS читает эти параметры
из query. Окно использует изолированный приватный WebView2, входной URL и код
передаются по stdin. Страна выхода и адрес берутся из текущего GMC2 ответа,
имя устройства — из имени этого ПК.

| Действие формы | Наблюдаемый контракт JS |
| --- | --- |
| Запрос кода | `POST /api/v2/notification/email` с `type`, `locale` и условным `mailAddress` |
| Проверка кода | `POST /api/v2/notification/email/verify` с `tokenId` и `code` |
| Регистрация | `POST /api/v2/secure/device` с `deviceName`, `email`, `tokenId`, `code`, `agreement`, `registrationType`, `serviceCode` |
| Снятие защиты | `POST /api/v2/restriction/workplace/release/email` с `email` и `tokenId` |

Ветка `restriction` использует токены reCAPTCHA официальной формы. Обработчик
ожидает явный успех завершающего POST и соответствующий callback с того же
домена. Для устройства это `device-registration?ExecutionType=register&IsConnected=true`,
для защиты — `restriction?ExecutionType=success`. Код выбирается из нового письма
нужного назначения, на адрес этого аккаунта и в пределах десяти минут. Старые UID,
сброс UIDVALIDITY и неоднозначные коды исключаются.

При первой живой проверке SDK-вход и отправка письма для устройства прошли.
Подтверждение устройства остановилось при чтении тела HTTP-ответа WebView2.
Чтение исправлено с учётом требования COM-потока использовать нулевое смещение
буфера. Получение письма подтверждено через read-only IMAP. Код и токены в отчёт
не включены.

Во второй попытке штатная очередь панели подтвердила регистрацию устройства и
перешла к защите аккаунта. Сервер прислал новое письмо второго назначения.
На экране ввода кода защита сохраняет заголовок «Verify with Email». Селектор
исправлен по маршруту и полю ввода. Оба заголовка и защита от ввода кода в форму
другого аккаунта покрыты тестом браузерного сценария.

[Реестр текущего контракта](../../verification-web-current.json) связывает исходный
SHA и публичные формы. `sdk-runtime-launcher-11316` учитывает код и экспорт
в `on_update`. Проверки очереди и почты выполняет инфраструктурная группа
`account-verification`. При новом SHA нужен подтверждённый контракт форм.
Прошли 14 сценариев SDK и 30 сценариев группы панели и почты. Из кэша
переиспользованы остальные 27 групп. Для повторного сбора оба экспорта уже готовы.
