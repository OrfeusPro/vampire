# Первый вход группы Viper: фактическая остановка

6 ноября 2026 года выполнена одна попытка Silvercrow через панель: прямой выход,
назначенный общий шаблон, SDK-only профиль текущего клиента SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
Вход NID принят; стадия `sdk_launcher_sign_in` завершилась HTTP 400 / SDK 1203.
Причина отказа не установлена. Код SignIn сам по себе не доказывает отсутствие
профиля SDK и не разрешает автоматический SignUp.

Формы регистрации устройства / снятия защиты не получены, лобби не открыто,
список серверов и персонажей не прочитан. Создание не отправлялось. Остальные
семь аккаунтов не запускались: пользователь выбрал проверку всей цепочки на одном
перед группой. Приватный результат без токенов сохранён в
`.local/verification-captures/entry-eight-20261106/silvercrow-sdk.json`.

## Зафиксированное назначение группы

Восемь записей сохраняют тип Бот и класс DarkMage / Viper: Silvercrow, Moonraven,
Shadowfox, Stormcrow на Canon 1; Frostwolf, Ironraven, Emberhawk, Crimsonfang на
Canon 2. После резервной копии всем включён `create_random_nickname=true`,
старый ник для создания очищен; alias и история попыток сохранены. Генератор
сработает только после принятого пустого списка. Предложенный ник не становится
именем созданного персонажа до подтверждения. Пароли и ключи не менялись.

Выбор по умолчанию для бота — уже существующее сохранение региона, сервера,
`character_index` и `character_key` из принятого списка. Отдельный серверный флаг
не подтверждён; поля запроса выбора не переименовывать в такой флаг.

## Что отделяет текущую попытку от полного входа

- Для диагностики 1203 нужен отдельно подтверждённый текущий Fetch-контракт.
  Нынешний SDK Launcher профиль предоставляет только launcher authentication;
  Fetch / Terms / SignUp / direct SignIn им не разрешены.
- `account-worker` использует прежний `recovered-release`. Текущего подготовленного
  игрового пакета в библиотеке нет. Готовые SDK proofs не предоставляют ему
  возможность входа в мир. Нужны текущие CharacterList / выбор и clock / lobby /
  ограниченный world; [экспорты уже собраны](../updates/HEADLESS-ENTRY-COLLECT-CURRENT.md).
  Старые неизменные семь scopes переиспользуются через готовый proof bridge.
- В lobby VersionResult изменился reader: после прежнего префикса появились
  FString и два u32. Прежний decoder ровно на 23 байта не годится для нового
  layout без source-bound сценариев.
- Существующий runtime factory поддерживает только Carnage на прежнем SHA.
  Viper Type 1 и его F / M presets найдены в таблицах; полный текущий packet /
  preset consumer ещё не подтверждён. Подмена только class ID не является
  готовым Viper factory.

Общие официальные формы подключены до лобби в том же свежем SDK контексте,
без второй авторизации. Проверены fixtures отказа, неизвестного состояния,
истечения срока, сохранения fingerprint только после успеха и terminal-режима
с десятиминутным сроком. [Порядок и критерии](../../../../../vampir-headless/BOT-ENTRY-FLOW.md).
Успешная отдельная почтовая верификация не закрывает перечисленные игровые контракты.

Для следующей диагностики [собраны точные текущие Fetch request / response](HEADLESS-SDK-FETCH-CURRENT-COLLECT.md).
Scope initializer имеет отдельный CRT-tail blocker; runtime Fetch ещё запрещён.

[Проверки, использование кэша и границы результата](EIGHT-ACCOUNT-ENTRY-VALIDATION.json).
