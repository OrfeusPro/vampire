# JP: официальный вход до каталога и отказ после выбора сервера

24 октября пользователь записал запуск лаунчера, авторизацию, запуск игры,
выбор сервера и сообщение о блокировке IP. Это новый эталон для сравнения с
[регистрацией и отказом SDK 1203](HEADLESS-JP-REGISTRATION-20261024.md).
Регистрацию Netmarble повторять не нужно.

## Источник и границы

Приватная запись:
`C:/Users/Валентин/.phone-exit/diagnostics/cfd3b953bad58e922130b0b285e22c7f/traffic.jsonl`.
SHA256 `f14509c5129c2d3123267d7cd57e518eef57f79b0cabb8cf5ec16b15dba29c72`.
Запись all-tcp завершена вручную через 82,174 секунды: 233 потока,
4 378 118 байт полезных данных. `capture-inspect.js` проверил формат,
порядок событий, смещения и счётчики. Штатная остановка записи не означает
завершение всех соединений.

Версия 1.13.16 взята из metadata игрового Login. Сам захват не подтверждает
полный SHA запущенного EXE. Существующие bounded decoders применены офлайн;
это наблюдение wire-формы, не новая проверка native readers текущего EXE.
Авторизация, отправка пакетов и воспроизведение captured credentials не выполнялись.

## Сравнение авторизации с ботом

Официальный клиент дошёл до каталога и успешного lobby Login, а предыдущий
вход бота остановился на SDK launcher sign-in с HTTP 400 / 1203 до каталога.
Это разные этапы отказа; 1203 нельзя объяснять игровым ответом 58 как одним
и тем же наблюдением.

В игровом Login официального клиента присутствуют metadata:

- I_GameCode `thered`, I_GameVersion `1.13.16`, I_SDKVersion `5.2.11`;
- I_CountryCD и I_JoinedCountryCode `JP`;
- I_OS `3`, I_Region `GLOBAL`, I_LanguageCD `en-US`, I_ChannelType `33`.

I_NMDeviceKey и I_DeviceKey сравнены в памяти с фиксированным профилем
`bot-tw-test@vampir.top`: оба совпали. Значения не выводились и не сохранялись
в производные отчёты. Это исключает различие именно этих двух полей на момент
сравнения, но не доказывает равенство всего HTTP-запроса SDK или аккаунта:
сам email в строках game Login отсутствует.

SDK / NID HTTP передаётся внутри TLS. Видны ClientHello / SNI для
`members.netmarble.com`, `apis.netmarble.com` и служебных узлов; URL path,
headers, POST body, токены и HTTP status этих запросов не раскрыты.
В локальном main.log лаунчера не найдены `launcher/token`, `launcher/sign-in`,
`countryCode` или 1203; он не дал недостающего HTTP-сравнения.
Нельзя утверждать, что точный auth-запрос официального клиента уже повторён.

Следующая проверка — один свежий обычный launcher-вход бота через подтверждённый
JP-маршрут после первого официального входа. Это проверит гипотезу изменения
серверного состояния аккаунта; гипотеза пока не подтверждена. Если 1203 останется,
нужен отдельный источник HTTP-контекста официального входа или проверка его
подготовки по сохранённому коду. Не повторять регистрацию и не подменять токены
значениями из захвата. Перед созданием всё равно нужны каталог, явный выбор
сервера и успешный пустой список персонажей.
