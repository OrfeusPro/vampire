## Цепочка native assembler

Функция `0x1444ddc10` получает строку после внешнего XOR и отдельное тело ключа.
Ожидаемая форма непустого списка — компактная строка `["cipher1","cipher2"]`.

| Участок | Подтверждённая операция |
|---|---|
| `0x1444ddcde..0x1444ddcf9` | Подстрока с позиции 2 длиной length−4, split по `","`, cull-empty=1 |
| `0x1444ddd10..0x1444ddd1b` | Начальная строка `{` |
| `0x1444ddd30..0x1444ddd4a` | Элемент списка и ключ передаются `0x14451d5c0` |
| `0x1444ddd4f..0x1444ddd55` | Пустой результат элемента прерывает сборку |
| `0x1444ddd66..0x1444ddd84` | Добавление plaintext-фрагмента и запятой |
| `0x1444dddb9` | Последняя запятая заменяется на `}` |
| `0x1444dddc4` | Собранная строка передаётся конструктору JSON |
| `0x1444dde2e` | При пустом списке строится пустой контейнер |

Внутри chunk helper `0x14451d5c0` участок `0x14451d9ce..0x14451d9dd`
убирает один последний нулевой байт перед UTF-8 conversion. Остальные нулевые
байты не вырезаются. Поэтому общий assembler также снимает ровно один NUL,
а не вызывает произвольный rstrip.

В Unicorn выполнены реальные ветви и цикл orchestration. FString constructor,
Mid/split/append/free заменены ограниченными shims; расшифровка и UTF-8 conversion
в shim используют общий chunk backend. Логирование отключено искусственным флагом.
Захват останавливается перед JSON-конструктором или на ранней ветке отказа/пустоты.
Native JSON parser, конечный контейнер, полный cleanup и клиентский RSA этим
исполнением не проверяются. Отдельная проверка native OAEP описана на прошлом этапе.

Девять сценариев включают 0/1/2/3 элемента, кириллицу/символ вне BMP, NUL,
пустой plaintext, ошибку последующего элемента, неверный JSON и повторный ключ.
Четыре граничных входа показывают ограниченность ручного native разбора:
например, `null` и `[""]` попадают в пустую ветку. Общий API их отклоняет.
Результат сборки неверного JSON не считается доказательством его принятия игрой.

## Общий API и ограничения

[sdk_secret.py](../../../../../vampir-shared/vampir_core/sdk_secret.py) дополнен
`decode_sdk_secret_constants(decrypted_list, key_body)`. Вход уже прошёл внешний
XOR и содержит JSON-список ciphertext-строк. Функция выполняет:
разбор списка → расшифровку элементов → один trailing NUL → строгий UTF-8 →
объединение фрагментов полей в `{…}` → строгий JSON-object.

Локальные бюджеты: 2048 UTF-16 единиц входа, максимум 16 элементов и
8192 plaintext bytes, плюс ограничения одного RSA chunk. JSON formatting
обрабатывается обычным парсером, а не ручным native поиском разделителя.
Пустой список возвращает `{}`; пустой элемент, неправильный тип/UTF-8/JSON,
повторные ключи и nonfinite constants отклоняются. Толерантность native JSON
к этим случаям не установлена; строгая политика — решение общего ядра.
При ошибке не возвращается частичный dict и не выводятся данные в сообщении.

Шесть тестов проверяют происхождение, native сборку и её повторное исполнение
с явными plaintext fixtures, настоящий RSA backend для нескольких элементов,
отказ после первого успешного элемента и строгие ограничения. Native replay
fixtures не выдаются за исполнение RSA клиента. Android backend ещё не проверен.
