## Реализация

`map_session.py` хранит только снимок серверной цели в памяти. После ID 206
наблюдатель `exchange_game_login` передаёт `ServerTargetPosition` в `MapProjection`.
Мир должен иметь явную привязку к Map 10/11; неизвестный мир даёт
`unsupported_world`, без выбора ближайшей карты. После close наблюдатель получает
None, снимок очищается. Координаты не добавляются в обычную summary runner.

`MapSessionServer` работает только на `127.0.0.1:17947`. Единственная операция —
GET `/state`; команд движения, файлов, авторизации и изменений настроек нет.
Host проверяется; CORS разрешён только `http://127.0.0.1:17946`. Ответ имеет
`Cache-Control: no-store`. Запрос ограничен socket timeout; сервер и его поток
закрываются владеющим контекстом. Доступ других локальных процессов к loopback
не является границей изоляции аккаунтов; feed предназначен для одной явно
запущенной диагностической сессии на личном ПК.

`run-map-session.py` — явный runner: проверяет content-addressed manifest проекции,
полный SHA установленного архива, текущий source profile и запускает ограниченную
сессию до 300 секунд. Пароль вводится через getpass, без аргумента командной строки.
Он не включает общий VPN и не выбирает телефон самостоятельно: SOCKS-маршрут
готовится отдельно. Ghidra и большие данные не нужны лёгкой модели / серверу;
проверка ресурсов остаётся в диагностическом runner.

В существующем `world-map.html` добавлен выключенный по умолчанию переключатель
«Показывать сессию бота» и кнопка «К персонажу». Polling раз в секунду с timeout
2 секунды включается явно; при скрытой вкладке / выключенном выводе прекращается.
Никаких данных сессии в localStorage, URL или файлы карты не записывается.
Кнопка выбирает точный мир и центрирует вид; в другом выбранном мире маркер скрыт.
Рядом показываются мир, высота и признак возраста снимка более 5 секунд.
Отсутствие feed очищает маркер и отключает кнопку. Все семь прежних разделов,
статические слои и навигационное исследование сохранены.

Это **цель входа**, не доказанное текущее положение после движения. Серверная
позиция до коррекций engine, проекция и сохранённая текстура не доказывают
проходимость, активных NPC или выполняющийся квест. Получение последующих
перемещений и мировых событий остаётся следующим этапом.

## Запуск

Сервер библиотеки ресурсов остаётся на 127.0.0.1:17946, как в инструкции атласа.
При готовом SOCKS-маршруте:

```powershell
python -X utf8 phone-exit/bots/vampir-headless/run-map-session.py --email '<почта бота>' --manifest '<CDN manifest>' --projection '<manifest проверенного аудита проекции>' --socks-port 17948 --client-version 261105 --server-id 256 --character-index 0 --region JP --seconds 120
```

Открыть [атлас](http://127.0.0.1:17946/maps/atlas/index.html), включить слой,
после получения позиции нажать «К персонажу». Закрытие страницы / слоя не
запускает и не останавливает игровую сессию; её срок задаёт runner.

## Проверки

Два теста feed проверили snapshot isolation, unknown world, cleanup, настоящий
loopback HTTP, CORS / Host guards, отсутствие command endpoint / POST и остановку
потока. 26 socketpair-тестов probe включают передачу позиции наблюдателю и None
после close; обычная summary координат не содержит. Восемь тестов selected runner
и три теста проекции прошли. Node-проверка `test-map-session-model.cjs` проверила
stale, чужой мир, выход за границы, disconnect и недопустимые поля. JS синтаксис
проверен через `node --check`.

Живая UI-проверка через JP / TECNO TECNO KJ5n прошла до ID 206. Атлас показал
мир 10010 / Blood Pool, кнопка выбрала этот мир и центрировала вид на маркере.
Признак устаревшего снимка виден. Выключение / включение слоя убирало и возвращало
маркер без нового входа; сетевая сессия при этом продолжалась.
