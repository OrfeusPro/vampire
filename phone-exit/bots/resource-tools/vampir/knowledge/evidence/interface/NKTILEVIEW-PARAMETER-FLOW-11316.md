# NkTileView: различия vtable и передача параметров отображения

25 октября 2026. Только статический offline разбор EXE SHA256
`d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.
Продолжение [packing arithmetic](NKTILEVIEW-PACKING-11316.md).
Нативное исполнение для новых методов, работа с процессом / профилями и
игровые команды не выполнялись.

## Поиск и его ограничения

Запрос `af939762563828f47f5556696279560582aa754470bc2b4dc8b7b36f3f3d0d33`
повторно использовал готовые getter / initializer 144a66f20 и 144a6a620.
Проверялись exact ASCII имена ItemSize, EntrySize, EntryWidgetClass,
ItemWidth, ItemHeight и TileSize, затем ограниченная форма descriptor:
выравнивание 8, указатель на ASCII имя, GenFlags +24 и offset +52 = 0x430.
Полного совместимого описания поля не установлено. Совпадения других классов
не присваиваются NkTileView. Этот поиск не доказывает отсутствие UProperty:
форма не покрывает все виды metadata и собственную сериализацию клиента.

Из уже проверенных записей vptr сравнивались только диапазоны
14965b6a0..14965ba08 и 149657a50..149657db8, ограниченные наблюдаемыми
адресами вторичных таблиц. В каждом 109 code pointers, 13 различий.
Это граница сравнения, а не доказательство полного размера / наследования vtable.
Прочие слоты не декомпилировались массово.

Выбраны четыре точных differing slot:

|0x300|144a898e0|

Запрос `74d23755bc3ca3afe71143143f295a055cbf690e30e2c06f0c58cb05c1e8f1a5`

Он не повторялся; его частичный Ghidra export не используется как завершённое

## Подтверждённые передачи

144a898e0 после двух вызовов проверяет receiver в owner +0x408, затем
передаёт параметры в связанный объект. Предшествующие вызовы не исполнялись;
их изменения состояния не восстановлены.

|Источник owner|Назначение receiver|Передача|
|---|---|---|
|+0x430, 16 байтов|+0x14b8|callee 144628e30, ранее bounded-проверен|
|+0x440, 16 байтов|+0x14d0|прямой MOVUPS|
|+0x450, 16 байтов|+0x14e0|прямой MOVUPS|

Последние два блока используются в ранее проверенной арифметике знаменателя
и удвоенного вычитания. Их source имена / единицы и связь с сериализованными
Spacing / Padding пока неизвестны. В конце метод вызывает 144626640 с DL=0.

144a863d0 после двух прямых calls выполняет virtual JMP по slot +0x300.
В текущей таблице это 144a898e0. Имена методов, условия вызова и полный контракт
передаваемых параметров этим не устанавливаются.

144a84a60 проверяет owner +0x408. В ветви нулевого значения строит связанный
объект через несколько вызовов и сохраняет указатель в +0x408. Статически
наблюдается также обработка связанного control pointer +0x410 / refcounts.
Полная factory, lifetime, успешное создание и entry template не проверены.
144a82420 проверяет +0x408 / +0x418 / +0x420 и вызывает 144604310; тип передаваемых
данных и поведение последнего callee остаются неизвестными.

Ни один из четырёх разобранных методов не дал подтверждённую запись исходного
значения в owner +0x430. Producer и именованное reflected поле остаются открытыми.
Это путь передачи параметров, не замена reflection schema и не клик бота.

## Воспроизведение

`inspect-nktileview-parameter-flow.py` проверяет полный SHA EXE, явные root
задания, выбранные слоты, границы unwind / полное декодирование, конкретные
инструкции передачи и все code pointers сравниваемых диапазонов.
Сохраняет SHA таблиц, все differing slots и полные source-bound fragments.

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/inspect-nktileview-parameter-flow.py --request 'F:/PhoneExit Resources/Vampir/knowledge/requests/5e9ecdf37aabff92ac230e066f3302b192031111f55b940fcae690fd99b41b31/manifest.json' --output 'F:/PhoneExit Resources/Vampir/code-clues/nktileview-parameter-flow-d00a-next.json'
```

Отчёт `code-clues/nktileview-parameter-flow-d00a-01.json` вне Git. Новый файл
не заменяет прежний. Далее нужны producer / named-property metadata для трёх
блоков и подтверждение entry factory. Старые cooked индексы не получают имена
по этой таблице offsets. Генерация внешнего вида остаётся после аудита.
