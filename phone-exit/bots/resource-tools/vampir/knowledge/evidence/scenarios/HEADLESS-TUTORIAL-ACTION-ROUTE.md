## Инициализация и завершение задачи

Инструкции `0x1464eace0` копируют поля выбранной строки в объект задачи:

| Поле строки | Поле объекта | Использование |
| --- | --- | --- |
| +0x0c | +0x1c, затем +0x08 | Первый аргумент запуска / завершения |
| +0x18 | +0x28, затем +0x78 | Второй аргумент запуска / завершения |
| +0x1c | +0x2c | Сохранённый флаг строки |
| +0x30 | +0x40 | Значение ветвления типа задачи |
| +0x60 | +0x70 | Сохранённый параметр; единицы измерения не установлены |

При нулевом результате virtual +0x38 вызывается virtual +0x18 с полями
объекта +0x08 / +0x78. Полное соответствие native layout колонкам TutorialStep
ещё требует проверки loader; названия колонок автоматически не присваиваются.

Общий метод `0x1464eacb0` получает контекст через `0x1464b0910`, читает
те же два поля и переходит JMP в `0x1464ae7c0`. Его длинный псевдокод включает
цель этого перехода: это не дополнительные инструкции короткого wrapper.

`0x1464ae7c0` находит строку группы и запись контекста, сохраняет ключ /
селектор. При ненулевом byte row+0x1c вызывает `0x1464c18d0`; в другой ветви
возможен локальный переход через уже изученные gate и запуск следующей задачи.
[Границы native-проверки локального перехода](HEADLESS-TUTORIAL-STEP-ADVANCE.md).

## Запрос ID 9903

`0x1464c18d0` проверяет набор ожидающих ключей в context+0x268. Найденный ключ
возвращает управление без повторной отправки. Иначе ключ добавляется, выставляется
byte context+0x308, вызывается `0x145692af0(3)`, создаётся пакет через
`0x14584d050`, в поля +0x10 / +0x14 записываются ключ и селектор, затем вызывается
virtual +0x38 сетевого объекта. Смысл режима `0x145692af0` пока не установлен.

Проверка имени / таблицы и инструкций constructor связывает пакет с
`PktTutorialUpdate`, ID 9903, vptr `0x14996b9a8`.
Getter `0x145857180` — `MOV EAX,0x26af; RET`.
Короткий constructor `0x14584d050..0x14584d06a` устанавливает этот vptr,
обнуляет поля +0x10 / +0x14 и byte +0x18. Он не имеет отдельной unwind-записи;
автоматический collect правильно оставляет его в очереди. Последовательность
инструкций отдельно доступна в source-bound отчёте поиска пакета.

Writer `0x145858ef0` вызывает по порядку:

| Поле объекта | Virtual slot архива |
| --- | --- |
| dword +0x10 | +0xc8 |
| dword +0x14 | +0xc0 |
| byte +0x18 | +0xf0 |

Каждый следующий вызов выполняется только после успешного предыдущего.
Разный slot для двух dword нельзя подменять предположением о двух одинаковых
uint32 в проводе. Реализации этих output slots, полное тело запроса, ответ и
снятие ожидающего ключа ещё проверить. Запрос ботом не отправлялся.

## Путь показа подсказки

Вызов задачи типа 16 ведёт через `0x1464ec130` в `0x14672fd40` с той же парой
параметров. Последний получает UI-объект из context+0xa58, вызывает
`0x144a8a510(...,1)`, затем `0x1467301b0` и обрабатывает найденную строку через
`0x14673c180`. Метод `0x1467301b0` сохраняет параметры в +0xa98 / +0xa9c,
вызывает инициализацию и при определённом результате проверки ставит callback
`0x146722630`. Конкретный callback нажатия панели ещё не найден.

Кандидат `0x1464ddec0` исключён из поиска callback: это destructor с записью
другого vptr `0x149cbbb78`, а не действие панели. Соседство записей таблиц
методов не даёт основания продолжать нумерацию slots через границу класса.
