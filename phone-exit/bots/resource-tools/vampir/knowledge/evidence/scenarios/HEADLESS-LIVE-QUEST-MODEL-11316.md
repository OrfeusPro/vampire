# Полученные квесты: изолированная модель и правая панель

26 октября 2026. EXE SHA256:
`d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.
Использован [полный проверенный ID 1854 decoder](HEADLESS-QUEST-SYNC-READER-11316.md).

LiveSession принимает ID 1854 только для явного текущего SHA и известных
character key / world ID. Модель хранит последнее целое сообщение с семантикой
last_received_message / applied_to_local_task=false. Это wire-наблюдение,
не применение native handler и не утверждение об активном задании.
Общий бюджет 128 считает группы вместе с Quest; body ограничено 8192 байтами.
Поэтому при одной группе допустимо 127 Quest. Превышение / decode error очищает
список целиком; частичный результат не публикуется. Unknown и пустое полученное
сообщение различаются. Close / смена мира очищают данные, чужой ключ отклоняется.

API schema 2 выдаёт quests и quest_snapshot из того же owner под его lock,
bot/session IDs. Ключи / uint64 progress / suffix — десятичные строки.
Сохраняются group types, порядок / индексы, raw state / progress и три raw uint32;
повторяющиеся ключи не объединяются по предположению. Каждый snapshot — deep copy.
Нет новых endpoints, подписок, таймеров, команд или хранения raw bodies.

Чистая UI-проекция принимает сообщение только при совпадении character key и
world ID, current semantics, границ и coverage. Правая панель показывает записи
и открывает карточку raw progress. ButtonQuest разрешает просмотр; «Следовать»
остаётся disabled. Временная оболочка / геометрия прежние, новые игровые
callbacks и точность исходного игрового окна не заявляются.

Названия есть в прежнем каталоге Quest_Name_en: например, строка 110110 —
Moving forward. Но raw08 PktQuest ещё не доказан как Quest.Id текущей таблицы;
соответствие ключа экземпляра / ID таблицы и актуальные CSV требуют проверки.
Поэтому сейчас title=null и UI использует «Квест <ключ>». Это временная метка
полученной записи, не подтверждённое название активного задания.
