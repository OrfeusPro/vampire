## Совпадения номеров в локальных счётчиках

Для `0x14649b840` готовый экспорт использован повторно. Дополнительно выгружен
только явный `0x14649b6d0`: функция меняет вложенные локальные maps по двум
byte-ключам в context+0x368. В зависимости от пятого аргумента она присваивает
или прибавляет int, удаляет запись при значении меньше 1. Прямой отправки
пакета в её инструкциях нет. Связь virtual +0xa0 в вызывающей функции
с сетевым ID 1801 не доказана.

Отдельно проверены три кандидата с непосредственным числом 1802:
`0x145f5db10`, `0x14648f620`, `0x1465dff70`. Первый выбирает числовые ключи
по локальному типу и строке и запрашивает счётчик; второй считает подходящие
локальные записи и вызывает virtual +0xa0 с результатом; третий в одной
ветви суммирует счётчики 1802 / 1803 / 1804. Эти экспорты не устанавливают
handler ID 1802 или источник полей ID 1801. Совпадение числа не является
сетевой привязкой. Поведение вызванных helpers целиком не исполнялось.
