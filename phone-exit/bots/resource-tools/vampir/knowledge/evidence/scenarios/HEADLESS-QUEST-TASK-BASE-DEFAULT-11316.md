## Происхождение значения

FindOrAdd 145B4AB90 при отсутствии записи вызывает insert 145B4A420, который
вызывает конструктор 145B48860. Конструктор создаёт временный QuestTask data
на стеке, затем копирует его через 145B4BD20 в node+8. Именно node+8 является
началом data; смещения ниже отсчитываются от него.

Инструкция 145B4888E (`4c63054b7eb203`) читает signed dword по 1496706E0.
Четыре исходных байта по этому адресу: `00000000`, то есть значение 0.
Временный объект начинается с RBP-69; stores 145B488AB, 145B488AF и 145B488B3
помещают значение соответственно в его +8 (sign-extended qword), +10 и +14.
Copy 145B4BD20 переносит эти поля в окончательную запись. Это проверено по
инструкциям целых функций, а не по угаданному типу из декомпиляции.

[Readiness predicate](HEADLESS-QUEST-TIME-TASK-BINDING-11316.md) читает именно
int data+14. Начальное значение теперь связано с конструктором; его смысл
и последующие возможные изменения этим не установлены. Синтетическое значение
3 прежнего Time replay не является значением загруженного задания.

## Проверка загрузки

Расширен существующий native loader/progress replay, использующий текущий CSV
и целые FindOrAdd/insert/constructor/copy/loader/lookup/progress функции.
Для шести строк 110120005, 010, 020, 030, 040, 070 квеста 110120 проверены
поля +8/+10/+14 непосредственно в загруженной native памяти: все равны 0.
Повтор с обратным порядком строк даёт те же значения для каждой записи.
Обе проверки продолжают выполнять 36 проекций прогресса и контроль неизменности
памяти. Подстановка готовых записей вместо конструктора не используется.

Файл CSV и его SHA, границы parser/string/allocation/hash/override fixtures
сохраняются из [loader projection](HEADLESS-QUEST-LOADER-PROJECTION-11316.md).
Тест не запускает настоящий движок и не устанавливает активное окружение.
Проверены шесть указанных записей, не все записи каталога.
