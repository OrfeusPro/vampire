## Исправленная ошибка проверки суммы

Source task901030010 требует одну покупку; выбранный проверенный продукт 10500003
даёт Item 91100005 за 75Gold. Значения проверяются build-shop-binding.py по CSV.
Старый шаблон суммы включал всю надпись Purchase Amount, значок золота и число.
На исходном кадре при стирании только 7 коэффициент совпадения оставался 0.965,
только 5 —0.951: оба выше порога 0.94. Следовательно, отсутствие одной цифры
могло ошибочно разрешить подтверждение.

Теперь подпись и числовой фрагмент — независимые шаблоны shop_amount_label и
shop_amount75. Для числа оставлен небольшой контекст по краям, чтобы
добавленная цифра перед/после 75 не разрешала покупку по подстроке.
Порог 0.94 сохранён. Проверки названия предмета, количества 1 и кнопки Buy остаются
обязательными. Пакет 1.0.8 содержит новый код, но пока не опубликован/не установлен.

## Устойчивость журнала

shop.py до подтверждения записывает reserved, синхронизирует файл, атомарно
заменяет журнал и на Android/Linux синхронизирует родительский каталог.
При ошибке записи/синхронизации Buy не нажимается. Если reserved уже сохранён,
сценарий после перезапуска/обновления проверяет результат, а не покупает снова.
Каталог данных лежит вне версий пакета. На Windows синхронизация каталога
пропущена: эта ОС используется только для воспроизведения, не телефонного бота.
Проверка настоящего fsync на Android и аппаратной перезагрузки ещё не проведена.

## Воспроизводимый прогон

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-shop-templates.py
python -X utf8 phone-exit/bots/resource-tools/vampir/build-shop-binding.py
python -X utf8 phone-exit/bots/resource-tools/vampir/build-window-bindings.py
python -X utf8 phone-exit/bots/resource-tools/vampir/replay-shop.py
python -m unittest discover -s phone-exit/bots -p 'test_*.py'
```

Входные кадры: `F:/PhoneExit Resources/Vampir/phone-tests/shop-901030/`:
guide.jpg, list.jpg, confirm.jpg и session-terminated.jpg. Их SHA256, точные
crop/масштаб/интерполяция шаблонов хранятся в template-provenance.json.
Финальный отчёт — **bot-replay.json**, включая хеши кода/шаблонов, варианты
кадров, результаты tick, планируемые нажатия и состояние журнала перед ними.
replay-shop.py не имеет подключения к API телефона; phone_commands_sent=0.

Прогон вызывает настоящий bot.py с реальными match-результатами OpenCV,
а не вручную выставленными found=true. Адаптер повторяет использованные
операции BotVision (области, округление размеров, scales, CCOEFF/SQDIFF,
маски/edge-template). Неизвестные операции завершают тест ошибкой.

**32 сценария прошли**: восемь случаев на каждом из четырёх вариантов кадра:
100%, 75%, 125% и сдвиг+8/+6 при 100%.

- Обычная последовательность открывает NPC, выбирает предмет и формирует одно
  нажатие Buy. Повторный кадр и перезапуск Python не приводят ко второй покупке.
- При отсутствии 7,5, количества или Small в названии формируются только два
  подготовительных нажатия; Buy не формируется, затем возвращается ошибка ожидания.
- Добавленный исходный глиф 1 перед или после 75 также блокирует Buy.
- KICKOUT_FOR_INSPECT останавливает сценарий без нажатий при всех четырёх вариантах.

Отрицательные изменения синтетические: стирание фрагментов и вставка исходного
глифа. Их координаты/порог записаны в negative_mutations; это не наблюдавшиеся
игровые цены или окна. Исходные скриншоты не перезаписываются.

## Масштабы и ограничения

Для шести текстовых элементов добавлены резервные образцы от полных кадров,
уменьшенных/увеличенных OpenCV INTER_LINEAR. Итого 24 шаблона с происхождением.
У каждого варианта собственный reference_size; bot.prepare_templates считает
масштаб от него, без повторного умножения при смене кадра. Альтернативы
проверяются только после неудачи основного шаблона; глобальный порог не снижен.
Это проверка устойчивости изображений, не восстановленная формула DPI и не
доказательство совпадения шрифтов на любом телефоне или при любой UI-настройке.

Desktop OpenCV4.13.0 отличается от Android 4.12.0. Положительного кадра успешной
покупки пока нет, поэтому финал прогона — purchase_outcome_unknown, а не успех
квеста. Полный цикл, фактический расход 75Gold, получение предмета, выдача награды,
время цикла телефона и автономность ещё требуют живой проверки.
По выбору пользователя работа продолжается на сохранённых кадрах;
окно отключения сессии на телефоне автоматически не закрывается.
