Для явного chained root `0x14575ee40` получен Ghidra export одной функции.
Начальные инструкции используют DX как номер пакета, затем ветвятся по нему,
выделяют память и переходят в соответствующие constructors. В псевдокоде
ветвь 0x709 / 1801 выделяет 0x20 байт и создаёт таблицу `0x149966f30`
с byte +0x10 = 0 и qword +0x18 = 0. E9-кандидат `0x1457630a0` относится
к этой общей фабрике, а не к найденному вызову из квестового интерфейса.

Это статическая привязка. В большом экспорте есть предупреждения о bad
instruction data, overlapping instruction и удалении недостижимого блока;
полная корректность всех ветвей фабрики не заявляется. Она не исполнялась
native replay. Отдельный constructor ID 1801 и его reset-поля уже проверены
целым native replay в предыдущем исследовании.

Источник параметров штатного запроса, его producer / lifecycle и handler
ID 1802 по-прежнему неизвестны. Фабрика не подтверждает, что клиент отправляет
именно 0 / 0 после ID 206. Допустим отдельный явно названный диагностический
эксперимент с reset-полями: одна отправка, ограниченное ожидание, без повторов;
это локальная политика исследования, а не восстановленный игровой UI.
Его принятие и содержание ответа необходимо проверить отдельно на сервере.
