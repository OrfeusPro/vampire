## Формат ответа

Constructor `0x14584d0a0` устанавливает vptr `0x14996ba48`, обнуляет code,
вызывает constructor вложенной записи `0x1457fee50` и обнуляет два флага.
Getter `0x1458571a0` возвращает 9904. Reader `0x14584f890` читает code,
затем через `0x144aae4e0` вызывает nested virtual +0x20, после чего читает флаги.
Вложенная запись имеет vptr `0x14992afc0` и уже проверенный reader `0x1457ff150`.

| 0 | uint32 little-endian, code | +0x10 |
| 4 | uint32 little-endian, raw08 / ключ | +0x20 |
| 8 | uint32 little-endian, raw0c / селектор | +0x24 |
| 12 | uint32 little-endian, raw10 | +0x28 |

Всего 19 байтов без ID и frame. Переносимый decoder `tutorial_result.py`
требует точный размер и текущий source SHA. Смысл raw10 и имена состояний /
флагов не присваиваются по одному wire layout.

Native replay исполняет целые packet / nested constructors, getter, result /
nested / scalar readers. 216 векторов покрывают коды 0 / 4223 / 0xffffffff,
нулевые / различные / граничные поля, state 0 / 1 / 2 / 3 / 4 / 255 и четыре
сочетания флагов. Все поля совпали с decoder. Все 19 коротких префиксов
отклонены без чтения за доступные байты. Базовый memcpy ограничен fixture;
выделение памяти и приложение состояния здесь не нужны и не исполнялись.

## Handler и два разных ожидания

В повторно использованной регистрации `0x1467b62f0` вызов constructor находится
по `0x1467c2250`, регистрация — `0x1467c2263`, handler vptr — `0x149dc72d0`.
Его slot +0x10 указывает на `0x1467cabc0`.

Handler сначала получает контекст и вызывает `0x1464c19e0`. Это короткая
функция без unwind-записи: при ненулевом byte context+0x308 она обнуляет его
и переходит в `0x145692af0(1)`; при нуле возвращается сразу. Смысл режима UI
ещё не установлен. Проверены точные 24 байта функции с обеими ветвями.

Затем handler вызывает общий gate `0x1467cee40` с code / ID 9904. При допуске
передаёт пакет в `0x1464c06d0(context, packet, 0)`. При отказе gate код 4223
ведёт в отдельный producer `0x1464c16d0(context, key, 1)`; прочие проверенные
коды не вызывают эти два пути. Название кода 4223 и смысл producer не установлены.
Автоматически повторять запрос либо воспроизводить эту дополнительную отправку нельзя
до проверки её условий и ответа.

45 native-сценариев исполняют целый handler и функцию сброса ожидания:
коды 0 / 1 / 4223 / 9400 / 0xffffffff, три ключа, исходное ожидание 0 / 1 / 255.
Проверены порядок вызовов, обнуление +0x308 до gate, ID, аргументы применения и
специальной ветви. Context lookup, UI mode, gate, применение и специальный producer —
явные fixtures. Gate fixture допускает только code 0; native-политика общего gate
для остальных кодов этим экспериментом не проверена.

Статический receiver `0x1464c06d0` при состоянии клиента `<6` сохраняет копию
пакета в очередь. При применении вызывает `0x141682d60(context+0x268, key)` —
кандидат на удаление ожидающего ключа; эффект helper ещё подтвердить.
Затем переносит запись в map состояния и обновляет локальную задачу. Флаг +0x31
участвует в выборе сохранения селектора или перехода к следующему; реальный gate
задачи остаётся отдельным условием. Эти внутренности receiver не исполнялись.
Ghidra показывает shared branches далеко за коротким начальным диапазоном:
не считать весь разросшийся псевдокод границами короткого wrapper.

Поэтому сброс общего ожидания +0x308, удаление ожидающего ключа и фактическое
выполнение шага — разные события. Полученный / прочитанный ответ ещё не доказывает
применение состояния. В runtime decoder пока не подключён к отправке или
автоматическому завершению обучения.
