# Начальный снимок обучения и первый локальный переход

Продолжение [очереди и начального ID 9905](HEADLESS-TUTORIAL-QUEUE-DRAIN.md).

## Исполнение начальной цепочки

`replay-release-tutorial-startup.py` исполняет в одном эмуляторе:

- `0x1464c4ba0`: обработку непустого снимка ID 9905;
- `0x1464a1460`: настоящие stores записи и включение в hash chain;
- `0x1464c67e0`: сверку ключей в случае, когда удаляемых записей нет;
- `0x1464cfeb0` / `0x1464d0510`: построение набора статусов и обход локальных задач;
- `0x1464cd6f0`: локальный переход;
- `0x1464c5770`: настоящую раннюю ветвь допуска с возвратом AL=0;
- `0x14142e7d0`: обход allocation bits наборов.

192 сценария покрывают 0 / 1 / 16 уникальных записей, найденные / отсутствующие
строки таблицы, row+0x50 0 / 1, state первой записи 0 / 1 / 2 / 3,
selector 0 / 1 и оба значения флага уведомления. В профиле 16 записей использованы
ключи из сохранённого живого наблюдения: 1001 и 15 других. Прочие состояния
равны нулю; raw10 содержит синтетические различные значения для проверки копии.
Это fixture, не новая живая сессия.

Для найденных строк серверный map получает все входные поля настоящим кодом,
включая raw10. При отсутствующих строках записи не добавляются. Пустой массив
не запускает начальную цепочку. На свежем локальном map и в проверенных условиях
row+0x50 <2 только первая запись со state 1 создаёт локальную задачу.

Group descriptor задаётся fixture с полем +8, равным 2. Для selector 0 / 1
и state 1 настоящий gate возвращает AL=0 до ветвей завершения. Локальный selector
увеличивается до 1 / 2, state остаётся 1, raw10 сохраняется; затем вызывается
fixture запуска задачи. Серверный selector не увеличивается вместе с локальным.
Флаг уведомления не подменяется командой завершения обучения.

### Границы

Table lookup / group descriptor, выдача новых ячеек map / набора статусов,
cleanup временных наборов, security-cookie helper и запуск задачи — fixtures.
Копирование полей, hash linking, итерация, построение статусов и ранний gate
не заменены Python-логикой. Подготовленные buffers / hash buckets исключают рост.

Проверены свежие уникальные снимки без существующих локальных задач.
Замена дублированного ключа, rehash, удаление отсутствующих в снимке записей,
ветви завершения gate и побочные эффекты запуска не исполнялись.
Row+0x50 и descriptor+8 ещё нельзя получать произвольным переименованием CSV.
Проверка не устанавливает активный экран пользователя или соответствие native
готовности событию ID 206. Вход и игровые команды не выполнялись.

## Найденные функции именованных полей

По точным ASCII литералам `UIEnteredStartStep` (`0x149a1a510`) и
`ServerProcessRequest` (`0x149a1aac0`) найдены функции изменения ячеек кэша:
`0x145c46830` для Tutorial и `0x145c46d20` для TutorialStep.
Они ищут запись по ключу, сравнивают имя колонки, записывают значение и вызывают
virtual callback соответствующего свойства. Это не доказательство полного
первоначального CSV loader или выполнения callbacks.

Статически подтверждены присваивания в объект строки TutorialStep:

| Колонка | Поле строки |
| --- | --- |
| TutorialId | dword +0x0c |
| Step | dword +0x18 |
| ServerProcessRequest | byte +0x1c |
| TaskType | byte +0x30 |
| TaskParam | FString +0x38 |
| SkipButtonMove / SkipButtonHide | byte +0x48 / +0x49 |
| ArrowHide / CloseAllPopUp | byte +0x4a / +0x4b |

Это связывает имена TutorialId / Step / ServerProcessRequest с полями, уже
прочитанными в поиске строки, инициализации задачи и producer ID 9903.
Для TutorialId есть дополнительная проверка связи через `0x145c48af0` и
rollback при отказе. Остальные callback-эффекты ещё не проверены.

В Tutorial поле Type записывается в byte +0x0c, ActivateType — в byte +0x20,
ActivateClass — в byte +0x38, UIEnteredStartStep — в dword +0x3c,
RemainWorld — в byte +0x40. Следовательно, условие startup по dword row+0x50
не является прямым чтением Type из CSV. Его происхождение ещё установить.
Также не установлено получение timer-параметра row+0x60 из TaskParam.
