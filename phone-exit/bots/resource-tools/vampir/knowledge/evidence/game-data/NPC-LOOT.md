## Подтверждённая цепочка

Диагностическая строка EXE, byte offset **161149426**, явно объявляет:
`Reward/Npc_Reward.xlsx / NpcReward.GroupId → Npc/Npc_Basic.xlsx / Npc.Id`.
Текст, смещение, путь и SHA256 EXE сохранены в `index.json:native_source`.
Перед сборкой SHA EXE сравнивается с обоими существующими отчётами доказательств.

NpcReward. RewardType=12 ссылается через RewardParam на группы Reward. GroupId;
все 2055 таких записей имеют найденную группу. Их 681 различных значений,
10868 строк группы в этом снимке, все с Type=1 и найденным Item. Id в Param.
Названия ERewardType/ERewardGroup взяты из ранее извлечённых native enum.
Структурные связи и исходные поля сохранены; серверный механизм розыгрыша
по этим данным не исполняется.

| Данные | entry pakchunk1-Windows | Количество |
|---|---:|---:|
| Npc / NpcName_en | 1544 / 481 | 5285 / 5518 |
| NpcReward | 1415 | 4534 строки, 941 NPC |
| Reward | 1475 | полный источник 96102 строки; экспортируются связанные группы |
| Item / ItemName_en | 194 / 462 | 5827 / 7593 |
| Asset | 19 | 78 |
| NpcSpawn | 1546 | 61307 |
| AreaRewardCandidate | 11 | 1655, отдельно от подтверждённой добычи NPC |

Для NPC без строки NpcReward показано «не найдены данные клиента», а не
«ничего не выпадает». Группы региональных наград entry11 сохранены и раскрыты
в отдельном файле, однако привязка GroupId → Area не доказана native-связью;
автоматически добавлять их к каждому монстру области нельзя.

## Изображения

- Каталог содержит **3615** ресурсных путей `/Texture/Image/Item/`, включая
  41 дополнительно декодированную FloatRGBA-картинку. Есть отдельные режимы
  «все предметы», «все изображения» и «добыча выбранного NPC».
- В подтверждённых NPC-группах **793** разных Item. Id. Для **790** найдено
  единственное точное совпадение Img с именем ресурса, для **2** есть несколько
  полных путей — показаны все кандидаты, выбор не делается.
- Для **1** изображения совпадения пока нет: Item. Id **11042015**,
  Img **IMG_Weapon_Orb_UnCommon_16**. Точного имени нет и в доступных entries.json;
  это не доказывает отсутствия файла во всей установленной игре/Android.
- У остальных предметов общего справочника могут быть незаданные/ненайденные
  изображения; статус хранится у каждой записи, заглушки не выдаются за ресурс.
- Выбор патча по `_sN` применяется только внутри одного полного пути и остаётся
  предварительным до проверки manifest/Android. Разные пути не объединяются
  из-за одинакового basename. Хеши всех 3615 PNG проверяются при сборке.

Дополнительный decoder `export-float-icons.py` читает **PF_FloatRGBA** как
little-endian RGBA16F и проверяет размеры, полный mip, конечность значений
и диапазон [0,1]. Сохраняет PNG после linear→sRGB и отдельный direct PNG;
alpha не гаммируется. HDR/NaN не обрезаются молча — обработка отказывается.
Сохраняются SHA uasset/uexp/исходных пикселей, mip offset, PAK/entry/offset.
Результаты: `item-icons-float/index.json`. Это проверенное декодирование байтов;
настройка цветового пространства Unreal и точный цвет Android ещё не сверены.
Картинки помечены `color_verified=false`. Из 21 первоначально пропущенной
иконки NPC-предметов восстановлены 20; остальные 21 из 41 относятся к общему
справочнику предметов, не прямым NPC-группам.

## Шансы

Поля **RewardRate**, **Rate**, **AcquisitionGroupType**, **AcquisitionMethodType**,
**MinValue/MaxValue**, **RewardGroup**, **RandomEachEffect**, **DropMethod**,
**IsHotTimeEventReward ** и ограничения сервиса сохраняются без изменений.
Пробел в конце имени последнего CSV-поля сохранён намеренно.

В native enum есть Fixed/Random/RandomEach и другие режимы. Одного имени и
числа недостаточно для доказательства знаменателя, числа попыток, состава
пула и модификаторов сервера. Поэтому проценты **не рассчитаны**, нигде не
используются Rate/100 либо Rate/sum как якобы подтверждённый шанс выпадения.
`chance_percent=null`, `chance_percent_verified=false`.
Строки разных групп/способов выдачи не объединяются в одну вероятность предмета.
Это каталог доступных параметров клиента, не обещание текущего дропа сервера.

## Файлы и воспроизведение

`index.json` — источники, NPC, проверки полноты; `items.json`, `assets.json`,
`reward-groups.json`, `item-images.json` — общие справочники;
`npcs/<Id>.json` — исходные строки конкретного NPC и размещения по мирам/областям.
Каждая строка имеет таблицу/entry/номер CSV-записи; исходный CSV SHA и смещение
в PAK находятся в `sources`. Числа записей — не byte offsets.
Исходные ключи/условия не подменяются интерпретацией. Массовые файлы вне Git/APK.

## Продолжение: загрузка rates и обратный поиск, 17 октября

Генератор `build-loot-rate-evidence.py` воспроизводимо проверяет EXE SHA256,
три именованных загрузчика, полные шесть unwind-фрагментов, точные литералы,
инструкции чтения/сохранения, CSV SHA/схемы и PE import-name таблицу.
Вывод: `code-clues/loot-rate-evidence.json`; компактная копия для просмотра
`maps/loot/rate-evidence.json` (хеш в индексе).

| Таблица | Native Load | Поле | Смещение объекта | Инструкция сохранения |
|---|---|---|---|---|
| AreaReward / entry11 | 0x145b67fb0 | RewardRate | +0x38 | 0x145b686f1 |
| NpcReward / entry1415 | 0x145b6b950 | RewardRate | +0x48 | 0x145b6c0e8 |
| Reward / entry1475 | 0x145b70fc0 | Rate | +0x50 | 0x145b71806 |

Все три пути вызывают accessor0x1445ef9f0, который выбирает 32-байтный
строковый слот CSV и передаёт его 0x1445eb010. Тот через PE import slot
0x148945bf8 вызывает **atoi** из api-ms-win-crt-convert-l1-1-0.dll.
Это подтверждённая импортом конвертация, не догадка по поведению.
Результат EAX сохраняется в 32-битное поле; в этих последовательностях нет
деления/нормализации процентов. Названия AreaReward.csv и
FRdAreaRewardInfoManagerTemplate::Load теперь доказаны точными литералами;
GroupId→Area по-прежнему не доказан. Отдельные конвертеры типов получения,
дальнейшие callbacks полей и серверный розыгрыш не восстановлены.

Полная таблица Reward: Rate1..590000000,27 пустых записей, 4 дробных значения
37.500000 в GroupId57401500 (Reward. Id57401512..57401515). Эта группа не входит
в найденные NPC-цепочки. NpcReward: 45..10000 и 2 пустых поля; AreaReward: 4..10000,
пустых 0. Исходные текстовые числа сохранены, atoi не заменён Python float.
Подтверждение atoi относится к загрузке Windows и не устанавливает формат
чисел либо вероятности на сервере. Вычисление процентов остаётся выключенным.

Циклы и отсутствующие группы диагностируются; разные способы/строки не
объединяются. Все 35211 цепочек проверены против производных исходных групп

## После загрузки rates и точные размещения, 17 октября

`build-loot-record-links.py` продолжает путь из Load: поиск/создание записи →
инициализация → copy-конструктор с записью vtable → виртуальный callback rate.
Проверено 24 опорных инструкции в 12 unwind-фрагментах; источники и SHA EXE
в `code-clues/loot-record-links.json`, компактная копия `maps/loot/rate-callbacks.json`.

- NpcReward: Load0x145b6b950 → lookup 0x145b59a70 →0x145b58940 →
  init0x145b57b10 →copy0x145b5ae40 →vtable0x1499b01c0.
  После записи RewardRate+0x48 вызывается слот 0x58.
- Reward: Load0x145b70fc0 →lookup 0x145b59c80 →0x145b59750 →
  init0x145b57dc0 →copy0x145b5b8d0 →vtable0x1499aed48.
  После записи Rate+0x50 вызывается слот 0x70.
- Оба слота содержат 0x1413fe190, точные байты **c2 00 00** (`ret 0`).
  В этих двух callbacks нет нормализации и розыгрыша. Это не доказывает
  отсутствия других потребителей полей, других runtime-типов или серверной логики.
- При создании объект копируется в map-record+8; это смещение подтверждено
  инструкциями передачи и не прибавляется к WorldXYZ/GUI-координатам.

Наблюдаемые методы проверки целостности/загрузки имён не названы функциями
розыгрыша. Их исследовательские выгрузки loot-*-discovery.json в code-clues
являются рабочими зацепками, не самостоятельными подтверждёнными связями.
Формула вероятности после этой работы по-прежнему не установлена.

## Карточка выбранного монстра, 17 октября

В большой карте выбор NPC открывает дроп с иконками, количеством из исходной
строки и всеми условными цепочками. Для каждой карточки доступно «Все источники».
Повторные размещения одного NPC не требуют выбора в группе; разные NPC с одинаковым
именем остаются отдельными кнопками с ID, уровнем и числом предметов.

Добавлены HP, AttackPower, DefensePower из Battle CSV1545 (5205 строк).
Цепочка Npc. BattleGroupId→Battle. GroupId подтверждена native-диагностикой ссылки
в table-dependencies.json (offset 161052610), её байты и SHA EXE проверяет
`build-monster-details.py`. Это клиентские базовые характеристики. Не выводится
придуманная семантика для Aggressive/Attribute/Type. Прочие боевые параметры и
ID навыков доступны в раскрываемой исходной записи. Для 1785NPC найдены Battle;
у 2NPC несколько вариантов — показаны все, ни один не выбран автоматически.

Рядом с дропом показаны исходные строки опыта/золота/других наград. Их значения
не объявлены гарантированными. Для NPC 200052 Void Chronicler: HP24318, атака 1537,
защита 0;29 предметов; опыт 12040, Gold158–192, EventDiamond1. Это значения строк
клиента, не итог за каждое убийство. Проценты по-прежнему неизвестны.

Иконки/количество не объединяют условные исходы: например, InvasionCoin имеет
варианты 1–2 и 10, они не складываются. Количество указано как «Кол-во в строке»;
множители вложенных групп и условия получения ещё не вычислены. По каждой
цепочке сохранены RewardRate, Rate, AcquisitionGroupType/MethodType, RewardGroup,
NpcRewardId, Reward-chainID и происхождение CSV. Отсутствие строк отображается
как «Дроп: данных нет», не как доказанное отсутствие добычи.

Размещения выбранного NPC доступны отдельным списком, радиусы/квестовые условия
видимости читаются из NpcSpawn и сохраняются вместе с остальными полями.
Новые данные загружаются по выбору монстра: `monster-manifest.json` и
`monsters/<NPC-ID>.json` с SHA. Не требуется загружать все 1785 карточки сразу.
Сборщик общей карты автоматически вызывает build-monster-details.py.
