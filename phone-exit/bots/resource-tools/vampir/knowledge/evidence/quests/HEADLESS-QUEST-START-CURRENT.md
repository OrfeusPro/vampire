# Реальное начало квеста 110110

7 ноября 2026. Клиент 1.13.22, SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
После сообщённого пользователем перезапуска ПК прежний loopback-владелец
отсутствовал. Bipoberiho на Canon 1 вошёл через новый независимый процесс.
Наблюдатель обновлений не включался. Другие аккаунты не запускались.

Выполнена одна явная команда QuestStart `1803` для `110110`. Получен полный
`1804`, code `0`, совпадающий ключ и одна запись квеста со state `2`, индексом
прогресса `0`. Ошибок чтения и несовпавших ответов нет. Персонаж остаётся онлайн.
Это начало задания, а не его завершение или прохождение первого Time-шага.
[Живой результат](QUEST-START-CURRENT-ONLINE.json).

До перезапуска другая сессия показывала state `1`. В новом владельце отправка
разрешена только по свежей единственной записи state `1` или `3`. Само исходное
значение новой записи не сохранено отдельно: нельзя выдавать прежнее наблюдение
за захват состояния непосредственно перед этой отправкой.

## Проверенная цепочка

`1455c9dc0` формирует именованное поле QuestInfoId и запись очереди с selector `0`.
`145d887c0` передаёт записи по `0x58` байт в `145d72d80`. Ветка selector `0`
проверяет pending `1804`, находит Quest и создаёт `1803` через `145828d70`.
Исходящий пакет содержит один uint64 QuestInfoId. Selector `1` относится к
обновлению `1810`, а не к началу. Selector события и серверное state различаются.

Целый predicate `145df9910` при остальных разрешённых условиях принимает
состояния модели `1` и `3`. Статически проверены enqueue, автоматический caller
`145d92400`, отдельный UI caller `14678d980` и групповое применение `145d95990`.
Это не восстановленная полная логика нажатия квестовой строки.

Ответ `1804` имеет uint32 code, uint64 key и вложенный QuestData. Он использует
тот же reader `1457a6a70` и таблицу `14994b730`, что подтверждённый текущий
QuestSync `1854`. Это коллекции групп и записей с suffix, а не отдельный Progress.
Сохранённый parent proof текущего INPUT переиспользован с полными SHA и входами.
Новая внешняя обёртка проверена отдельно с явным nested provider.

137 сценариев и 233 вызова Win64 проверяют request wire, внешний reader ответа,
producer и условия начала. Native исполняются шесть whole roots и два leaf
конструктора; четыре дополнительных whole exports проверяются статически.
Constructor вложенного QuestData также исполняется через result constructor.
JSON / named fields, pending, Quest row, level, predecessor, condition, model
lookup, отправка и nested INPUT boundary имеют явные providers.
Эти fixtures не подтверждают настоящий UI или engine effects.
[Контекст](../../native-contexts/quest-start-current.json),
[проверки и SHA](QUEST-START-CURRENT-VALIDATION.json).

Первый collect получил шесть новых exports. Следующий сохранил псевдокод,
но отклонил handler: его tail выходил за выбранные unwind ranges. Повтор с
зафиксированной причиной исключил этот root из native-области; handler остаётся
точным статическим окном. Проверка границ не отключалась, частичный report не
подставлялся вместо завершённого. Последующий scoped collect использует готовые
материалы без JVM.

## Владелец и допуск

Schema `3` ограниченного world-пакета добавляет отдельный proof и policy
`quest-start-manual-v1`. Обычная сборка пакета schema `2` не разрешает начало.
Сохранены проверка точного клиента, полный набор входов и атомарная публикация.
Работающий владелец сохраняет пакет, с которым вошёл.

`--manual-start-quest` разрешён для одного аккаунта. Owner ждёт успешного входа
в мир и свежей записи соответствующего персонажа / мира. Очередь использует
текущие key / sequence; partial send и backpressure не порождают повтор.
Подтверждение требует полного socket acceptance и совпадающего `1804` в срок.
Повторный ответ, другой ключ / мир, смерть, смена мира, повреждённый ответ,
Stop и неизвестный исход не запускают вторую команду. Перевхода по таймауту нет.

Из корня проекта, с уже подготовленным selector и сохранённым account ID:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/build-bounded-world-current.py --manual-quest-start
python -X utf8 phone-exit/bots/vampir-headless/run-bounded-world.py --account $accountId --profile $selector --manual-start-quest 110110 --port 49152 --detached
```

Обе команды относятся к следующему явному запуску. Текущую онлайн-сессию ради
проверки команд не заменять. Закрытие Codex не завершает независимого владельца;
перезапуск ПК завершает процесс и TCP-соединение. Автозапуска Windows нет.

Отдельный `quest-start-current` включён в штатные `on_update`, guard, tooling-группу
и кэш и связан с существующим контрактом `quests` в
[реестре контрактов](../../update-contracts.json). Он проверяет границы допуска
и воспроизводимый текущий контекст.
Поиск контекста следующего SHA остаётся отдельным пробелом; старые адреса для
нового EXE не допускаются. Готовая матрица вложенного INPUT повторно не исполняется.

## Что осталось для выполнения шага

Квест начат, текущий серверный индекс — `0`. Для первого `110110010` нужен
current Time callback / timer / readiness и provider `1810`. Исторический
Time replay и текущие загрузчики использовать повторно; переносить только
недостающий контекст. Вектор `1810` берётся из actor component либо отдельной
source fallback-ветви, а не из QuestActionPos CSV. Семантику fallback и допустимые
аргументы проверить явно. Далее следуют Time, диалог, обучение, движение и переход
между мирами. Их серверное выполнение этим пакетом не заявляется.

В живом пакете допущено только ручное начало. Новые исполнители не внедряются
в память работающего процесса. Сохранить соединение и сначала подготовить
следующий воспроизводимый пакет действий.
