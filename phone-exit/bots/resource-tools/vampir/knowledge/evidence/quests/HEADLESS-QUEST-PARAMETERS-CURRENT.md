# Параметры задания: передача в разборщик и числовой доступ

6–7 ноября 2026. Клиент 1.13.22, SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
Пакет продолжает [выбор группы диалога](HEADLESS-QUEST-DIALOGUE-CURRENT.md).
Готовые экспорты трёх переходников использованы повторно; два общих корня
получены одним scoped collect. Два callback-адреса оказались пятибайтными
прямыми переходами, их байты и цели проверяются без повторного экспорта.
[Машинный контекст](../../native-contexts/quest-parameters-current.json).

## Передача параметров

126 native-сценариев исполняют factory `145566ad0`, переходник задачи
`1455d2620` и общий dispatcher `1445d3a50`. Проверены выделение объекта / reader
с отказами, virtual provider из task `+0x40` / slot `+0x38`, создание capture,
успех / отказ десериализации, передача полученного JSON и оба callback.
Переходы `1455642a0 → 14555dd70` и `1455b5820 → 1455b0040` исполняются;
getter capture `14140e350` также взят из точных байтов клиента.

Выделение памяти, reader constructor, JSON deserialize, сброс task,
деструкторы и конечные потребители представлены fixtures. Очистка lambda
фиксирует границу без освобождения capture. Проверены native-счётчики reader
и JSON control, аргументы, однократность callback, сохранность входов и guards.
Это структурная передача параметров; выбор активной задачи и внутреннее
исполнение её потребителя здесь не доказаны.

## Числовое поле

436 сценариев исполняют целые accessor `1445cd610` и scalar reader `1415eb520`.
Покрыты отсутствующее / null поле, UTF-16 ключи, невыровненный output,
дробные и предельные значения int32, NaN / Inf, отказ числового provider
с записью и без записи. Реально исполняются inc / dec shared control;
поиск JSON, virtual `TryGetNumber`, сообщения об ошибке и деструкторы — fixtures.

Accessor возвращает признак наличия поля в AL. Он не является признаком
успешного `TryGetNumber`: при отказе без записи получается исходный ноль,
а запись перед отказом всё равно проходит через native `CVTTSD2SI`.
Непредставимое значение даёт `INT_MIN` при проверенном режиме MXCSR.
Возвращаемый RAX целиком не трактуется как bool.

Конкретный строковый JSON provider не исполнен, поэтому 150 сценариев
со строковым `classInfoId` остаются с исходным значением и открытым преобразованием.
Fallback allocation самого scalar reader тоже остаётся за границей проверки.
Для всех 562 вызовов проверены Win64 ABI, границы чтения / записи и стек.

## Обновление и оставшийся путь

`quest-dialogue-current` включает новый proof как дочерний результат, со всеми
зависимостями и экспортами. Текстовый граф и прежняя матрица выбора группы
используют сохранённые результаты. Неизменный повтор проверяет полные SHA
и завершающий барьер входов без новой native-эмуляции и JVM.
[Приёмка и точные manifests](QUEST-PARAMETERS-CURRENT-VALIDATION.json).
Проверка ограничена указанным SHA; автопоиск контекста следующей версии открыт.

Действующий Bipoberiho сохраняет прежнюю сессию. Этот пакет не публикует
`offer_quest_step`, не разрешает отправку 1810 и не подтверждает действие по 1811.
Следующий общий пакет должен связать упорядоченные QuestTask и progress index
с настоящей задачей, затем проверить вид действия, TargetId, readiness,
актуальную позицию владельца и ожидаемый переход. Диалоги дополнительно требуют
активной реплики, выбора ответа и поведения пропуска. После отдельного допуска
provider / action остаётся живой квестовый сценарий.
