# Русские названия квестов текущего клиента

Источник EXE 1.13.22, SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
PAK `pakchunk1-Windows.pak`, SHA256
`2f2517ff83865ac13021f96d9babd8407e4fbee512ff29806106844e5d7d7ed3`.

## Что подключено

Общий прототип распознаёт 1 341 русское название и описание цели для этого
SHA. Например, 110110 — «Движение вперед», 110120 — «Зов крови». Двенадцать
неоднозначных ID остаются с подписью «Квест ID»; первый / последний перевод
не выбирается произвольно. Неизвестная версия также не получает название
из другого SHA.

Именованные таблицы взяты из уже проверенного каталога PAK:

- `ProjectRED/Content/RED/Data/CSV/Quest.csv`: 1 353 записи,
  SHA256 `f9b941f557103b79918b362aaeec0c50796631dedf1d5b6ab4d4092651ba74c2`.
- `ProjectRED/Content/RED/Data/CSV/L10N/ru/Quest_Name.csv`: 1 691 запись,
  SHA256 `c0215204ed57b9eec79f527a66935392a9a493cc624ad0d7aee019f1c46b5577`.

Текущий именованный PAK proof удерживает directory identity и точные CSV payloads.
Новая проверка сверяет архив, аутентифицированный индекс, производители / runtime,
два CSV и связь ID. Payloads совпали с каталогом 1.13.16, поэтому новый маленький
`quest-names-current.js` использует те же неизменяемые объекты строк.
Это переиспользование одинаковых данных после нового доказательства;
старый EXE не объявляется текущим. Полного повторного извлечения PAK нет.

## Привязка входящего ID

Сохранённый current receiver `145d84e70` читает qword записи по `+08` и передаёт
его в `145de69f0`. Проверен только явный forwarding prefix этого wrapper.
Current named producer `145d72d80` получает property `QuestInfoId`, сохраняет
возвращённый ключ и передаёт его в тот же lookup `145b4bf30`.
Инструкции полных экспортов receiver / producer сверены с точными байтами EXE.
ID 1854 и portable key field используют готовый packet-observation proof.

Существующий receiver export переиспользован; для named producer получен один
недостающий экспорт. Завершающий scoped `collect` использовал готовые материалы
без новой JVM. Native сценарии входящих пакетов не исполнялись повторно.

Полный chained wrapper, применённая модель задания, активный индекс, текущая
позиция actor и отправка действия этой проверкой не доказываются.

## Проверка и обновление

`verify-quest-labels-current.py --write` явно генерирует маленький адаптер;
обычный запуск сверяет результат. Неизменный повтор использует композиционную
квитанцию после проверки всех SHA, без PE / key-binding / catalog / renderer replay.

Клиентская проверка `quest-labels-current` включена в `on_update` через
`entry-package-check-guard`; tooling test зарегистрирован в `MODULES`, отдельной
группе и общем gate. Контракт представления — данные `quests`, уже объявляющий
ресурсы `*Quest*`. Его частичное покрытие и допуск игрового выполнения не расширены.

Поддержка ограничена зарегистрированным контекстом этого SHA и архива. Новый
layout, другой архив, несовпадающий каталог или неоднозначный key binding дают
конкретный отказ; автоматический поиск / регистрация контекста для следующего
EXE и публикация изменившихся текстов ещё не завершены. Готовая механическая
проверка и генератор повторного ручного разбора неизменных функций не требуют.

Проверены текущий / прежний / неизвестный SHA, неизвестные и неоднозначные ID,
передача названия через общую live-модель, неизменяемость строк и отказы на
изменённых доказательствах. Итоговые квитанции и кэш —
в [приёмке](QUEST-LABELS-CURRENT-VALIDATION.json).

## Онлайн и дальнейшая работа

Новый каталог включён в исходники прототипа и снимок следующего запуска панели.
Работающая панель сохраняет прежний снимок ресурсов: её перезапуск командой
отклонён автоматической проверкой разрешений. Доставка в эту уже запущенную
панель остаётся непроверенной; игровой процесс не останавливался.

Текущий Bipoberiho сохраняет прежнего владельца. Он пока не публикует список
квестов, поэтому русское название в его настоящем списке ещё не проверено.
Тест общей модели использует явно синтетический snapshot и не выдаётся за
сообщение сервера. Соединение ради названий не разрывалось.

Открыты привязка настоящих диалогов / вариантов ответа и provider выбранного
шага с подтверждением результата. Каталоги `Dialog_Name` / `DialogChoice_Name`
найдены в ресурсах; наличие фразы не означает, что персонаж получил её сейчас.
