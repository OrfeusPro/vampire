# Загрузка и порядок задач квеста 110120

Клиент 1.13.22, SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
Проверка продолжает [модель задачи](HEADLESS-QUEST-MODEL-CURRENT.md) и использует
готовые именованные `QuestTask.csv` и `L10N/ru/QuestTask_Name.csv` из текущего
`pakchunk1-Windows.pak`. В контексте закреплены SHA архива, таблиц и полных
экспортов. [Контекст](../../native-contexts/quest-loader-current.json).

## Порядок массива и локализация

Текущие загрузчики `145b5f680` и `145b6a0b0` обрабатывают шесть исходных строк
квеста 110120. Lookup `145b4c280` и проекция `145de7870` читают записи и массив
указателей, созданные загрузчиками в той же памяти. Сценарий меняет порядок
входных строк и проверяет связь индекса с записью, типом и счётчиками прогресса.
При прямой загрузке индекс 0 даёт `110120005`, при обратной — `110120070`.
Русские названия проверяются после применения override, параметры исходной
задачи сохраняются.

Прошли 36 проекций и 38 проверок Win64 ABI. Сценарий исполнил 21 функцию
целиком и 14 коротких фрагментов. Проверены границы записей, порядок указателей,
контрольные байты входов и выходов, сохранность массива и точные количества
входов в исполняемый код и providers.

У всех шести строк пустой `ServerServiceGroupId`. Исполняется ветка фильтра
`145a4d700` для пустого значения. В Ghidra переход `145a4d732` к отдельной функции
`145c03670` учтён как tail call по точным байтам и unwind-границам. Эту ветку
понадобится исполнить в следующем пакете для непустой группы.

Русский override читает настройки по `+0x1ec` и `+0x1ed`, тогда как в 1.13.16
использовались `+0x1e4` и `+0x1e5`. В сценарии значения нулевые. Чтение файла,
заголовок, аллокация, хеширование и связанные операции со строками используют
ограниченные providers. Активная локаль, установленные значения настроек,
полный порядок каталога и выбранный сервером шаг остаются открытыми.

## Повтор после обновления

Штатная проверка `quest-loader-current` выбирается для точного SHA клиента.
Кэш сверяет EXE, текущий PAK, два CSV, экспорты, код и среду выполнения.
Три готовых экспорта использованы повторно. Финальная сборка материалов
взяла все функции из уже сохранённых экспортов без новой JVM.
При несовпадении входа требуется новое доказательство для этой зависимости.
Результаты штатного прохода и повтора записаны в
[машинной квитанции](QUEST-LOADER-CURRENT-VALIDATION.json).
Команда для локального воспроизведения из корня:

```powershell
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_quest_loader_current.py
```

Во всём текущем `QuestTask.csv` 1 627 строк имеют непустую группу, и у всех
группа `10000`. Следующий пакет проверит один общий фильтр на текущих
`ServerGroup.csv` и `ServerServiceGroup.csv`. Строка Canon 1 содержит ID `387`
и `ServicePhase=10000`. В навигации по текущему коду найдено чтение этой колонки
и запись фазы в `record+0x28` загрузчика `145c06500`. Активный `RegionType`
потребует отдельного подтверждения. Для отправки квестового действия также
нужны активный шаг, его provider и корреляция с серверным ответом.
