6 ноября 2026. Клиент 1.13.22 с SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
Архив `pakchunk1-Windows.pak` с SHA256
`2f2517ff83865ac13021f96d9babd8407e4fbee512ff29806106844e5d7d7ed3`.

Проверены связи между `QuestTask.Param`, `Dialog.GroupId`,
`DialogChoiceGroupId`, вариантами ответа и их целевыми группами. Русские
поля `Name`, `Title` и `Text` связываются по `Id` из двух именованных таблиц.
Маска `Untranslated` сохраняется по полям. Неоднозначное имя остаётся без текста.
Граф содержит 1 049 сценариев задания, 3 009 групп с 8 302 репликами и
235 групп с 241 вариантом ответа. Он хранится в библиотеке ресурсов.
Происхождение каждой таблицы и точный SHA закреплены в контексте и квитанции.
[Контекст и пять входных таблиц](../../native-contexts/dialogue-resources-current.json).

Для задачи `110120020` в «Зове крови» таблица задаёт группу `11012002`
из шести реплик. Поля `UnableToSkip`, `UnableToSkipLine`, `IgnoreAutoSetting`
и `Order` остаются исходными данными графа. Для порядка показа, смены
активной реплики и реакции на пропуск требуется проверка исполнителя диалога.
Граф содержит 150 сценариев со строковым `classInfoId`, девять ссылок
на отсутствующую группу и три перехода с нулевым ID. Для строкового класса
открыта семантика native-конвертации, для нулевого ID открыт смысл перехода.

## Что подтвердил стенд

Один scoped collect выгрузил восемь отсутствовавших функций. Полные экспортные
инструкции сверены с границами и байтами текущего EXE. В числе выбранных
функций есть потребители полей `DialogChoiceGroupId`, `DialogGroupId` и трёх
флагов. Их поведение осталось за границей исполнения.

Целая функция `14555dd70` исполнена в 26 сценариях с проверками Win64 ABI,
памяти и порядка вызовов. Она пробует прямой `dialogGroupId`, при отсутствии
прямого значения проходит `classBranch`, сравнивает `classInfoId` и записывает
последнюю найденную группу в `+0x20`. Вариант с явным нулём проходит через
прямое значение. При отсутствии подходящего значения прежнее поле сохраняется.
Стенд подаёт результаты JSON, текущий класс и пустые shared controls через
fixtures. Для ненулевого shared control, реального JSON scalar reader,
привязки parser к выбранному task и запуска окна нужны отдельные доказательства.

## Штатное обновление

`quest-dialogue-current` зарегистрирован в `on_update` и собственной tooling
группе. Guard удерживает SHA EXE, установленного архива, пяти CSV, экспортов,
проверочной среды, нативной квитанции и графа. Покрытие квестов остаётся частичным.
Неизменный повтор сверяет входы и квитанции. Native-кэш не включает тексты CSV,
поэтому пересборка ресурсной части может взять готовый результат выбора группы.
Общий guard сейчас консервативно наследует зависимости проверки названий.
Автоперенос адресов на следующий SHA и привязка изменившегося архива открыты.
[Машинная приёмка](QUEST-DIALOGUE-CURRENT-VALIDATION.json).

## Следующая проверка

Пройти связь выбранного quest task с вызовом проигрывателя диалога, затем
связать доступный ответ или пропуск с подтверждённым изменением текущего шага.
Чтение `classInfoId` начинается у `1445cd610`. Состояние панели «Сообщения»
по-прежнему зависит от наблюдений текущей сессии. Bipoberiho остался онлайн
в прежней сессии. Клик по реплике, пропуск и продолжение квеста ждут
подтверждённой игровой привязки.
