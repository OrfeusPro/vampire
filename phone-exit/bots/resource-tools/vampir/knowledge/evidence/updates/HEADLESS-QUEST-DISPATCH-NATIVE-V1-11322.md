# Проверка обработчиков Tutorial и QuestSync

Обновлятор Vampir проверяет исполнение Tutorial 9905 и QuestSync 1854
в ограниченном стенде на SHA 03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f.
Стенд использует подготовленные экспорты и сверяет инструкции с EXE.
Для QuestSync статический рецепт находит регистрацию по конструктору
из текущего доказательства чтения. Затем сверяет таблицу, handler, receiver,
getter и связи с заглушками по базе 1.13.16.

Tutorial прошёл 192 сценария. Из них 64 подтвердили глубокую копию в очередь,
128 подтвердили передачу в заглушку apply. Исполнялись пять целых функций.
Стенд проверил сохранность прежнего элемента очереди, независимость копии
от исходных записей и выбор ветки на пороге состояния. Настоящий apply,
опустошение и рост очереди требуют отдельных сценариев.

QuestSync прошёл 140 сценариев с 1560 последовательными проекциями записей.
Исполнялись зарегистрированный trampoline, handler, getter и receiver.
Стенд проверил обе ветви сброса, обход групп, поля записи, порядок уведомлений
и аргументы виртуального вызова модели. Изменения модели, создание progress
и эффекты уведомлений моделируются заглушками.

Стенд проверил 384 вызова Win64 для Tutorial и 140 для QuestSync, границы памяти,
сохранность регистров и возврат из заглушек. Глобальный указатель ограничен
восемью байтами в памяти эмулятора. Заглушка apply завершает проверенный
хвостовой переход с сохранённым адресом возврата. В эмуляторе заглушки
начинаются с RET, который перехватывает проверка вызова. Это исключает
декодирование тела за границей страницы.

Селектор подключает два раздельных этапа исполнения и статическую привязку
QuestSync. Ключи учитывают SHA источника, контекст, экспорты, код и runtime.
Финальный барьер сверяет доказательства и того же завершённого владельца
области проверки. Первый компонентный прогон занял 12.93 с.
Два повтора заняли 6.12 и 6.61 с.
Каждый взял шесть этапов из кэша без Ghidra, разбора PE и native-сценариев.
[Селектор](../../quest-dispatch-native.json).

Набор из 1946 тестов завершился без ошибок с тремя прежними пропусками.
Шесть дополнительных проверок прошли. Дальше предстоит проверить реальное
применение Tutorial, опустошение очереди и обновление модели QuestSync.
Связь с runtime и серверное подтверждение требуют своих доказательств.
