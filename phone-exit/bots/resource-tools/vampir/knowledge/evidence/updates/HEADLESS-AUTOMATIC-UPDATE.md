# Автоматическое обновление Vampir

28 октября 2026. Проверена установленная 1.13.22, полный SHA
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
[Машинная квитанция и SHA отчётов](AUTOMATIC-UPDATE-ACCEPTANCE.json).
[Команды и эксплуатация](../../RESUMABLE-UPDATE.md).

## Реализовано

`update --auto` выбирает полную опись той же установки и возобновляет подходящий
проход. Опись, функция, semantic suite и онлайн разделены. Изменение правил
создаёт новую identity с выборочным использованием готовых этапов.

Реестр источников / typed projections вынесен из Python; восемь прежних пропусков
контрактных привязок включены в каталог. Последняя доказанная база выбирается
по роли. Generic UTF-8 adapter переносит функции / bounded leaf, проверяет links,
источник, layout и выполняет прежние сценарии на целевом EXE. Успешный контекст
сохраняется как база этого semantic семейства для следующего патча.
Остальные семейства имеют явные причины отсутствующего адаптера / зависимостей;
это пробелы реализации и знаний, а не утверждение, что вся эта логика изменилась.

Кэш этапов использует материалы выбранного архива, его baseline и зависимости.
Полная опись не выдаётся за выполненное извлечение: missing artifacts обрабатываются
даже при равном inventory SHA. Общие проверки / функции / missing exports
дедуплицируются; SourceStore переиспользует исходники и PE-разбор внутри прохода
и сверяет их перед завершением. Независимые чтения используют два workers.
Ghidra и публикация выполняются одним координатором. Готовые BinDiff пары
могут дополнить поиск контрактных closed-shape кандидатов; score не заменяет
проверку всей closure. Холодный BinExport не запускается автоматически.

Кэшированные этапы и неизменные offline отказы не анализируются заново.
Для каждого cache hit полный журнал не переписывается: durable stage receipt
уже существует, а общий checkpoint выполняется при следующем новом этапе / в конце.
Очередь разделяет корневые причины и потребителей, ресурсные схемы и function frontier.
Число причин / baseline пар не является числом самостоятельных ручных задач.

Пакеты следующего входа неизменяемы; указатель публикуется после финальной проверки
входов и обязательных tooling / контрактных gates. Runtime validator читает
доказательства без Ghidra / replay, проверяет точный EXE, SDK, конфигурацию, правила
и consumers. Один immutable selector закрепляется до workers / anonymous handoff.
Текущий owner не переключается; prepared SDK не использует старый fallback.
Новые quest / tutorial / creation действия этим runtime adapter не разрешаются.

Ручной ярлык «Обновление Vampir» создан в корне проекта. Наблюдатель использует
действующий Windows Scheduler broker, переживает закрытие Codex и не имеет
автозапуска Windows. Poll 15 секунд, quiet 120 секунд; это условия запуска аудита,
не доказательство завершённой установки. Stop дренирует принадлежащий ему update.
Журнал ограничен 2 МиБ на прогон, хранится 20 прогонов; status показывает фазу.

## Проверки

- Тесты оркестратора, typed registry, SourceStore, BinDiff кандидатов и admission
  прошли; актуальные штатные tooling receipts перечислены в квитанции.
- Отдельный generic adapter проверен на искусственном неизвестном SHA: реальные
  native сценарии, изменённые layout / callee / leaf, публикация и последняя база.
- Реальный 20 → 22 UTF-8: 142 conversion / length и 80 scalar сценариев, всего 222.
- Настоящий Scheduler: start → second start = already_running → stop; owner завершён,
  update child не запускался, игра не затронута. Loopback / socketpair runtime tests
  используют синтетическое admission; они не доказывают живой вход нового клиента.
- Повреждённые источники / exports / rules / пакет другого SHA отклоняются.
- 165 архивов проверены полными SHA; первичный проход выполнил 109 ресурсных этапов.
  Это не 109 подтверждённых semantic контрактов: для многих таблиц нет подходящего baseline.

| Проход | Время | Reuse этапов | Новые JVM | Native suite | Context checks |
| --- | ---: | ---: | ---: | ---: | ---: |
| Первичный холодный проход | 1702,777 с | 0 | 1 | 1 | 4 |
| После завершения интеграции | 646,922 с | 117 | 0 | 1 | 4 |
| Неизменный повтор | 436,075 с | 132 | 0 | 0 | 0 |

В неизменном повторе индекс проверен без writer. Сохранённые результаты
переиспользованы; время всё ещё включает полные SHA и проверку артефактов.
Это замер этой пары и библиотеки, не оценка следующего патча.

## Остаток

`needs_review` сохранён по фактам. Launcher, world-session, map, quests и game-ui
не допущены для 1.13.22; новый next-profile не назначен. Function-only proofs
не превращены в разрешение игрового входа. Следующая работа — общие data / call
blockers и reviewed semantic adapters из machine run, без повторного экспорта
готовых функций и без нового полного ручного обхода.
