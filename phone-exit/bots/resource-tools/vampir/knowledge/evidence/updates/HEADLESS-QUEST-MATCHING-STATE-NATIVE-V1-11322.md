# Применение QuestSync progress к существующей задаче

Штатный обновлятор переносит и проверяет matching-task область QuestSync
на полном SHA 03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f.
Исполняются две целые функции state / progress и два точных leaf.
Native-код копирует 32 байта progress в существующую задачу и читает индекс
через sender getter. Проверка использует синтетический объект и vtable.

Матрица из 324 сценариев покрывает три ключа, три прежних и три новых state,
шесть значений index и два выравнивания входа. Проверяются все 32 байта,
guards, сохранность входного progress и единственное изменение record state.
Стенд подтвердил 648 вызовов Win64 и 324 входа в каждый native root / leaf.

Task callbacks заданы двумя слотами vtable с одной физической заглушкой.
Её роль определяется по фактическому адресу возврата native-вызова.
Стенд сверяет этот адрес с раздельными source-bound callsites и сравнивает
результат с матрицей переходов. Это подтвердило 72 callback start и 252 update.
Заглушка проверяет, что копирование уже завершилось, а record state ещё прежний.
State сохраняется после возврата callback.

Статический перенос использует последнее доказательство базы 1.13.16,
проверенный целевой reader proof и полный SHA обоих EXE. Сверяются whole
инструкции, control flow, прямые вызовы, виртуальные операнды и точные leaves.
Экспортируются только два roots. Factory, shared move/release и owner binding
имеют явные trap-границы для неисполняемых ветвей.

Новое семейство использует готовый стенд Tutorial с проверкой живых кадров
CALL / RET, Win64 ABI и разрешений памяти. Отдельный selector подключает
статический перенос и native-этап к обычному обновлению. Ключ учитывает
источники, lineage, контекст, код, правила, exports и runtime. Перед публикацией
проверяются тот же владелец scope и свежие SHA материалов.
[Native selector](../../quest-matching-state-native.json).
[Правило переноса](../../quest-matching-state-transfer.json).

Первый компонентный прогон занял 43.45 с.
Два повтора заняли 16.86 и 16.71 с.
Каждый использовал четыре готовых этапа без нового Ghidra, PE и native replay.
Набор из 1969 тестов прошёл с тремя прежними пропусками.
Шесть дополнительных проверок и проверки базы знаний завершены отдельно.

## Следующие границы

Подтверждена существующая задача с совпадающим ключом. Текущие 23 task tables,
выбор типа factory, создание и replacement не входят в эту матрицу.
Готовый baseline replacement содержит 378 сценариев и исправленный экспорт
factory. Следующий пакет должен перенести его отдельно, затем связать
виртуальный wrapper модели с готовыми state / progress.
Реальные эффекты task callbacks, gameplay, таблицы задач и runtime-контракт
сохраняют собственные проверки.
