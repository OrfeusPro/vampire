# Пути Windows в планировании ресурсов

При заключительной проверке первого resource-v2 пакета найдено расхождение:
для отсутствующего архива `AbsentCase.PAK` прежний `WindowsPath` сопоставлял
source rows с другим регистром, а новый словарь строк терял эти строки.
Группы и поиск теперь используют `Path`; порядок строк и исходное написание
путей в результате сохранены. На системах с чувствительным регистром остаются
правила их `Path`, принудительное приведение всех путей к нижнему регистру не нужно.
[Точные входы и результаты](AUTO-RESOURCE-WINDOWS-PATHS-V2-11322.json).

Новый тест проверил три написания отсутствующего архива, две строки источника,
их порядок, повтор memo и целый `stage_inputs` против прежнего кода.
Прошли 1198 инфраструктурных тестов; три прежних symlink-теста пропущены из-за
прав Windows. Проверки alias retarget без дополнительных прав выполнены.
Новый case-тест на Windows выполнен, а не пропущен.

Для трёх реальных архивов заново проверены использованные байты и финальный
SHA / alias barrier. Ключи целиком совпали с ранее допущенными; повтор inputs
не выполнил новых чтений. Прежние legacy hashing loops и native suites не
запускались. Первичные длительности зависят от нагрузки на файловую систему;
ускорение всего обновления этим результатом не заявляется.

[Первый отчёт](HEADLESS-RESOURCE-PLANNING-V2-11322.md), его fact и manifests
сохранены. Для исходных восьми файлов перед исправлением создан архив точных
байтов с SHA-привязкой. Исправление имеет собственные tooling, freeze и evidence.
Все 59 прежних frozen native code / context inputs остались неизменными.
Ghidra, новые native сценарии, extraction, игровые команды и назначение профиля
не выполнялись. Полный ordinary update и онлайн-допуск ещё требуют своей проверки.
