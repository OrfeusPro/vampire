# Подготовка Lobby Login в Vampir 1.13.22

Исходный EXE имеет SHA256
`03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f`.
Полный экспорт функции `0x1467d1200` использован из `run-6204f055a2a7`.
Конструктор `0x145749670` и два getter выбранного сервера исполняются по
байтам PE. Пакет принят на границе `0x144aaf380` с текущим vtable
`0x1499437b8`. После возврата отправителя проверен вызов деструктора.

Пройдено восемь сценариев с выключенным флагом VersionResult. Варианты
покрывают Windows, другой selector, незаданный kind, выключенный SDK,
отсутствующие manager, auth и NID, а также пустые строки. В сценарии
Windows с kind 2 и выбранным Canon 1 записаны числа `2, 2, 387, 0` и
байт `7`. Ветки SDK и NID заполняют свои поля независимо. Код проверяет
порядок вызовов, значения шести строк, ABI и границы памяти стенда.
Проверка чисел и metadata также использует текущий Python binder.

Значения SDK, NID, имя устройства и операции FString заданы на стенде.
Подготовленные поля переданы во второй native стенд отправителя. Его
текущие writer, OUTPUT, CRC и XOR сформировали кадр, совпавший с Python codec
во всех восьми случаях. Передача полей между двумя стендами выполняется
переносимой проекцией. Деструктор проверен на границе вызова. Реальные данные
аккаунта, активная ветка VersionResult с дополнительным числом, транспорт
и живое принятие игровым сервером остаются отдельными проверками.

`verify-lobby-login-prepare-current.py` публикует неизменяемый отчёт.
`lobby-login-prepare-current` связывает его с автообновлением и проверяет
полные SHA входов перед повторным использованием. Проход без изменений
использует сохранённый результат.
