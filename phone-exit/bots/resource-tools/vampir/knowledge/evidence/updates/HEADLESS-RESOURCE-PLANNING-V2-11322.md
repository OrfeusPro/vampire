# Планирование ресурсов без повторных полных обходов

Обычные `knowledge-index.py update --auto --plan-only` и следующий
`update --resume <run.json> --plan-only` завершились с состоянием `planned`.
Resource-readiness занял 15,478174 и 15,254757 секунды. Первый проход выполнил
полный SHA-аудит установки, повтор заново проверил её файлы перед использованием
сохранённого аудита. Это проверка плана и продолжения; целый update, semantic
совместимость и онлайн-вход этим результатом не подтверждаются.
[Машинные отчёты и точные входы](AUTO-RESOURCE-PLANNING-V2-11322.json).

Предварительный read-only замер показал стоимость исторических blobs и разрешения
путей: один архив с 6849 файлами занял 15,390131 секунды. Общий table index
содержит 125 строк и один source path; его размер не был главным узким местом.
Новый поиск hints один раз читает stage-cache manifests. Результат не даёт допуска:
отрицательный hint оставляет архив в очереди, положительный запускает прежнюю
полную проверку inputs, content-addressed manifest и SHA всех outputs.
Изменённые архивы сразу остаются pending; Journal затем проверяет их точный ключ.

В обоих обычных проходах найден один готовый resource-кандидат; он проверен
полностью. Для 108 заведомо неготовых архивов пропущено чтение historical blobs
ради readiness lookup. Эти архивы остаются в очереди; отсутствие готовности
не выдаётся за отсутствие материалов. Discovery прочитал 1288 JSON за 12,897061
и 12,329991 секунды. Поиск hints по общей истории остаётся расходом и следующим
кандидатом на отдельный индекс. Перед допуском нужен прежний authoritative lookup.

`resource-planning-v2.py` хранит JSON, SHA, разрешённые пути и выбранные table rows
только в пределах одного прохода. Данные возвращаются копиями. На трёх реальных
архивах legacy и scoped inputs совпали целиком, включая stage keys и config
provenance. Всего использовано 10304 файла; повторное построение трёх inputs
заняло 0,016079 секунды без новых SHA / JSON reads. Первый scoped проход занял
7,377015 секунды; обязательный заключительный барьер — 8,804127 секунды.
Первичные замеры зависят от файлового кэша и не доказывают ускорение всего update.

Барьер заново читает полные SHA через исходный digest, проверяет появление /
удаление файлов и повторно разрешает aliases до и после чтения. Изменение size /
mtime не требуется для обнаружения подмены. При собственной записи входа также
нужен новый Scope. Новый resource stage проходит свой барьер перед записью
квитанции; общий барьер выполняется после bundle preparation до публикации
next-use pointers. Plan-only проходит свой барьер перед сохранением плана.
Неизменная сессия не использует новые inputs скрытно.

Прошли 1197 инфраструктурных тестов, 35 из них новые. Три теста реальных symlinks
пропущены из-за прав Windows; проверки retarget через детерминированный resolver
выполнены. Покрыты точный legacy-формат, selected / unrelated изменения,
подмена с прежними size / mtime, границы директорий, missing inputs, мутация
кэша вызывающим кодом и изменение historical input во время bundle preparation.
Сохранены 59 прежних frozen code / context inputs. Ghidra, native suites,
извлечение архивов и игровые команды не запускались; профили не назначались.

Остаются повторные child-proof / source validations в publication v2, разделение
resource extraction / comparison keys и общий полный проход после этих изменений.
Готовые native результаты повторно не исполнять без изменения их входов.
