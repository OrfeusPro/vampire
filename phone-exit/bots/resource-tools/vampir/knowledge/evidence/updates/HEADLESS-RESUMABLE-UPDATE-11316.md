## Version / Login: подтверждённая ограниченная часть

| Пакет | Constructor | Prepare | Vtable | ID |
| --- | --- | --- | --- | ---: |
| PktVersion | `0x1456d7be0` | `0x1467ce6a0` | `0x149926d08` | 1 |
| PktLogin | `0x1456d7570` | `0x1467ce030` | `0x1499263d0` | 3 |

Оба конструктора и оба участка присваивания tag связаны с pointer
`0x14b1b9e98` → ASCII literal `0x149960020`:
`32283C4C6485307BCF524765A84409C3`. Строка содержит 32 символа и терминатор;
в проверяемом wide FString получаются 33 элемента / 66 байт.

В native replay исполнены целые constructors и actual ID getters, затем
ограниченные tag slices для poison 0 / 0x55 / 0xaa / 0xff — четыре случая на
пакет. Проверены vptr, descriptor и canaries. ASCII FString conversion,
allocation и memcpy остаются точными fixtures с проверкой аргументов.

Статически подтверждена связь wrapper constructor `0x1467cc380` → table
`0x149dc9320` → slot `+0x48` → Version prepare. Для Login найдена constructor
call `0x1467ce1d3`; разбор stack layout связывает destination с полем `+0x110`.
Version constructor проверяет tag field `+0xb0`. Старые адреса автоматически
не переносились. Reports и их SHA приведены в квитанции.

Полные Version / Login prepare, SDK getters, сетевой writer / reader и принятие
сервером этой проверкой не исполнены. Поэтому контракты `game-version` и
`game-login` сохраняют неполное покрытие, несмотря на успех tag replay.

повреждение, выборочное повторение, отказ профиля и успешное продолжение после
исправления. Они не заменяют реальные межверсионные доказательства каждой роли.
