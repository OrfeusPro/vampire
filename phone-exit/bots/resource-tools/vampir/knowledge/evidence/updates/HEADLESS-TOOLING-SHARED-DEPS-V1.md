# Зависимости проверок Version и общих фикстур

Четыре скрипта `verify-version-*-context.py` перенесены из общих входов
в 10 групп, которые уже учитывают `update-native-version-helpers.py`.
Закрытый список в `version-helper-case-contracts.py` выбирает скрипт по роли.
Адаптер хэширует выбранный скрипт при подготовке и загружает его при исполнении.
Группы с общим `update-run.py` сохраняют эти зависимости, поскольку проход
может читать реестр и все контексты. `tooling-cache` использует временный
реестр и подменённый engine.

Девять контекстов `version-*-11320.json` добавлены в те же 10 групп.
Имя файла вычисляется в тесте адаптера из семейства и суффикса версии.
Тест системных функций читает три файла из этого же набора. Дополнительно
`verify-version-nm-device-context.py` включён у всех потребителей адаптера.

Импорты тестовых помощников прослежены за границы исходного списка реестра.
Восемь групп используют `test_vampir_update_run.py` и
`test_vampir_research_update.py`. Второй вызывает общий fixture PE из
`test_vampir_knowledge_index.py`. Для подготовленного runtime добавлены
импортируемые тесты и зависимости локального протокола, включая два JSON
с телами пакетов. Два широко используемых инструмента аудита и контрактов
остаются общими входами. Всего зарегистрировано 563
входов, на 83 больше. Список из 144 тестовых
модулей и состав 27 групп сохранены.

## Приёмка

Обновлённые ключи проверены одним автоматическим прогоном. Он выполнил
27 групп и 2036 тестовых случаев
за 663.685 с. Сохранены прежние case IDs с той же
кратностью и 4 пропуска. Шесть дополнительных проверок
прошли. Повтор использовал 27 квитанций за
42.021 с, запусков групп — 0.

Для каждого из четырёх скриптов смоделирована смена одного SHA в фактических
определениях ключей из проверенных квитанций. До переноса менялись все 27
ключей, после переноса — 10. Это 1167 случаев из 2036, остальные 17
групп сохраняют свои ключи. Новый SHA общего `research-workflow.py`
по-прежнему затрагивает все 27 групп. Проверка ключей использует формулу
штатного runner и сохранённые определения. Симуляция подставляет другой
SHA в копию определения ключа.

Остальные неоднозначные зависимости требуют отдельной сверки потребителей.
Результат относится к инфраструктурным тестам. Клиентские контракты и работа
онлайн подтверждаются отдельными проверками.
