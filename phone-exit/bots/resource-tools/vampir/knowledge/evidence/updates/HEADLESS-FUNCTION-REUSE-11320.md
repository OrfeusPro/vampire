# Автоматическая сверка функций между 1.13.16, 1.13.18 и 1.13.20

Проверено 28 октября 2026. Общий этап `function-reuse` подключён к штатному
`knowledge-index.py update`. Сначала выбирается последняя явная декларация
каждой роли: база 1.13.18, если она есть; иначе 1.13.16 напрямую в новую версию.
Работа одинаковых функций объединяется по полному SHA и адресу; происхождение
всех использующих их ролей сохраняется. Более новая непроверенная декларация
блокирует применение старого доказательства к той же роли.

## Проверенные источники и результат

| Версия | Полный SHA256 EXE | Функций в общем плане |
| --- | --- | --- |
| 1.13.16 | `d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960` | 220 |
| 1.13.18 | `d30708283d893756b0fc1ffe700344be1a41fe746683106704b01ce32611532c` | 138 |
| 1.13.20, цель | `544ef516fb168caaac13d2072ef02393d69407e964b0d8f338d50ded5cf3804c` | 358 всего |

109 source-bound contexts содержат 1159 ролей. После выбора последних версий
и объединения повторов получилось 358 функций с зависимостями. Реальный
offline прогон подтвердил **10**, остальные **348 требуют проверки**.
Это очередь функций, а не число квестов или прежних строк допуска runtime.
В отчёте перечислены конкретные причины: неизвестные границы, не объявленные
callees / данные, косвенные вызовы и внешние переходы. Старые экспорты повторно
не создавались, Ghidra и авторизация не запускались.

Content-addressed отчёт в библиотеке ресурсов:
`knowledge/function-reuse-catalog/2371523ff98469c2708ea7f2749fd0d7bfe28577d6cab187ce095ed1f785a58b/manifest.json`.
Его SHA256 совпадает с именем каталога. Настоящий отчёт принят
`update-run.apply_function_reuse` с действующим графом контрактов; подходящих
новых `reviewed` bindings в этом графе для этих 10 функций нет. Они остаются
самостоятельными доказательствами каталога, допуск целых контрактов не меняется.

## Что автоматизировано

- `function-reuse-plan.py` читает явные роли и проверенные полные экспорты,
  выбирает базу, собирает ограниченные замкнутые группы зависимостей и запускает
  обычный resolver. Неизвестные зависимости не заменяются предположениями.
- `closed_shape` в `update-bindings.py` проверяет unwind-границы, все инструкции,
  локальные переходы, объявленные прямые callees и RIP-данные с известным SHA.
  Поиск ограничен окном и числом кандидатов; неоднозначность сохраняет очередь.
  Проверка зависимостей доходит до устойчивого состояния, включая циклы.
- `verify-function-reuse.py` сохраняет отдельный кэш явно заданных функций.
  Ключ включает источники, рецепты, зависимости, инструменты, Python и Capstone.
  Повтор сверяет полные SHA EXE и целостность отчёта; изменение входов требует
  нового результата. В штатном обновлении кэшируется весь этап каталога.
- `update-run.py` может заполнить только отсутствующий `reviewed` binding по
  точной паре baseline SHA / адрес. Существующие привязки не перезаписываются.
  Повторный Ghidra export пропускается только при полном доказательстве всех
  использований адреса; сохраняется отдельный receipt `equivalent`.
  Он не выдаётся за новый export и не заменяет source-specific semantic checks.

Для `game-version / utf8-length` отдельно подключён рецепт
`0x14144c550` из 1.13.18: на 1.13.20 найден `0x14144c5b0`, полная форма
инструкций совпала. Эта функция не объявляет целый игровой профиль совместимым.

## Воспроизведение

Из корня репозитория, без сети и игровых команд:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/function-reuse-plan.py --source-sha256 544ef516fb168caaac13d2072ef02393d69407e964b0d8f338d50ded5cf3804c
python -X utf8 phone-exit/bots/resource-tools/vampir/verify-function-reuse.py --source-sha256 544ef516fb168caaac13d2072ef02393d69407e964b0d8f338d50ded5cf3804c --contract game-version --key utf8-length
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_function_reuse.py
```

Общий tooling набор — 39 тестов: relocation, глубокие callees, циклы,
изменение данных, неоднозначность, выбор базы, объединение ролей, изменение
входов между чтениями, настоящий planner → adoption, целостность кэша,
пропуск лишнего export и сохранение `requires_port`. Отдельно проверяются
штатный update runner, схема контрактов и граница tooling / client проверок.
`update-binding-closure` подключён к `on_update` с зависимостями общего набора.

## Границы

Подтверждается ограниченная эквивалентность тела функции и объявленной цепочки
зависимостей. Семантические сценарии, callbacks / OS / engine effects,
ресурсные связи, новые данные, квестовые действия и живая сессия остаются
отдельными проверками. Runtime и profile не активируются автоматически.
Старая закрытая сессия не возобновлялась. Следующий пакет — явно дополнить
границы и зависимости из очереди и переносить затронутые semantic checks;
уже подтверждённые функции повторно вручную не разбирать без изменения входов.
