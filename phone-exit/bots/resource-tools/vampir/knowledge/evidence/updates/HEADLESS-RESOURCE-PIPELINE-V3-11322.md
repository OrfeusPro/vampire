# Независимые ресурсные этапы обновления v3

Обычный обновлятор подключает `resource-pipeline-v3` через машинный selector.
Reference hashes прежних blobs, текущий record index, извлечение CSV и два
сравнения имеют отдельные входы / кэш. Отсутствующая база таблиц оставляет
общий блокер сравнения и сохраняет получение текущих CSV.
[Машинные доказательства и полные SHA](AUTO-RESOURCE-PIPELINE-V3-11322.json).

## Реальные файлы и продолжение

Разовый импорт проверил 84 834 прежних blob records для 109 архивов и активировал
неизменяемый reference после полного SHA / alias barrier. Три отсутствующих
исторических входа отмечены явно. Импорт занял 2085,169 секунды; исходная версия
этих blobs неизвестна. Последующие потребители проверяют snapshot, отдельную
activation receipt и актуальные tools, не обходя старые blobs заново.

Первый ресурсный проход обработал 109 архивов, но прекратился до завершающего
барьера. Его 111 завершённых stages и CSV сохранились; причиной завершения
процесса этот пакет не располагает. Это не успешная холодная приёмка.
После проверки отсутствия известного owner и активных Python / Java процессов
его lock сохранён в отдельном архиве. Это единичное ручное восстановление,
а не реализация общей безопасной очистки stale locks.

Продолжение запущено независимым Windows Scheduler owner. Первый проверочный
скрипт после завершающих барьеров ошибочно запросил метрики закрытого index
scope и не сохранил отчёт. В новом запуске метрики взяты из результата finish;
код продукта не менялся, сохранённые артефакты сверены заново. Первый завершённый
проход занял 273,643 секунды, следующий неизменный —
270,834 секунды. В обоих проверены все 109 архивов,
заключительные resource / alias barriers и полные SHA 166 установленных файлов.
Новых index adapter calls, native replays и JVM — 0. При продолжении сверены
105 прежних asset comparisons: полный список результатов и счётчики совпали;
три missing references сохранили свой блокер. Во втором проходе выполнено
0 новых comparisons; использованы 218 результатов сравнения из кэша.
Legacy blobs rehashed — 0 в обоих завершённых проходах.

Это замер ресурсной части с сохранённой описью execution tools, проверенной
по полным SHA и runtime. Полный ordinary update с новым recipe и общая стоимость
подготовки execution inputs этим замером не подтверждены. Готовые 34 native
семейства и их сценарии не запускались повторно.

## Полученные данные и границы

Получены 3344 записи таблиц: ProjectRED — 249, pakchunk0 — 1, pakchunk1 — 3094.
Уникальных CSV — 2941, их объём — 194 732 578 байт. 403 записи повторяют
содержимое. Все 109 metadata reports имеют `state=extracted`, ошибок — 0.
Собственный агрегатор проверил SHA 2 400 523 байт этих metadata и связал
те же pointers с обоими завершёнными проходами.

Accounting охватывает 350 979 records: 147 314 skipped и 200 321 non-CSV.
147 079 skipped распознаны по proven UAsset magic. Остальные 235 сохраняют
пробел: 77 size budget, 76 encrypted и 82 объединённых legacy encrypted / size.
CSV recipe ограничен UTF-8 BOM, stored / decoded до 16 MiB и полем до 1 MiB.
`record_scan_complete` означает достижение начала индекса; authoritative
directory index и логические пути не разобраны. У всех CSV `internal_path`
неизвестен. Точные bytes, схема и кандидатная связь не подтверждают логическую
идентичность ресурса, semantic совместимость или admission.

Итог: 1 bounded processing passed и 108 requires_review.
У 108 архивов отсутствует matching table baseline, у трёх из них также нет
исторического blob reference. Причины остаются отдельными общими блокерами;
число архивов не равно числу ручных задач. Профиль и игровые сессии не менялись.

## Проверки и следующий пакет

Прошли 1326 tooling тестов, включая 83 новых: reference — 24, record index — 20,
CSV — 22, pipeline — 17. Три прежних Windows symlink cases пропущены из-за прав.
Проверены corruption / alias retarget, смена helper / EXE при прежнем PAK,
missing / foreign baseline, неоднозначный record index, interrupted import,
границы размера, field limit, accounting и порядок cache activation после barrier.
59 прежних frozen native inputs сохраняются. Реальный selected-index preflight
проверяет отдельную область, его полный отчёт приведён в машинном evidence.

Далее нужны общий замер нового ordinary update, сужение повторных execution-input
и archive SHA затрат внутри замороженного владельца, безопасное hard-crash
recovery и разбор конкретных directory / encrypted / table-baseline gaps.
Новый патч получает собственные отчёты для новых SHA; исторические доказательства
не переименовываются. [Запуск и диагностика](../../RESUMABLE-UPDATE.md).
