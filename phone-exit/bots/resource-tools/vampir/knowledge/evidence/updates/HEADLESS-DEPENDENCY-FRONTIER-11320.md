# Общая очередь зависимостей функций 1.13.20

Проверено 28 октября 2026. Продолжение
[пакета сверки функций](HEADLESS-FUNCTION-REUSE-11320.md).
Целевой EXE SHA256:
`544ef516fb168caaac13d2072ef02393d69407e964b0d8f338d50ded5cf3804c`.
Базы 1.13.16 / 1.13.18 и их полные SHA сохранены в предыдущем документе.

## Подключённый результат

В общий план добавлены 27 уже экспортированных helpers: 12 для 1.13.16 и
15 для 1.13.18. Их 17 export artifacts проверены полным SHA. Контексты
`function-reuse-dependencies-11316.json` и `function-reuse-dependencies-11318.json`
помечены `dependency_only`: они не создают новые основные роли и не меняют
выбор последней версии роли. Анализ helper начинается только по фактическому
прямому вызову из выбранной функции. Сам экспорт не подтверждает поведение.

Отчёт общего реального прогона в библиотеке ресурсов:
`knowledge/function-reuse-catalog/1419f6d8e3bd90503883bd548cb5d956e85853ddfee5ff572f4d7b8b7e102e63/manifest.json`.
SHA256 совпадает с именем каталога.

| Учёт | Проверенный результат |
| --- | --- |
| Основные роли | 1159, без искусственных ролей helpers |
| Основные функции | 356: 10 подтверждены, 346 требуют проверки |
| Достигнутые вспомогательные функции | 30: подтверждений 0 |
| Всего с зависимостями | 386: 10 подтверждены, 376 требуют проверки |
| Контексты | 111, включая два dependency-only |

Прежние 358 функций включали 356 основных и две вспомогательные. Новый пакет
добавил ещё 28 достигнутых зависимостей: 27 явно объявленных и один уже известный
helper, вызванный ими. **Новых подтверждений основных функций нет.** Рост общей
очереди отражает найденные зависимости, а не регрессию проверенного кода.

`dependency_frontier` группирует реальные прямые связи по полному SHA / адресу
зависимости и считает уникальных потребителей. В текущем отчёте 706 записей.
Например, `0x144aad190` из 1.13.16 имеет 36 прямых потребителей, а
`0x141483080` — 31. Это приоритет исследования, не обещание закрыть столько же
функций. Повторные роли одной функции не увеличивают счётчик. Различаются
отсутствующая декларация, известный source gap и неподтверждённая target shape.
Эти данные сохраняются в штатном cached этапе `function-reuse` обновлятора.

## Почему не снята очередь

Сначала проверены 27 уже готовых exports: у helpers остались собственные
пробелы в данных / переходах / границах. Затем отдельный ограниченный shortlist
из 32 прямых missing helpers для 56 потребителей с callee-пробелами:
23 имеют внешние или косвенные переходы, у четырёх из них также RIP references;
девять не являются explicit unwind roots. Самостоятельно замкнутых helpers нет.
Дерево вызовов не расширялось, Ghidra и сеть не запускались.

Shortlist SHA256:
`f4d664cba844a8feac51a281db91ee0abe24e003c34f91476d714d49b67cf8b3`,
путь в библиотеке `knowledge/function-reuse-helper-shortlist/<SHA>/manifest.json`.
Список 32 адресов, источники, прямые потребители и причины сохранены в отчёте.
У группы из 11 функций с data-пробелами найдены LEA-ссылки на таблицы / vtables;
в одном случае также чтения `.rdata` и `.data`. Размер таблицы и допустимость
динамического содержимого из размера операнда LEA не выводились.

## Проверки и следующие границы

Общий tooling набор расширен с 39 до 42 тестов и прошёл. Новые случаи:
helper подключается по вызову, неиспользованный helper не анализируется,
некорректный флаг отклоняется, frontier объединяет повторные роли и различает
изменённую target shape. Отдельное read-only ревью не выявило блокирующих проблем.
Действующий `on_update` уже включает planner и его тесты в зависимости кэша.

Далее нужен отдельный source-bound пакет таблиц / dispatch / границ для выбранной
группы из frontier и перенос соответствующих семантических проверок. Один только
повтор экспорта проблему не решает. Известные gaps сохранены для следующего
исследования; неизменённый результат переиспользуется по ключу кэша.
Игровая сессия, runtime и profile не включались.
