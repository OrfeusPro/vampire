# Общий барьер владельца для выбранных экспортов

`update-owner-scope-v3.py` объединяет использованные файлы между batch-проверками
одного update. `retain()` возвращает только provisional declaration:
`admission_completed=false`, `source_barrier_completed=false`, без
`validation_sha256`. Приватная selected SQLite также помечает строки provisional.
Выбранные инструкции проверяются при чтении из точного SourceStore; это ещё
не итоговый допуск. Публикацию next-use pointers разрешает общий финальный барьер.
[Точные источники, отчёт и границы](AUTO-UPDATE-OWNER-SCOPE-V3-11322.json).

`finish()` владельца заново проверяет SourceStore и SHA объединения файлов
через исходный digest. В итог попадают также поздно добавленные sources.
Удаление первоначального или сохранённого source, изменение source inventory
во время барьера, перенаправление paths, конфликт SHA, изменение tools/runtime
и подмена с прежними size/mtime блокируют допуск. Владелец закрывается после
успеха или ошибки; для нового прохода нужен свежий SourceStore. В root update
общий барьер перенесён после bundle preparation, перед публикацией указателей.
Обычный `research-scoped-v2` сохранил собственные полные проверки.

Прошли 1218 инфраструктурных тестов: 20 новых (17 owner и три integration).
Три прежних symlink-теста пропущены из-за прав Windows. Новые owner-тесты
пропусков не имеют. Проверены в том числе single-use owner и порядок
prepare → owner barrier → pointer publication.

Реальный проход 34 семейств использовал 102 этапа и 34 публикации из кэша:
native / JVM / native PE rebuild — 0. Все stage actions эмуляции и Ghidra
были запрещены runner до исполнения. Publication guard, native engines и
самостоятельный scoped research не менялись; 59 прежних inputs сохранены.
35 provisional scopes дали 144 уникальных файла для заключительной проверки.
Owner проверил все три EXE source одним общим барьером; вместе с собственным
барьером publication получено шесть source validation reads.
В одной и той же точке publication reads уменьшились с 84 до трёх.

Полный измеренный проход занял 184,722085 секунды против прежних 185,417547.
Существенного ускорения всего прохода пока нет: оставшееся время связано
с повторными child-report / tools / snapshot validations. Следующий этап —
измерить их и добавить versioned memo с проверенной совместимостью кеша.
Новый алгоритм нельзя скрывать под старым publication guard.

Область результата — выбранные материалы и инфраструктура. Semantic функции,
целый обычный CLI update и онлайн-вход этим пакетом не подтверждаются.
Текущая сессия и профиль не переключались.
