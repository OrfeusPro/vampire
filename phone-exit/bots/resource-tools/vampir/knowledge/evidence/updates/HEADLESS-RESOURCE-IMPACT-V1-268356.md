# Влияние именованных ресурсов после общего SHA-барьера

Штатный resource pipeline теперь сохраняет отдельный расчёт по объявленным
потребителям и публикует его квитанцию после завершения общего SHA owner.
Карта, квесты и игровой UI получают точные совпавшие пути и причины fallback.
Расчёт не меняет выполнение проверок, ключи контекстов или игровой допуск.

## Правило и происхождение

Selector resource-impact-engine.json включает resource-impact-post-barrier-v1.
Потребители и archive/path patterns берутся из update-contracts.json; адреса
или допуски из Markdown не извлекаются. Используются уже проверенные named
comparison / current directory / baseline pointers того же открытого owner.
Полный SHA текущего архива должен совпасть с аудитом. Для неизменного архива
также регистрируется полный SHA, затем выполняется свежий общий барьер.

Именованные изменения сопоставляются с patterns по canonical path. База
сравнения явно сверяется с before SHA аудита. База 15cf... не выдаётся за
ближайшую 7c186d92... . Изменённый путь можно наблюдать относительно старой
базы, но несовпадение баз остаётся причиной проверки. Паттерн, охватывающий
не только CSV, сохраняет named_tables_do_not_cover_resource_pattern.
Неизвестный совпавший hash, неполная опись, missing comparison и отсутствующий
архив также дают собственные причины. Данные сохранённой проверки потребителя
пока не подтверждены: execution_reuse_allowed всегда false.

## Кэш и публикация

Анализ находится в resource-impact-analyses-v1. Ключ учитывает точный аудит,
объявления потребителей, pointers сравнений, код, selector и Python runtime.
Неизменный расчёт переиспользуется; повреждение отчёта не запускает его тихую
пересборку. Cache pointer назначается только после общего owner barrier.

После завершения owner создаётся resource-impact-receipts-v1 с analysis pointer
и точной квитанцией барьера. Проверяются её SHA, epoch и покрытие inputs.
Тёплый проход сохраняет analysis, но получает новый барьер и новую квитанцию.
До завершения owner или после сбоя квитанция не публикуется.
В обычном update она доступна в resource_impact журнала и в metrics.resource_pipeline.impact.

## Приёмка настоящих данных

EXE: 03edad26033c85835ad8fdc1825df7aeb635e2c199055598ad926bf84b43739f; ресурсный патч Revision268356.
Компонентный аудит содержит только девять изменённых архивов и ссылку на
исходную полную опись. Это проверка выбранного компонента, а не полный
ordinary update и не вывод о всей установке. Проверены 45 сочетаний архивов
и пяти resource patterns трёх покрытых потребителей. Четвёртый, game-version,
требует DefaultGame.ini из ProjectRED-Windows.pak вне выбранной области;
его unmatched pattern сохранён, отсутствие покрытия явно видно в отчёте.

| Потребитель | Сочетаний archive/pattern | Уникальных изменённых путей | Неизвестных совпавших путей |
| --- | ---: | ---: | ---: |
| game-version | 0 | 0 | 0 |
| map-data | 18 | 1 | 0 |
| quests | 9 | 37 | 0 |
| game-ui | 18 | 17 | 0 |

Изменённые пути объединены по archive/path/state, без двойного счёта
пересекающихся patterns. Это изменения относительно доступной старой named
базы. Широкие patterns, несовпадение before SHA и отсутствие подтверждённого
consumer context сохраняют fallback; ни один потребитель не получил reuse.
Подробные paths, counts и причины находятся в неизменяемом analysis report.

Расчёт уже сформирован и назначен после исходного owner barrier; отдельная
квитанция фиксирует его в pending_caches этого барьера. Два последующих
повтора заняли 193.708343 с и 157.450206 с: каждый дал один
cache hit и ноль новых analyses. Оба прохода
переиспользовали девять named comparisons: 0 новых сравнений / capsules,
0 CSV extraction, 0 native replay и 0 JVM. Свежие SHA-барьеры сохранены.

## Проверки и остаток

20 новых автоматических случаев проверяют порядок prepare → owner → publish,
тёплый кэш с новым epoch, порчу proofs/cache, несовпадение баз и source slots,
неизвестные hashes, широкие patterns, неизменные архивы и запись в журнал.
Зарегистрированный набор завершил 1686 тестов с тремя прежними пропусками;
шесть дополнительных checks прошли. Обычный путь включён в definitions,
selector и on_update. Старые native engines и named capture helpers не менялись.

Далее нужны точные ресурсные inputs сохранённых consumer checks и полнота
покрытия каждого pattern. Только после этого можно сужать resource_inputs и
cache keys выбранного потребителя. Текущий affected plan диагностический;
одного уточнения его paths недостаточно для экономии исполнения.
Девять старых unknown SHA и non-table assets остаются отдельными пробелами.
Admission / prepared-next / игровая сессия не менялись. Watcher не включался.
59 frozen native inputs, 45 прежних facts и исторические разделы сохранены.
