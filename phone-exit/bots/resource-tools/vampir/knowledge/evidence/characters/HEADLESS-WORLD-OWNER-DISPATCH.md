# Вызов владельца из функции движка

20 октября 2026. Продолжение [владельца и ID205](HEADLESS-WORLD-FINISH-OWNER.md).
Найден и исполнен вызывающий участок `0x14430da70`: он читает указатель
из поля `+0x158` и вызывает слот `+0x7b0` полученного объекта. С настоящими
таблицами трёх ранее проверенных владельцев этот путь доходит до ID205.

Поле `+0x158` и содержащий его объект задаёт тест. Это ещё не доказательство
выбора соответствующего класса после ID110 в настоящем жизненном цикле.
По одному совпадению смещения виртуального слота тип объекта не определяется.

## Подтверждённый вызов

В полном теле `0x14430da70` исполняется последовательность:

| Адрес | Инструкция и действие |
| --- | --- |
| `0x14430db74` | `mov rcx, [rbx+0x158]`: получить указатель |
| `0x14430db7b` | Проверить его на null |
| `0x14430db80` | `mov rax, [rcx]`: прочитать таблицу получателя |
| `0x14430db83` | `call [rax+0x7b0]`: вызвать метод этого получателя |

В тесте поле получает объект, созданный настоящим конструктором владельца.
RCX на входе `0x1468f1e90` проверяется: он совпадает с указателем из поля,
а не с содержащим объектом. Затем исполняется прежняя цепочка
owner → service `+0x80` → service `+0x70` → условие → конструктор ID205.

Если основной указатель null, вызова владельца нет. Если он не null и
дополнительно задан указатель `object+0x168`, после вызова владельца исполняется
virtual `+0x2e8` второго объекта. Эта вторичная цель перехвачена. Одного
наличия второго указателя без первого недостаточно для её вызова.

## Проверенные условия

Исполнены 45 сценариев. Для трёх конструкторов проверены состояния сервиса
1, 2 и 4, наличие / отсутствие владельца и вторичного объекта. Отдельно
проверены значения байта `object+0x13a` 0, 1 и 6 при ненастроенном cache-флаге.
Основная матрица использует значение 7, которое пропускает начальную ветвь
проверки режима; это явное тестовое условие, не установленный тип мира.

В начальной ветви mask `0x6a` разрешает значения 1, 3, 5 и 6. В тестах с 1
и 6 настоящие инструкции обращаются к двум перехваченным проверкам,
получают 0 и записывают `+0xd8 = 0`, `+0xd9 = 1`. Для значения 0 эти
проверки пропускаются. Другие backend-ветви этой начальной части не покрыты.

При наличии владельца состояние 2 или 4 приводит к ID205 и записи 5.
Состояние 1 остаётся 1. Без владельца состояние сохраняется во всех случаях.
Исходные значения сервиса заданы тестом; эта работа не заменяет доказанную
ранее подготовку 1 → 4 настоящим `0x14561b390` при наличии объекта мира.

Функция полностью доходит до возврата. Обход через `0x144262710`, его
callback `0x143963850`, вторичная цель и операции с внешними коллекциями
перехвачены. Тест подтверждает передачу callback, но не его исполнение.
Отправка пакета перехвачена на прежней границе; очереди и сокета здесь нет.

## Остальные кандидаты и граница типов

Экспортированы также:

- `0x143c1ce70` и `0x143c1cfd0`: слот `+0x7b0` у объекта из поля `+0x300`;
- `0x14432beb0`: большой участок с вызовом через поле `+0x158`;
- `0x1454fc6f0`: общий базовый конструктор владельцев.

Эти участки прочитаны статически и не исполняются новым replay. Два первых
не считаются вызовами того же класса только по номеру слота. Для них сохранены
аналитические имена `OwnerDispatch_CandidateA/B`; для большого участка —
`OwnerDispatch_CandidateD`. Проверенный участок пока остаётся
`OwnerDispatch_CandidateC`, поскольку исходное C++ имя не установлено.

Базовый конструктор вызывает `0x145392fe0`, устанавливает таблицу
`0x149886190` и инициализирует несколько полей. Его полное исполнение и
типовая цепочка до объекта движка ещё открыты; в прежнем replay он перехвачен.

Следующее действие — найти запись в поле `+0x158` и источник выбора класса,
сверить класс с доступными данными уровня, затем связать загрузку после ID110.
Не выдавать тестовую подстановку указателя за настоящее создание мира.
Мировая позиция и реальная серверная сессия также остаются открытыми.
