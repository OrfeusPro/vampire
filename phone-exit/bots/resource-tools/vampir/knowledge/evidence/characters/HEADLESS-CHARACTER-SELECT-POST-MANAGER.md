После применения данных ID110 обработчик получает отдельный singleton,

конструктором, getter и таблицей менеджера, вместо прежних перехватов.

Это ещё не установленный запуск ID201. Смысл конкретных получателей и их

## Идентичность получателя

Конструктор `0x1455808c0` записывает this в глобальный адрес `0x14b573528`
и устанавливает таблицу `0x1498ab150`. Getter `0x14558ee60`, точные байты
`48 8b 05 c1 46 fe 05 c3`, читает этот глобальный адрес.
В сценариях исполняется конструктор, проверяется записанный указатель,
затем настоящий getter вызывается обработчиком ID110.

Этот singleton отличается от сервиса перемещения:

| Объект | Getter | Таблица | Цель слота `+0x60` |
| --- | --- | --- | --- |
| Менеджер после ID110 | `0x14558ee60` | `0x1498ab150` | `0x1455967f0` |
| Сервис перемещения | `0x1456048e0` | `0x1499f11f0` | `0x145dc29c0` |

Проверен ложный кандидат `0x145c8c380`: перед вызовом `0x145c8c425`
через слот `+0x60` стоит getter `0x14558ee60`. Совпадение номера слота
не связывает этот вызов с ID201. Его инструкции сохранены в отчёте;
полностью этот кандидат новым сценарием не исполняется.

## Настоящая последовательность после принятия ID110

1. `0x145596150` сравнивает `manager+0x2728` с 64-битным значением
   `packet+0x20` и при различии записывает его. Назначение поля не выводится
   только из совпадения этого числа с полями других менеджеров.
2. Слот `+0x58` таблицы указывает на `0x1455910d0`. Он обходит индексы
   0–204, вызывает запрос политики через слот `+0x38` и при false обращается
   к `0x144aa3f40`. В проверенном профиле этот backend отсутствует, поэтому
   ветви чтения конфигурации не выполняются. Все 205 обращений проверены.
3. `0x14558d3f0` снова обходит 205 записей с шагом `0x30` от `manager+0x50`.
   Записи 146 и 147 исключены. Для остальных проверяются флаг `+0x69`,
   ненулевой count `+0x78` и ненулевой указатель объекта `+0x70`
   (все смещения — от менеджера с добавлением `index*0x30`).
4. При выполнении всех трёх условий вызывается слот объекта `+0x60`,
   которому передаётся u32 из `manager+0x54+index*0x30`.

Число 205 здесь — число записей менеджера, не доказанный диапазон packet ID.
Типы и назначение этих записей ещё не установлены. Не считать получателей
обработчиками пакетов или отправителями резервирования без связи с их кодом.

## Проверенные сценарии

Восемь полных сценариев исполняют чтение ID110, фильтр, применение данных,
setter состояния и описанное продолжение в одном эмуляторе:

- свежий менеджер без получателей;
- все записи с активными получателями: 203 вызова по порядку;
- отдельно выключенный флаг, нулевой count и null-указатель: вызовов нет;
- отклонённый код 1;
- код `0x1197` при байте менеджера фильтра 0 / 1: продолжение разрешено /
  отклонено соответственно.

При принятии проверен порядок setter → slot `+0x58` → refresh и запись
исходного значения пакета в `+0x2728`; состояние сервиса равно 1.
При отклонении методы менеджера не вызываются, исходное поле сохраняется.

## Границы и дальнейшая работа

Получатели и их таблицы заданы тестом; их слот `+0x60` только записывает
аргумент и индекс. Запрос политики возвращает false, backend конфигурации
отсутствует. Остальные ветви `0x1455910d0` не исполнены. Прежние границы
диагностики, интерфейса, вложенного применения данных и игрового объекта
сохраняются. Чтение пакета и вызов обработчика локальные, сервер не использован.
