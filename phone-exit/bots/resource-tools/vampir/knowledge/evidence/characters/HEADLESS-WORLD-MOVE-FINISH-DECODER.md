## Непустые массивы

Исполнены 16 полных тел: каждый из пяти массивов отдельно с 1, 2 и 8 элементами,
затем все вместе с двумя элементами. Входы содержат Unicode, граничные целые,
enum за пределами диапазона, bool со значением 255, присутствующие и отсутствующие
необязательные данные, signed zero. Все 309 коротких префиксов совместного
тела отклонены без чтения за доступной границей.

Native callbacks, конструкторы, функции чтения элементов и append исполняются.
Выделение storage ограничено восемью элементами и заменено явной границей.
Очистка временных объектов перехвачена; настоящее время жизни аллокаций
и повторное использование уже заполненного объекта не проверены.

Новый элемент массива `packet+0xe8` имеет native stride `0x78`:

| Поле элемента | Wire-чтение |
| --- | --- |
| `+8` | Байт enum с пределом 5 |
| `+0x0c` | u32 |
| `+0x10` | u64 |
| `+0x18` | Ещё один u64 без преобразования |
| `+0x28` | Bool наличия вложенного значения |
| Вложенное значение `+0x30` | При наличии: три float32, затем байт направления |

Биты трёх float32 расширяются в double в native-полях `+0x38/+0x40/+0x48`.
Байт направления проходит ранее подтверждённую нормализацию; общий декодер
сохраняет исходный wire-байт. При отсутствии значения его представление в
общем декодере — `None`, а не выдуманные координаты.

Остальные схемы переиспользованы из проверенных участков ID102/ID110:
внешность `+0x78` с массивом `+0x30`, массив `<IQ>` в `+0xb8`, большой элемент
с необязательными тремя float32 в `+0xc8`, массив u32 в `+0x100`.
Неизвестные поля не получают названия игровых идентификаторов или единиц времени.

## Общий API

`vampir_core.world_move_finish_result.decode_world_move_finish_result` принимает
immutable `bytes` и обязательные `max_payload_size` / `max_collection_items`.
Размер ограничен диапазоном 81–16777215, общий лимит записей — 0–65535.
Лимит суммируется по всем пяти массивам. Обрезанное тело, лишний хвост,
некорректный UTF-8 и превышение лимита отклоняются.

Возвращается неизменяемый `WorldMoveFinishResultBody(result_code, data)`.
Данные скрыты из `repr`. `data` использует существующий `SelectionRecord`:
доступ по native-смещению через `.at(offset)`, таблицы виртуальных функций
опущены. Код результата остаётся 32-битным значением без проверки принятия.

Вектор `data.at(0x30)` — `WireVector3` с исходными битами float32.
Направление `data.at(0x48)` — `WireHeading` с исходным байтом. Эти типы
переиспользованы из общего декодера ID110. Семантика мировой позиции не
выводится из имён типов или успешного чтения.

Элемент массива `data.at(0xe8)` сохраняет скаляры по смещениям таблицы выше;
поле `.at(0x30)` содержит `None` либо вложенную запись с вектором `.at(8)`
и направлением `.at(0x20)`. В большом массиве `+0xc8` необязательные float32
сохраняются как исходные u32-биты в полях `+0x58/+0x5c/+0x60`.

## Единое чтение и обработчик

Семь сценариев сохраняют один экземпляр эмулятора: сначала исполняются чтение
и обработчик ID110, затем настоящий конструктор и чтение тела ID206, после
чего полученный объект передаётся его настоящему обработчику. Ручной объект
ID206 из прежнего тестового setup не поступает в обработчик.

Проверены коды 0, 1 и `0x1197` при двух значениях байта фильтра, а также тело
со всеми непустыми массивами. Принятые ответы проходят `0x1467a5d30` →
`0x145dbef80` → virtual `+0x78` → базовый метод → запись состояния 6.
Отклонённые ответы сохраняют состояние 1. Счётчик ссылок возвращается к 2.
Поле `packet+0x20` доходит до сервиса и `player+0x1f8`; элемент `+0xe8`
передаёт нормализованный enum и два исходных скаляра в границу `0x145679730`.

Сам вызов диспетчера тестовый. Приход ID206 после ID110, сетевой триггер,
жизненный цикл загрузки и настоящий игровой объект не подтверждены. Поиск
и создание actor, UI, SDK, диагностика и внешние применения данных остаются
границами из предыдущего отчёта обработчика. Сокет не используется.
