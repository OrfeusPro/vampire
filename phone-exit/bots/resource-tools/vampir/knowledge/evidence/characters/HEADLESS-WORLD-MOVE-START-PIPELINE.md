## Полный путь ответа

`0x1458429f0` создаёт объект пакета; `0x145845140` читает тело из 30 байт
через настоящий архив и преобразование вектора. Тот же объект передаётся
в `0x1467a61a0`. Его вызов диспетчером тестовый; тело пакета не подменяется
синтетическими полями между чтением и обработчиком.

Обработчик исполняет getter ID204 из настоящей таблицы, затем общий
`Result_Gate` / `0x1467a8e10`. Код 0 принимается. В проверенных сценариях
код 1 отклоняется; код `0x1197` принимается при байте менеджера, отличном от 1,
и отклоняется при 1. Это проверка конкретных ветвей фильтра, не классификация
всех серверных ошибок. Интерфейс ошибки перехвачен на `0x1466fa250`.

При принятии исполняется настоящий tail jump к `0x145dbf720`.
Подтверждены записи:

| Источник | Назначение |
| --- | --- |
| `service+0x40`, прежний ID мира | `service+0xf4` |
| `packet+0x14`, новый ID мира | `service+0x44` |
| 24 байта вектора `packet+0x18` | `service+0x60` |
| Нормализованный enum `packet+0x30` | `service+0x59` |

Поле `service+0x40` этим методом не меняется. При отклонении данные назначения
остаются исходными. Вектор переносится побайтно, включая signed zero;
использование его как мировой позиции ещё не проверено.

## Ветви продолжения

Фактические вычисления сервиса исполняются. Ответы следующих внешних методов
заданы тестом и не считаются доказательством их настоящей семантики:

1. Слот сервиса `+0xa8`, адрес `0x145dc0830`. При true сервис вызывает
   вспомогательный метод другого сервиса, `0x145decbc0`, получает метку через
   слот `+0xc8` и вызывает `SelectionService_SetState` / `0x14560a400` с новым
   ID мира. Метка и SetState здесь перехвачены; настоящий loader не запускается.
2. При false проверяется `0x144aaaab0`. Если этот внешний метод возвращает
   true, сервис вызывает вспомогательный метод и слот `+0x70` / `0x145dc2930`.
   Состояние 5 предварительно переводится настоящим setter в 2. Затем настоящий
   guard ID205 разрешает отправку и пишет 5. Для состояний 2 и 4 тоже получен
   пакет; из состояния 1 пакет не готовится.
3. Если оба внешних условия false, исполняется подготовка через слот `+0x30`,
   затем вычисляется условие повторного использования текущего мира:
   ID из `+0x40` равен новому `+0x44`, и либо новый enum равен 3, либо прежний
   enum равен 3, новый равен 0 и bool ответа истинный.
4. При выполнении этого условия вызывается `0x1456907a0` с u64 из
   `packet+0x38`. В сценариях он возвращает false; сервис доходит до настоящего
   запроса ID205. Состояния 2–4 разрешают пакет и переход в 5, состояния 1 и 5
   сохраняются без пакета. Ветка задержки при true здесь не исполняется.
5. При невыполнении условия повторного использования и причине `service+0xf0`
   равной 24 сервис передаёт указатель на себя в `0x145da8510`. Это перехваченная
   граница продолжения. Другие причины ведут через отдельную задачу движка;
   исполнение её callback здесь не проверялось.

## Проверки и границы

35 полных сценариев покрывают принятие / отклонение, два внешних условия,
состояния 1–5, совпадающие / разные ID мира, сочетания enum и bool, enum 255
с ограничением до 22 и код 0 при байте менеджера 1. Три теста проверяют
воспроизводимость, перенос данных и различия эффектов ветвей.

При подготовке ID205 исполняются настоящий guard, конструктор заголовка
и setter состояния. Отправка перехвачена до I/O: проверяются таблица пакета
`0x149919e68` и флаг `+0x0a == 1`. Полный кадр и очередь уже проверены
[отдельным сценарием ID205](HEADLESS-WORLD-MOVE-FINISH-SEND.md).

Состояние после выбора задано явно; настоящий ID110 в этом сценарии не читается.
Перехвачены диагностика, получение внешних менеджеров, конфигурация прежнего
мира, подготовка игрового объекта, оба внешних условия выбора ветви, проверка
u64, интерфейс и границы загрузки / отправки. Списки слушателей пусты;
коррекция вектора по внешней настройке выключена. Приход пакета от сервера
и влияние остальных подсистем не подтверждены.
