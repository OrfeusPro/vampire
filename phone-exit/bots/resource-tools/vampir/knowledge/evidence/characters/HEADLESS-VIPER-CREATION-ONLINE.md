# Silvercrow — Viper создан на Canon 1

Команда `run-bounded-create.py` через прямой выход создала Viper
**Bipoberiho** на EU Canon 1 / 387. Game Login и Create Result 104 приняты
с кодом 0. До Create то же соединение вернуло принятый пустой список.
Одна игровая попытка записана в постоянном журнале.

Отдельный последующий вход прочитал принятый список с одним персонажем.
Имя и ключ совпали с Create Result. Подтверждённый ключ
`649946739230497792` и слот 0 назначены в существующей панели;
состояние журнала — `existing_verified`.
[Машинный результат](SILVERCROW-CREATE-CURRENT-ONLINE.json).

## Исправление границы входа

Первый запуск остановился в прежнем top-level ограничении профиля
до SDK и игрового соединения. Create не ставился в очередь,
попытка в журнале не создавалась. Нижние guards уже поддерживали новый
capability, а внешний entrypoint ещё требовал `recovered-release`.
Он исправлен с проверкой точного текущего Create scope и его родительского
entry selector. Новая регрессия вызывает настоящую входную функцию:
без capability отказ происходит до авторизации, с capability достигается
ветка source validation. После исправления четыре profile/runner теста
и source check прошли. Следующий запуск создал персонажа.

## Границы результата

Онлайн подтверждены один аккаунт, один сервер, создание выбранного Viper
и последующее чтение identity. Модель внешности и явная Latin JSON policy
описаны в [пакете factory](HEADLESS-VIPER-CREATION-CURRENT.md).
Точное совпадение загруженного экрана и внешний вид не проверялись.

Проверочные соединения завершены после списка. Выбор персонажа, world finish,
независимый постоянный owner и подтверждённый серверный default flag требуют
следующего пакета. Остальные семь аккаунтов ещё не запускались.
