## Настоящий путь получения строк

`0x145dc0830` дважды вызывает сервисный слот `+0xc8` / `0x145dc3f30`:
с ID из `service+0x40` и с ID из `service+0x44`. Метод выполняет lookup
`0x145c5d860`, hash `0x145c60180`, accessor `0x141482990`, затем слот записи
World `+0x20` / `0x141482e60`, возвращающий FString по `record+0x48`.
Связь этого поля с колонкой LevelPath установлена
[прежним разбором World](HEADLESS-WORLD-STATE-LABEL.md).

Эти функции исполняются вместе с предикатом. Записи создаются настоящим
конструктором World; исполняется блок записи LevelPath из парсера. Аллокация
реестра, getter реестра, копия пустого шаблона и операции FString остаются
ограниченными тестовыми границами. При отсутствии записи слот возвращает
пустой FString с Num 0.

## Правило сравнения

Проверенный код сначала сравнивает FString.Num, включая завершающий NUL:

- Одинаковые Num меньше 2 дают false без чтения символов.
- Одинаковые Num от 2 сравниваются функцией `0x1414596e0`.
- Разные Num дают true, кроме случая, когда сумма равна 1. Поэтому пустые
  FString с Num 0 и Num 1 считаются одинаковыми.

Строковая функция читает UTF-16 code units. Одинаковые символы продолжают
цикл до NUL. Различающиеся ASCII-символы проходят через встроенную таблицу,
которая уравнивает верхний и нижний регистр. При различии с не-ASCII символом
сравниваются сами code units. Поэтому `Level/A` и `level/a` дают false,
а `Ж` и `ж` — true. Полное Unicode-приведение регистра не выполняется.

Проверены 81 сочетание путей и отсутствующей записи, а также четыре сценария
с выделенной пустой строкой Num 1. Fixture копирования FString сохраняет это
представление: преобразование через Python `''` незаметно заменило бы Num 1
на Num 0 и не проверило бы нужную ветвь.

## Текущие строки World и композиция с ID204

Повторно запущена существующая проверка источников World: SHA CSV, актуальные
снимки извлечений, отпечатки и полные SHA базового / patch-архива. Использованы
реальные строки World.Id 1 / 2 с путями `Lobby/Title` и
`Lobby/CharacterSelect/CharacterSelect_02`. Для двух источников исполнены
по пять запросов, включая Id 3, не представленный в тестовом реестре из двух
выбранных строк. Это проверка данных установки,
не реестра работающей игры или приоритета монтирования.

Шесть дополнительных сценариев составлены с прежним ID204 pipeline:

| Условие | Наблюдаемая граница продолжения |
| --- | --- |
| Один ID и один путь, enum 3, состояние 2 | Настоящий guard готовит ID205 и пишет 5 |
| Разные ID, одинаковые пути с разным ASCII-регистром | Callback `0x145da8510`; SetState не вызывается |
| Разные пути | Вызов SetState с новым ID мира |
| Один путь отсутствует, второй непустой | Вызов SetState с новым ID мира |
| Оба пути отсутствуют, ID разные | Callback `0x145da8510` |
| Ответ ID204 отклонён | Предикат не вызывается |

Это явная композиция двух эмуляторов: после чтения ID204 и применения данных
сервиса берутся фактические `+0x40/+0x44`, передаются второму эмулятору с
нативным lookup / предикатом, а вычисленный bool возвращается первому.
Состояние не считается общим живым реестром. Предикат не заменяется Python-
сравнением строк; Python используется только для независимой проверки результата.

## Ограничения и продолжение

Проверены 101 сценарий и три теста. При обоих отсутствующих путях native-код
возвращает false; это не разрешение боту двигаться по неизвестному уровню.
Вызовы SetState / callback и отправка пакета остаются границами, loader и сокет
не работают. Источники второго транспортного условия и u64-проверки ещё открыты.

Дальше — инициатор резервирования после ID110 и отправка ID201–203, затем
проверка реального порядка ответов. Прямых E8-вызовов `0x145dc29c0` и
`0x145dc2e60` существующий scanner не нашёл; проверенные вызовы идут через
слоты сервиса `+0x60/+0x68`. Это ограниченный поиск, не доказательство
отсутствия других форм вызова. Реальный вход, устройство и мировая позиция
остаются открытыми.
