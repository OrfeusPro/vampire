# Владелец вне дерева Codex: одноразовая задача Windows

26 октября 2026. Это изменение запуска Python, не новая роль native-кода игры.
Предыдущая проверка breakaway доказывала выход dispatcher, а не перезапуск Codex.
После перезапуска пользователем API 17947 отказал в соединении, PID 32636
и 43344 отсутствовали, listener 1087 отсутствовал. Нового game-result.json нет.
Перед этим та же Redmi-сессия имела uptime 2523,5 секунды, heartbeat 496 / 496.
Windows загружена в 12:05:41, проверка выполнена в 18:49:38: перезагрузки ОС
между этими наблюдениями не было. Точная причина завершения процессов неизвестна;
ответ BlockedIp для этого завершения не получен. Автоматический вход не повторялся.

## Изменение

`run-live-sessions.py --detached` теперь использует `scheduled_worker.py`:
одноразовая задача Task Scheduler под текущим вошедшим пользователем,
interactive token / RunLevel 0, без триггеров, повышения прав и пароля Windows.
Задача запускает windowless Python непосредственно как владельца, вне ancestry
вызывающего приложения. После readiness определение задачи удаляется;
это не автозапуск и не системная служба. Обычный API Stop и 24-часовой timer
игрового владельца сохраняются. При неудачном запуске собственная задача
останавливается и удаляется. Перехода к старому способу скрытно нет.

Параметры и пароль передаются ограниченным anonymous pipe (до 1 MiB).
Задача получает только PID dispatcher и числовые значения двух pipe handles;
DuplicateHandle запрашивает PROCESS_DUP_HANDLE, без чтения памяти процесса.
Параметры игрового запуска, email и пароль не записываются в action / argv /
XML задачи или на диск. Запускаемый script и UTF-8 Python проверяются до
регистрации; произвольный EXE этим helper не поддерживается.
Readiness ограничен 64 KiB. В stdout остаётся только startup acknowledgement;
затем игровой worker направляет вывод в NUL прежним ready_channel.

Первая проба обнаружила две реальные границы: PowerShell stdin требует явного
UTF-8 для пути пользователя с кириллицей; планировщик запрещает BREAKAWAY
с PermissionError / 5. Поэтому задача выполняет Python script в собственном
процессе через runpy, не создаёт ещё один breakaway child. Проверка не требует
изменения прав, политик Windows или настройки защиты.

## Доказательство и ограничения

`test_vampir_scheduled_worker.py`: 2 теста на настоящем Task Scheduler прошли.
Тестовый worker получает synthetic Unicode secret через pipe, поднимает loopback
HTTP; launcher затем принудительно завершается вместе со всем своим деревом
через taskkill /T /F. HTTP продолжает отвечать и закрывается явным Stop.
При отсутствии readiness task останавливается и удаляется; неверная команда
отклоняется до регистрации. После тестов PhoneExit-OneShot-* задач нет.
Тестовый worker имеет собственный timer; фоновых процессов без владельца нет.

Также прошли прежние 3 breakaway-теста и 8 тестов live sessions, включая
50 synthetic accounts, изоляцию Stop и срок жизни. CLI --help проверен.
Эти тесты не авторизуются в игре и не отправляют игровых команд.

Это подтверждает границу дерева процессов на synthetic HTTP worker, а не
перезапуск самого Codex с новым онлайн-персонажем. Новый реальный вход,
сохранение game owner **и транспорта** после такого перезапуска и несколько
реальных аккаунтов остаются непроверенными. Старый private transport helper
ещё использовал прямой breakaway; следующий запуск транспорта должен тоже
использовать отдельного владельца вне дерева Codex и сохранить свой Stop / TTL.
Старую Redmi-сессию нельзя показывать онлайн по сохранённому снимку.
