## Создание объекта: пока статическая связь

`0x1468ea580` получает менеджер через `0x14558ee40`, выделяет `0x260` байт,
устанавливает таблицу shared control block `0x1499e7460` и вызывает
конструктор `0x145d5b0e0` для объекта по смещению `+0x10` от выделенной памяти.
Пара указателей сохраняется в `manager+0x38/+0x40`.
Именно эту пару читает проверенный ранее `0x145c8ba50` в обработчике ID110.

Конструктор вызывает базовый `0x145d5ae60`, затем устанавливает таблицу
объекта `0x1499e1a68`. В ней слот `+0x60` указывает на `0x14292acb0`:
он записывает переданный байт в `object+0x140` и возвращается.
Слот `+0x80` / `0x145d65a60` имеет дополнительные условия и lookup;
его нельзя заменять постоянным результатом при описании реального клиента.
Слот `+0xa0` / `0x145206320` копирует пару из `object+0x80/+0x88`
и увеличивает weak reference count, если control block присутствует.

В новом replay создание объекта и эти виртуальные методы не исполняются.
Там сохраняется прежняя тестовая таблица объекта; граница явно указана
в отчёте. Полный конструктор требует отдельной проверки вложенных объектов.

## Применение ключа: исполненная цепочка

Настоящий `0x145d61e60` копирует u32 `main+0x30` в `player+0x10`, затем:

1. Вызывает `0x1458819c0` с этим ключом.
2. Lookup получает реестр через `0x145889c80` и передаёт ключ в `0x145889510`.
3. Find выбирает bucket, обходит цепочку записей с шагом `0x1c8`, сравнивает
   исходный u32 и возвращает адрес значения `entry+8` либо null.
4. Accessor `0x141482990` читает указатель из descriptor `+8`.
   Он сохраняется в `player+0x138`.

Исполняются reader → фильтр результата → handler → применение → lookup →
find → accessor. Getter реестра перехвачен и возвращает тестовую таблицу:
инициализация TLS и живые данные игры здесь не проверяются.

Проверены пустой bucket, совпадение первой и последующих записей, промах
после коллизий, inline / выделенные buckets и ключ `0xffffffff`.
Отдельно исполнен ранний возврат пустой таблицы, когда счётчики `+0x20`
и `+0x4c` равны, хотя в выделенной памяти осталась совпадающая запись.
Структура таблицы ограничена валидными конечными цепочками; повреждённый
реестр и циклы не считаются поддержанными входами.

## Границы и следующий шаг

Нативный getter реестра возвращает singleton `0x14b14be80`. Найденные
`0x14588b390` и `0x14588b600` обходят его записи; наличие этих функций
не доказывает название исходной таблицы. Нужна связь с её регистрацией
или parser и именами столбцов.

Перенос `main+0x188` в `player+0x20` подтверждён прежним replay, но пока
остаётся переносом сырого вектора. Мировая позиция и текущий мир не доказаны
этим lookup. Сетевой runtime сохраняет нейтральные имена полей.
Реальная сессия, подтверждение устройства и продолжение состояния 1 открыты.
Для будущей карты использовать уже созданный атлас и навигационные данные,
указанные в главном README; привязку живых координат ещё нужно проверить.
