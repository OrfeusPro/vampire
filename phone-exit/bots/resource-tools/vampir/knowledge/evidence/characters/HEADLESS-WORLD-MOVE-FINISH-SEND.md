## Условие и записи состояния

Исполнены все 256 значений `service+0x30` при нулевом `service+0xc1`.
Запрос подготавливается только из состояний 2, 3 и 4. Функция условия
сначала записывает состояние 5 через настоящий `0x1456140f0`, затем разрешает
продолжение. Повторный вызов из состояния 5 возвращает 0 до подготовки пакета.
Из состояния 1, оставленного ID110, этот запрос не отправляется.

Дополнительные пять сценариев с `service+0xc1 == 1` исполняют ветвь подготовки
отложенного перехода: виртуальный слот метки `+0xc8`, затем настоящий
`0x14560a400`. Объект UI отсутствует, поэтому состояние становится 3,
флаг `+0xc1` сохраняется равным 1, отправки нет. Метка и преобразование строки
перехвачены; исполнение настоящего планировщика не подтверждено.

После разрешения запроса метод `0x145dc2930` записывает:

- `service+0x150 = 0`;
- `service+0x158 = 1`;
- `service+0x154 = max(float(config+0x238), minimum)`.

Значение конфигурации читается как signed i64, преобразуется в float32.
Минимум взят из фактических байтов `17 b7 d1 38` по адресу `0x14898d130`:
приблизительно `0.0001`. Проверены ноль, отрицательные значения, 1,
`2**40` и границы signed i64. Назначение и единицы служебных полей пока не
доказаны; они не выдаются за реализованный таймаут runtime бота.

## Кадр и общий модуль

Захваченный после настоящего конструктора заголовок передаётся в отдельное
исполнение `0x1467aaa10` → send-B → writer → CRC/XOR → очередь.
Это явная граница композиции двух сценариев, а не единый непрерывный вызов
от условия до очереди. Первый вызов virtual send в сценарии условия перехвачен.

Проверены четыре кадра: номера последовательности 0, 1 и 65535, нулевой
и ненулевой ключи, переход номера с 65535 на 0. Каждый кадр содержит 11 байт:
трёхбайтовая длина, CRC32, ID и номер последовательности; тело пустое.
При нулевом ключе применяется ранее подтверждённый резервный XOR-ключ.
Очередь владеет копией байтов, уведомление о пробуждении перехвачено.

В общий `vampir_core.send_frame` добавлен
`encode_world_move_finish_frame_b(sequence, key_bits)`. Результат совпал
побайтно со всеми четырьмя native-кадрами. API не выполняет I/O, не меняет
номер последовательности и не определяет готовность к отправке. Условия
завершения перемещения должен установить вызывающий код по реальной сессии.
