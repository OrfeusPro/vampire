# BinExport / BinDiff: сравнение сборок

Добавлены как отдельные offline инструменты исследования. Они помогают искать
кандидатов адресов между сборками; совпадение, включая similarity / confidence 1,
не подтверждает роль функции, совместимость протокола или готовность runtime.

## Закрепление и установка

- BinDiff 8, официальный MSI с действительной Authenticode-подписью при загрузке.
  MSI извлечён через административный образ, системная установка не выполнялась.
- BinExport commit `1fc1d734db5924c9bc9067ae244cb9b94c94efcb`, собран под
  установленную Ghidra 12.1.4 с отдельной JDK 21 и Gradle 8.14.3.
- Архивы и SHA закреплены в [lock](../../../binary-diff-tools.lock.json),
  Maven / Gradle зависимости — в
  [verification metadata](../../../binexport-verification-metadata.xml).
  Повторная сборка использует strict dependency verification.

Официальные источники: [BinExport](https://github.com/google/binexport),
[BinDiff](https://github.com/google/bindiff). Готовый опубликованный Ghidra ZIP
относится к 11.0.3, поэтому для нашей версии использована сборка исходников.
Интеграция Ghidra у upstream имеет Tier 4; успешная сборка сама по себе
не подтверждает корректность каждого найденного соответствия.

Установщик и команды:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/binary-diff.py install
python -X utf8 phone-exit/bots/resource-tools/vampir/binary-diff.py export --source '<EXE snapshot>' --project '<existing .gpr>' --program ProjectRED-Win64-Shipping.exe
python -X utf8 phone-exit/bots/resource-tools/vampir/binary-diff.py compare --primary '<old export manifest>' --secondary '<new export manifest>'
python -X utf8 phone-exit/bots/resource-tools/vampir/binary-diff.py candidates --comparison '<comparison manifest>' --address 0x1467ce6a0
python -X utf8 phone-exit/bots/resource-tools/vampir/binary-diff.py prepare --comparison '<comparison manifest>' --address '<old address>' --question '<existing question ID>'
```

В последней команде адрес относится к **старой** сборке. Пути manifest берутся
из вывода предыдущих команд. Установка, исходники, логи, выгрузки и SQLite
результаты находятся в `F:/PhoneExit Resources/Vampir/`, вне Git и runtime.
Корень задаётся `--root` либо `PHONEEXIT_VAMPIR_RESOURCES`.
Для экспорта предусмотрен `--heap-gib 2|4|8|16`, по умолчанию 4 ГБ.
Лимит относится только к принадлежащей команде JVM. Старый большой проект
при первом прогоне заполнил стандартные 2 ГБ; процесс был завершён после
проверки его PID, сохранён лог, повтор запущен с 8 ГБ. Это не успешный замер
экспорта при 2 ГБ. Настройки других процессов Ghidra не меняются.

Java получает отдельный путь временных Unix domain sockets без кириллицы;
для Gradle используется системное хранилище сертификатов Windows. Проверка TLS
сохраняется, настройки защиты Windows и других приложений не меняются.

## Происхождение и применение

Перед экспортом проверяются полный SHA фактического EXE и SHA импортированной
программы Ghidra. Проект открывается `-readOnly -noanalysis`. Экспортируется
имеющийся разбор; нового полного autoanalysis и декомпиляции всего EXE команда
не запускает. BinExport может создавать временные определения функций в памяти;
они не сохраняются в исходный проект и не становятся подтверждёнными unwind roots.

Экспорт имеет manifest с SHA источника, инструмента, скрипта и результата.
Ключ повторного экспорта включает содержимое баз Ghidra: новый разбор того же
EXE получает отдельный результат. Прежний экспорт не перезаписывается.
Сравнение привязано к двум manifest и SHA базы. Повреждённые источники / выгрузки /
база отклоняются. Для Ghidra используется общий lock; команда ждёт завершения JVM.
Неоднозначные совпадения сохраняются, произвольные кандидаты не исполняются.

Дальнейший порядок: найти старый адрес через `candidates` → проверить начало
новой функции → `knowledge-index.py prepare` с новым адресом → использовать
готовый экспорт либо `collect` → сверить объявленные callees, данные, ветвления
и соответствующие contract checks → зафиксировать вывод через `finish`.
Эта команда пока не добавляет новый адрес в `update-contracts.json` автоматически
и не подменяет проверенный профиль. Отсутствие кандидата означает пробел покрытия,
а не отсутствие функции в EXE.

`binary-diff.py prepare` передаёт единственный найденный адрес в обычный research
workflow с полным SHA новой сборки и SHA сравнения в причине эксперимента.
Нулевой или неоднозначный результат останавливается до создания задания.
Это подготовка исследования, а не автоматическое подтверждение соответствия.

Offline тест `test_vampir_binary_diff.py` проверяет сохранение неоднозначности,
статус кандидата даже при максимальном confidence, отказ на изменённых входах,
повреждении инструментов и неизвестной схеме SQLite. Он не подтверждает
качество сопоставления всей игры. Время полного обновления измеряется отдельно.

## Фактическая проверка 23 октября 2026

[Машинная сводка с SHA и ручной очередью](BINARY-DIFF-RESULTS.json).
Текущий source SHA:
`d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.

Экспорт существующего текущего проекта получен за 221,713 секунды, размер
13 492 788 байт. Self-comparison дал 3 995 соответствий. Повтор сравнения использует
сохранённую базу; отдельно измерена проверка входов кэша. Для `0x1467ce6a0`
получен кандидат на тот же адрес и успешно создан обычный research request.
Это проверка работоспособности адаптера на одной сборке, не перенос адресов.

Полный экспорт большого исторического проекта SHA
`98802d550890354da73cfef101bc49c1691f104beccb8b6d878594ba8952807e`
не завершён. Второй прогон с лимитом 8 ГБ остановлен после 653,063 секунды;
working set достиг примерно 8,94 ГБ, с учётом памяти вне Java heap. Лог и
измерения сохранены, принадлежащий команде JVM завершён. Экспорт и сравнение
1.13.14 → 1.13.16 через BinDiff не объявляются готовыми. Это отдельная ручная
задача: ограничить / измерить большой экспорт перед следующим полным прогоном.
Другие инструменты сверки сохранённой пары этим результатом не отменяются.

Девять offline тестов адаптера прошли. Повторная установка проверяет закреплённые
файлы, тест кэша подтверждает отсутствие запуска Ghidra. Авторизация, игровые
действия и переключение профиля не выполнялись. Полный холодный экспорт не
включён автоматически в каждый update.
