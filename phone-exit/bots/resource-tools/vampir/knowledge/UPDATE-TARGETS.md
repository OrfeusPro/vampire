# Ориентиры для следующего обновления

Машинный план: [release-update-targets.json](release-update-targets.json).
Он хранит точный baseline SHA, полные diagnostic strings, их кодировку,
исторические функции и обязательные проверки. Это вход поиска, не runtime profile.
Добавлять ориентир следует после проверки его источника и инструкции, а не по
похожему имени. Исторические адреса из плана нельзя применять к новому EXE.

## Что выполняется автоматически

После завершения загрузки запускать обычный
[knowledge-index.py update](RESEARCH-WORKFLOW.md). При изменении EXE и без
`--audit-only` он вызывает `locate-release-update-targets.py`.

Инструмент сверяет полные SHA двух сохранённых EXE и точные строки. Ищет RIP LEA
к заданным строкам и проверяет инструкции только в связанных unwind roots:
не более 16 literals на ориентир, 32 roots на задание. Нет общего disassembly EXE,
автоматического обхода callees, запуска игры, авторизации или чтения её памяти.

Статусы:

- `candidate`: один корень с проверенными ссылками и без непроверенных ссылок
  на тот же ориентир. Это ещё не подтверждение роли или контракта.
- `requires_review`: строка отсутствует, несколько корней, ссылка попала внутрь
  другой инструкции либо диапазон не декодируется полностью. Сохраняются адреса
  и причины; произвольный адрес вместо них не выбирается.

Отчёты сохраняются по содержимому в библиотеке
`F:/PhoneExit Resources/Vampir/code-clues/update-targets/`. Одинаковые входы
используют тот же отчёт. Повреждённый источник отклоняется, прежний отчёт сохраняется.
`update` сохраняет результат в `native_targets`, ошибки и неоднозначности — в queue.
Старые profile, facts и baseline автоматически не продвигаются.

Отдельный повтор поиска без повторного чтения всех PAK:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/locate-release-update-targets.py --source-sha256 d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960
```

## Проверка на 1.13.16

Baseline EXE SHA256:
`98802d550890354da73cfef101bc49c1691f104beccb8b6d878594ba8952807e`.
Новый EXE SHA256:
`d00a197796b7cee30f46854b2a8579049726c2bfba542d359f41b3817ec8b960`.
Отчёт:
`code-clues/update-targets/443dd60a21695f3127bf30a4db2b1828550c23adcf6b3414385d0f2002200371/manifest.json`.

| Ориентир | Прежняя функция | Новый кандидат |
| --- | --- | --- |
| Полная diagnostic signature GetTokenByLauncher | `0x1444ef840` | `0x1444ee9d0` |
| Полная diagnostic signature SignInByLauncher | `0x144504980` | `0x144503b10` |
| ASCII IsInspect | `0x145810700` | Несколько ссылок; requires_review |

Для IsInspect два новых roots декодированы, ещё два имеют непроверенные границы
инструкций. В baseline тот же быстрый decoder не покрывает mapper целиком;
его прежняя роль доказана отдельным Ghidra/native исследованием. Поисковик не
считает неполную новую декодировку подтверждённым mapper.

Явный `prepare` двух launcher candidates показал missing exports и requires_port
для старых auth checks. `collect` сохранил причину очереди: отсутствует отдельный
Ghidra comparison project нового SHA. Проверки не обходились. Ни новый профиль,
ни живой вход результатом этого этапа не подтверждены.

## Что смотреть после кандидатов

В `manual_port_targets` записаны конкретные функции прошлого SHA, инструменты
и обязательные связи: SDK defaults / PC platform, GMC2 URL и headers, NMENV /
zone / market / client_id, launcher body и launcherToken header, ключи и callbacks,
Fetch / условия / первый SDK-профиль. Эти пункты требуют новых явных адресов;
автоматическое расширение дерева вызовов не подключено.

Ресурсные ориентиры также в плане: полный SHA / стабильность установки,
DefaultGame.ini / NetworkSetting, версия, prefix и CDN URL; patch revision из
windows.manifestlist. Извлечённые таблицы и карта требуют семантической сверки.

Пять offline тестов покрывают уникальность, неоднозначность, отсутствие строки,
ложный LEA внутри immediate, повтор без дубликата, повреждённый источник и ссылки
плана на существующие tools/checks. Ещё девять update tests проверяют в том числе
вызов поиска при новом EXE, сохранение отказа в очереди и запрет поиска в audit-only.
Fixtures не выполняют сетевые или игровые действия.

Дальше: отдельный проект Ghidra для нового SHA с импортом без общего анализа;
экспорт только явно запрошенных функций, затем перенос затронутых проверок.
