# Групповые проверки инфраструктуры

`automatic-update-tooling` сохраняет прежний fixture-only допуск. Его независимый
каталог `MODULES` находится в `test_vampir_update_automation.py`, группы и зависимости —
в `tooling-groups-v1.json`. Инструменты не запускают игру и не подтверждают
совместимость клиента. Native и online проверки остаются отдельными.

## Обычный путь

Штатное обновление и `research-scoped-v2.py` используют
`tooling-check-dispatch-v1.py`. Он проверяет групповые квитанции при каждом
вызове, включая изменение runtime и продолжение после сбоя. Другие check IDs
передаются прежнему runner без изменения разрешений. Старые v1 requests
сохраняют свой frozen workflow; их исторические квитанции не переписываются.

Каждый модуль назначен ровно одной группе. Его исходник входит в зависимости
этой группы; общие helpers могут иметь несколько потребителей. Полное покрытие
зарегистрированных зависимостей проверяется до запуска. Неоднозначные связи
сохраняются общими; группировка не объявляет их доказанными узкими связями.

Группа получает собственный ключ: упорядоченные модули, проверенное правило,
полные SHA входов, runner / worker и установленного Python / библиотек.
Изменение общего helper запускает его потребителей. Полный manifest и каталог
проверяются как управляющие входы; ключ отдельной группы использует её запись
и программную часть агрегатора без литерала `MODULES`. Добавление независимой
группы сохраняет пригодные квитанции прежних групп.

Workers работают в отдельных процессах с временными ресурсными ROOT, максимум
по два одновременно. Сохраняются стандартный unittest loader, собственные
`load_tests`, порядок внутри группы, повторяющиеся case IDs и причины skips.
Windows Job принадлежит runner: перед импортом tests выполняется handshake,
при timeout / отмене завершаются принадлежащие группе потомки.

## Запуск и продолжение

Из корня проекта:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/tooling-groups-v1.py
```

JSON различает `executed_groups` / `cached_groups`, фактически исполненные
и взятые из кэша cases / skips. Прокси обычного unittest не выдаёт кэшированные
cases за новый полный прогон. Квитанции и журналы находятся вне Git в
`F:/PhoneExit Resources/Vampir/knowledge/tooling-groups-v1/`.

Завершённые группы сохраняются сразу после полного барьера их входов и runtime.
После обрыва обычный повтор использует эти результаты. Failed / timeout
сохраняются как конкретный результат; повтор разрешается явно:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/tooling-groups-v1.py --retry-failed
```

Повреждение pointer / receipt / worker result / log отклоняется; скрытого
повторного исполнения нет. Несколько владельцев одного кэша блокирует OS lock;
после аварии процесс освобождает его штатным механизмом ОС. Полный итог публикуется
после свежей сверки всех входов. SHA сравниваются по содержимому, size / mtime
не служат допуском. Атомарный снимок всей файловой системы не создаётся.

`--cache-root` выбирает отдельный кэш, `--workers 1` ограничивает параллелизм.
`--workspace`, `--manifest` и `--registry` предназначены для отдельного checkout
и диагностических fixtures; они не разрешают произвольные shell-команды.

## Добавление проверки

Добавить модуль в независимый `MODULES`, ровно одну группу и зависимости
`automatic-update-tooling`. Новый исходник и каждый фактически используемый
helper должны входить в соответствующую группу либо в общие зависимости.
Учитывать импорты тестовых помощников за пределами `MODULES` и файлы, имена
которых строятся по семейству. Для закрытого списка регистрировать все
допустимые входы. Неизвестные связи оставлять общими.
[Разбор Version и фикстур](evidence/updates/HEADLESS-TOOLING-SHARED-DEPS-V1.md).
Изменение самого runner / worker требует нового результата по их SHA.

Проверить cold / warm путь и выборочную инвалидацию подходящими fixtures.
Сохранить доказательство и границы через `prepare → collect → finish`.
Групповой tooling результат не заменяет source-bound semantic проверки
и не может дать native / runtime admission.
