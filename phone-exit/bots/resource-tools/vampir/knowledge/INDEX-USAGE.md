# Поиск по существующим экспортам Vampir

Проверено 21 октября 2026. Инструмент [knowledge-index.py](../knowledge-index.py)
строит производную SQLite FTS5 базу из существующих Ghidra exports. Он не запускает
игру или Ghidra и не подключается к серверам. [План развития](INDEX-PLAN.md).

## Команды

Из корня репозитория `G:/OSPanel/home/vampire`:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py build
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py verify
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py status
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py search I_TID --release installed --limit 4
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py function 144555470 --release installed
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py callers 14455cb10 --release installed
```

По умолчанию база находится в
`F:/PhoneExit Resources/Vampir/knowledge/search.sqlite3`, вне Git и runtime бота.
Параметры `--root` и `--database` задаются перед командой. Корень библиотеки также
можно задать через `PHONEEXIT_VAMPIR_RESOURCES`. Нужны Python с SQLite FTS5 и
зависимости существующего инструмента `build-headless-sdk-config.py`.

`--release installed` вычисляет SHA установленного EXE. Можно явно указать полный
SHA, однозначный префикс от 8 символов или `all`. Если установленной версии нет в
базе, поиск завершается ошибкой: старые адреса не подставляются. Сборка сама не
создаёт snapshot новой версии. `search` ищет буквальную фразу; `function` возвращает
варианты экспорта и их наблюдения; `callers` — сохранённые связи вызовов.

Это объём существующих материалов, а не число всех функций игры. Источники:

- `c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`;

Поиск `I_TID` для установленной версии возвращает строки `0x14990cfb8` и
`0x14954010c`, ссылки на функции `0x14560c880` и `0x144558870` и пути к сохранённому
псевдокоду. Поиск адреса `0x144555470` и вызывающих `0x14455cb10` также проверен.
Повторная сборка без изменений возвращает `reused: true` с теми же количествами.

## Проверка происхождения и границы

Импортируются legacy `functions.json`, release `details.json` и `bootstrap.json`
из каталогов Ghidra библиотеки. Проверяются receipt, SHA отчёта и потребляемого
псевдокода, SHA immutable EXE snapshot и соответствие экспортированных байтов
инструкций и явных строк этому EXE. Исторические хеши скриптов сохраняются как
происхождение; совпадение старых скриптов с сегодняшними файлами не требуется.

Без receipt отчёт остаётся в inventory как `unverified`, код из него не
импортируется. Повреждённый проверяемый материал прерывает сборку. Новая база
подменяет прежнюю только после успешного импорта и проверки целостности.
Неизменившийся набор материалов повторно проверяется и используется без импорта;
при появлении новых материалов пока пересобирается вся база.

Разные версии одного адреса разделены. Повторные экспорты сохраняются как
наблюдения; неполный вариант не затирает полный. Timeout декомпиляции может дать
инструкции без псевдокода. `function_missing` хранится отдельно и не доказывает,
что функция существует по этому адресу.

Прямые `CALL` берутся из текста Ghidra с проверенными исходными байтами; это не
независимая повторная декодировка инструкций. Связи из старого поля `calls`
помечены отдельно как `reported_call`. Полнота косвенных вызовов, tail calls и
vtable не заявляется. Поиск строк дополнен ограниченным чтением данных по `LEA`
из уже экспортированных инструкций; это не полная выгрузка всех строк EXE.

Аналитические имена и совпадения строк не подтверждают роль функции. Роли,
вопросы, native replays, PAK, таблицы, UI и карты пока не включены в этот поиск.
Перед исследованием по-прежнему проверять `function-registry.py --query`,
`questions.json` и соответствующие evidence. Очередь новых экспортов, перенос
claims по версиям и общая автоматизация обновлений остаются следующими этапами.

## Тесты

```powershell
python -X utf8 -m unittest discover -s phone-exit/bots -p test_vampir_knowledge_index.py -v
```

Пять тестов проверяют разделение версий, варианты и повторную сборку, отсутствие
receipt, отсутствующие функции, timeout декомпиляции, поиск строки со ссылкой на
владельца, повреждение выходных файлов и байтов, выход пути за каталог receipt.
При ошибке прежняя база остаётся побайтово неизменной.
