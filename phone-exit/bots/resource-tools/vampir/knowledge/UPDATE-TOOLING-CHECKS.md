# Проверки инструментария без привязки к версии игры

`source_scope` разделяет два вида offline checks:

| Scope | Что доказывает | Привязка к SHA клиента |
| --- | --- | --- |
| `client` (по умолчанию) | Объявленный контракт кода/данных игры в пределах fixtures | Обязательна; другой SHA даёт `requires_port` |
| `tooling` | Работу инструментария на искусственных данных | Не нужна; совместимость клиента не подтверждает |

Простая смена флага не позволяет превратить native check в tooling. В
`research-workflow.py` есть явный список просмотренных пар ID/test pattern.
Для tooling требуются `offline_reviewed=true`, пустой `source_sha256`, отсутствие
`artifact_dependencies` клиента и `system_runtime_files`. Неизвестные scope,
чужой ID/pattern или смешение с клиентскими источниками отклоняются.

## Просмотренные наборы

- `update-contract-registry` — схема, зависимости и ограничения контрактов;
- `update-binding-closure` — поиск/замыкание функций на synthetic PE;
- `update-run-offline` — продолжение, кэш, повреждения, зависимости и builder
  на временной synthetic установке;
- `tooling-check-scope` — границы этой классификации и кэша.

Эти checks включены в `on_update`. Runtime distributions и все объявленные
исходники/зависимости продолжают проверяться по hash. Изменение теста, кода
инструмента или runtime инвалидирует кэш. Сам SHA игры в tooling cache key не
входит: report содержит `source_sha256=null`, `source_scope=tooling` и
`proves_client_compatibility=false`.

## Ограничения доказательства

`update-contracts.py` запрещает назначать tooling check обязательным
доказательством игрового контракта. `finish` выполняет такие checks как gates
инструментария, но не добавляет их к client evidence; для `bounded_native`
по-прежнему нужна прошедшая source-bound client проверка. Старые source-bound
facts и их reports не изменяются.

Кэш tooling не разрешает отправку команд, активацию профиля или перенос
непроверенных packet layouts/адресов. Остальные checks остаются `client`;
поддержка нового SHA не добавляется им автоматически.

## Фактическая проверка 27 октября 2026

4 новых теста scope, 14 регрессий research workflow и 6 тестов contract registry
прошли. Штатный `update --resume` выполнил все четыре tooling набора: 28 tests,
все passed. Три ложные строки переноса инструментальных тестов исчезли из
очереди: 148 → 145. Новый scope-check тоже сразу включён в автопроход.

После этого те же четыре checks вызваны с SHA прежней 1.13.16 при запрете
`subprocess.run`: получены буквально те же reports/cache keys, что для 1.13.18,
без нового запуска тестов. Это проверяет реальное переиспользование кэша, а не
только фикстуру unit test. Совместимость обоих клиентов из этого не выводится.

Журнал: `knowledge/update-runs/0e4e1d2aaa28535737a8648a5fdf28afc1e8fe0fa98e9d2bb009d9df214fb375/run.json`
в библиотеке ресурсов. Состояние `needs_review`, подготовленных профилей 0,
активация/baseline promotion false; обязательные SDK/игровые проверки остаются.
Новых Ghidra-запусков 0. Этапы после изменения ядра обновления были пересчитаны
по новым tool hashes; это автоматическая валидация, не ручной перенос игры.
