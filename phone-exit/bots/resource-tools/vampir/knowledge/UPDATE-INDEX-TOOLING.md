# Автоматическая проверка индекса знаний

`knowledge-index-incremental` переведён в `source_scope=tooling` после просмотра
всего `test_vampir_knowledge_index.py`. Это дополнительная пара в явном
allowlist, введённом в [разделении tooling/client](UPDATE-TOOLING-CHECKS.md).

Все PE и exports создаются тестом во временном каталоге; knowledge root тоже
подменяется временным каталогом и восстанавливается через cleanup. Настоящая
установка игры, Ghidra-процесс, сеть и игровые команды не используются.

14 тестов проверяют разделение SHA, варианты функций, добавочный импорт,
повреждение старых/новых материалов, receipts, удаление exports, пропущенные
blocks/fallthroughs, timeout и placeholder bodies. Они доказывают поведение
индексатора на fixtures, а не совместимость игры. Все 14 тестов прошли;
4 теста ограничений tooling scope также прошли.

`on_update=true` сохранён, фиктивный допуск единственного SHA 1.13.16 удалён.
В кэше остаются SHA исходников, runner, самого теста и metadata Capstone.
Изменение этих входов требует нового прогона. Без изменения входов версия
клиента не является причиной ручного переноса индексатора.

Tooling report содержит `source_sha256=null` и
`proves_client_compatibility=false`. Его по-прежнему нельзя использовать как
доказательство игрового контракта или native claim; runtime profile и игровые
checks сохраняют отдельные ограничения. Старые facts/reports не изменены.

Штатный `update --resume` 27 октября 2026 подтвердил `passed`: очередь
145 → 144 строки, то есть закрыто 6 из исходных 150. Новых Ghidra-запусков 0;
после изменения workflow этапы были пересчитаны по новым tool hashes.
