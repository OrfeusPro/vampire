# Возобновляемое offline обновление

`knowledge-index.py update` связывает аудит файлов, граф контрактов, поиск
привязок, явный экспорт, проверки и подготовку отдельного профиля. Процесс
не авторизуется, не отправляет игровых команд, не переключает ботов и не
продвигает подтверждённый baseline.

## Запуск и продолжение

Из корня репозитория:

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py update --baseline '<baseline manifest>' --plan-only
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py update --baseline '<baseline manifest>'
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py update --resume '<run.json>'
python -X utf8 phone-exit/bots/resource-tools/vampir/knowledge-index.py update-status --run '<run.json>'
```

`--baseline` и `--resume` взаимоисключающие. Для новой установки используется
`--install`; при продолжении берётся сохранённая установка. `--plan-only`
считает SHA и сохраняет план без Ghidra, native replay и профиля. Прежний
`--audit-only` также оставляет только аудит / план.

`update-status` читает журнал, показывает этапы, владельцев locks и ручную
очередь. Он не перепроверяет установленную игру: `installed_inputs_checked`
равен false, `results_current` для завершённого журнала — null. Свежесть входов
проверяется при `update` / `--resume`, включая полные SHA, а не только mtime.

## Определения и границы

[update-contracts.json](update-contracts.json) содержит ID контрактов,
зависимости, привязки по полному SHA, способы поиска, ID проверок, границы
покрытия и условия сборки профиля. Команды проверок определены только в
[research-checks.json](research-checks.json); ориентиры — в
[release-update-targets.json](release-update-targets.json) и его дополнительных
планах. Определения не дублируются в каждом результате.

Поиск поддерживает точные ориентиры, ограниченный prefix candidate,
явный direct call, constructor / vtable slot и уже проверенную привязку этого
SHA. Для перенесённого prefix candidate сравниваются объявленные callees,
данные и ветвления; неизвестный вызов или неоднозначность оставляют задачу
в очереди. Поддержка нового SHA в проверке не добавляется автоматически.

Недостающие unwind roots собираются последовательно пакетами до 32 адресов.
Готовые полные exports используются повторно. Обход дерева вызовов и полный
анализ EXE не запускаются. BinDiff остаётся отдельным источником кандидатов,
а не обязательным полным экспортом каждого патча.

Контексты связывают полный SHA EXE, фактические exports, зависимости и SHA
архивов. Если авторитетные логические пути ресурса неизвестны, используется
консервативная зависимость от архива; `logical_paths_verified: false` не даёт
оснований заявлять точность до отдельной таблицы. Граф умеет выбирать известные
логические пути, но scanner наблюдаемых строк не выдаётся за полный PAK index.

## Кэш и сохранность

Журнал, этапы, контексты, машинные проверки и профили сохраняются вне Git:

- `knowledge/update-runs/<ID>/run.json` — изменяемый журнал с digest payload;
- `knowledge/update-stages/` — неизменяемые результаты и зависимости этапов;
- `knowledge/update-contexts/`, `update-context-checks/` — контексты и replay;
- `knowledge/prepared-profiles/` — подготовленные профили, без активации.

Повтор сверяет сохранённые входы и SHA выходных файлов. Повреждённый артефакт
отклоняется, прежние факты и рабочий профиль не подменяются. Проверки используют
собственный кэш исходников / fixtures / runtime. Для Ghidra сохраняются владелец
и отдельный lock; второй экземпляр вместо работающего не запускается. После
аварии сначала проверяют PID и дочерние процессы, locks по возрасту не удаляют.

Зависимости инструментов разделены по этапам. Сборщик профиля перед обращением
к кэшу повторно проверяет выбранные native reports, их зависимости, exports,
сопоставление с portable helpers и CRT / locale. Отсутствие, повреждение или
два подходящих отчёта блокируют сборку; случайный «самый свежий» не выбирается.

## Готовность и измерения

Снимок установленной сборки, профиль `prepared_offline` и подтверждённый живым
входом профиль — разные результаты. Готовность считается по возможностям:
launcher, world-session, map, quests, game-ui. Успех launcher не закрывает вход
в мир. Для неполного контракта / проверки без нового SHA сохраняются конкретная
причина, evidence, затронутая возможность и следующая проверка.

Машинный отчёт не заменяет смысловые факты: вывод агента сохраняется через
`finish`. `wall_seconds` измеряет текущий прогон; сохранённые `phase_seconds`
для повторно использованных этапов относятся к их первоначальному исполнению.
Отдельно записываются проверки кэша, исполненные этапы, повторные использования,
новые context replay и завершённые запуски Ghidra. Это не замер времени будущего
патча или живой сессии.
`manual_tasks` считает строки очереди, включая причины незавершённых зависимостей;
это не обязательно число независимых исследований.

После завершения загрузки основанием служит изменение файлов. Среда рано утром
остаётся ориентиром; фонового расписания нет. Исследовательские инструменты,
Ghidra, native replay и база не включаются в лёгкий runtime бота.
