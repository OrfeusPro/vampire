## Идентичность пакета

`0x145cc64e0` вызывает `0x145758a70` для массива записей. Эта функция
устанавливает таблицу `0x1498f3fd0` и копирует массив в объект пакета.
В таблице:

| Слот | Метод | Подтверждение |
| --- | --- | --- |
| `+0x10` | `0x145730250` | Настоящий writer исполняется |
| `+0x20` | `0x145735cf0` | Reader экспортирован; здесь не исполняется |
| `+0x28` | `0x14576d250` | Байты `b8 f6 06 00 00 c3`, ID 1782 |
| `+0x38` | `0x14576d910` | Ссылка `0x14576d919` → ASCII `PktOptionSet` / `0x1498f4020` |

Запись создаётся настоящим конструктором `0x1457891a0`, 21 байт:
таблица `0x1498ec270`, индекс u8 в `+0x08`, значение u32 в `+0x0c`.
Writer записи `0x145787410` вызывается через её таблицу.

## Условия после выбора персонажа

Сохранён прежний путь чтение ID110 → фильтр → обработчик → производный
manager slot `+0x58`. Теперь его слот `+0x60` / `0x145cc64e0` исполняется
вместо перехвата, включая базовый `0x1455967f0`.

Для проверенного вызова индекса 27:

1. Базовый метод сравнивает прежнее значение с новым. Если оно совпадает,
   возвращает false и пакет не создаётся. Если различается, записывает новое
   значение в `manager+0x54+index*0x30` и продолжает локальные уведомления.
2. Производный метод требует найденную запись реестра и разрешающий аргумент
   вызова. Здесь этот аргумент передаётся настоящим slot `+0x58` и равен 1.
3. При байте `record+0x39 == 2` вызывается другой менеджер через
   `0x145d16660(index, value)`. Эта граница перехвачена; её протокол не назван.
4. Для остальных типов требуется ненулевой `record+0x38` и true от
   `0x144aaaaa0` для транспортного объекта. Только тогда готовится массив
   из одной записи, пакет и вызов отправки через транспортный слот `+0x38`.

Локальная запись значения выполняется и в сценариях, где серверного пакета нет.
Поля реестра и готовность транспорта заданы тестом, их живые значения не получены.
Назначение самой опции 27 по её номеру не угадывается.

## Полное тело writer

Writer пакета вызывает `0x1456e6460`: записывает u16 количества, затем
передаёт каждую запись в `0x144aa6c90` → item slot `+0x10`.
Последний helper — проверенные 16 байт с tail jump; его пять инструкций
и байты сохранены, ложная PE unwind-запись не создаётся.

Формат тела: `<H count>` + `count × <B index, I value>`, little-endian.
Шесть исполненных профилей содержат 0, 1, 2 и 8 записей, включая индекс 255
и значения `0xffffffff` / `0x80000000`. Writer сохраняет сырые значения,
не ограничивает индекс числом записей менеджера. Это не политика приёма сервера.
Число элементов в fixture ограничено восемью; произвольные размеры не проверены.

Значения двух реально подготовленных в сценарии пакетов переданы отдельному
эмулятору writer. Тела для индекса 27: `01 00 1b 01 00 00 00` и
`01 00 1b ff 00 00 00`. Это явная композиция двух локальных исполнений,
не полный кадр CRC/XOR и не сетевой приход / отправка.

## Проверки и дальнейшая работа

10 сценариев проверяют значение 0 / 1 / 255, совпадающее старое значение,
отсутствующую запись, запрещённую синхронизацию, отключённый транспорт,
отдельный тип сохранения и два отклонённых ответа ID110. Пакет готовится
в двух сценариях; три теста проверяют воспроизводимость, условия и wire-байты.

Allocator, lookup / accessor, копирование 16-байтовых записей, cache / profile
эффекты, очистка и транспорт перехвачены. Пакет с настоящей таблицей и данными
доходит до границы отправки; writer и архивные примитивы исполняются отдельно.
Полный frame / очередь / сокет для ID1782 и ответ сервера не проверены.
