# Коллекции Vampir

18 октября 2026: отдельный раздел `maps/collections/index.html`, общий пункт
«Коллекции». Основная карточка `?collection=ID`, предмет открывается в
`../loot/items.html?item=ID`. Навигационное исследование отложено по просьбе
пользователя; этот раздел не меняет выводы о проходимости карты.

По присланному пользователем примеру список переделан в широкие строки:
название и бонусы слева, иконки94px справа (76/66px на узком экране).
EnchantLevel выводится поверх иконки, Count>1 — отдельной меткой.
Имя/редкость/полное требование доступны в hover/focus подсказке; на телефоне
подсказка закреплена снизу, иконки перенесены под описание. Заголовок ведёт
в полную карточку с прежними подробными строками состава. Счётчики прогресса
и отметки регистрации из примера не имитируются: данных аккаунта нет.
Изменение оформления не добавляет игровых связей; manifest/SHA данных прежние.
CSS/JS имеют версию20261018-rows. Syntax и HTTP/deployed сверены;
визуальная проверка браузером по-прежнему не выполнена.

## Источники и воспроизведение

`python -X utf8 phone-exit/bots/resource-tools/vampir/build-catalog-pages.py`
разворачивает UI и вызывает `build-collections.py`. Только данные можно
пересобрать отдельным вызовом `build-collections.py`.

Библиотека `F:/PhoneExit Resources/Vampir`; входные CSV — `table-study/`,
индекс `index-pakchunk1-Windows.json`. Перед чтением проверяются SHA256,
полный заголовок и число записей. В каждой записи сохранены CSV entry и
номер записи с учётом заголовка. `maps/collections/manifest.json` содержит
все входные SHA, путь/SHA клиентского EXE, native diagnostics и ограничения.
Выход `collections.json` содержит состав, исходные условия, бонусы,
локализацию и ссылки на изображения с их исходным происхождением.

SHA256 текущего `collections.json`:
`8218798df48c381ade18042b08f2c531a46f1a421a1169d495736b2fc32692c3`.
При загрузке UI проверяет этот SHA по manifest; это проверка согласованности
локальных файлов, не цифровая подпись сервера.

| CSV | Роль и соединение |
|---|---|
| 51 | 6766 требований: GroupId → CSV53.Id; CollectType=1 → CollectParam=Item.Id; Count и EnchantLevel сохранены отдельно |
| 53 | 4079 групп: CollectionTabId → CSV54.CollectionTabId, OperationGroupId → StaticOperation.GroupId |
| 54 / 397 | 5 настроек категорий / английские CollectionTitle по тому же ID |
| 406 | Английские имена групп по Id; только буквальная подстановка ReplaceString1/2 из CSV53 |
| 1521 | StaticOperation: все строки группы без объединения Min/Max или накопления |
| 1427 / 486 | Отображение OperationType / имя и Desc по enum EOperationType |
| maps/loot/items.json | Уже собранные Item, имена, редкость, фоны и иконки с provenance |

`code-clues/native-enums.json`: ECollectionType::Item=1, EOperationType.
`code-clues/table-dependencies.json`: четыре native diagnostic строки
повторно сверены по байтам UTF-16LE в установленном клиентском EXE:

- offset160614034: Collection.GroupId → CollectionGroup;
- offset160611698: CollectionGroup.OperationGroupId → StaticOperation;
- offset160612130: CollectionGroup.DateTimeSetting → DateTimeSetting;
- offset160612562: CollectionGroup.FixedTermId → FixedTermId.

Имена ролей CSV поддержаны уникальными схемами, точными соединениями и этими
diagnostics. Это не новое восстановление binary parser binding для каждой
таблицы. Полиморфная ветка CollectParam подтверждается enum Item и точными
ID; native обработчик регистрации/расходования предмета не воспроизводился.
Cooked-таблицы и EXE — данные/код клиента, не исходный C++ проект.

## Что доступно

4079 групп, 6766 требований, 1010 различных предметов, 73 типа бонусов.
Все требования имеют предмет, все группы имеют состав, имя и бонусы.
Категории клиента: Krvna1732, Poenari419, Kicel1573, Bezdan280,
пятая75. Английская локализация пятой содержит `2026-09-29 Registered`;
строка сохранена буквально, смысл категории не придуман.

Поиск по имени/ID коллекции, имени/ID требуемого предмета и имени бонуса.
Фильтры категории/редкости/бонуса пересекаются. По уточнению пользователя
по умолчанию «Качество: от обычных к высшим»: CSV53.Rarity0→1→2→3→4→5,
затем специальные100/101 и неизвестные. Это редкость коллекции, не вычисленный
рейтинг её предметов. Внутри качества — числовой DisplayOrder, равенства
сохраняют CSV sequence. Режим sort=quality или отсутствие sort. Это выбранный
пользователем порядок справочника, не доказанный полный компаратор игры.
8Node tests, включая ascending grade и DisplayOrder вместо алфавита, прошли;
JS syntax/HTTP/deployed сверены. Данные и SHA прежние.

Отдельный режим «Порядок данных клиента»: категория по CollectionTabId, затем числовой CSV53.DisplayOrder;
при равенстве сохраняется последовательность исходного CSV (stable sort).
У всех4079 записей DisplayOrder заполнен, но внутри категорий1/4/5 есть
повторы:1484/207/57 повторных значений соответственно. Поэтому этот режим
не объявляется восстановленным полным native-компаратором игры: приоритет
редкости, прогресса, избранного и tie-break игры ещё не доказаны. Категории
2/3 имеют уникальный DisplayOrder. Новых native связей этим изменением нет.
При отсутствии/некорректном DisplayOrder запись идёт после известных значений.
Дополнительно доступны сортировка по редкости, затем алфавиту и ID, и чисто
по алфавиту; специальным значениям100/101 не присваивается ранг выше Mythic.
Явный sort=rank сохраняет редкие-сначала, sort=name — алфавит;
sort=source выбирает порядок данных. Порции60, автоматическая догрузка
и кнопка «Показать ещё»; q/tab/rarity/bonus/sort/limit сохранены в URL,
возврат из карточки сохраняет фильтры; sessionStorage хранит прокрутку списка.

В составе — Count, EnchantLevel, имя, редкость и ссылка на полный предмет.
У1006 из1010 предметов ровно одна иконка; у4 — заглушка. Проверено915
различных файлов иконок (несколько Item используют один ресурс). Фон —
существующая текстура редкости предмета, неоднозначный ресурс не выбирается.
Описание бонуса открывается при наведении/фокусе кнопки, включая Tab;
показаны исходные Min/Max, для IsPercentage есть пояснение о неизвестном
масштабе. Раскрытие карточки хранит все исходные записи и provenance.

355 групп имеют хотя бы DateTimeSetting, FixedTermId или ServerServiceGroupId.
Эти условия отображаются предупреждающей подписью, полные значения доступны
в исходных записях. Живое расписание, доступность/активация бонуса на сервере,
прогресс аккаунта и правила расходования не вычисляются. Срок не считается
истёкшим по одной строке и никакие группы не скрываются как недоступные.

—5 проверок всех исходных SHA, всех требований/заточек, всех бонусов,
локализации/подстановок и байтов native diagnostics.

по составу/бонусу, точного пересечения фильтров включая rarity0, порядка
редкостей/специальных значений, алфавита и неизвестных единиц бонуса.

После добавления DisplayOrder —7Node проверок, включая numeric порядок,
стабильность при совпадениях, неизвестные/некорректные значения и ноль.
7Node/JS syntax/HTTP/deployed сверены. Источник поля — уже SHA-закреплённый
CSV53 в manifest, данные/их SHA не изменились.

Все10 прошли. JS syntax проверен;5 HTTP200 UI файлов побайтно совпали
с исходными; файлы всех915 иконок существуют. Сервер127.0.0.1:17946 отвечает.

отклонил доступ по URL policy; альтернативный доступ для обхода не применялся.
