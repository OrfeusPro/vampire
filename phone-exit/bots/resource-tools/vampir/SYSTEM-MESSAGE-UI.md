# Vampir: код общего сообщения → WBP → текстовый элемент

Продолжение [PACKET-RESULT-GUARD.md](PACKET-RESULT-GUARD.md), 16 октября2026.
Связан конкретный общий путь системного сообщения. Это не доказательство,
что любая ошибка игры или наблюдавшееся отключение сессии используют этот виджет.

## Воспроизведение

`python phone-exit/bots/resource-tools/vampir/build-system-message-link.py`
создаёт `F:/PhoneExit Resources/Vampir/code-clues/system-message-link.json`.
EXE SHA256:
`c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`.

Проверены17 опорных инструкций, семь UTF-16 литералов,11 unwind-фрагментов,
native registration/vtable, четыре cooked-варианта. В каждом варианте сверены
SHA uasset/uexp и байты экспортов класса/контролов. Сохранены PAK/entry,
хеши каталогов, superclass imports, локальные слоты и цепочки родителей.

## Цепочка вызовов

1. Из guard общий путь идёт в0x145f8a7a0, затем0x144a279d0.
2. После ранее найденных проверок текста и UI-флага0x144a279d0 делает tail-jump
   в0x144a1c510 с подобъектом manager+0x770.
3. В0x144a1c510 есть точная диагностика
   `FNkSystemMessageProcessor::AddSystemMessage()` и строка ресурса
   `Common/MessageBox/WBP_SystemMessageUI` в0x144a1c6a0.
4. После проверки готовности менеджера вызывается0x144a18d60 для создания UI.
   При пустом результате дальнейшие операции прекращаются.
5. Объекту передаётся текст через0x144a832e0 в0x144a1c71e.

Путь ресурса соответствует
`/Game/RED/UI/Common/MessageBox/WBP_SystemMessageUI` в каталоге ресурсов.
Это системное сообщение. Нельзя автоматически считать его диалогом OK/Cancel.

## Класс и именованные поля

В обоих вариантах WBP superclass import — `/Script/NkUMG.NkSystemMessageUI`.
Native registration0x144a61920 содержит точные NkSystemMessageUI и /Script/NkUMG,
передаёт initializer0x144a64490. Initializer устанавливает vtable0x149603550.
Его слот+0x530 ведёт в0x144a7acb0.

Эта функция ищет имена в дереве виджета, проверяет классы результатов и сохраняет:

| Поле | Найденный элемент | Связь |
|---|---|---|
| +0xa00 | TextMessage | NkRichTextBlock в обоих WBP; запись0x144a7ad1d |
| +0xa08 | ImageBackGround | Поиск CommonMessageNotifyLightUI, затем ImageBackGround внутри его дерева; запись0x144a7adc0 |

Text writer0x144a832e0 читает ровно+0xa00. При null выходит; иначе подготавливает
значение и вызывает метод текстового объекта. Совпали именованный поиск,
поле хранения, потребитель поля и тип элемента в ресурсе. Это сильнее одного
совпадения имени TextMessage среди многих окон.

## Варианты и геометрия

| Виджет | Patch | Base |
|---|---|---|
| WBP_SystemMessageUI | pakchunk500-Windows, entry575 | ProjectRED-Windows, entry7883 |
| WBP_CommonMessageNotifyLightUI | pakchunk500-Windows, entry667 | ProjectRED-Windows, entry7975 |

У SystemMessageUI извлечены16 контролов/экспортов и два локальных слота на вариант;
у вложенного виджета —22 и шесть соответственно. Среди этого набора не найдено
кнопки OK. Это не доказывает отсутствие любого runtime-ввода или всех возможных
вложенных зависимостей, но не даёт оснований придумывать подтверждающую кнопку.

У Canvas-слота HorizontalBox_0 сохранены offsets(0,0,0,45), anchors min(0,0)
и max(1,0), alignment(0.5,0). То есть45 — локальная вертикальная величина,
а не доказанный экранный прямоугольник на телефоне. Горизонтальная область зависит
от родителя. Для TextMessage нет восстановленной цепочки decoded-slot родителей;
это пробел декодирования/композиции, а не доказательство отсутствующего родителя.
Runtime DPI, позиционирование, состояние анимации Open и Android остаются неизвестны.

## Справочник модуля

build-window-bindings.py добавляет systemMessageReference в ui-window-reference.json.
Проверяются scope, класс, поле+0xa00, четыре разных варианта и нужные типы контролов.
Абсолютная геометрия и runtimeActionsEnabled остаются false. Отчёт связан SHA.

Запись KICKOUT_FOR_INSPECT сохраняет widget_binding_proven=false и прежнюю
pause_without_dismissal_or_reconnect. Новый справочник прямо задаёт
appliesToObservedKickout=false: наблюдавшееся окно безопасности не привязывается
к найденному общему сообщению по одному сходству текста. Три новых теста защищают
раздельность, scope, геометрию и неполный/дублированный набор вариантов.
