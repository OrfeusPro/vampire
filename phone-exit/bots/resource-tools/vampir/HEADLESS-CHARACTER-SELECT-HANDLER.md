кода с тестовыми объектами, а не вход на сервер.

## Проверенные пути

Обработчик `0x14675e9a0` выполняет следующие ветвления:

| Условие | Проверенное действие |
| --- | --- |
| Код `0x26` | Отдельная ветвь интерфейса; общий фильтр и применение персонажа не вызываются |
| Код `0x3c` | Отдельная ветвь закрытия / открытия окна; проверены отсутствие окна и совпадение текущего окна |
| Остальные проверенные коды | Вызывается `0x1467a8e10` с идентификатором пакета 110 |
| Фильтр отклонил код `0x24b9` | В `0x145c8b6b0` передаются поля пакета `+0x338`, `+0x328` и `+0x318` |
| Фильтр отклонил другой проверенный код | Вызывается виртуальный метод сервиса по смещению `+0x38` |
| Фильтр разрешил продолжение | Получается объект персонажа, применяются данные, вызывается событие сервиса |

Для фильтра проверены значения 0 и 1 в байте `manager+8`; назначение этого байта
пока не установлено. Код 0 разрешает продолжение в обоих случаях. Код `0x1197`
на проверенном пути разрешает продолжение при значении байта 0, но отклоняется
при значении 1. Это поведение локального фильтра, не подтверждение серверного
смысла кода и не универсальное правило успешной сессии.

Всего исполнен 31 сценарий, включая разные коды результата, дополнительные
метаданные, флаг платформы и непустые массивы с 1 и 8 элементами.
Пройдены 3 новые проверки обработчика и 3 проверки целостности экспорта Ghidra.
Общий декодер использован для сверки фактических записей в состояние.

## Перенос данных

`0x145c8ba50` получает пару указателей из полей `manager+0x38` и `manager+0x40`.
Её инструкции увеличения счётчика ссылок исполняются; освобождение ссылки
в конце обработчика возвращает тестовый счётчик к исходному значению 2.
Исходный менеджер и объект персонажа предоставлены тестовым окружением.

Функция `0x145d61e60` вызывается на данных, прочитанных из того же тела пакета.
Подтверждены следующие записи:

| Источник | Назначение |
| --- | --- |
| `main+0x08` | `player+0x08` |
| `main+0x30` | `player+0x10` |
| Три расширенных float32 из `main+0x188` | 24 байта в `player+0x20` |
| Вектор направления `main+0x1b0` | Углы поворота в `player+0x38` |
| Условие `main+0x260 == 2` | Логическое поле `player+0x249` |
| Логическое поле пакета `+0x349` | `player+0x24a` |
| Пакет `+0x2b0` | Поле `+0xf0` объекта от getter `0x1455b8260` |
| Пакет `+0x308` | Поле `+0x250` объекта от getter `0x1455b81a0` |

Если поле пакета `+0x348` истинно, обработчик устанавливает `service+0x1a8` в 1.
При ложном значении поле сервиса сохраняется. Не связывать поле `+0xf0` выше
с ранее исследованным `state+0xf0` пакета ID109 только по совпадению смещения:
идентичность получателей этими сценариями не доказана.

Метод сервиса `0x145dbe660` исполняется и вызывает границу обработки события
`0x1456140f0` с байтовым аргументом 1. Подписчики события заменены тестовой
границей. Циклы по массивам также исполняются: `main+0x1d8` передаёт enum и u64,
а `main+0x238` — байт и индекс, начинающийся с 1.

## Границы подтверждения

Менеджеры, таблицы виртуальных функций, метаданные и владельцы ссылок тестовые.
Диагностика, вложенные применения внешности / таблиц, поиск класса, копирование
строки, методы интерфейса и других подсистем перехвачены. Список слушателей
персонажа пуст; поля платформенных callbacks и слабая ссылка менеджера пусты.
Другие пути и полное время жизни объектов не проверены.

Вызов `0x145dea660` после виртуального метода `+0x10` относится к заголовку окна.
Это сверено по инструкциям вызова и PE import table: `GetActiveWindow` и
`SetWindowTextW`. В сценариях этот вызов перехвачен; функции Windows не вызываются.
Эту ветвь нельзя использовать как подтверждение получения мировой позиции.

Общий декодер сверяется с фактическими записями обработчика в объект персонажа
и менеджеры. Следующий шаг — найти подтверждённого потребителя координат и
продолжение события сервиса, затем связать жизненный цикл клиента и проверить
реальный вход с подтверждением устройства. Игра, сеть, аккаунт и Android
этим этапом не использовались.
