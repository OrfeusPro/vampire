# Vampir: ветви входа в собранном клиенте

15 октября 2026. Макеты: [ENTRY-FLOW.md](ENTRY-FLOW.md).
Источник — Windows Shipping EXE с SHA256
`c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`.
Это статический анализ собранного кода, не исходный C++ проект.
Игра не запускалась, память процесса не читалась, код не менялся.

## Повторение и доказательства

Из корня репозитория:

```powershell
python -m pip install --target phone-exit/.tools/vampir-analysis -r phone-exit/bots/resource-tools/vampir/requirements-native.txt
python phone-exit/bots/resource-tools/vampir/build-native-entry-code.py
python -m unittest discover -s phone-exit/bots -p test_vampir_native_entry.py
```

Capstone 5.0.6 закреплён версией и SHA Windows x64 wheel. Это инструмент ПК,
в APK/пакет бота зависимость не добавляется. Перед генерацией нужны актуальные
entry-reference.json и native-enums.json из библиотеки на F:.

Результат: `F:/PhoneExit Resources/Vampir/code-clues/entry-code.json`.
Сохранены 16 проверенных RIP-relative LEA-ссылок на все девять выбранных
диагностических строк; 2060 инструкций в 13 фрагментах шести корневых диапазонов.
Каждый фрагмент имеет RVA, смещение файла и SHA; каждая инструкция — байты,
адрес, мнемонику, операнды, RIP-ссылки и прямую цель ветви/вызова.
Пять разобранных проверок имеют ожидаемые байты якорных инструкций:
изменение любого якоря останавливает генерацию.

Диапазоны взяты из PE exception directory, а не из предполагаемого пролога.
UNW_FLAG_CHAININFO связывает продолжения с корнем. LEA-кандидат принимается
только на границе полностью декодированного диапазона с совпавшим RIP-операндом.
Это ограниченный поиск LEA, не полный индекс всех ссылок EXE.

Адреса ниже — VA при image base `0x140000000`; для RVA вычесть базу.
Это адреса конкретной сборки Windows, не Android-координаты или API вызова.

## Подтверждённые ветви и границы интерпретации

| Участок | Что видно в инструкциях | Что ещё неизвестно |
|---|---|---|
| `0x14641809c–0x1464180a3` | Проверяется AL. Ненулевой результат ведёт к `0x1464181bc` и прямому вызову `0x146425730`. Нулевой проходит через диагностику отказа SignIn и покидает эту ветвь | Полный смысл вызываемой проверки и предыдущие условия |
| `0x1464257b5–0x1464257f8` | ESI загружается из `[RAX+0x308]`, передаётся в диагностику GetLastPlayedServerId. Сравнение с глобальной переменной может заменить его другой глобальной величиной | Имена глобальных переменных и политика резервного сервера |
| `0x14642588b–0x146425896` | Вызов получает ESI через EDX. Нулевой RAX ведёт к None server Info, ненулевой — к `0x1464259ac` | Имя возвращаемого типа, конкретный попап и его кнопки |
| `0x1464263dc–0x146426404` | BL записывается в `[RSI+0xbd9]`. Для значения 4 результаты двух AL-проверок могут выбрать 7 и повторить обработку последовательности | Названия состояний и функций проверок |
| `0x146426409–0x146426439` | Ветвь значения 7 после вызовов выставляет 10 и повторяет обработку | Видимые экраны этих состояний |

Корень `0x146417ad0` содержит диагностику **UTitleUI::OnButtonClicked()**,
а также встроенную ветвь `_BeginGame`. Нельзя называть весь этот диапазон
одной функцией `_BeginGame`: там обрабатываются разные кнопки.
`_BeginGameImpl` связан диагностикой с корнем `0x146425730`; продолжение
`0x146425879` не является самостоятельной функцией.

У `_ChangeSequence` (`0x146426330`) действительно есть значение 10.
У найденного ELobbyState Max=8. Прямое использование ELobbyState для названий
этих значений неверно; внутренний тип Sequence пока не установлен.
Его значение 4 нельзя подписывать CharacterCreateIntro только по совпадению номера.
