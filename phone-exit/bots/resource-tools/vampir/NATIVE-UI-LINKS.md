# Vampir: индекс ссылок кода на макеты и попапы

15 октября 2026. Главный файл: [README бота](../../vampir/README.md).
Источник EXE — Windows Shipping, SHA256
`c7552efd2125e7981945d3443cc1d70a41ac0a8a4cb42e7c77e0d40b4713dfc8`.
Код не запускается и не меняется; устройства не опрашиваются.

## Найти окно без повторного сканирования

```powershell
python -X utf8 phone-exit/bots/resource-tools/vampir/query-native-ui.py WBP_PatchUI
python -X utf8 phone-exit/bots/resource-tools/vampir/query-native-ui.py WBP_ServerSelectPopup --full
```

Команда принимает точное имя или полный `/Game/RED/UI/...` путь. Перед выводом
проверяет SHA EXE, индекса UI и JSON выбранных макетов. `--full` показывает
контекст инструкций, метаданные архивов и неподтверждённые кандидаты.
Старый отчёт при изменившихся источниках не выдаётся как актуальный.

Обновление: `python phone-exit/bots/resource-tools/vampir/build-native-ui-links.py`.
Зависимость — закреплённый Capstone из requirements-native.txt, см.
[NATIVE-ENTRY.md](NATIVE-ENTRY.md). Сначала актуализировать native-enums.json
и ui-catalog/index.json. Библиотека: `F:/PhoneExit Resources/Vampir`.
Результат: `code-clues/native-ui-links.json`, массовые данные вне репозитория.

## Покрытие и ограничения

Найдены 975 точных UTF-16LE путей, совпавших с каталогом. Для 942 макетов
подтверждены 1203 RIP-relative LEA-ссылки на границах инструкций; среди них
279 ресурсных путей попапов. Сохраняются имя/смещение/SHA литерала,
инструкция с байтами, корень unwind-цепочки, SHA фрагмента, соседние инструкции,
пути/размеры/sample SHA PAK, entry и SHA asset/body для вариантов макетов.

11 корней не прошли полный линейный разбор; 38 LEA-кандидатов в них сохранены
отдельно и не входят в подтверждённые ссылки. Первичная проверка некоторых
хвостов показывает байты, похожие на встроенные таблицы RVA, но полный CFG-разбор
ещё не реализован. Не перескакивать неизвестные байты и не выдавать их за код.
Остальные 2863 фрагмента декодированы целиком в границах exception directory.

Это индекс ссылок. LEA строки ещё не доказывает вызов CreateUI, видимость,
состояние кнопки, текст конкретного сообщения или соответствие Android.
Отсутствие ссылки не доказывает отсутствие использования: есть другие формы
адресации, ссылки в ресурсах, ZBP и динамические загрузчики.
paths_without_verified_lea включает все пути каталога без принятой LEA,
в том числе без найденного литерала; это не список неиспользуемых ресурсов.

## Проверенные зацепки входа

| Макет | LEA VA | Корень RVA | Смещение литерала EXE |
|---|---|---|---|
| WBP_TitleUI | 0x146411237 | 0x64111b0 | 163915288 |
| WBP_PatchUI | 0x146425cd2 | 0x6425b50 | 163887800 |
| WBP_PatchPopup | 0x146419053 | 0x6418de0 | 163883840 |
| WBP_CharacterSelectUI | 0x1463dfba7, 0x1463f1618 | 0x63dfb20, 0x63f1580 | 163859384 |
| WBP_ServerSelectPopup | 0x146411077 | 0x6410ff0 | 163910744 |
| WBP_LoginPopup | 0x145f7b95d | 0x5f7b8c0 | 162180960 |

Для WBP_PatchUI корень уже связан диагностикой с `_BeginPatch`.
Перед ссылкой находятся AL-проверка и сравнение `[RAX+0x18c]` с 1, а после —
конструирование строки пути и вызовы. Это усиливает связь обработчика с макетом,
но тип объекта и полная семантика вызовов ещё не восстановлены.

Для WBP_TitlePanelUI отдельная принятая LEA не найдена; явная ссылка уже
восстановлена через UserWidget в cooked TitleUI, см. [ENTRY-FLOW.md](ENTRY-FLOW.md).
Для трёх общих MessageBox-кандидатов прямой принятой LEA также нет.
Не превращать KICKOUT_FOR_INSPECT в доказанную связь с одним из них:
локализованный текст и оконный ресурс пока связаны только на уровне кандидатов.
