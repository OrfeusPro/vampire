# Vampir: готовность типов условий

Продолжение [CONDITION-STATE.md](CONDITION-STATE.md), 16 октября2026.
Готовность означает возможность проверки типа; это не выполнение условия.

## Проверяемое доказательство

`python phone-exit/bots/resource-tools/vampir/build-lock-gate-code.py`
создаёт `F:/PhoneExit Resources/Vampir/code-clues/lock-gate-code.json`.
Проверены SHA того же EXE,37 опорных инструкций, четыре unwind-фрагмента и отдельный
диапазон getter. Имена типов связаны с condition-types.json по SHA.
Полные инструкции, байты и файловые смещения остаются в отчёте.

## Структура таблицы и начальные значения

Таблица размещена в context+0x60. Её записи имеют шаг12, ключ типа — byte+0,
значение готовности — byte+1. Это отдельный контейнер от массива разрешённых ID.

В конце reset0x145cf3440 цикл `0x145cf3a50..0x145cf3af6` перебирает типы0..10.
Сравнение типа с10 и SETE задаёт значение: true только для ForcedLock=10,
для всех0..9 — false. Цикл находит/создаёт запись и пишет её byte+1.
Не распространять этот вывод на произвольные ключи вне0..10.

Getter0x145ce3dd0 сначала требует два флага context+0x221/+0x222, затем ищет
запись типа и возвращает byte+1. Отсутствующая запись даёт false.
Внутри getter есть отдельная ветвь типа11 после флагов. В предикате одного
условия0x145cda340 тип11 имеет собственный ранний true ещё до вызова gate;
это два разных пути, и их нельзя смешивать.

ForcedLock имеет готовность true, но его ветвь предиката возвращает false,
а групповой предикат заранее запрещает группу с таким типом. Готовность true
не означает «разблокировано» даже в начальном состоянии.

## Изменение готовности

Общий setter0x145ced600 получает RCX=контекст, DL=тип, R8B=новое значение.
Он ищет ключ и сравнивает текущее значение. Helper0x145cd16c0 возвращает адрес
byte+1 найденной/новой записи: его арифметика шага12 и INC RAX также проверены.

- При изменении/вставке записывает значение; при ненулевом значении вызывает
  пересчёт0x145cf07f0, затем выполняет общий путь callback.
- Если значение уже совпало и равно0, выходит без пересчёта.
- Если значение совпало и ненулевое, всё равно вызывает пересчёт, с другим
  аргументом DL. Смысл этого управляющего аргумента ещё не назван.

Поэтому готовность повторно true не является безусловным no-op. И наоборот,
переход в false в этой функции не запускает тот же пересчёт автоматически.
Назначение callback и событий, вызывающих setter, ещё требуется проследить.

## Отдельный путь EnterArea

Функция0x145cf5b10 работает с ключом4, совпадающим с подтверждённым EnterArea.
Если записи нет или её значение не1, получает/создаёт запись и пишет1,
вызывает пересчёт и затем callback. Если1 уже было, всё равно вызывает пересчёт.
Это изменение готовности проверки EnterArea. Функция не доказывает, что персонаж
вошёл именно в AreaId из Value1: само условие проверяется другим helper.

## Что остаётся

Связаны инициализация, чтение и изменение таблицы. Источники событий setter,
регистрация EnterArea-пути и семантика callback пока неизвестны. Готовность не
вычисляется для реального персонажа; Android не проверен. Исследование дополняет
referenceRevision4, но не включает новый evaluator или действия на телефоне.


**Продолжение V34:** [UNLOCK-REGISTRATION.md](UNLOCK-REGISTRATION.md) связывает
семь прямых setter-вызовов, в том числе с именованными результатами выбора
персонажа и гравировки. Три других корня пока имеют только адреса, а tail/callback
пути не исключены.
