# Структура справочника Vampir

Исследовано 18 октября 2026. Часть структуры реализована ниже; остальные разделы остаются предложением.

## Источники и воспроизведение

Запуск: `python -X utf8 phone-exit/bots/resource-tools/vampir/study-catalog-categories.py`.
Результат: `F:/PhoneExit Resources/Vampir/maps/catalog-category-study.json`.
Отчёт сохраняет SHA256 входов, таблиц и клиентского EXE, номера CSV entries,
полные заголовки, счётчики и смещения native reference diagnostics.
Проверены 17 выбранных CSV по SHA; типы всех 5827 Item сверены с CSV194.
Enum-имена взяты из уже извлечённого native-enums.json. Присутствует67
различных Item.Type. Внутренние имена таблиц из одних заголовков не выводятся.

## Главное меню

| Раздел | Вкладки / фильтры | Готовность данных |
|---|---|---|
| Карта | Nocturne, миры/подземелья, порталы, объекты, цели заданий | Атлас есть; проходимость/часть поворотов неизвестны |
| Монстры | Уровень, мир, личный дроп, связанные навыки | Карточки и связи уже есть; runtime/шансы не доказаны |
| Предметы | Оружие, броня, аксессуары, книги, карты навыков, коробки, расходники, материалы, облики, транспорт, питомцы | Типы/картинки доступны; полные правила систем неодинаково исследованы |
| Навыки | Название/ID, класс, категория клиента, книги/связанные предметы/NPC | Карточки есть; не приравнивать Category=NormalSkill к активному навыку |
| Развитие | Коллекции, крафт, заточка/разбор, Sephira, артефакты, Tomb, Follower | Есть таблицы и native references; часть связей ещё исследовать |
| Задания | Сюжетные, дополнительные, ежедневные, обучение, Wanted, подземелья, Bloodline, гильдия | Граф заданий есть; живое выполнение и доступность не вычисляются |

Подземелья сначала вкладка «Карты», позже отдельный раздел при готовой
карточке: вход, требования, связанные NPC, задания, награды. Магазины/обмен,
события/призывы и достижения подходят в «Ещё» после проверки связей.
Не выводить пустые страницы только из-за найденного имени системы.

Artifact/ArtifactEnchant, Pet/AdventureStage/LimitBreak, Vehicle/LimitBreak,

Точные workbook/sheet и смещения сохранены в JSON. Это подтверждает наличие
систем в клиентских данных, но не актуальную серверную доступность.

Характерные CSV-кандидаты:51(6766строк)/53(4079строк) с полями коллекций;
200(563строки) рецептов,202(1771строка) с CraftInfoId/Cost;

Число строк не равно числу доступных коллекций/подземелий/товаров;

## Переходы и порядок реализации

Общее меню, отдельные URL каталогов и карточек; состояние поиска/фильтров/
прокрутки сохраняется при возврате. Один объект имеет одну основную карточку.
Книги — вкладка предметов плюс быстрый переход из навыков, без копии карточки.
Монстр → добыча → предмет → навык; предмет → коробки/рецепты/карта источников.
Краткие карточки карты открывают полную страницу через «Подробнее».

Сначала вынести существующие карточки/каталоги и объединить меню; затем
добавлять «Развитие» по готовности подтверждённых связей. Серверный календарь,
рыбалка, сбор ресурсов и торговые маршруты сейчас не обещаются: в этом
исследовании достаточные связи для них не установлены.

## Реализовано 18 октября: первые отдельные страницы

Общее меню: Карта, Монстры, Предметы, Книги, Навыки. Раздел Монстры пока
открывает существующий просмотр NPC/наград; новая полная страница монстра
остаётся следующим шагом. Предметы и книги имеют отдельные каталоги
loot/items.html и loot/books.html, подробности по ?item=ID. Навыки —
atlas/skills.html, подробности по ?skill=ID. Каталог навыков включает
служебные записи клиента и явно это сообщает.

Поиск/тип/редкость предметов, поиск/связи навыков, порции60 и limit в URL.
Названия предметов сортируются по редкости, затем имени и ID; навыки по
имени и ID. Ссылка возврата сохраняет параметры списка; sessionStorage
сохраняет прокрутку списка при клике по карточке (изображения могут
дозагружаться после возврата). Книги —403, предметы —5827, навыки —3447
целевых ID, включая3446 найденных Skill и1 отсутствующую запись.

SkillCard — общий модуль карты и отдельной карточки, без копии описания
или параметров. ItemDetails переиспользуется без изменения подтверждённых
связей; на странице предмета доступны характеристики/заточка/эффекты,
коробки, рецепты и личные цепочки наград NPC. Проценты и runtime условия
не выводятся как доказанные. Старые loot/index.html?item ссылки сохранены,
новые ссылки ведут в items.html. Старый atlas/index.html?skill=ID без
skillNpc=1 переходит в skills.html; явный фильтр NPC остаётся на карте
с компактным блоком и ссылкой на полную карточку.

Сборка: build-npc-loot.py → build-world-map.py. Оба вызывают
build-catalog-pages.py для развёртывания UI. Если меняются только файлы
каталога, достаточно build-catalog-pages.py; world-map/item-details
обновляются своими основными сборщиками. build-monster-details.py добавляет
в skill-npcs.json ссылки/происхождение изображений из уже проверенных
карточек, SHA индекса обновляется в monster-manifest.json.

Проверки:34Python+34Node существующих тестов данных/моделей прошли;
7JS syntax и source/deployed JS сверены. Живой браузер: поиск321001,
карточка Frenzy→Demon King Sword со свойствами; книги403→поиск21014000→
Whirlpool110016; типSkillCard1585; пустой поиск; навык50250→карта3NPC/147
размещений→снятие фильтра24071запись. Карточки/ссылки возврата проверены,
длительное хранение состояния и разные viewport отдельно не заявлены.
Снимок каталога книг — phone-exit/.tools/ux-audit-321001/07-books-catalog.png.

## 18 октября — классы, догрузка и уровни NPC

В навыках и книгах добавлен «Класс персонажа», подпись класса на карточке
и параметр class в URL списка/возврата. Для книг фильтр также доступен
в общем каталоге при типе SkillBook. Пустой класс не равен All.
Общие записи All включаются при выборе конкретного класса.

Воспроизведение: build-catalog-classes.py (также вызывается из
build-catalog-pages.py). maps/catalog-classes-manifest.json закрепляет SHA
maps/catalog-classes.json. Источники: CSV36 Class Id/Type/Resource,
CSV401 ClassName-en Id/Name, CSV1505 Skill.ClassType; Item.ClassInfoId
из SHA-проверенного items.json и подтверждённый target книги из item-details.
Enum EClassType из native-enums.json сверяется с Class.Type/Resource.
Отчёт сохраняет входные SHA, CSV entries/records и сырой класс обоих объектов.
Это явные соединения полей таблиц, не новая восстановленная native-проверка
допуска. Успешное изучение/использование на сервере не проверено.

Классы: Viper/DarkMage, Grim Reaper/Reaper, Carnage/Gunner,
Bloodstained/SwordMan, Akasha/Fighter. Для книги конкретный Item.ClassInfoId
не расширяется до всех из-за Skill.ClassType=All. При несовместимых явных
полях статус conflict исключается из конкретного класса, неизвестные ID/
токены не угадываются. Текущие403книги:375specified,27all,1unknown;
конфликтов нет. По102книги на класс с учётом27общих. Skill3446:
929specified,263all,2254unknown; отсутствующий target201006 тоже показывается
в неизвестных в каталоге. Viper460/GrimReaper448/Carnage426/
Bloodstained459/Akasha460 навыков, включая общие записи.

Догрузка по60 при приближении к концу списка работает в предметах/книгах,
навыках и прежнем просмотре добычи. IntersectionObserver плюс passive scroll;
повторный вызов ограничен busy/requestAnimationFrame, конец списка останавливает
догрузку. DOM карточек дополняется, а не пересоздаётся. Кнопка остаётся как
ручное действие. Ссылки ранее показанных карточек получают актуальный limit;
поиск/фильтры сбрасывают порцию и DOM, возврат сохраняет class/q/limit.

NPC: исходный level виден в каждом option списка; сортировки по уровню вверх/
вниз и по имени, диапазон от/до. Неизвестный уровень не подменяется нулём,
идёт после известных и не проходит ограниченный диапазон. Выбранный NPC
сохраняется, если он остаётся в результатах. В списке размещений/групп карты
уровень также показан из scene.npcs. Новых игровых связей не добавлено.

Проверки:24Python+32Node прошли, включая5 новых тестов неизвестных/общих/
многоклассовых и конфликтующих полей. Классовый manifest SHA и6 deployed
файлов сверены; syntax JS/inline NPC viewer пройден. В живом браузере:
книгиViper102 (автодогрузка60→102), навыкиViper460 (60→120), прежний
просмотр предметов5827 (60→120 без кнопки); NPC диапазон50–60 дал86строк,
все уровни попали в диапазон, сортировка60→50 проверена. Снимки08-books-class.png
и09-npc-levels.png в phone-exit/.tools/ux-audit-321001/. Остальные viewport и
работа после обновления версии клиента отдельно не проверены.

## 18 октября — отдельный каталог и страница NPC

Главное меню «Монстры» теперь ведёт на atlas/monsters.html, подробности
?npc=ID. Прежний loot/index.html сохранён как отдельный просмотр наград.
Новые ссылки NPC с карты и предметов ведут на полную страницу. Поиск,
уровни от/до, сортировка уровень/имя, точный мир и личные предметы
сохраняются в URL и ссылке возврата. Догрузка по60 добавляет карточки;
контекст limit обновляется и у ранее показанных ссылок NPC.

build-monster-details.py расширен с1785NPC Nocturne на все5285NPC
существующего loot index. Во всех5285 найден хотя бы один Battle по
ранее проверенной Npc.BattleGroupId→Battle.GroupId; все варианты сохраняются.
Новых native joins нет. В detail добавлены placements из уже загруженного
NpcSpawn с точным NpcInfoId. Сохранены61307размещений, из них17488
относятся к сцене Nocturne. Картография/проекция/границы не менялись.
3908NPC имеют размещения,652 — личные предметные цепочки; общий каталог
содержит также мирные/технические/неразмещённые определения.

monster-manifest.json закрепляет новый npc_catalog file/SHA. Лёгкий
npc-catalog.json содержит имя/уровень/миры из старого индекса, detail spec,
число Battle/предметов/размещений и on_nocturne. Его источники сохраняют
SHA loot index/scene; source/entries подробных таблиц остаются в manifest.
Каждый полный JSON остаётся закреплённым по SHA. skill-npcs.json и проверка
имён навыков сохраняют прежний охват обратных связей NPC только Nocturne;
новые NPC-страницы показывают свои SkillIdList независимо от этого индекса.

MonsterCard вынесен из world-map.js в общий monster-card.js; параметры,
варианты Battle и непредметные награды отображаются тем же компонентом
на карте и отдельной странице. SkillCard также общий. На странице видны
имена/ссылки навыков, личные предметы с иконками/редкостью/количествами
по отдельным строкам и source chains. Награды областей находятся в отдельном
ленивом details, не прибавляются к личным предметам. Количества альтернатив
не складываются; проценты и гарантии не выдуманы. Портреты NPC этим изменением
не добавлены. Размещения имеют ссылки с world/npc/spawn; NPC вне Nocturne
открывает соответствующий world.html, не пустую карту Nocturne.

Сборка: build-npc-loot.py → build-world-map.py. Последний вызывает обновлённый
build-monster-details.py, затем build-catalog-pages.py (ассеты monster-card,
monsters-catalog HTML/JS/model и меню). Только build-catalog-pages.py не
пересобирает NPC data; после изменения данных нужна основная сборка.
