# Координаты из оригинальных таблиц RF Online Next

14 октября 2026 найден и разобран собственный формат **RFT v26**.
Предыдущее утверждение «координаты ещё не извлечены» из MAP-PROVENANCE.md
описывает состояние до этого разбора. Теперь основной источник координат —
игровые таблицы, а снимки используются для привязки координат к изображению.

## Источники

Файлы RFT расположены в **pakchunk941-Windows** и патчах `_0_P`–`_3_P`
клиента `F:/Games/Netmarble Game/RFonlineNext`. Версия проверенного телефона —
1.30.7. Данные PAK не зашифрованы, распакованы Oodle; расшифровка индекса/AES
не использовалась. Каждая таблица хранится отдельным файлом с номером записи:
`F:/PhoneExit Resources/RF Online Next/data-study/rft/<pak>/<entry>-<name>.rft`.
В извлечении 986 экземпляров, 541 имя таблицы. `catalog.json` сохраняет все
варианты; `latest.json` выбирает максимальный числовой ранг патча для имени.
Реальный порядок монтирования клиентом отдельно не подтверждён.

Для каждого экземпляра сохранены путь и размер PAK, номер записи, смещение
в PAK, размер распакованных данных, SHA256, ранг патча и строки заголовка.
Одинаковое имя таблицы может иметь несколько языковых экземпляров в одном PAK:
их **нельзя сохранять в один файл по имени**. Номер записи предотвращает замену.

## Разобранные данные

| Таблица | Записей | Содержание |
|---|---:|---|
| RF_MapInfoTable | 822 | Значки карты, названия, MapIndex/RegionIndex/TabIndex, Location, тип значка, JumpTo |
| RF_RegionTable | 968 | Координаты регионов, стартовая зона, группа возрождения, функции региона, BGM |
| RF_MapInfoTable_Area | 1602 | AreaIndex/AreaType, группа зоны, TargetPosition1 |
| RF_MapInfoTable_Spawn | 8741 | NPCIndex/тип, TargetPosition1/2/3, направление, дальность боя |
| RF_MapInfoTable_LevelInfo | 429 | Подписи уровней, значки и координаты |
| RF_TeleportTable | 7 | Правила телепорта, радиус, проверка PvP и policy команды |
| RF_StringTable (RU) | 86483 | Русская локализация ключей, включая названия регионов |

Записи и схемы находятся в `data-study/rft/decoded/`. Декодер читает описание
полей прямо из RFT, отклоняет неизвестные типы и требует точного конца файла.
Тип 20 — три float64; enum хранится согласно типу в описании поля.
Некоторые строки локализации содержат буквальные `\uXXXX`; преобразование
в Unicode выполняет build-native-points.py. Поле языка внутри схемы называется
KO_KR даже у русских экземпляров: язык выбран по содержимому записей, не имени поля.
Последний найденный русский экземпляр — запись 25 pakchunk941-Windows_3_P;
его точные смещение/хеш сохранены в native-points.json.

`RF_TeleportTable_Map` и `RF_MapTable` пока не разобраны полностью: декодер
отклоняет их вместо публикации неправильно прочитанных записей. Исходные RFT
сохранены. Таблица телепортов описывает правила; её 7 строк нельзя считать
семью координатами входов.

## Какие позиции используются

83 точки редактора извлечены из RF_MapInfoTable для **MapIndex 101 и 103**.
Тестовые строки Map_Name_Test с нулевыми позициями исключены.
Если Location значка нулевая, используется **RF_RegionTable.Location**
по RegionIndex. Это обычный случай: знак ссылается на позицию своего региона.
В каждой точке указано `location_source`, сохранены исходные X/Y/Z и индексы.

Пример: **Черная равнина** имеет позицию
`[-51177.6796875, 65617.3203125, 5812.83935546875]` из RF_RegionTable.Location.
Эти значения не являются пикселями экрана. Кнопки и путь персонажа ещё не проверены.

Матрица world X/Y → пиксели чистой карты получена по одноимённым точкам
сохранённого ручного каталога с RANSAC. Для MapIndex 101: 72 опорные точки,
69 inliers, медианная ошибка 2.32 px. Для 103: 7 опорных, 6 inliers, 0.79 px.
Полные матрицы, исключённые точки и ошибки каждой пары сохранены.
Это подтверждает географическую привязку, а не возможность пройти маршрут.
В метаданных navigation_verified=false до живого теста.

Четыре позиции не согласуются с сохранённым игровым снимком (3 на 101,
1 на 103). Их оригинальные X/Y/Z сохранены, но редактор использует прежнюю
отметку снимка вместо явно расходящейся позиции. У этих записей
calibration_review_required=true, native_atlas_candidate и atlas_position_source.
Нужно проверить актуальную карточку города и версии ПК/Android; не считать
все 83 привязки одинаково подтверждёнными.

## Файлы для дальнейшей работы

- `F:/PhoneExit Resources/RF Online Next/maps/native-points.json` — 822 исходные
  записи, 83 координаты на атласе, русские названия, матрицы и происхождение.
- `pc/assets/maps/rfonlinenext/native-points.json` — копия для продукта.
- `pc/assets/maps/rfonlinenext/index-native.json` — каталог редактора.
  Он имеет приоритет над ручным index.json; ручной каталог сохранён для сравнения.
- `data-study/novus-world-anchors.json` — 69 отдельно извлечённых относительных
  трансформов SceneComponent. Они имеют schema_verified=false и **не используются**
  как фарм-точки. Основной каталог использует RFT.

Свои точки фарма из профилей не заменяются этим каталогом. Их map_points
по-прежнему хранят нормализованные координаты изображения; новый каталог
добавляет точные игровые опорные локации для настройки и будущей навигации.

## Повторное извлечение после обновления

Сначала сохранить библиотеку этой версии. Затем обновить инвентаризацию PAK,
пересканировать изменённые архивы, в отдельной библиотеке выполнить:

```powershell
python phone-exit/bots/resource-tools/rfnext/extract-rft.py
python phone-exit/bots/resource-tools/rfnext/decode-rft.py RF_MapInfoTable RF_MapInfoTable_LevelInfo RF_MapInfoTable_Area RF_MapInfoTable_Spawn RF_TeleportTable RF_RegionTable RF_StringTable
python phone-exit/bots/resource-tools/rfnext/decode-rft.py --ru
```

Команда --ru выбирает русский экземпляр RF_StringTable по фактическому языку
и максимальному рангу патча из catalog.json, сохраняет его с архивными
метаданными и отклоняет неоднозначный выбор. Не выбирать по KO_KR и не
смешивать разные языки по имени таблицы.
Проверить хеши/версию карты и ручных снимков, затем:

```powershell
python phone-exit/bots/resource-tools/rfnext/build-native-points.py
powershell -NoProfile -File phone-exit/pc/test-rf-map-editor.ps1
```

При изменении версии RFT, неизвестном типе, непотреблённом хвосте файла,
неправдоподобных координатах или малом числе опорных совпадений остановить
генерацию и сохранить ошибку. Не подставлять неверные данные в редактор.
Оригинальные файлы игры остаются нетронутыми. Никакие данные не публиковались на FTP.

## Монстры в правом списке карты, 14 октября 2026

`build-monster-catalog.py` соединяет RF_MapInfoTable_Spawn.NPCIndex с
RF_NPCTable.NPCIndex и русским RF_StringTable по NameStringIndex.
Регион привязывается через RegionIndex, карта через MapIndex. Выбираются
NPCType=2; это кандидаты списка монстров, а не доказательство доступности
каждой строки в текущем клиенте. Сохранены все ненулевые TargetPosition1/2/3,
исходные XYZ, проекция на атлас, уровни, подтип, Key, смещения строк и SHA256
исходных таблиц. Другие NPC и объекты этим каталогом не подменяются.

Результат: `maps/monster-catalog.json` постоянной библиотеки и
`pc/assets/maps/rfonlinenext/monster-catalog.json`: 765 записей появления,
56 регионов Novus. В index-native.json добавлен monster_targets у локаций.
Это данные для будущего списка в редакторе; видимый выбор монстра в редакторе
и автономное перемещение к нему пока не реализованы.

USB-vivo, Черная равнина, RegionIndex=68001: в ресурсах 14 записей.
Первые шесть строк справа проверены по живому кадру rf-monster-list.png:
Ониксовый ящер, Древний ониксовый ящер, Ониксовый глат,
Ониксовый рекс-каннибал, Ониксовый эш, Огненный ониксовый эш — уровень 55.
Выбор первой строки выделил отдельную точку с меню Пешком/Телепорт/Метка
(rf-monster-target.png). Телепорт не подтверждался. Остальные строки требуют
прокрутки и проверки; порядок таблицы пока не считается порядком интерфейса.
TargetPosition — позиция из таблицы появления; точка прибытия телепорта
может отличаться. Флаги ui_list_membership_verified/navigation_verified
явно разделяют подтверждение списка и проверку перехода.

Расширен ограниченный декодер: type13 float32, массивы с uint16 длиной,
enum_storage=4 uint32 (не путать с обычным type4, занимающим один байт).
RF_NPCTable: 11650 строк, RF_RegionSpawnTable: 19, RF_SpawnInfoTable: 1005;
все файлы потреблены точно до конца. Проверка названий первых шести монстров
и уровня встроена в генератор и останавливает его при расхождении.

После обновления, вслед за build-native-points.py, выполнить:

```powershell
python phone-exit/bots/resource-tools/rfnext/decode-rft.py RF_NPCTable RF_RegionSpawnTable RF_SpawnInfoTable
python phone-exit/bots/resource-tools/rfnext/build-monster-catalog.py
```

Повторный build-native-points.py пересоздаёт index-native.json, поэтому
генератор монстров запускается после него. Неподдерживаемые схемы отклоняются.

Последующая проверка прокруткой: rf-monsters-middle.png и rf-monsters-page2.png
подтвердили оставшиеся восемь строк Черной равнины и порядок всех 14 монстров.
Генератор теперь проверяет весь список и помечает все его строки подтверждёнными.
Отдельная последняя строка «Просмотр: Черная равнина» не является монстром.
Эти три снимка сохранены в постоянной библиотеке maps/ui-checks/.
В редактор ПК добавлены прокручиваемый список монстров выбранной локации,
подсветка позиций и добавление первой позиции в профиль. Сохраняются
catalog_monster_id, npc_index, catalog_location_id и target_world_xyz.
Тест редактора проверяет последнюю строку списка, видимость панели, сериализацию
этих полей и отсутствие изменения исходных настроек при отмене окна.
Автономный фарм и исполнение телепорта этим изменением не добавлены.
