# RF Online Next: происхождение карты и точек

**Обновление:** координаты теперь извлечены из собственных RFT-таблиц.
См. [NATIVE-POINTS.md](NATIVE-POINTS.md). Ниже сохранена история получения
ручного каталога; основной редактор использует index-native.json.

Дата исследования: 14 октября 2026. Версия игры на USB-vivo V2061: **1.30.7**,
пакет `com.netmarble.rfnext`, язык русский. Исходный клиент ПК:
`F:/Games/Netmarble Game/RFonlineNext`. Исходные архивы не изменялись.

## Что взято из архивов

Чистая карта Novus собрана из шести обзорных текстур 4096×4096 с внутренними
путями `.../WorldMapTexture/RegionMapTileTex/1010/NovusWorld_101_X_Y`.
Индекс PAK зашифрован; прочитаны открытые последовательные записи FPakEntry,
данные распакованы Oodle, текстуры декодированы в PNG. Ключ AES не использовался.
Имена внутренних ресурсов взяты из uasset, а не из расшифрованного индекса.

`F:/PhoneExit Resources/RF Online Next/maps/novus-world.json` содержит исходные
плитки, SHA256 каждой, порядок осей, размер холста и обрезку. Исходный холст
12288×8192, обрезка `[58,1402,12167,6797]`, результат **12109×5395**.
Одноимённые подробные плитки 512×512 относятся к другому слою.

В продукт скопирована уменьшенная карта 4096 px по ширине:
`pc/assets/maps/rfonlinenext/novus-world.png`. Хеши исходной и уменьшенной карты
есть в соседнем `index.json`. Оригинал остаётся в постоянной библиотеке на F.

## Откуда взяты точки

**Готовые мировые координаты локаций из игровых таблиц не извлечены.**
Ссылки `RF_MapInfoTable_Minimap` и `RF_MapInfoTable_LevelInfo` найдены в
PrimaryAssetLabel. Эти записи группируют ресурсы значков; сами по себе они
не подтверждают наличие координат. Есть также DataAsset/WorldMap с данными
значков. Их разбор и поиск настоящих таблиц координат остаются отдельной задачей.
Кандидаты сохранены в `maps/table-candidates.json` постоянной библиотеки.

Текущий каталог — **83 наблюдаемые локации**, включая поселения и фарм-зоны.
Это не доказанный полный список всех локаций/подземелий игры.
Названия и уровни вручную переписаны с русских игровых снимков. Центр значка
помечен вручную на превью 2048×922; оригиналы снимков имеют 2400×1080.
При перекрытии подписей название/уровень требуют дополнительной проверки.
В частности, уровень Лоудиского леса и карантинной зоны не указан: подпись
перекрыта. Перед использованием маршрута сверить карточку выбранной локации.

Все ручные исходные данные находятся в **map-labels.json** рядом с этим файлом.
Не редактировать сгенерированный index.json вместо исходного файла.
Главный снимок `map-title-ready.png` хранится в корне библиотеки на F;
остальные исходные снимки — `maps/survey/<source_view>.png`.
Снимки сделаны через ADB screencap на USB-телефоне. Персонаж не отправлялся
в эти локации, кнопки покупки/телепорта не подтверждались при сборе точек.

## Привязка координат

Снимок сопоставляется с рельефом чистой карты: SIFT + RANSAC, similarity transform.
OCR не используется. Это офлайн-инструмент исследования на ПК, не зависимость
Android или бота. Для каждого вида сохранены число совпадений, число inliers,
медианная ошибка, матрица и SHA256 снимка в `<view>.registration.json`.
Измеренная медианная ошибка рельефа около 1.3–1.7 px исходной карты;
она не включает ручную погрешность центра значка и не доказывает точность пути.

Для исходного снимка `(sx, sy)`:

```
x = m00*sx + m01*sy + m02
y = m10*sx + m11*sy + m12
```

`x,y` находятся в `[0,1)` относительно обрезанной карты Novus.
Это **координаты изображения, не X/Y игрового мира и не координаты нажатия**.
В каждой точке index.json сохранены source_view, source_preview_point,
source_frame_point, source_sha256, provenance и navigation_verified=false.
В каждом профиле собственные точки хранятся как map_id=novus_world_101,
map_points=[[x, y]]; активная точка хранится отдельно по id.

## Как проверить после обновления игры

1. Сохранить нынешнюю библиотеку/JSON/снимки. Создать библиотеку новой версии
   отдельно; сравнить PAK по отпечаткам из pak-scan-progress.json.
2. Пересканировать изменённые архивы. Сканер переиспользует entries.json и сам
   не обнаруживает устаревший кэш: не подставлять старые entries новой версии.
3. Собрать обзорную карту снова и сверить хеши, размер, порядок и обрезку.
4. Сделать свежие снимки карты на том же языке, сверить название/уровень/значок
   каждого POI. При смене разрешения обновить координатное пространство.
5. Выполнить build-map-catalog.py. Кэш регистрации учитывает SHA256 снимка и
   исходной карты; изменение любого из них вызывает повторную регистрацию.
6. Обновить map-labels.json, затем запустить build-map-catalog.py. Сверить
   наложение значков визуально, особенно края карты и новый остров.
7. Проверить поиск, масштаб, сохранение/отмену профиля через
   pc/test-rf-map-editor.ps1. Отдельно проверить переход и прибытие на телефоне.

Не переносить старые мировые/экранные координаты автоматически. Свои точки
профилей можно сохранять только после подтверждения неизменной географии.

## Воспроизведение

Из корня проекта:

```powershell
python phone-exit/bots/resource-tools/rfnext/build-map-catalog.py
powershell -NoProfile -File phone-exit/pc/test-rf-map-editor.ps1
```

Хранилище переопределяется переменной PHONEEXIT_RF_RESOURCES. Копия каталога
точек сохраняется в `F:/PhoneExit Resources/RF Online Next/maps/novus-locations.json`.
Скрипты, ручной каталог и эта документация также сохраняются в библиотеке.
Редактор подключён в ПК к RF-профилю кнопкой «Карта Novus · точки…».
Точки сохраняются и передаются через прежний Bot API; модуль RF 1.0.1 пока
реализует автозапуск и не исполняет фарм/маршруты. APK для редактора не менялся.
