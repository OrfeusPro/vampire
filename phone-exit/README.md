# Phone Exit

Цель: выход ПК в интернет через Wi-Fi Android, соединение напрямую через WebRTC,
PHP-хостинг нужен для согласования связи. Правила: `../AGENTS.md`.

Перенос на другой ПК: **«Аккаунт…» → «Экспорт…» / «Импорт…»** в Windows 0.4.10.
Файл защищён паролем; привязанные телефоны и персональный APK сохраняются.
[Инструкция переноса](docs/account-transfer.md).

Windows 0.4.11: [группы игр, поиск запущенных EXE и связанных процессов](docs/game-groups.md).
«Только эта» включает VPN для одной группы, сохраняя остальные для обычной сети.

## Обязательный результат

- Режим «Весь трафик»: системный TCP/UDP и DNS ПК через телефон.
- Режим «Выбранные приложения и игры»: выбранные процессы через телефон,
  остальные через обычное подключение ПК. Выбор EXE, учёт дочерних процессов.
- Потеря телефона останавливает трафик, направленный через него.
- На Android всегда Wi-Fi, без автоматического переключения на мобильный интернет.

## Текущая версия

`pc/`: Node.js 22+, werift 0.25.0, локальный SOCKS5 CONNECT на 127.0.0.1:1080.
Каждое TCP-соединение имеет отдельный надёжный DataChannel. Лимит нового APK: 128 TCP-потоков и 64 UDP-ассоциации,
кредитное окно 256 КиБ, кадры до 16 КиБ, корректное завершение направлений TCP.

`android/`: Java, foreground service с уведомлением и остановкой, WebRTC,
ввод кода сопряжения, DNS и TCP через конкретную Wi-Fi Network,
запрет доступа к локальным/служебным адресам. Камера и микрофон не нужны.

**На vivo проверен системный VPN Windows: TCP, UDP, DNS, блокировка при потере
транспорта и возврат интернета после отключения. Выбор EXE тоже прошёл проверку
разделения трафика, но остаётся тестовым: дочерние EXE нужно добавлять вручную,
конкретные игры и реальный IPv6-выход ещё не проверены.**

### Android 0.3.2

Тёмный интерфейс в цветах Windows: фон, карточки, мятный акцент и индикатор доступа.
Версия берётся из BuildConfig и показана под названием приложения. Экран прокручивается

### Запуск клиента

**Актуальный режим — персональный APK без кодов.** Установите
`PhoneExit-personal.apk` из корня `phone-exit` на свои телефоны и откройте один раз.
Телефон сам включит foreground-доступ с уведомлением, зарегистрируется на сервере
и появится в приложении ПК вместе со страной. На ПК: двойной щелчок по
`Phone Exit.vbs`, выбрать телефон, режим «Весь трафик · VPN» и нажать «Подключить VPN».
Подтвердите запрос Windows для виртуального интерфейса. Настраивать прокси
в браузере не требуется. «Отключить» возвращает обычный интернет.
Для VPN обновите телефоны до приложенного APK 0.3.2; старые версии работают
только в режиме «Прокси · TCP».
Этот APK предназначен только для ваших устройств: обладатель файла может добавлять
телефоны в ваш список. Сборка персонального APK: `android/build-personal.ps1`.
Данные аккаунта ПК защищены DPAPI в `%USERPROFILE%/.phone-exit/account.bin`; не удаляйте
этот файл для обычного обновления APK. Перенос аккаунта на другой ПК ещё не реализован.

При потере Wi-Fi телефон закрывает TCP и UDP, остаётся ожидать сеть и автоматически
возвращается в доступные после восстановления. Ошибки HTTP повторяются с паузой
до 30 с. Статус «не в сети» появляется после 45 с без heartbeat, плюс интервал
обновления списка. Кнопка «Остановить» на телефоне выключает автоматический режим;
после неё для включения нажмите «Включить автоматический доступ».
Служба возобновляется при системном перезапуске/после boot, когда enabled-флаг включён;
реальная перезагрузка пока не проверялась. Принудительная остановка Android и
ограничения фоновой работы производителя могут потребовать открыть приложение.
Основание платформенной реализации: [sticky service](https://developer.android.com/reference/android/app/Service),
[foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types).

Реальный USB-тест `pc/test-personal-usb.ps1` прошёл на vivo: обнаружение с пустым
списком ПК без предварительного ключа телефона, страна UA, три HTTPS, закрытие
активного TCP при потере Wi-Fi, offline, автоматическая регистрация и HTTPS после
восстановления Wi-Fi без повторного открытия приложения. Сборка и lint пройдены
(0 ошибок, 2 предупреждения). Другие физические телефоны ещё не проверялись.

Ниже сохранена инструкция стандартного APK и ручного режима для совместимости.

Оконный клиент Windows: двойной щелчок по `Phone Exit.vbs` в каталоге `phone-exit`.
Добавьте личный телефон: задайте имя, нажмите «Добавить телефон», скопируйте
код и один раз вставьте его в Android, затем нажмите «Подключить ПК».
В следующий раз на телефоне достаточно «Включить доступ для своего ПК».
На ПК выберите доступный телефон в списке стран и нажмите «Подключить телефон».
Связь установится автоматически, без повторной передачи кода. До четырёх телефонов,
несколько устройств одной страны отображаются отдельно. Страна по IP Wi-Fi,
при ошибке определения — «Страна неизвестна».
После связи код убирается из окна. Кнопка «Остановить» и закрытие окна завершают
TCP-клиент и потоки; телефон остаётся доступен своему ПК до остановки на Android.
Если список ещё пуст, кнопка запускает прежний ручной одноразовый сценарий.
Используется Windows PowerShell 5.1/WinForms, установленный Node.js 22+ и зависимости
в `pc/node_modules` (`npm ci`, если их нет). На этом ПК зависимости уже установлены.
Запуск без консольного окна; не требует администратора и не меняет системный прокси.
Это пока приложение из исходников с launcher, отдельный установщик/EXE не собран.
SOCKS5 `127.0.0.1:1080` нужно указать в поддерживающей прокси программе.
Привязки хранятся с защитой DPAPI CurrentUser в `%USERPROFILE%/.phone-exit/phones.bin`,
на Android — AES-GCM/Android Keystore. Копирование кода — по кнопке пользователя.
В буфере обмена код остаётся до его замены; не публикуйте его.
Телефон обращается к Cloudflare trace для страны по IP; GPS и сохранение IP не нужны.
Подробнее: `docs/phone-directory.md`. Системные часы обоих устройств должны быть точными.

11 октября 2026: на подключённом vivo V2061 проверены сохранённая личная
привязка после перезапуска клиента, страна «Украина», автоматическое соединение,
HTTPS через Wi-Fi и повторное соединение/HTTPS без повторного ввода кода.
Других физических телефонов для теста сейчас нет; несколько стран, изоляция
устройств и истечение статуса покрыты локальными тестами каталога.
После проверки клиент ПК открыт в ожидании, выход Android включён для своего ПК.

Проверка окна: `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File desktop.ps1 -SelfTest`
из каталога `pc`. Проверяет запуск настоящего клиента, показ кода, остановку,
удаление кода из окна, повторный запуск и завершение клиента при закрытии окна.
USB-проверка личной привязки/страны/автоматического соединения/повторного
подключения: добавить `-UsbTestSerial SERIAL`. Она сохраняет привязку к vivo,
запускает нашу Android-службу, дважды проверяет HTTPS и завершает клиент ПК.
Снимок `desktop-preview.png` не содержит кода; USB-проверка снимает подключённое окно.

В каталоге `pc`: `npm ci`, затем `npm start`. Клиент выводит одноразовый JSON
с кодом сопряжения. Вставить его в Android-приложение и нажать «Подключить ПК».
Код не сохраняется на диск; не публиковать его. Сопряжение действует 10 минут.
После установления ручной связи комната TCP больше не опрашивается; TCP может
работать дольше. Для сохранённых телефонов отдельно продолжается опрос каталога.

Проверка после установки APK: `curl.exe --socks5-hostname 127.0.0.1:1080 https://api.ipify.org`.
Это отправит запрос определения внешнего IP через Wi-Fi телефона.
Ctrl+C останавливает клиент. При ошибке прямой связи TURN не включается автоматически.

Для диагностического сервера используется ранее проверенный
`https://demochko.com/hosting-webrtc-probe/signal.php`. Внешние файлы и настройки
хостинга в этом этапе не менялись. Android принимает только этот сервер.

### Android

Gradle 8.11.1, JDK 17, Android SDK platform 35, Android Gradle Plugin 8.9.2.
WebRTC: `io.github.webrtc-sdk:android:150.7871.01`, Maven Central.
Сборка на этом ПК: `./build.ps1` из каталога `android`. JDK, SDK и Gradle
находятся в игнорируемом `phone-exit/.tools/`; пути SDK заданы в local.properties.
Для другого ПК: настроить JDK 17/SDK 35, затем `./gradlew.bat :app:assembleDebug`.
Установка на разрешённое USB-устройство: `adb install -r app/build/outputs/apk/debug/app-debug.apk`.

USB-телефон обнаружен: vivo V2061, Android 12 (API 31), arm64, Wi-Fi включён.
11 октября 2026 пользователь разрешил установку SDK и принятие лицензии.
При выполнении `sdkmanager --licenses` были также приняты лицензии дополнительных
SDK-пакетов; сами дополнительные пакеты не устанавливались. Установлены
command-line tools, платформа 35, build-tools 35.0.0 и platform-tools.
APK собран через Gradle и установлен на этот телефон. Первый реальный
HTTPS-запрос через SOCKS/WebRTC/Android Wi-Fi выполнен успешно; три параллельных
запроса также прошли и вернули одинаковый внешний IP (сам IP не сохранялся).
Оба USB-теста пройдены: три параллельных HTTPS-запроса, открытый TCP-поток,
остановка кнопкой и потеря Wi-Fi. После остановки поток закрыт, клиент ПК
завершён. Heartbeat закрывает SOCKS без ответов телефона за 8–10 с.
Тест: `cd pc; node test-usb.js SERIAL stop` или `node test-usb.js SERIAL wifi-loss`.
Тест передаёт код в debug-only UsbTestActivity, защищённую системным разрешением
android.permission.DUMP (ADB shell/system). Обычная MainActivity не принимает
автоматическое сопряжение из Intent. Тест проверяет HTTPS и останавливает приложение;
wifi-loss кратко выключает Wi-Fi и включает обратно в finally.

На этом телефоне активный AdGuard запрещал прямую привязку к физическому Wi-Fi
с ошибкой EPERM. После отключения AdGuard пользователем соединение заработало.
Приложение не отключает фильтры или VPN автоматически и не использует LTE вместо Wi-Fi.

## Проверки

`cd pc; npm test`: настоящий локальный WebRTC между двумя peer connection,
SOCKS5, три параллельных бинарных потока по 700000 байт, завершение TCP в обоих
направлениях с финальным ответом, запрет BIND/UDP и остановка при закрытии peer.
Тестовый exit разрешает loopback только внутри теста, Android таких прав не имеет.
Результат 11 октября 2026: тест пройден, npm audit — 0 найденных уязвимостей.
Android `:app:assembleDebug` и `:app:lintDebug` пройдены (0 ошибок lint;
1 предупреждение о совместимости настроек резервного копирования). Последний APK повторно
установлен и проверен двумя USB-сценариями после ограничения тестового компонента.
После тестов Wi-Fi включён, сервис Android и клиент ПК остановлены.

`android/tests/PublicAddressTest.java`: проверка public/private IPv4/IPv6,
IPv4-mapped и IPv6 transition адресов. Выполняется обычной Java без телефона.

Остаётся: повторить native-тест на удалённом Wi-Fi, добавить UDP
и системный клиент Windows с двумя режимами.
USB-тест на одной сети не заменяет повторную проверку на удалённом Wi-Fi.

Протокол: `docs/protocol.md`. Требования к системным режимам: `docs/windows-modes.md`.

Пинг под статусом подключения — время ответа подключённого телефона через WebRTC.
Обновляется каждые 2 секунды; без свежего ответа и после отключения отображается «—».
Пинг до конкретного сайта или игрового сервера может быть выше.

Иконка Phone Exit: мятный телефон со стрелкой, исходник `assets/phone-exit-icon.png`.
Windows использует её в окне, панели задач и ярлыке `Phone Exit.lnk` в папке продукта.
На Android 0.3.3 добавлены adaptive launcher icon, иконка в заголовке и одноцветная
иконка foreground-уведомления. Способ генерации и полный запрос: `assets/README.md`.

Запуск Windows: двойной щелчок по ярлыку Phone Exit на рабочем столе или поиск Phone Exit в меню Пуск. Консоль не открывается. При переносе папки пересоздать ярлыки: powershell.exe -NoProfile -ExecutionPolicy Bypass -File pc/install-shortcuts.ps1.

Для запуска из папки продукта откройте **Phone Exit.exe**. Он использует соседнюю
папку `pc`, поэтому EXE отдельно переносить нельзя. Сборка запускателя:
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File pc/build-launcher.ps1`.
Повторный запуск показывает уже открытое окно. Сохранённые телефоны видны сразу,
проверка их доступности выполняется автоматически после запуска.

Windows 0.3.4: окно работает непосредственно в процессе Phone Exit.exe; на панели
задач используется иконка приложения. PowerShell 5.1 применяется как встроенный
движок, отдельный процесс powershell.exe для окна больше не создаётся.
Личный профиль хранится в `.phone-exit` в домашней папке текущего пользователя Windows; путь определяется по SID через реестр. Прежний DPAPI-профиль переносится автоматически без замены аккаунта. Это исключает виртуализацию AppData при запуске из MSIX-среды.
Проверка реального запуска EXE: `Phone Exit.exe --startup-test` (проверяет личный
профиль и появление доступного телефона, затем закрывается). Результат без ключей
записывается в игнорируемую `.tools/startup-result.json`.

## Исправление ошибки 429 в 0.4.1

Старый сервер сигнализации исчерпал лимит 30 комнат. Добавлен отдельный сервер
Phone Exit с отдельным хранилищем и лимитом 512 комнат. ПК автоматически выбирает
его для APK 0.4.1. Установите PhoneExit-personal.apk поверх старой версии на каждом
телефоне и откройте приложение; данные привязки сохранятся. Старые APK продолжают
использовать старый адрес и могут получать 429.

Проверены сборка APK/lint, 10 локальных тестов, 40 независимых комнат на хостинге
и настоящее соединение с USB vivo через новый сервер: HTTPS, пинг, UDP DNS/STUN.
Удалённый Samsung нужно обновить и проверить на его сети. Системный TUN в этой
проверке повторно не включался. Протокол: docs/catalog-v2.md.

## Сравнение скорости 0.4.2

APK 0.4.2 поддерживает разовый замер Wi-Fi по явной команде подключённого ПК.
`$env:PHONE_EXIT_DIAG_COMPARE='1'; ./pc/probe-phone.ps1 -Name SM-G990B` последовательно
скачивает 5 МБ напрямую на телефоне и через SOCKS/WebRTC. Содержание не сохраняется,
результат содержит только размеры и время; сводка в игнорируемой
`.tools/network-comparison.json`. Нужен свободный телефон с включённым доступом
и свободный локальный порт 1080. Протокол: docs/network-comparison.md.
Сборка/lint и 11 тестов прошли; реальная USB-проверка vivo: напрямую 0,691 с
(около 58 Мбит/с), через туннель 1,220 с (около 33 Мбит/с). Это локальная сеть,
не измерение удалённого Samsung и не системный TUN-тест.

Удалённый Samsung после обновления до 0.4.2: напрямую 5 МБ за 0,690 с
(около 58 Мбит/с), через туннель за 30,287 с (около 1,32 Мбит/с).
Пинг во время проверки 324–830 мс. Прямая загрузка быстрая; падение скорости
возникает при передаче к ПК. Этот результат не разделяет uplink телефона,
международный маршрут и ограничения реализации WebRTC; Discord и TUN данным
замером не проверяются.

## Ускорение транспорта Windows 0.4.4

По умолчанию ПК использует нативный node-datachannel 0.33.4 (версия закреплена
в package.json/package-lock.json) вместо SCTP на TypeScript. Запуск прежний:
`Phone Exit.exe`; Android Samsung обновлён до 0.4.4, данные привязки сохранены.
Оба транспорта используют прямой WebRTC/DTLS и прежний протокол потоков, без TURN.

Удалённый Samsung: Werift 5 МБ за 33,054 с (~1,21 Мбит/с); нативный транспорт
за 6,846 и 6,453 с (~5,84–6,20 Мбит/с). После переноса в обычный main.js —
6,926 с (~5,78 Мбит/с). HTTPS, UDP DNS/STUN прошли; пинг остаётся ~330–630 мс.
Это улучшение SOCKS/WebRTC. Работа Discord и конкретного игрового лаунчера через
системный VPN этим замером не подтверждена. Прямой upload телефона ~67 Мбит/с,
download ~83 Мбит/с, поэтому запас скорости ещё есть; международный путь отдельно
не измерен. Проверены 13 npm-тестов и оконный запуск/остановка/переподключение.

Уменьшение кадров, задержанные ACK и объединение credit не подтвердили улучшения;
два последних прототипа удалены. Окно Android→ПК увеличено до ограниченного 1 МиБ,
старые APK совместимы; одно это изменение Samsung не ускорило.
Для явного сравнения можно задать `PHONE_EXIT_TRANSPORT=werift`; обычный клиент
автоматически не меняет транспорт при ошибке. Детали: docs/network-comparison.md.

## TCP-окно и скорость 0.4.6

Windows автоматически согласует с APK 0.4.6 окно Android→ПК 2 МиБ и очередь
DataChannel 512 КиБ. Они ограничены; прежние APK сохраняют прежние параметры.
Настройки TCP-буфера ОС и размер кадра 16384 остаются стандартными. Обновление
телефона — установить `PhoneExit-personal.apk` поверх приложения, данные сохраняются.

Samsung SM-G990B: одинаковые 20 МБ в одном потоке — прежние настройки
10,1–11,1 Мбит/с, новые 15,4 Мбит/с. Четыре потока суммарно 20 МБ —
19,7–20,3 и 21,2 Мбит/с соответственно. Замеры последовательные, скорость маршрута
может меняться. Пинг в финальном тесте 315–487 мс. Все 19 UDP DNS-запросов
под нагрузкой получили ответы; HTTPS, UDP STUN и цепочка sing-box→SOCKS прошли.
Пользователь подтвердил сохранение звука Discord после 0.4.4. Видео, конкретный
игровой лаунчер и длительная нагрузка более 30 устройств пока требуют проверки.

APK собран, lint без ошибок; 13 локальных тестов и оконный SelfTest прошли.
Для повторения нагрузочного сравнения: `PHONE_EXIT_DIAG_PARALLEL=1` и
`PHONE_EXIT_DIAG_LONG=1`, затем `pc/probe-phone.ps1 -Name SM-G990B` при свободном
телефоне и порте 1080. Тест передаёт 40 МБ, содержимое не сохраняет; счётчики
только по явной диагностической команде. Подробности: docs/network-comparison.md.

Дополнительное сравнение Samsung 0.4.6, по 32 МБ в каждой фазе:
4 потока — 13,3–18,8 Мбит/с, 8 — 22,4–22,6, 16 — 19,1–22,6.
Лимит продукта уже 128 TCP/64 UDP; для этих загрузок его повышение не нужно.
8 потоков — ориентир для загрузчика, который сам поддерживает скачивание частями,
не настройка, автоматически делящая любой TCP-поток. Повторить сравнение можно с
`PHONE_EXIT_DIAG_STREAMS=4,8,16` и `PHONE_EXIT_DIAG_TOTAL_BYTES=32000000`
вместе с `PHONE_EXIT_DIAG_PARALLEL=1`. Такой запуск передаёт 96 МБ.

## Несколько транспортов, эксперимент 0.4.7

APK 0.4.7 и Windows умеют использовать четыре независимых WebRTC соединения:
одно для UDP/heartbeat, три для распределения новых TCP потоков. Согласование
проходит внутри основного защищённого DataChannel, без дополнительных PHP комнат,
TURN и изменения ключей. Общие ограничения 128 TCP/64 UDP сохраняются.

Samsung, восемь загрузок суммарно 32 МБ: одно соединение 18,5–18,9 Мбит/с,
четыре — 32,0 и 32,2 Мбит/с в двух замерах, но один повтор просел до 5,5.
После повторных замеров пользователь разрешил применение: обычный клиент
автоматически выбирает четыре соединения при объявленной поддержке APK 0.4.7.
Старые APK и диагностический Werift сохраняют одно. `PHONE_EXIT_PEERS=1`
явно возвращает один транспорт; `2` отделяет TCP от UDP, но ускорения не показало.
При потере любого канала
закрывается весь туннель. Сборка APK/lint без ошибок, 14 тестов и оконный SelfTest
прошли; полный системный TUN с несколькими транспортами ещё не перепроверен.
Протокол и подробные результаты: docs/multi-peer.md.
Повтор четырёх соединений с проверкой sing-box дал 32,3 Мбит/с, просадка
не повторилась; её причина остаётся неизвестной. Запуск — обычный `Phone Exit.exe`,
настройки вручную не нужны. Прежний тестовый ярлык остаётся совместимым и явно
выбирает четыре соединения, требуя APK 0.4.7. Финальная проверка без override
выбрала четыре автоматически: 31,427 Мбит/с, основной RTT 320–335 мс, UDP 9/9.

## Windows 0.4.8: переподключение и несколько приложений

После обрыва ПК автоматически возвращается к выбранному телефону, когда он
доступен. Повторы с паузой до 30 секунд; TUN остаётся включённым и блокирует
назначенный туннелю трафик. «Отключить» или закрытие окна отменяют ожидание.
Повторное подключение переиспользует TUN и не вызывает новый запрос UAC.
Настройка действует до остановки сеанса, а не после перезапуска программы.

Для нескольких игр/программ выберите «Выбранные EXE · VPN (тестовый)» →
«Список приложений…» → «Добавить EXE…». Можно выбрать несколько файлов и
дополнять список позже; удаление по одной записи, сохранение кнопкой «Готово».
Добавляйте саму игру и лаунчер. Найденные дочерние EXE автоматически включаются
в текущий сеанс. Их первые соединения до обнаружения могут пройти напрямую,
поэтому важные EXE добавляйте явно заранее. Режим остаётся тестовым.

Проверены оба системных режима на настоящем Windows TUN с USB vivo APK 0.4.7:
HTTPS/UDP DNS/STUN, обрыв, блокировка, автоматическое восстановление без нового
TUN, отмена и возврат обычного интернета. Выборочный тест также проверил новый
дочерний EXE и обычный интернет невыбранного EXE во время обрыва.
14 npm-тестов, проверки состояния/процессов и оконный SelfTest прошли.
Телефон обновлять не нужно; отдельная проверка этих изменений на удалённом
Samsung, смены Wi-Fi/IP и конкретных игр пока не проведена.
Подробности и ограничения: [docs/recovery-and-apps.md](docs/recovery-and-apps.md).
