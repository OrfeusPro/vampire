## Android 0.9.6: совместимость выхода с VMOS

Пользователь подтвердил: ошибка 0.9.5 возникает на двух облачных VMOS, обычный
телефон и UgPhone работают. Возврат false из bindProcessToNetwork не доказывает
конфликт VPN: Android также документирует его для недействительной Network.
Причина на конкретных VMOS пока не измерена.

После отказа привязки только роль выхода может использовать обычные сокеты/DNS
системной сети. Условие: выбранная валидированная Wi-Fi/LTE совпадает с default,
нет прежней process binding и видимых VPN-сетей. Обычный успешный путь привязки
сохранён. В совместимом режиме HTTP, DNS, TCP и UDP используют один подход;
IPv4 и запрет частных адресов сохранены. Проверки перед операциями и default
network callbacks закрывают сессию при изменении условий. Между проверкой и
системным вызовом остаётся гонка смены сети: это не гарантия жёсткой привязки.
Клиентский VpnService сам такой режим не включает. Приоритет Wi-Fi сохранён;
если выбранный Wi-Fi не является default и привязка запрещена, обхода через LTE нет.

Активная кнопка «Переподключить доступ» закрывает текущие подключения и заново
выбирает сеть. Старые callbacks не перезапускают уже заменённую сессию. Повтор
после отказа — через 15 с; периодическая проверка больше не обходит эту задержку.
«Доступен» появляется после успешного обращения к каталогу, до него — проверка.

Проверки: 26 JVM-тестов, сборка/lint (0 ошибок, 16 предупреждений), подпись.
На vivo пройдены два настоящих native WebRTC прогона: обычная привязка и
принудительно выбранный только в test APK совместимый режим. В каждом — три
HTTPS, UDP DNS, пакет через hev TUN, закрытие при потере транспорта. Это
проверяет совместимый путь на физическом устройстве, не воспроизводит отказ VMOS.
Проверка двух проблемных VMOS после обновления остаётся необходимой.
APK 0.9.6/code 46 установлен поверх vivo, доступ включён, клиентский VPN выключен.
Приватный FTP-релиз опубликован; авторизованный HTTPS manifest и полное APK
скачивание проверены по размеру/SHA256:
`d5e5b51edb7fc8109e8dcd85431765164b59bba9043a17c2239205b8ca0be5fa`.

## Android 0.9.4 и Windows: IPv4, Wi-Fi и мобильный интернет

16 октября пользователь явно изменил прежнюю Wi-Fi-only политику: обе Android-роли
могут использовать мобильную сеть. Также запросил IPv4-only для VPN на Android/ПК.
Это актуальная политика; разделы ниже описывают историю предыдущих версий.

Android больше не объявляет IPv6-адрес/маршрут TUN; IPv6 не разрешён для прямого
обхода. TCP/UDP на выходе выбирают только публичные IPv4, прежний запрет LAN
сохранён. ExitService, управление и обновления по кнопке выбирают валидированную
Wi-Fi/cellular сеть; выход закрывает старые потоки при смене сети и автоматически
возвращается в ожидание на новой. Активный VPN-клиент после смены сети по-прежнему
нужно отключить и подключить заново. Статус выхода показывает Wi-Fi/мобильную сеть,
в UI указано использование SIM-трафика. Установку обновлений подтверждают вручную.

WifiBinding разрешает новую привязку, если Android уже удалил старую Network,
даже когда native factory ещё освобождается. Поздний release прежнего владельца
не снимает новую привязку. Живую занятую сеть не подменяет. Статусы различают
ожидание старого соединения и отказ Android, вместо общего «Wi-Fi недоступен».
Это исправление подтверждено тестами; конкретный телефон со второго скриншота
не идентифицирован и отдельно не проверен.

Windows: DNS AAAA возвращает NOERROR без адресов, FakeIP только IPv4, IPv6
отклоняется для VPN-трафика. В выборочном режиме маршрут IPv6 невыбранных EXE
остаётся прямым, но перехваченный DNS не выдаёт AAAA всем приложениям.
Переключение системного IPv6 ОС не выполняется. Подробности [Windows](docs/windows-modes.md).

24 JVM-проверки Android, сборка/lint/подпись, 5 проверок конфигурации/настоящего
WebRTC UDP ПК и `sing-box check` обоих режимов прошли. Реальный Android VpnService
через realme JP: 3 HTTPS/JP, DNS, STUN; Netmarble `/restriction` по IPv4 — HTTPS 200,
IPv6 не предлагается, отдельный WebView открыл страницу. В 0.9.3 этот WebView
возвращал сетевую ошибку -6, прямой IPv6 запрос сбрасывался, IPv4 работал.
Параметры авторизации со скриншота не использовались. Первый прогон WebView после
IPv4-изменения завершился таймаутом, финальный повторный прогон успешно открыл
страницу за 14,3 с вместе с сетевыми проверками. Игровая авторизация с аккаунтом
не проверялась. LTE на USB-vivo недоступен; оба LTE-режима требуют другого телефона.

ПК через настоящий WebRTC/realme JP и loopback sing-box: A/AAAA проверены,
Netmarble HTTPS 200, 5 МБ скачаны полностью. Системный TUN в этом новом прогоне
не включался. Для применения новых правил переподключить VPN в окне ПК.

0.9.4/code 44 установлен на vivo, опубликован в приватный FTPS releases;
проверены HTTP 403, удалённый SHA256/размер, manifest и полное авторизованное
HTTPS-скачивание. SHA256 `f039d99b2167f2fa068fb90b6f169fc644158f2b91a8df8f7c48d85aab8eee25`.
Дополнительно повторён native regression финального APK: 3 HTTPS, UDP DNS,
hev IP-пакет и потеря транспорта прошли. После тестов намерение доступа vivo

## Android 0.9.3: мобильный интернет на VPN-клиенте

По уточнению пользователя подключающийся телефон теперь может использовать
мобильную сеть или Wi-Fi. `PeerDirectory.clientNetwork` выбирает валидированную
физическую сеть с интернетом, предпочитает текущую default-сеть, исключает сам VPN.
Выбор из списка, HTTPS-сигнализация и native WebRTC используют выбранную сеть;
cellular больше не исключён из ICE клиента. Выходной телефон по-прежнему выбирает
только Wi-Fi; его DirectoryAgent/ExitEngine и политика запрета LTE не менялись.

При исчезновении выбранной сети VPN блокирует трафик до Stop, как раньше.
Автоматический переход активного VPN с Wi-Fi на LTE не добавлен: сначала
отключить VPN, переключить сеть и подключиться заново. Обновлён текст интерфейса.
20 JVM-тестов прошли, включая мобильную сеть без Wi-Fi, отказ выхода работать
через LTE, исключение VPN/невалидированных сетей и выбор физической сети.
Сборка/lint/подпись 0.9.3/code 43 проверены, APK установлен поверх vivo.

Wi-Fi восстановлен. Пользователь подтвердил, что LTE проверит на другом телефоне.
Успешная передача через мобильную сеть пока не подтверждена устройством.

## Android 0.9.0: подключение через другой личный телефон

телефон → WebRTC → Wi-Fi другого телефона. Выбор собственного id и занятого

автовосстановление VPN-клиента пока не реализовано. Предоставление доступа
после остановки клиента включается пользователем отдельно.

PHP и Windows-транспорт не изменены. Закрытый ключ ПК в APK не передаётся.
Приватный APK теперь также даёт доступ к другим личным выходам; локальный список

## Редизайн Windows, 13 октября 2026

В нативный клиент перенесены логотип, графитовая палитра, боковая навигация и
структура [макета Figma](docs/redesign-2026-10-13/README.md). Первый экран —
реальные личные устройства: компактные или крупные карточки, табличный вид,
поиск по имени/персонажу/модели/стране, фильтры доступности и бота, сортировка.
Фильтры не меняют исходный список транспорта. Выбор сохраняется по id при
обновлении и сортировке; скрытые фильтром устройства исключаются из выбора.

Карточка показывает имя персонажа или телефона, страну, модель, иконку игры
и настоящее состояние бота. Пауза/запуск, настройки и меню дополнительных
действий доступны прямо из карточки. Недоступные, устаревшие и ожидающие
результата устройства не принимают новые быстрые команды. Групповой запуск
и пауза требуют подтверждения числа подходящих устройств. После подтверждения
цели повторно разрешаются по постоянному id, а не по изменяемому номеру строки.

## HTTP API, совместимость VMOS и удалённое обновление · 0.6.0

В APK добавлен отдельный API управления личным телефоном без ADB и root.
Бот на ПК получает скриншот и отправляет tap/swipe/back/home/launch через HTTP.
Игровые сценарии пока не подключены. [Контракт API и ограничения](docs/control-api.md).
По просьбе пользователя переключатель управления включён при новой установке;
явное выключение сохраняется. Службу специальных возможностей нужно вручную
разрешить на каждом Android.
Скриншоты требуют Android 11+, существующий VPN по-прежнему поддерживает Android 8+.
Экран должен быть разблокирован; системные подтверждения установки не нажимаются.

Windows показывает установленную APK-версию в строке каждого телефона.
Выберите телефон → «Обновить телефон»: команда по HTTPS загрузит проверенный APK
и покажет уведомление. На телефоне нажмите «Установить загруженное обновление»
и подтвердите системный запрос. Разрешение установки из Phone Exit выдаётся вручную.
Без root тихая установка не обещается. APK до 0.5.0 не поддерживают этот API:
для них нужно один раз вручную установить новый персональный APK поверх старого,
не удаляя данные. `account.bin` не заменять. Персональный APK отдавать только себе.

Для собственного бота запустите `pc/start-control-api.ps1` и используйте
`http://127.0.0.1:17842/v1/devices`. Ключ заголовка Authorization хранится в
DPAPI-файле `control-api.bin` профиля текущего пользователя. Получить его для
настройки своего бота: `pc/start-control-api.ps1 -ShowKey` (не публиковать вывод).
Пример запроса: `POST /v1/devices/<id>/commands` с JSON
`{"command":"status","args":{}}` и `Authorization: Bearer <ключ>`.
Ответ 202 содержит id задания; результат опрашивается
`GET /v1/devices/<id>/commands/<id задания>`. Не повторяйте нажатие при неизвестном исходе.
`status` сообщает UID процесса и признаки `su`; это пассивная диагностика,
наличие `su` не означает подтверждённые root-права приложения.

## Текущая версия

`pc/`: Node.js 22+, werift 0.25.0, локальный SOCKS5 CONNECT на 127.0.0.1:1080.
Каждое TCP-соединение имеет отдельный надёжный DataChannel. Лимит нового APK: 128 TCP-потоков и 64 UDP-ассоциации,
кредитное окно 256 КиБ, кадры до 16 КиБ, корректное завершение направлений TCP.

`android/`: Java, foreground service с уведомлением и остановкой, WebRTC,
ввод кода сопряжения, DNS и TCP через конкретную Wi-Fi Network,
запрет доступа к локальным/служебным адресам. Камера и микрофон не нужны.

### Запуск клиента

**Актуальный режим — персональный APK без кодов.** Установите
`PhoneExit-personal.apk` из корня `phone-exit` на свои телефоны и откройте один раз.
Телефон сам включит foreground-доступ с уведомлением, зарегистрируется на сервере
и появится в приложении ПК вместе со страной. На ПК: двойной щелчок по
`Phone Exit.vbs`, выбрать телефон, режим «Весь трафик · VPN» и нажать «Подключить VPN».
Подтвердите запрос Windows для виртуального интерфейса. Настраивать прокси
в браузере не требуется. «Отключить» возвращает обычный интернет.
Для VPN обновите телефоны до приложенного APK 0.3.2; старые версии работают
только в режиме «Прокси · TCP».
Этот APK предназначен только для ваших устройств: обладатель файла может добавлять
телефоны в ваш список. Сборка персонального APK: `android/build-personal.ps1`.
Данные аккаунта ПК защищены DPAPI в `%USERPROFILE%/.phone-exit/account.bin`; не удаляйте
этот файл для обычного обновления APK. Перенос аккаунта на другой ПК ещё не реализован.

При потере Wi-Fi телефон закрывает TCP и UDP, остаётся ожидать сеть и автоматически
возвращается в доступные после восстановления. Ошибки HTTP повторяются с паузой
до 30 с. Статус «не в сети» появляется после 45 с без heartbeat, плюс интервал
обновления списка. Кнопка «Остановить» на телефоне выключает автоматический режим;
после неё для включения нажмите «Включить автоматический доступ».
Служба возобновляется при системном перезапуске/после boot, когда enabled-флаг включён;
реальная перезагрузка пока не проверялась. Принудительная остановка Android и
ограничения фоновой работы производителя могут потребовать открыть приложение.
Основание платформенной реализации: [sticky service](https://developer.android.com/reference/android/app/Service),
[foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types).

## Быстрый канал управления 0.7.0 (12 октября 2026)

Сохранены VMOS HTTP адреса и подпись. APK 0.7.0/versionCode 18 сообщает
control.api=3/directControl=true. Gateway лениво создаёт отдельный native WebRTC

### Карта, точки и Fast Travel

Редактор сверён с MultiBot на `127.0.0.1:8099/dashboard`. По умолчанию показана
только область карты: x=0.265–0.735, y=0.095–0.945 полного снимка, как в старом
редакторе. «Весь кадр» оставлен отдельным видом. Базовый размер карты ограничен;
масштабирование и обрезка пересчитываются в координаты исходного полного снимка.
Существующие точки не мигрируют и не меняются от вида, размера окна или вкладок.

Инструменты: добавить, переместить перетаскиванием, удалить, задать телепорт.
ЛКМ в режиме добавления рядом с точкой больше не удаляет её; ПКМ не меняет
телепорт. Отмена хранит последние 100 изменений точек/телепорта в памяти окна.
Перетаскивание за пределы изображения отменяет перенос. Отправка остаётся явной.

Справа показаны непустые строки Move из сохранённого изображения выбранной
локации; выбор записывает прежнее `teleport_point`, есть «Без Fast Travel» и
режимы «Телепорт + бежать» / «Только телепорт». Для Tyriosa выбор блокирован
маршрутом. Это каталог снимков, не живое распознавание списка на телефоне:
в текущем снимке Ulan три строки, в просмотренном старом боте четыре.
Figma: 09 (`33:82`) и 10 (`33:162`), предыдущие варианты сохранены.
Тесты проверяют добавление без случайного удаления, перенос/удаление/отмену,
координаты телепорта, вид карты и отсутствие горизонтальной прокрутки списка.
Команды и настройки телефона в этих проверках не отправлялись.

## Выбор игры в настройках устройства

Вкладка «Бот» выбирает игру из локального каталога модулей. Выбор в поле не
назначает игру и не отправляет команды: назначение выполняется отдельной кнопкой.
Для смены игры требуется подтверждение; несохранённые изменения блокируют назначение.
Сейчас реализованы назначение и редактор только LordNine. Другие игры не выдаются
за поддерживаемые: для них нужны собственные редактор, схема настроек и проверки.
Фарм, карты, восстановление и разбор вещей относятся к LordNine, а не к общей
форме управления устройством. При просмотре другой игры эти элементы скрываются,
сохранение настроек LordNine недоступно, существующий профиль не изменяется.

## DPI между мониторами, 13 октября 2026

Windows-клиент включает Per-Monitor V2 до создания окон. Общий класс окон
обрабатывает WM_DPICHANGED: пересчитывает геометрию, шрифты, минимальный размер
и рабочую область выбранного монитора. Масштаб хранится отдельно для каждого
окна; перенос редактора не меняет масштаб основного окна. Карточки, значки,
поля и строки списков перерисовываются вместо растягивания Windows как картинки.
Диалоги, открытые после переноса, используют текущий масштаб родительского окна.

`pc/test-desktop-dpi.ps1` проверяет Per-Monitor V2 и пять циклов сообщений
WM_DPICHANGED для DPI 96/120/144/192, возврат размеров и независимость окон.
Проверены реальные переносы тестовых окон между подключёнными мониторами
1920x1080 (DPI 96) и 3840x2160 (DPI 144). UiTest и scoped-тест редактора
сохраняют снимки основного окна, диалогов и вкладок «Бот»/«Фарм» на обоих
мониторах; снимки просмотрены. Controls/fleet/scoped/UiTest прошли.
Команды бота, сохранение профиля и VPN в этих проверках не запускались.
Уже работающий экземпляр нужно перезапустить для загрузки новых классов UI;
для этого изменения повторная сборка EXE не требуется.

Табличный список устройств получил закреплённую шапку «Устройство / Связь /
APK / Бот / Действия», плотные строки без промежутков между карточками,
разделители, флаги и значки выбранной игры. Версия APK берётся из versionName
каталога телефона; при отсутствии версии показано «—», без подстановки версии
модуля бота или клиента ПК. Версия также видна в карточках и accessibility.
Fleet-тест проверяет APK, неподвижную шапку вне области выбора и границы действий
при масштабах 100%/150%; UiTest со списком 11 телефонов прошёл. Просмотрены
снимки таблицы и карточек. Настройки телефонов и команды бота не изменялись.

Верхняя полоска карточек отражает актуальный статус: мятная — бот работает,
жёлтая — пауза, запуск, ожидание или выполняемая команда, красная — ошибка
либо телефон offline. Нет бота, остановлен или статус устарел — нейтральная
серая полоска. Полоска 3 логических px обрезается по скруглению карточки;
