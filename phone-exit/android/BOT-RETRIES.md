# Повторный запуск бота: APK 0.8.12

Движок автоматически запускает новый проход только после `pause=true` с непустой
ошибкой текущего запуска. Обычные waiting/loading/running не перезапускаются.
Ручная пауза, Stop, управление экраном, редактор точек и остановка из-за смены
настроек не запускают повтор. Явный Start/Resume начинает новую серию попыток.

Максимум пять повторных запусков в одном шестичасовом окне. Между ними пять секунд.
Успешный промежуточный tick не сбрасывает число попыток. Счётчик и начало окна
сохраняются в state.json; через шесть часов бюджет обнуляется при следующем отчёте,
а API сразу показывает истёкший бюджет как 0. Уже остановленный после лимита бот
самостоятельно не возобновляется от одного сброса счётчика.

Каждый повтор меняет generation: Python начинает с пустого состояния и нового
распознавания, не продолжает старый маршрут и не повторяет непроверенную команду.
Старые отчёты отвергаются; ручная пауза отменяет ожидающий повтор.

API добавляет retryCount, retryLimit, retryAt, retryWindowStarted, retryExhausted,
lastRetryError, lastRetryStep, retryHistory (до шести записей). Во время ожидания
status=waiting, step=auto_restart_pending, error=null. Если пять перезапусков
не помогли, status=error, desired=paused, error содержит последнюю реальную причину,
reason=retry_limit_reached. Снимки отдельных ошибок сохраняет прежний временный архив.

ПК показывает «Перезапуск N/5» в свежем списке и последнюю причину в деталях.
На телефоне видны число попыток и последняя причина. Потеря разрешений, которая
ставит бот на паузу без error, требует восстановления разрешений пользователем.

Проверки 14 октября 2026: APK 0.8.12/versionCode 38 собран, lint 0 ошибок /
16 предупреждений. На настоящем Android instrumentation прошли пять попыток,
отказ от шестого перезапуска, последняя причина и история, граница 6 часов,
сохранение бюджета после успешного tick, ручная отмена и отсечение старого отчёта.
Шестичасовая граница проверена подстановкой времени, не шестичасовым ожиданием.
78 replay-проверок Lord Nine и компиляция панели ПК прошли.
Полный тест Python/Binder/локального capture пока остановлен отсутствием службы
специальных возможностей на USB-vivo. Пользователю отправлена просьба включить её.
Тестовые данные vivo восстановлены в состояние без назначенного бота.

Проверка UI через desktop.ps1 -UiTest прошла. Старый способ instrumentation
перезапускал основной процесс и помечал службу управления crashed на vivo.
Для проверки Python/Binder используется отдельная тестовая сборка с
-PphoneExitTestRunner=net.phoneexit.BotRuntimeInstrumentation и
-PphoneExitTestProcess=net.phoneexit:bot. Это затрагивает только тестовый APK;
обычный runner по умолчанию остаётся в основном процессе для прежних тестов.
