# Назначение игры в клиенте ПК

Проверено 14 октября 2026 на ROG ASUS AI2201_B · NL, APK 0.8.12.
Телефон находился в каталоге, но прямой control WebRTC возвращал
ice_no_candidates. Прежний API сохранял назначение только после ответа Android,
поэтому в ПК выбранный RF Online Next не появлялся в профиле.

Теперь назначение сохраняется в локальном профиле перед передачей телефону.
assignmentPending и assignmentError отделяют выбор ПК от подтверждения Android.
При следующей установке/запуске и фоновой синхронизации сначала проверяется
фактическое назначение. При смене работающего бота подтверждённая Stop предшествует
Assign; новое назначение само не запускает сценарий. После неизвестного исхода
сначала читается состояние, команды не повторяются вслепую.

Управление ботом (назначение, каталог, установка, настройки, Start/Stop/Pause)
без открытого WebRTC использует прежний аутентифицированный зашифрованный
HTTPS control mailbox. Изображения и ручное управление сохраняют прямой канал;
не добавлен сторонний relay/TURN. При открытом канале команды используют его.
Пакеты по-прежнему скачиваются по авторизованному HTTPS с проверкой подписи/хеша.

В главной карточке и настройках есть «Назначен на ПК · ожидает передачи».
Телефону без профиля больше не подставляется Lord Nine как назначенная игра.
Сохранённые старые профили не меняются автоматически.

21 проверка Bot API/control API прошла, включая отсутствие двойной отправки,
отказ устройства, локальное назначение, защищённый HTTPS и работающий WebRTC.
Настоящий UiTest прошёл с 12 телефонами. ROG подтвердил назначение RF Online Next;
модуль 1.0.1 установлен и остановлен, настройки переданы. Игра этим тестом
не запускалась. Локальный шлюз перезапущен с исправлениями; уже открытый EXE
загружает C# UI один раз и получает новое оформление после переоткрытия окна.
