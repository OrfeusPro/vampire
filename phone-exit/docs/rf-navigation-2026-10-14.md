Два касания с разведением действительно увеличивают карту. Надёжно сработали
штрихи с началом 0/80 мс, окончанием на 1600 мс, исходным расстоянием примерно

Пешком / Телепорт / Метка. В тесте использована точка полного кадра [830,650],
нормализованная координата атласа примерно [0.316827,0.561630].
Диалог телепорта к свободной точке отличается от диалога телепорта к значку:
он сообщает о телепортации в локацию и последующем автоматическом движении
к выбранному месту. Показанная цена 8900 обычных монет. После подтверждения
персонаж переместился от входной платформы, стрелка на карте сместилась.
Это не доказывает точность автоматического сценария: тест выполнен вручную.
Игровой автобой включён вручную на месте, кнопка сменилась на голубое кольцо 35m.

На воде ранее получено «Невозможно добраться до локации». Границы доступности
произвольных координат из таблиц пока не извлечены. Принадлежность записи
RegionIndex не является геометрической границей навигации. Не подменять цель
соседней точкой и не считать все пиксели суши проходимыми.

## Реализация для испытаний

APK 0.8.13 / движок 4: локальная SIFT/RANSAC привязка атласа, без OCR и передачи
снимков на ПК; host-команды gesture и longPress используют существующие проверки
актуальной generation, разрешений, foreground игры и геометрии кадра.
Поддержаны предыдущие движки 1–3. Атлас поступает в игровом модуле.
Распознавание отклоняет малое число совпадений, узкую область опорных точек,
большую ошибку, отражение и вращение; точка вне видимой безопасной области
не выдаётся как доступная для нажатия. Это проверка привязки, не проходимости.

Нативный replay на vivo: точка [442.753,346.595] против контрольной [442.66,346.66],
97 inliers, median residual 0.268 atlas px, первый холодный вызов 6783 мс.
Первый расчёт включает загрузку и признаки атласа; последующая скорость ещё
требует измерения. Цикл около секунды для полной навигации не подтверждён.

Модуль 1.1.0 (пока не опубликован): ограниченный сценарий выбора активной точки,
сдвига, трёх разведений, удержания, выбора Пешком либо явно выбранного телепорта,
проверки белой стрелки у цели на двух кадрах и включения автобоя.
Для подтверждения телепорта требуются его специальный заголовок, кнопка и
значок обычных монет; generic OK не подтверждается. Недоступная точка или
непроверенный переход ставят сценарий на паузу без автоматического повторения.
Не добавлены восстановление после смерти, обслуживание и выбор другого монстра.
Изменение точки сбрасывает только маршрут; отмена поколения запрещает действия.

ПК: список монстров и собственные точки; у точки доступен флажок телепорта
за игровые монеты, по умолчанию пешком. Фарм включается отдельным флажком,
назначение и сохранение точки сами не запускают бот.

## Проверки и ограничения

101 Python replay-тест (в том числе 17 RF) проходит. Проверки редактора карты
проходят, результат просмотрен. APK собран с lint, установлен на USB-vivo.
Длительный полный автономный маршрут пока не подтверждён.

Попытка запуска живого маршрута через instrumentation остановила основной
процесс приложения (`exit-info`: stop net.phoneexit due to start instr).
Android оставил службу в Crashed services при включённом переключателе.
Тест остановлен, его исходные настройки восстановлены. Для повторной проверки
используется обычный запуск BotService через защищённый API; тестовый модуль
временно находится в приватном cache, исходные installed/settings/state сохранены
в .tools/rf-live-backup и должны быть восстановлены по завершении.
Штатного AccessibilityService.requestRebind API нет: попытка использовать его
отклонена компилятором и удалена. Secure settings и разрешения код не меняет.
Нужен ручной цикл выключения/включения службы для восстановления привязки.

## Повторный обычный запуск

После ручного переключения Android показал Bound services=Phone Exit и пустой
Crashed services. Обнаружена ошибка именно тестовой PowerShell-оснастки:
map_points сериализовался как [x,y] вместо [[x,y]]. JSON исправлен; модуль
теперь отклоняет скалярную точку понятной invalid_farm_point без исключения.
Добавлен соответствующий replay. Профиль ПК этой оснасткой не менялся.

На живом экране появились два состояния энергосбережения: «В режиме ожидания»
и «Ведется автобой». Вместо меняющегося заголовка шаблон перенесён на стабильную
инструкцию «Проведите, чтобы выйти…». Выход из этого окна самим сценарием
подтверждён. Добавлено отдельное распознавание результатов режима вне игры
с ограниченным закрытием только по специальному заголовку и кнопке.

Старый hud_eye дал confidence около 0.60 на текущем vivo; снят новый образец.
Проверка этого исправления в живом маршруте не завершилась: 23:39:05 по времени
телефона com.vivo.abe остановила процессы Phone Exit и сняла привязку службы.
Это отдельная причина от предыдущего завершения процессом instrumentation.
Ожидавший запрос Stop прерван; сохранено desired=paused, затем восстановлены
исходные installed/settings/state. Результат восстановления проверен:
модуль 1.0.1, исходные настройки, пауза. Тестовый модуль не опубликован.

Текущие проверки: 19 RF replay-тестов, 84 Lord Nine; редактор карты и полный
Windows UiTest проходят. Окончательный APK собирается повторно после удаления
неподдерживаемого вызова requestRebind. Новая версия требует проверки полного
маршрута на телефоне с устойчивой фоновой работой перед публикацией.

## Разные экраны и сдвиги

Открытие миникарты больше не использует фиксированные .1375/.0556 координаты.
Ищется hud_map_anchor; его найденные центр и ширина задают положение и масштаб
смещения до заголовка миникарты. Без подтверждённого якоря нажатия нет.
HUD подтверждается сочетанием якоря слева и auto_off/auto_on справа. Изображение
активной кнопки 35m заменило цветовую долю, которая могла совпасть с фоном игры.
Зоны поиска кнопок расширены для небольших сдвигов; поиск использует несколько
масштабов. Сами координаты фарма по-прежнему пересчитываются по свежей карте
после каждого сдвига и жеста двумя пальцами.

`resource-tools/rfnext/check-screen-variants.py`: синтетические проверки
сдвига [45,25], масштаба UI .85 со сдвигом и canvas 1920×1080 с letterbox.
Ошибка проекции соответственно 0.202 / 0.260 / 0.198 px; 78/87/76 inliers.
Это offline SIFT regression, а не доказательство работы Android на иных моделях.
Python-тесты дополнительно проверяют масштабированный сдвинутый якорь и отсутствие
нажатия при его потере. Всего 105 тестов (21 RF и 84 Lord Nine).

Следующий живой запуск с новой версией дошёл до open, но служба снова исчезла:
Bound/Enabled/Crashed services стали пустыми, обновление статуса прекратилось.
Полный маршрут не подтверждён. Тест отменён через desired=paused, оригинальные
installed/settings/state восстановлены. Нужна устойчивая фоновая работа vivo
либо другой тестовый телефон; повторное включение службы временно помогает,
но не устраняет OEM-ограничение. Ничего не опубликовано.
