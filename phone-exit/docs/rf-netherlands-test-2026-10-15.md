# RF: новый персонаж на телефоне Нидерланды

Пользователь сообщил о новом персонаже на ROG ASUS AI2201_B · NL.
Через защищённый Bot API подтверждены rfonlinenext 1.0.1, engineVersion=3,
desired=stopped, status=installed. Фарм-точки USB-vivo не переносились.
Попытка отдельного deviceInfo через прямой канал завершилась таймаутом;
результат этой попытки не считается успешным подключением экрана.

Для проверки нового навигатора требуется движок 4. Сборка personal APK
0.8.13/versionCode39 прошла build/lint ранее. 15 октября через FTPS опубликован
только APK и его метаданные в существующем приватном каталоге releases.
control.php, signal.php и каталог игровых модулей этим действием не изменялись.
Перед передачей проверен HTTP403 приватного каталога, после передачи — размер
и SHA256 файла на FTP, затем атомарно заменены APK и manifest.
SHA256: 0459e46dc2c66f2f01ad80657120c24431e1ba791ec4d1c0936825da71c02978.

Команда checkUpdate отправлена только NL; ответ телефона:
status=ready_for_confirmation, availableVersion=0.8.13,
autoDownload=false, silentInstall=false. Пользователь должен подтвердить
установку Android и вернуться к персонажу. Остальным телефонам команд нет.
После обновления нужны свежий status, доступность службы и снимок нового
персонажа перед выбором маршрута. Фарм автоматически не включался.

Локальный пакет RF 1.1.0 подписан, 9852321 байт; 106 Python-тестов проходят.
Пакет пока не опубликован; полноценный автономный цикл на другом устройстве
ещё не проверен. Автозапуск остаётся отдельной функцией, фарм включается явно.

## Продолжение после подтверждения Android

Телефон подтвердил APK 0.8.13 / engine4, accessibility=true. Экран получен
через явный transport=https существующего шифрованного почтового канала.
В Bot API gateway добавлен этот opt-in для проверяемых команд: действие
никогда не переигрывается автоматически после неизвестного результата WebRTC.
Авторизация, шифрование, ограничения размеров, дедупликация и Android-проверки
команд остаются существующими. Обычный путь по умолчанию не менялся.
Gateway перезапущен отдельно от VPN; актуальный процесс слушает 127.0.0.1:17842.
21 Node API тест пройден, включая явный выбор HTTPS и сохранение ручных пауз.

Реальный экран 1280×720, персонаж уровня 71, активный радиус 17m. Отличия от vivo
1280×576 воспроизведены: заголовок миникарты открывает помощь о зоне; нажатие
в её изображение [150,90] открыло Novus. Смещение от найденного якоря изменено
на [120,65] с масштабированием по ширине якоря. Текст Мир Новус заменён RGBA
шаблоном без фона. Масштабы поисков расширены .65–1.5. По кадру NL confidence:
hud_map_anchor .993, auto_on .876, map_title 1.0.

Пользователь выбрал небольшое перемещение в текущем участке. На карте стрелка
около [638,359], участок у Обители покоя (Lv70), рядом Лагерь в оазисе.
Выбран соседний пиксель [620,350], свежая SIFT-привязка: 515 inliers,
median error .724 atlas px. Цель в нормализованном атласе
[0.1373750802143071,0.5604432488287301]. Это тестовая цель, не граница региона.
Настройки сохранены отдельно для NL, revision2, activePoint=nl-nearby-test,
travel_mode=walk; телепорт и расход валюты не запрашивались. Оригинал профиля
сохранён в .tools/nl-profile-before-route.json. Никакие точки vivo не копировались.

RF1.1.0 опубликован в приватном каталоге, установлен на NL с сохранением stopped.
После запуска выявлен sleep_title mismatch (.832 при пороге .87) на реальном NL.
Исполнение поставлено на паузу, подготовлен 1.1.1 с отдельным masked-шаблоном NL
и сохранённым вариантом vivo. Он установлен и запущен повторно; SHA256 пакетов
проверены удалённым чтением FTPS. На FTP оставлена только текущая RF1.1.1,
Lord Nine не заменялся. Размер пакета 9864579 байт; 106 Python-тестов проходят.
Полный цикл и стабильность в этот момент ещё проверяются, не объявлены успешными.

## Проверка подхода и уточнение телепорта

В 1.1.2 ложное распознавание белой надписи энергосбережения на светлой земле
ограничено проверкой тёмного фона. Не больше трёх попыток пробуждения подряд.
В 1.1.3 добавлены реальные варианты кнопок меню NL с сохранением вариантов vivo.
На NL пеший маршрут завершился: два подтверждения стрелки у цели, закрытие карты,
подтверждённый включённый автобой, status=running / step=farming. Один из циклов
занял 715 мс (capture 44 / match667). Это проверка одного подхода, не длительной
автономной работы и не восстановления после смерти.

Пользователь уточнил обычный способ: выбрать нужную точку карты → «Телепорт».
Ближайший телепорт и дальнейший подход выбирает сама игра. Каталог телепортов
не используется для предварительного выбора места. Revision3 переключила тест
на travel_mode=teleport. Попытка закончилась farm_point_menu_not_recognized;
следующий свежий кадр уже показал меню. Причина задержки пока не установлена.
Повторять нажатия вслепую нельзя. Ручное нажатие «Телепорт» открыло точный диалог:
«Отправиться туда сейчас?» и автоматический подход после телепортации в Обитель
покоя, стоимость 11 200 обычной игровой валюты. Подтверждение на этом этапе
не нажималось; окно отменено перед новым автономным тестом.

Исходный кадр диалога: .tools/rf-nl-teleport-confirm.jpg, NL1280×720.
Шаблоны 1.1.4: заголовок crop[522,272, 757,296], кнопка[644,479, 798,515],
значок монеты[657,381, 677,402]. Сохраняются прежние шаблоны с суффиксом _vivo.
Все три признака обязательны; общее OK и неизвестная валюта не подтверждаются.
На исходном кадре confidence1.0 для каждого. 109 Python-тестов прошли.
Пакет 1.1.4 подписан, опубликован с проверкой удалённого SHA256 и установлен
на NL в состоянии paused. Старый пакет RF на сервере удалён после смены индекса;
Lord Nine сохранён. APK для этого изменения не требуется.

Для следующего теста выбрана ещё одна соседняя точка: [430,375] свежей карты,
392 SIFT inliers / median0.741 atlas px. Нормализованная цель
[0.14097308412507503,0.5657163459648286], revision4, travel_mode=teleport.
Результат самого перелёта ещё требует живой проверки.
