# Дополнительные соединения WebRTC, протокол multi-peer-v1

Эксперимент APK 0.4.7. Общие лимиты ExitEngine остаются 128 TCP и 64 UDP,
а окно каждого TCP — 2 МиБ при согласовании с Windows. Отдельных каталогов,
HTTP комнат и сторонних relay для дополнительных соединений нет.

Android объявляет hello features multi-peer-v1 и limits.maxPeers=4. ПК выбирает
1, 2 или 4 общих соединения через PHONE_EXIT_PEERS. После разрешения пользователя
по умолчанию четыре при объявленной поддержке APK 0.4.7 и нативном транспорте,
одно для старых APK/Werift. Явный override проверяется и не подменяется.
Число 2 означает основной UDP/heartbeat плюс один отдельный TCP-транспорт,
4 — основной плюс три TCP-транспорта. Новые TCP соединения распределяются
по дополнительным транспортам по очереди; один поток не делится между ними.
UDP и исходный control остаются на основном PeerConnection.

На основном защищённом PeerConnection ПК создаёт ordered DataChannel
phone-exit-links-v1. Только после основного hello; не более одного канала.
Текстовые JSON сообщения до 32768 UTF-8 байт:

```
{type:"offer",lane:1..3,value:{type:"offer",sdp:"..."}}
{type:"answer",lane:1..3,value:{type:"answer",sdp:"..."}}
{type:"candidate",lane:1..3,value:{candidate:"...",sdpMid:"0",sdpMLineIndex:0}}
```

Offer отправляет только ПК, answer только телефон. Повтор offer/answer,
неизвестный lane или тип отклоняется. Кандидаты ПК идут после offer, ожидающие
remote SDP очереди ограничены 64. Никакой сигнализации через непроверенный HTTP;
только существующий DTLS. Каждый новый PeerConnection использует прежние STUN,
собственный ICE/DTLS/SCTP и проверку fingerprint, без TURN и ICE-TCP.
На Android фабрика общая, выход и ICE остаются привязанными к Wi-Fi.

На каждом дополнительном PeerConnection ПК создаёт ordered phone-exit-lane-v1.
Телефон сообщает {type:"lane-ready",lane:...}; далее ping/pong с десятичным id
раз в 2 с. Отсутствие ответа 8 с закрывает весь клиент. Основной heartbeat
продолжается во время настройки, общий срок настройки 40 с. Потеря любого
соединения или канала настройки останавливает SOCKS и все потоки; автоматического
продолжения через оставшиеся соединения или обычную сеть нет.

На дополнительных соединениях Android принимает только control lane и TCP
phone-exit-tcp-v1-N. DNS и PublicAddress фильтр прежние. У UDP нет отдельной
дополнительной реализации. Все selected/candidate ICE адреса всех соединений
передаются прежним исключениям TUN до его включения. Новый режим сам не создаёт
маршрутов и не требует прав администратора.

При Stop/потере Wi-Fi закрываются потоки и каналы всех соединений. Нативные
наблюдатели освобождаются сериализованно перед PeerConnection и общей фабрикой.
Секреты каталога и аккаунта не изменяются, SDP не хранится и не логируется.

Локальный тест multi-peer.test.js: четыре настоящих соединения native↔Werift,
шесть параллельных бинарных TCP потоков с half-close, распределение по трём
соединениям, UDP остаётся на основном, закрытие SOCKS после потери lane control.
USB vivo 0.4.7: HTTPS, UDP DNS/STUN и четыре независимых соединения; 8 загрузок
суммарно 32 МБ за 2,802 с (91,372 Мбит/с), heartbeat 5–32 мс. UDP 2/3 ответов
в короткой фазе — не считать отсутствие ответа доказанной потерей пакета.
Это локальная сеть; отдельные удалённые замеры приведены ниже. Полный TUN
с несколькими транспортами пока не подтверждён.

## Удалённый Samsung 0.4.7

Пользователь обновил Samsung и включил доступ. Каждый запуск — 8 HTTP загрузок
по 4 МБ, суммарно 32 МБ, одинаковые окна 2 МиБ/512 КиБ. Последовательные замеры:

| Соединения | Скорость, Мбит/с | Основной heartbeat, мс | UDP DNS ответы |
| --- | ---: | --- | --- |
| 1 | 18,874 | 316–647 | 14/14 |
| 4 | 32,020 | 335–349 | 8/8 |
| 4, повтор с предварительной проверкой sing-box | 5,544 | 322–342 | 46/46 |
| 2 | 18,412 | 315–332 | 14/14 |
| 4, третий запуск | 32,178 | 316–332 | 8/8 |
| 1, повтор базы | 18,493 | 334–841 | 13/14 |
| 4, повтор с sing-box | 32,282 | 325–333 | 8/8 |

В третьем запуске четыре независимых транспорта подтвердили выигрыш примерно
70% относительно первой базы; дополнительные TCP heartbeat 317–567 мс.
Время отдельных загрузок 6,867–7,857 с. В тесте двух транспортов все загрузки
заняли 13,567–13,830 с, дополнительные heartbeat 335–480 мс.
Однако один повтор сильно просел, причина не установлена; изменялся и маршрут.
Первоначально режим оставляли только явным экспериментом. Поддержка нескольких соединений
реализована и проверена, устойчивое ускорение и отсутствие редких просадок не
подтверждены. Нового полного TUN/Discord/игрового теста нет.
Повтор с sing-box не воспроизвёл просадку: 32,282 Мбит/с; дополнительные RTT
322–943 мс, все восемь загрузок 6,492–7,851 с. Причина предыдущей просадки
остаётся неизвестной, не считать её доказанной ошибкой sing-box.

14 npm-тестов и оконный SelfTest прошли. APK сборка/lint: 0 ошибок,
11 существующих предупреждений. После изменения ограничения локальных ICE
кандидатов отдельный настоящий multi-peer тест повторён и прошёл.
Диагностический probe теперь записывает число соединений, время каждой загрузки
и сводку последних RTT дополнительных каналов (снимки метрик раз в 2 с,
не отдельный ряд всех pong). SDP, IP и содержимое в этих файлах отсутствуют.

Для явного повторения на свободном телефоне/порту 1080:

```powershell
$env:PHONE_EXIT_PEERS='4'
$env:PHONE_EXIT_DIAG_PARALLEL='1'
$env:PHONE_EXIT_DIAG_STREAMS='8'
$env:PHONE_EXIT_DIAG_TOTAL_BYTES='32000000'
powershell -NoProfile -ExecutionPolicy Bypass -File pc/probe-phone.ps1 -Name SM-G990B
```

Удалённый APK до 0.4.7 явно отклоняет этот режим; обычный запуск прежних APK
совместим и использует одно соединение. Для обычного оконного клиента явно
заданный PHONE_EXIT_PEERS наследуется дочерним Node. Прежде чем проверять
системный режим, все дополнительные ICE адреса должны войти в transport событие.

После повторных успешных удалённых замеров около 32 Мбит/с пользователь прямо
разрешил применение по умолчанию. Отсутствие редких просадок не заявляется.
Обычный EXE выбирает четыре только по hello multi-peer-v1 + maxPeers=4;
старые APK сохраняют один. PHONE_EXIT_PEERS=1 остаётся контрольным вариантом.
Автоматического прямого выхода или переключения на старый режим после ошибки нет.
Финальный запуск без PHONE_EXIT_PEERS: четыре автоматически, 32 МБ за 8,146 с
(31,427 Мбит/с), основной RTT 320–335 мс, дополнительные 326–740, UDP DNS 9/9.
HTTPS/UDP STUN/sing-box цепочка, все 14 npm-тестов и оконный SelfTest прошли.

Отдельный Phone Exit - Boost.vbs запускает тот же Phone Exit.exe с процессной
переменной PHONE_EXIT_PEERS=4; системные переменные не меняет, PowerShell окно
не открывает. Локальный ярлык Phone Exit — Ускорение (тест).lnk имеет прежнюю
иконку EXE. Закрыть текущее окно перед этим запуском: нельзя держать два клиента
с одним локальным SOCKS портом. Обычный Phone Exit.exe автоматически согласует
число соединений; переменные тестового VBS на будущие запуски не влияют.
