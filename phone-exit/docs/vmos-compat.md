# Совместимость VMOS HTTP · Phone Exit 0.7.0

Выбран пользователем режим без root/Shizuku/ADB. Это совместимый поднабор
API управления устройством, не замена облачной инфраструктуры VMOS.
Базовый адрес `http://127.0.0.1:17842`, пути `/vcpcloud/api/padApi/<method>`.
Сохраняются поля code/msg/ts/data, padCode, taskId/taskStatus/taskResult/errorMsg.
padCode — id личного телефона из каталога. Authorization: Bearer ключ gateway;
для неизменённого VMOS-клиента AK=`phone-exit`, SK=тот же локальный ключ,
HMAC-SHA256 по существующей схеме VMOS, проверка x-date ±45 с и SHA256 тела.
Никакие ключи VMOS cloud для локального API не нужны. HTTP только loopback;
между ПК/хостингом/телефоном остаётся HTTPS и AES-GCM.

Поддерживаемые адреса:
Новые VMOS команды и параметры кадров требуют APK 0.6.0 (control.api=2).
Старый APK 0.5.x умеет исходный JPEG screenshot через /v1 без args;
gateway не выдаёт игнорируемые им PNG/resize/input параметры за выполненные.
- userPadList, padInfo, padDetail: свой каталог и фактическая доступность.
- padProperties: модель, версия Android/APK, размеры, root/разрешения/возможности.
- listInstalledApp, getListInstalledApp: приложения, версии, launcher activity.
- startApp: запуск существующей launcher Activity.
- getLongGenerateUrl, generatePreview: свежий скриншот и ограниченный временный URL.
- screenshot: асинхронное задание; screenshotInfo возвращает URL готового кадра.
- syncCmd/asyncCmd: ограниченный перевод Android-команд, без исполнения shell.
- simulateTouch/simulateClick/simulateSwipe/simulateLongPress: ограниченные жесты.
- inputText: Unicode в доступное обычное поле ввода; закрытые игровые/парольные
  поля и окна системных разрешений не обходятся. ACTION_SET_TEXT заменяет значение
  поля, а не вводит виртуальные клавиши игры.
- padTaskDetail/executeScriptInfo: queued/delivered/done/expired → статусы VMOS;
  при неизвестном исходе действий повтор не выполняется.
- Phone Exit checkUpdate/installUpdate остаются в /v1 API.

Новые команды /v1: deviceInfo, apps, foreground, keyevent, longPress, gesture,
inputText. keyevent поддерживает Home/Back/Recents, Volume Up/Down, Enter в
доступном поле, Delete в обычном поле. Нет универсальной инъекции KeyEvent.
Gesture: до 10 strokes, до 64 точек/путь, длительность до 5 с.
Screenshot: jpg/png, quality 0–100, width/height 1–1280, размер файла ≤1.4 MB.
Текст до 4096 UTF-16 символов; JSON команды в UTF-8 до 11 KB (включая escape).
Без заданных размеров сохраняет пропорции (длинная сторона ≤1280).

syncCmd распознаёт только целиком: `wm size`, `pm list packages [package]`,
`input tap x y`, `input swipe x1 y1 x2 y2 [ms]`, `input text ...`,
`input keyevent <поддерживаемый код>`, `monkey -p <package> -c
android.intent.category. LAUNCHER 1`, `am start -n package/activity` (только
декларированная launcher activity), известный короткий запрос foreground.
Нет оператора shell, произвольных pipes, подстановок, скриптов или запуска su.
Список apps постраничный (offset/limit, максимум 256 на страницу); syncCmd
`pm list packages` возвращает 501, если список не помещается в страницу, чтобы
не выдавать неполный список за полный. simulateTouch принимает один палец,
только завершённые down/move/up; прочие touch-параметры — ошибка 501.
`pidof`, stopApp/restartApp, force-stop, изменение глобального поворота,
перезагрузка, reset, switchRoot, управление ADB, системными файлами, GPS/SIM,
прокси/сертификатами и облачными ресурсами отвечают code 501, supported=false.
`pidof` не заменяется выдуманным PID. Каталог приложений не доказывает их запуск.
Возврат к Home не выдаётся за остановку игры.

Совместимый виртуальный экран — 1280×720 в landscape, 720×1280 в portrait.
Координаты syncCmd переводятся в фактическую геометрию Android. Явные width/height
simulateTouch задают контейнер координат; screenshot resize может менять пропорции,
как VMOS HTTP. Фактические размеры отдельно в deviceInfo. Не переносить шаблоны
между разными соотношениями сторон без проверки игры.

Только локальный gateway хранит расшифрованные preview в RAM: 30 с, максимум
8 кадров/8 MiB; URL содержит случайную capability, возвращает один кадр,
не живую видео-трансляцию. После истечения/удаления телефона URL недоступен.
Задания gateway также ограничены 256/120 с, после перезапуска их taskId неизвестны.
Чужие/удалённые телефоны и задания из другого аккаунта не доступны.
При работе через start-control-api.ps1 изменения списка заблокированных телефонов
в DPAPI профиле поступают gateway примерно за секунду; смена аккаунта останавливает
gateway и требует повторного запуска. Уже исполняемые действия не отменяются.
Пакет на несколько устройств может частично выполниться при сетевом сбое;
проверяйте записи каждого padCode/taskId и не повторяйте весь пакет автоматически.
Синхронное ожидание до 20 с, задача не отменяется и не повторяется после таймаута:
code 110012 и taskId позволяют узнать окончательный исход.

Специальные возможности и включатель управления выдаются вручную на каждом
телефоне. Расширенное чтение UI используется только для активного поля/foreground,
не собирает дерево или содержимое приложений в журнал. Тесты ввода выполняются
в отдельном временном приложении fixture, без запуска и изменений реальной игры.

Источник форматов: https://cloud.vmoscloud.com/vmoscloud/doc/en/server/OpenAPI.html
и фактический клиент MultiBot в папке пользователя (syncCmd отсутствует в текущем
каталоге документации VMOS, поэтому контракт сверяется с существующим кодом).

## Быстрый канал управления 0.7.0 (12 октября 2026)

Сохранены VMOS HTTP адреса и подпись. APK 0.7.0/versionCode 18 сообщает
control.api=3/directControl=true. Gateway лениво создаёт отдельный native WebRTC
peer на телефон; offer/полный ICE answer передаются AES-GCM через HTTPS broker.
После установки соединения команды и результаты идут по надёжному DTLS DataChannel
phone-exit-automation-v1, без PHP и TURN. Прямой канал независим от VPN-потоков.
WifiBinding удерживает process Wi-Fi binding до закрытия последнего native peer.

Протокол: команда JSON до 12000 байт с id/request/at/command/args; ответ JSON до
2100000 байт, бинарные части: 16 байт request, u32 BE total, u32 BE offset,
до 16384 байт данных. Последовательные offsets обязательны. До 4 ожидающих команд,
backpressure 256 KiB/8 с. История ответов ограничена 256 записями/8 MiB на канал;
завершённые записи вытесняются при заполнении. Известный request не повторяется при
обрыве; Android dedup общий с HTTP, до 4096 за 180 с. Ping 2 с, ПК закрывает канал
без pong за 10 с; Android за 14 с после подключения. Новый запрос может установить
новое соединение, предыдущие незавершённые действия не повторяются.

При живом прямом канале доступность подтверждается heartbeat: временная потеря
HTTPS-каталога не выключает его. Удаление/blocked телефона закрывает канал.
Старый APK использует HTTPS-команды. Обновления по-прежнему используют HTTPS.
Android idle control poll 4 с, после прямого соединения 15 с, ошибки backoff до
30 с. Установка/служба специальных возможностей требуют прежних разрешений.

USB vivo: настоящий native Android↔Node WebRTC по Wi-Fi, JPEG720×1280 quality65,
12 циклов screenshot+tap с темпом 2/с, все 12 эффектов подтверждены fixture metrics.
Кадр 171–354 мс, tap108–128 мс, полный цикл 288–477 мс. Первый setup2508 мс.
USB передавал только SDP через временный androidTest instrumentation; не кадры
или команды. Instrumentation перезапускает процесс, поэтому test script временно
перепривязывает уже вручную включённую accessibility-службу на USB: список других
служб и прежнее разрешение сохраняются. Это тестовая процедура, не функция APK.
Fixture/test APK и временные SDP удалены, приложение запущено снова.
Это текущая сеть, не подтверждение скорости удалённого WAN. APK собран/lint пройден.

До сбоя HTTPS подтверждены все 9 телефонов 0.6.0/api2, enabled/accessibility=true;
JPEG каждого удалённого проверен. PNG720×1280 у 7 удалённых прошёл; у последнего
SDK37 сработал честный screenshot_too_large, меньший PNG ещё не проверен.

Resource usage (не сообщает превышений за 24 ч) и Errors (нет новой причины сбоев,
отказы private protection-check — ожидаемая защита). Причина HTTPS не доказана.
