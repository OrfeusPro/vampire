# Автоматическое подключение и страны

Пожелание пользователя: активные Android-телефоны появляются в списке на ПК,
пользователь выбирает страну и подключается без передачи нового JSON каждый раз.
Реализован личный список: персональный APK автоматически регистрирует телефоны,
доступность и страна видны на ПК; подключение к выбранному устройству без кодов.
Стандартный APK также поддерживает прежнюю одноразовую ручную привязку.
Общий каталог и обслуживание телефонов других пользователей не входят в продукт.

Страна обозначает выход в интернет и определяется по внешнему IP Wi-Fi телефона,
а не по GPS, языку интерфейса или SIM. Несколько телефонов из разных стран дают
несколько стран в списке. Несколько телефонов из одной страны группируются,
но каждый остаётся отдельным устройством с именем и состоянием доступности.
Определение по Wi-Fi-запросу к [Cloudflare trace](https://www.cloudflare.com/cdn-cgi/trace)
при включении доступа на телефоне (`loc`). Cloudflare получает обычный запрос
с внешнего IP телефона. GPS не используется; полученный IP не сохраняется и
не передаётся в каталог. При ошибке доступен вариант «Страна неизвестна».

Нужна первоначальная доверенная привязка устройств и долговременная защищённая
авторизация; одноразовый код текущего протокола нельзя превращать в публичный
постоянный ключ. Для каждой сессии создавать новый ключ/комнату сигнализации.
Не хранить секреты в логах, репозитории или обычных открытых настройках.

Телефон объявляет готовность только при включённом пользователем обслуживании
и доступном Wi-Fi, с foreground-уведомлением и кнопкой остановки. Каталог хранит
ограниченный по времени статус: пропавшие устройства автоматически становятся
недоступными. На ПК выбор страны запускает согласование прямого WebRTC через PHP.
PHP остаётся каталогом и сигнализацией, не передаёт интернет-трафик.

Показывать имя телефона, страну и доступность. Не обещать успешное соединение
на основании одного online-статуса: прямой WebRTC может не пройти через NAT.
При потере телефона закрывать потоки; автоматический переход на другой телефон
требует отдельного решения, поскольку меняет IP и разрывает текущие соединения.

Пользователь выбрал только личные привязанные телефоны. На Android одна
привязка к ПК; её можно удалить отдельной кнопкой. На ПК до четырёх телефонов
с учётом ограничений текущего PHP-сервера (30 комнат, 100 сообщений в комнате).
При удалении устройства нужно также удалить привязку на телефоне.

Windows сохраняет ключи в `%USERPROFILE%/.phone-exit/phones.bin` с DPAPI CurrentUser.
Android шифрует конфигурацию AES-GCM ключом Android Keystore; резервное копирование
приложения отключено. Перенос файла на другой Windows-профиль не переносит доступ.
Долговременный ключ не передаётся PHP. Ключ комнаты каталога меняется каждые
5 минут, HMAC-SHA256 от ключа привязки. Каждое TCP/WebRTC-подключение получает
свежий случайный 256-битный токен обычного протокола v1.

Доступность — свежий heartbeat телефона (15 с), исчезает через 45 с без обновления.
Оба устройства должны иметь правильные системные часы; принимаются сообщения
с отклонением не более 45 с. Сообщения старых комнат и дубли запросов не запускают
новое соединение. Клиент использует текущую и предыдущую комнату при смене периода.
На Android после остановки соединения с ПК выход возвращается в режим ожидания;
кнопка «Остановить» выключает весь доступ. После потери Wi-Fi приложение ждёт сеть
и само регистрируется снова; серверные ошибки повторяются с backoff до 30 с.
ПК не переключает страну или телефон сам при разрыве связи.

Персональная регистрация, личный feed и защита сообщений описаны в `protocol.md`.
Приватный APK связан с DPAPI аккаунтом текущего профиля Windows; не публиковать файл.
После первого открытия не нужно повторять запуск для восстановления Wi-Fi.
Foreground notification показывает включённый доступ; пользователь может остановить его.
Фактически проверены: автообнаружение на пустом списке ПК, UA, HTTPS, Wi-Fi loss,
offline, автоматическое возвращение и HTTPS без открытия Activity. Перезапуск ОС
и политика фоновой работы разных производителей пока требуют отдельных проверок.
