# Каталог устройств для 30+ телефонов

Новый независимый endpoint: HTTPS `/phone-exit/directory.php`. Старые файлы сайта
и `hosting-webrtc-probe/signal.php` не меняются. На сервере хранится последняя
зашифрованная регистрация каждого телефона, а не растущая очередь heartbeat.
Ключ аккаунта для API: HMAC-SHA256(feedToken, `phone-exit-catalog-v1`).
Сервер сохраняет только SHA256 этого ключа как имя аккаунта, ciphertext и время
последнего обновления. Трафик пользователя через каталог не проходит.

POST JSON: `{version:1,token,op,...}`. `token` — 64 hex, HTTPS обязательно.
`pulse`: `{id,box}` — id 32 hex; box использует прежний ECDH/AES-GCM registration-v1.
Возвращает `{request:null|{iv,data}}`. Период 15 с. Телефон опрашивает только свою
запись и больше не создаёт комнаты для фонового ожидания.
`list`: возвращает `{devices:[{id,box,updated}],limit:256}`. ПК проверяет ciphertext,
время внутри него (45 с), совпадение id, blocked и неизменность ключа телефона.
`connect`: `{id,request:{iv,data}}`; request — AES-256-GCM, ключ SHA256 от
UTF8 `phone-exit-connect-v1` + бинарного phone token. IV 12 байт, AAD та же метка.
Plaintext `{at,request:<32 hex>,pairing:<v1 session>}`. Запрос живёт 45 с;
Android отклоняет повторные request, неверный тег и несвежие сообщения.

Сервер: 256 записей на аккаунт, максимум 32 аккаунта, ограниченные кадры/файлы,
flock, приватный каталог данных вне webroot, запись 0600. Не сохраняет token API,
имена, страны, ключ телефона, посещённые адреса или содержимое трафика в открытом виде.
Ответы no-store; TLS проверяется штатно. Шифрование не предотвращает DoS со стороны
обладателя персонального APK; он уже имеет capability добавления своих устройств.

ПК читает также старую комнату регистрации для совместимости. Для устойчивой
работы 30+ телефонов необходимо обновить APK на них: старый агент по-прежнему
создаёт комнаты и упирается в прежние серверные ограничения. Реальная нагрузка
хостинга с 30+ физическими устройствами требует отдельной проверки.

## Сигнализация 0.4.1

Зашифрованная регистрация содержит необязательное поле `signal`.
Значение `https://demochko.com/phone-exit/signal.php` означает поддержку нового
продуктового endpoint. Любое другое значение или отсутствие поля выбирает старый
закреплённый адрес. ПК передаёт endpoint транспорту и проверяет соответствие
`pairing.signal` выбранному телефону. Android 0.4.1 разрешает оба закреплённых
адреса по HTTPS без userinfo, query, fragment и нестандартного порта.

Формат offer/answer/candidate прежний. Новое хранилище вне webroot независимо
от диагностического: максимум 512 комнат, 100 сообщений и 262144 байта на комнату;
сопряжение 600 с, очистка после 900 с без обращений. Квота пересчитывается после
очистки. APK до 0.4.1 не принимает новый адрес и должен обновиться.
