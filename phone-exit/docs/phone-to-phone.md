## Каталог и ключи

Существующий `directory.php` сохраняет непрозрачный `box` целиком. Дополнительное
поле `box.peer` — AES-256-GCM (случайный IV 12 байт), ключ SHA256 от UTF-8
`phone-exit-peer-directory-v1` и 32 байт feedToken, AAD — та же метка.
Оно содержит id, name, token, country, busy, at, signal, role=exit.
Основной ECDH ciphertext для ПК остаётся прежним; закрытый ключ ПК в APK не передаётся.
Чтение каталога использует прежний HMAC catalogKey. Принимаются только записи
со совпадающим id, свежестью 45 секунд, известным HTTPS endpoint и ролью exit.
Свой id исключается. Старые APK без peer не предлагаются: выход нужно обновить.
Обладатель персонального APK теперь может подключаться к другим личным телефонам;
APK остаётся приватной capability. Локальный blocked-список ПК на Android не переносится.

Запрос connect: прежний AES-GCM `phone-exit-connect-v1` с token выхода,
новый случайный request 128 бит и токен WebRTC 256 бит на каждое подключение.
Сигнализация: role=pc на клиенте, role=phone на выходе. Протокол каналов
`phone-exit-control-v1`, `phone-exit-tcp-v1-N`, `phone-exit-udp-v1-N` прежний.
TCP: open/ready, бинарные кадры до 16384, credit, eof, error; окно клиента
262144, выхода 1048576. UDP: ненадёжный unordered канал, open/ready,
SOCKS5 UDP-заголовок, целый кадр до 1400 байт. Heartbeat 2 секунды, 8 секунд без pong.

## Android VPN

VpnService с явным системным согласием, foreground-уведомлением и остановкой.
Подключение требует Android 10+ (minSdk официального native AAR — 29).
Предоставление доступа остаётся доступно с Android 8: overrideLibrary ограничен
этой зависимостью, её JNI не загружается на API 26–28; вход в VPN защищён проверкой SDK.
TUN → закреплённый hev-socks5-tunnel → SOCKS5 на случайном loopback-порту → WebRTC.
IPv4 и IPv6 default routes, DNS 1.1.1.1 через выход. Никакого прямого fallback.
Phone Exit исключён из TUN для сигнализации/ICE и управления; остальные приложения
направляются через VPN. Выход использует только прежние Wi-Fi sockets и фильтр LAN.
При ошибке транспорта TUN удерживается, SOCKS/потоки закрываются; отключение
пользователем снимает VPN. Это не гарантия при force-stop/краше процесса: для неё
нужна системная блокировка соединений без VPN. Автозапуск VPN не реализуется.

Предоставление доступа останавливается при включении клиента и не возобновляется
самостоятельно после остановки VPN. Кнопка предоставления доступа включает его явно.
Смена ролей не отменяет работающего бота. Wi-Fi обязателен в первой реализации.

## Клиент через мобильный интернет: 0.9.3

Пользователь уточнил, что хочет выключать Wi-Fi на **подключающемся** телефоне,
сохраняя выход через Wi-Fi другого телефона. Это меняет политику только клиента.
`PeerDirectory.clientNetwork` принимает валидированную Wi-Fi/cellular сеть
с INTERNET/NOT_VPN. Текущая физическая default-сеть имеет приоритет; при активном
VPN выбирается доступный Wi-Fi, затем cellular. Невалидированная сеть и VPN
