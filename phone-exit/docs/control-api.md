# HTTP API управления личными телефонами · v1

Phone Exit APK остаётся Wi-Fi exit node. Управление не требует root, VPN или ADB.
ПК использует локальный HTTP gateway на 127.0.0.1:17842. Начиная с APK 0.7.0
команды и кадры идут через отдельный прямой WebRTC DataChannel. HTTPS
`/hosting-webrtc-probe/phone-exit-api/control.php` нужен для начального обмена
offer/answer/ICE, повторного подключения и обновлений. Уже установленный прямой
канал продолжает работать при недоступности HTTPS. Старые APK используют HTTPS
для каждой команды; частота такого режима ограничена опросом телефона.
Старые PHP и настройки сайта не изменяются. Это API устройства, не API игры.

По просьбе пользователя управление включено по умолчанию при новой установке;
явное выключение сохраняется при перезапуске/обновлении. Службу специальных
возможностей пользователь вручную включает в Android. Stop общего доступа останавливает агент.
Без Wi-Fi команды не выполняются. API скриншотов требует Android 11+;
на Android 8–10 сообщается unsupported, VPN продолжает работать. Защищённые
экраны не обходятся. Shell, root и произвольные keyevent не поддерживаются.
APK 0.6.0 объявляет control.api=2 и расширяет команды; APK 0.5.x — api=1.
APK 0.7.x объявляет api=3. В 0.7.1 минимальный интервал запуска скриншотов —
1000 мс, действий — отдельно 1000 мс. Это позволяет один кадр и одно действие
в секунду на телефон. Избыточные запросы ждут своей очереди в пределах таймаута;
после отмены или потери доступа отложенное действие не запускается. Программа
бота должна ограничивать частоту сама и не накапливать устаревшие действия.
Совместимые VMOS адреса, подпись и ограничения: [vmos-compat.md](vmos-compat.md).

Gateway запускается `pc/start-control-api.ps1`. Ключ локального API создаётся
случайно и хранится DPAPI CurrentUser в профиле `control-api.bin`; передавать
`Authorization: Bearer <ключ>`. Получение ключа для своего бота описано в README.
Ключи аккаунта передаются Node только через stdin. Слушать внешний интерфейс нельзя.

- `GET /v1/devices`: личные телефоны, online, установленная versionName/versionCode,
  controlEnabled/accessibility/screenshot, состояние обновления. Старые APK:
  версия неизвестна и управление не поддерживается.
- `POST /v1/devices/<id>/commands`: `{command,args}` → HTTP 202 `{id,status:"queued"}`.
  Команды: `status`, `screenshot`, `tap {x,y,width,height}`, `swipe
  {x1,y1,x2,y2,width,height,durationMs}`, `back`, `home`, `launch {package}`,
  `checkUpdate`, `installUpdate` (загрузка и уведомление для подтверждения).
  Дополнительные команды api=2: deviceInfo, apps, foreground, keyevent, inputText,
  longPress, gesture. Координаты в пикселях пропорционального кадра deviceInfo
  frameWidth/frameHeight; эти размеры должны совпадать с текущим экраном.
  После явно растянутого screenshot пересчитайте координаты в frameWidth/frameHeight.
  Swipe durationMs 100–3000. Скриншот JPEG/PNG, максимум 1280 по длинной стороне
  без явного resize; ответ содержит width/height и nativeWidth/nativeHeight.
- `GET /v1/devices/<id>/commands/<request>`: queued/delivered/expired/done и
  расшифрованный `{ok,result}` либо `{ok:false,error}`. delivered без результата
  означает неизвестный исход; действия автоматически не повторять.

Команды и результаты: AES-256-GCM, SHA256(UTF8 `phone-exit-control-v1` + raw
phoneToken), AAD та же метка, IV 12 случайных байт. Plaintext содержит id устройства,
32 hex request, at в миллисекундах. Срок команды 60 с, расхождение часов 45 с.
Результат привязан к тем же id/request. Телефон сохраняет request до выполнения;
после сбоя уже доставленная команда не выполняется повторно. PHP передаёт только
ciphertext, удаляет результаты через 120 с; скриншоты не пишутся в логи.
Максимум 32 задания на аккаунт и 4 ожидающих на телефон, результат до 2 MiB,
хранилище до 8 MiB. Сервер помечает доставку атомарно, не повторяет её.

FTPS аккаунт bot ограничен каталогом hosting-webrtc-probe. Новый API расположен
в отдельном подкаталоге phone-exit-api, прежний signal.php не изменяется.
Данные API и частные APK — в phone-exit-api/private, доступ извне запрещён
отдельным `.htaccess` с `Require all denied`; перед загрузкой APK проверяется HTTP 403.
Этот файл защиты обязателен. Каталог личных телефонов остаётся прежним.

Обновление: проверка каждые 30 мин через тот же авторизованный HTTPS endpoint,
скачивание APK только по Wi-Fi. Частный APK хранится в защищённом каталоге и выдаётся только
с capability аккаунта. Manifest: versionCode/versionName/size/sha256. Проверяются
размер, SHA256, applicationId, более высокий versionCode и совпадение сертификата
с установленным APK. Установка только кнопкой на телефоне, системное подтверждение
не обходится. Разрешение «установка неизвестных приложений» выдаётся вручную.
После установки registration сообщает реальный BuildConfig, не версию manifest.
Первое обновление старого APK ставится вручную: в нём ещё нет обновляющего агента.

## Быстрый канал управления 0.7.0 (12 октября 2026)

Сохранены VMOS HTTP адреса и подпись. APK 0.7.0/versionCode 18 сообщает
control.api=3/directControl=true. Gateway лениво создаёт отдельный native WebRTC
peer на телефон; offer/полный ICE answer передаются AES-GCM через HTTPS broker.
После установки соединения команды и результаты идут по надёжному DTLS DataChannel
phone-exit-automation-v1, без PHP и TURN. Прямой канал независим от VPN-потоков.
WifiBinding удерживает process Wi-Fi binding до закрытия последнего native peer.

Протокол: команда JSON до 12000 байт с id/request/at/command/args; ответ JSON до
2100000 байт, бинарные части: 16 байт request, u32 BE total, u32 BE offset,
до 16384 байт данных. Последовательные offsets обязательны. До 4 ожидающих команд,
backpressure 256 KiB/8 с. История ответов ограничена 256 записями/8 MiB на канал;
завершённые записи вытесняются при заполнении. Известный request не повторяется при
обрыве; Android dedup общий с HTTP, до 4096 за 180 с. Ping 2 с, ПК закрывает канал
без pong за 10 с; Android за 14 с после подключения. Новый запрос может установить
новое соединение, предыдущие незавершённые действия не повторяются.

При живом прямом канале доступность подтверждается heartbeat: временная потеря
HTTPS-каталога не выключает его. Удаление/blocked телефона закрывает канал.
Старый APK использует HTTPS-команды. Обновления по-прежнему используют HTTPS.
Android idle control poll 4 с, после прямого соединения 15 с, ошибки backoff до
30 с. Установка/служба специальных возможностей требуют прежних разрешений.
