# Локальная запись TCP в Phone Exit

21 октября 2026. Диагностический режим Windows, отдельный от runtime бота.
Он наблюдает TCP-данные внутри своего SOCKS-прокси, до отправки в WebRTC и
после получения из WebRTC. В игру ничего не внедряется. Передаваемые байты,
порядок, credit/backpressure и маршруты не изменяются.

## Как записывать

1. Перезапустить Phone Exit после обновления файлов, подключить нужный телефон
   и выбрать VPN для EXE игры / лаунчера. Старое уже открытое окно новую кнопку
   не загружает. Перезапуск отключает текущую связь, поэтому сначала закрыть игру.
2. Открыть «Диагностика TCP» в левой панели.
3. Указать точные адреса игровых соединений: `хост:порт`, по одному в строке.
   Например, `game.example:12001` — только пример, не реальный сервер Vampir.
   Нужны актуальные адреса лобби / выбранного игрового сервера, не адрес телефона,
   не локальный SOCKS 1080, не URL. Маски и запись всего трафика не поддерживаются.
   DNS-имя и IP считаются разными адресами: автоматического DNS-сопоставления нет.
4. Нажать «Начать запись», дождаться «ИДЁТ ЗАПИСЬ», затем запускать лаунчер / игру.
   Записываются только новые SOCKS CONNECT, открытые после включения режима.
   Соединение, открытое раньше, не начинает записываться посередине потока.
5. Пройти вход и нужный короткий сценарий. Нажать «Остановить» или закрыть
   диагностическое окно. Запись также завершается при остановке транспорта.

Файлы могут содержать SDK / игровые токены, идентификаторы и другие данные
аккаунта. Это приватная сырая запись; она не обезличивается перед сохранением.
Ничего автоматически не загружается на сервер и не добавляется в Git.
Диагностические события в stdout / интерфейсе содержат только состояние, случайный ID, счётчики и
фиксированная причина завершения, без содержимого и адресов соединений.

## Хранение и ограничения

В оконном клиенте каталог находится в текущем профиле Phone Exit:
`<профиль Windows>/.phone-exit/diagnostics/<случайный ID>/`.
Точный путь показан в окне. Для CLI родитель может явно задать
`PHONE_EXIT_DIAGNOSTICS_DIR`; сама эта переменная запись не включает.

Для одной записи: 180 секунд, 8 МиБ полезных данных суммарно в обе стороны,
12 МиБ JSONL, 2 МиБ очереди записи, 32 768 событий и 16 соединений.
Превышение любого лимита или ошибка диска выключает только наблюдение;
TCP / VPN продолжают работу. Такой захват считается ограниченным, не полным.
При обрыве или перезапуске клиента запись не возобновляется автоматически.
Новый запуск записи создаёт новый каталог, старые файлы не перезаписывает.

`traffic.jsonl` хранит `start`, `open`, `data`, `close`, `end`.
Каждый `data` содержит flow, направление `c2s` / `s2c`, смещение в этом направлении,
длину, время относительно начала и base64 байтов. Границы chunks — наблюдения
TCP / WebRTC, не границы игровых пакетов. `summary.json` описывает завершение.
`complete` относится к штатному завершению записи, не к завершению всех TCP-сессий.
Принудительное убийство процесса может оставить файл без `end` / summary.

## Проверка и извлечение потоков

Из корня `phone-exit/pc`:

```powershell
node src/capture-inspect.js "C:/полный/путь/traffic.jsonl"
node src/capture-inspect.js "C:/полный/путь/traffic.jsonl" --export
```

По умолчанию инструмент выводит SHA256, счётчики и признак завершения, без тел,
адресов и токенов. Проверяются ограничения, порядок flow, base64, длины и смещения.
Экспорт создаёт соседний новый каталог `streams` с отдельными бинарными файлами
для каждого направления. Существующий каталог не перезаписывается. Эти файлы
также приватные. Незавершённая последняя строка и повреждённые записи отклоняются;
отсутствующий `end` при целых строках обозначается `finalized=false`.

Запись не снимает TLS или внутреннее шифрование игры. HTTPS остаётся зашифрованным.
Следующий этап для Vampir — сопоставить полные потоки с проверенными framing /
key-change codecs и сравнить поля официального Login с ботом. Декодер самих
игровых пакетов и автоматический подбор адресов в это окно пока не включены.

## Проверено

Точные фильтры, выключенное начальное состояние, смещения и бинарные данные,
экспорт без перезаписи, все лимиты, ошибки файловой системы, повреждённый файл.
В реальном локальном WebRTC через native / werift проверены три параллельных TCP,
совпадение захваченных данных с переданными, half-close и продолжение передачи
после лимита записи. Собственный тест окна проверяет start/stop-команды,
запрет неверного фильтра, состояние записи, resize и DPI; снимок проверен визуально.
Smoke test главного окна прошёл. Реальная запись Vampir / удалённого телефона
этими тестами не подтверждена.
