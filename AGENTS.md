# Phone Exit: действующие правила проекта

Здесь только устойчивые требования и порядок работы. Состояние, версии и результаты
проверок вести в README компонентов; историю не дописывать в AGENTS.md.
Поздние явные уточнения пользователя имеют приоритет над прежними записями.

## Работа с проектом

- Код продукта размещать в `phone-exit/`. Язык интерфейса и документации — русский.
- Не создавать подагентов без прямой просьбы пользователя.
- Делать коммиты законченных изменений с понятным описанием. Проверять пробелы
  между словами и числами; не исправлять технические обозначения массовой заменой.
- Использовать закреплённые зависимости и lock-файлы. Не коммитить SDK,
  node_modules, сборки, ключи, токены, данные комнат и приватные captures.
  Секреты задавать при запуске, не выводить в логи.
- Не заменять персональный `account.bin` при обычной пересборке: он связывает
  этот ПК и выданные APK. Персональный APK содержит capability аккаунта;
  передавать только своим телефонам, не публиковать открыто.
- Сохранять реальные профили, привязки и несохранённые пользовательские изменения.
  Проверки UI не должны незаметно сохранять настройки или отправлять игровые команды.
- Старые диагностические проекты не удалять без разрешения. Ранее разрешённая
  очистка отдельных probes описана в архиве и не разрешает новую массовую очистку.

## Сеть и режимы

- Цель — выход Windows / Android через личные привязанные телефоны без настройки
  роутеров. На Windows нужны весь трафик и выбранные приложения / игры, включая
  отдельные EXE игры, лаунчера и нужные дочерние процессы. TCP, UDP и DNS проверять
  отдельно; SOCKS CONNECT сам по себе не подтверждает системный VPN.
- В обеих Android-ролях разрешены Wi-Fi и мобильный интернет. Валидированный
  Wi-Fi имеет приоритет даже при системном default LTE; LTE — запасной.
  Показывать выбранную сеть и учитывать расход SIM-трафика.
- VPN-трафик Windows и Android — IPv4. IPv6 выбранного для туннеля трафика не
  должен обходить VPN; системный IPv6 ОС глобально не отключать.
- При потере телефона выбранный для туннеля трафик блокируется. В выборочном
  режиме остальной трафик сохраняет обычный выход. После явного Stop не включать
  передачу автоматически. На телефоне показывать foreground notification и Stop.
- Сигнализация PHP передаёт только служебные данные через HTTPS; пользовательский
  трафик идёт по защищённому WebRTC. TURN по умолчанию отсутствует; при невозможности
  прямой связи сообщать ошибку, не включать сторонний relay скрытно.
- SOCKS и локальный API слушают только loopback. На телефоне отклонять loopback,
  private, link-local и multicast назначения, включая результаты DNS. Доступ к LAN
  через телефон не разрешён. Использовать обычную проверку TLS и DTLS WebRTC.
- Ограничивать потоки, кадры, очереди и таймауты; поддерживать backpressure,
  двустороннее закрытие и cleanup при потере канала. Не оставлять фоновые процессы
  без владельца. Ключ сопряжения — минимум 256 случайных бит, вне Git и логов.
- Маршруты, драйверы и права администратора применять только по необходимости
  в согласованном включении режима. Не менять firewall / защиту ОС и не отключать
  чужие VPN / фильтры автоматически; конфликт объяснять пользователю.

## Данные, управление и публикация

- По умолчанию не собирать содержимое трафика, посещённые адреса и постоянную
  телеметрию. Согласованная [TCP-диагностика](phone-exit/pc/DIAGNOSTICS.md) включается
  явно, имеет лимиты и хранит приватные записи вне Git. При reconnect сама не включается.
- Продуктовый VMOS-совместимый API работает без root / Shizuku / ADB. Не выдавать
  неподдержанную команду за выполненную; неизвестный результат действия не повторять
  вслепую. Accessibility / разрешения Android и установку APK подтверждает пользователь
  штатным способом. Тихую установку без дополнительных прав не обещать.
- Не менять WHM и существующий сайт. Деплой продукта — в отдельный каталог;
  сохранять используемые PHP endpoints и данные Phone Exit.
- До распространения APK / внешней публикации проверять сборку. Для частного
  релиза проверять фактический HTTP 403 каталога private, размер, SHA, версию и
  подпись APK. Опубликованный файл не подменять без увеличения versionCode.
  Пароли публикации передавать только через stdin; HTTP не использовать как обход TLS.

## Подтверждение результата

- Проверять изменение в соответствующем объёме: локальные тесты протокола,
  настоящий WebRTC для интеграции, сборка / lint Android и нужные UI-проверки.
  Для транспорта учитывать параллельные TCP / UDP, DNS, таймауты, half-close,
  переполнение, потерю выбранной сети / канала и изоляцию аккаунтов / комнат.
- Заявление о работе на удалённом телефоне требует проверки на удалённом устройстве:
  HTTPS, выходной IP, нужный UDP-сценарий и блокировка после потери транспорта.
  USB / текущая сеть не доказывают WAN, все игры или длительную стабильность.
- Если SDK / устройство недоступны, явно разделять собранное, проверенное и ещё
  непроверенное. Обновлять README по фактам; гипотезы и fixtures обозначать.
- Перед коммитом проверять diff и ссылки. Для изменений Vampir дополнительно
  выполнять проверки знаний из `bots/AGENTS.md`; историю и runtime не смешивать.
